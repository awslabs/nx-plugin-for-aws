## 步骤 1：初始化新的 Nx 工作区

运行以下命令，使用您选择的包管理器创建一个 <Link path="guides/workspace">Nx 工作区</Link>：

<CreateNxWorkspaceCommand workspace="my-project" />

:::tip[选择 IaC 提供商]
系统将提示您选择首选的基础设施即代码（IaC）提供商，可以是 [CDK](https://docs.aws.amazon.com/cdk/) 或 [Terraform](https://developer.hashicorp.com/terraform)。您可以通过使用 `--iac` 运行命令来跳过提示，例如：

<Infrastructure>
<Fragment slot="cdk">
<CreateNxWorkspaceCommand workspace="my-project" iac="cdk" />
</Fragment>
<Fragment slot="terraform">
<CreateNxWorkspaceCommand workspace="my-project" iac="terraform" />
</Fragment>
</Infrastructure>
:::

完成后，导航到项目目录：

```sh
cd my-project
```

## 步骤 2：使用生成器搭建项目脚手架

在本快速入门指南中，我们将添加 tRPC API、React 网站、Cognito 身份验证以及 CDK 或 Terraform 基础设施。根据您正在构建的项目类型，您可以选择任意组合的生成器来快速引导您的项目。查看左侧导航栏中的 __生成器__ 以查看完整的选项列表，或尝试使用<Link path="get_started/graph-builder">图形构建器</Link>以可视化方式构建您的工作区。

作为快捷方式，您可以使用下面的按钮复制命令来搭建完整应用程序的脚手架。

<EmbeddedGraph preset="quick-start" workspace="my-project" iac="cdk" orientation="horizontal" skipWorkspace />

:::tip[使用 AI 构建]
<Link path="get_started/building-with-ai">Nx Plugin for AWS MCP Server</Link> 已在您的工作区中配置好，因此您可以让您喜欢的 AI 编码助手（如 Kiro 或 Claude）为您构建这些项目，而无需自己输入 CLI 命令。
:::

否则，请按照以下步骤自行运行每个生成器。

### 添加 tRPC API

<RunGenerator generator="ts#api" requiredParameters={{ name: 'demo-api', framework: 'trpc', auth: 'iam' }} />

这将在 `packages/demo-api` 文件夹中创建 API。

### 添加 React 网站

<RunGenerator generator="ts#website" requiredParameters={{ name: 'demo-website' }} />

这将在 `packages/demo-website` 中搭建一个新的 React 网站。

### 添加 Cognito 身份验证

<RunGenerator generator="ts#website#auth" requiredParameters={{ project: '@my-project/demo-website', cognitoDomain: 'my-demo' }} />

这将设置必要的基础设施和 React 代码，以便为您的网站添加 Cognito 身份验证。

### 连接前端到后端

<RunGenerator generator="connection" requiredParameters={{ sourceProject: '@my-project/demo-website', targetProject: '@my-project/demo-api' }} />

这将配置必要的提供程序，以确保您的网站可以调用您的 tRPC API。

### 添加基础设施

根据您选择的 IAC 提供商添加基础设施项目。

<Infrastructure>
<Fragment slot="cdk">
<RunGenerator generator="ts#infra" requiredParameters={{ name: 'infra' }} />

这将配置一个 CDK 应用程序，您可以使用它在 AWS 上部署基础设施。
</Fragment>
<Fragment slot="terraform">
<RunGenerator generator="terraform#project" requiredParameters={{ name: 'infra' }} />

这将配置一个 Terraform 项目，您可以使用它在 AWS 上部署基础设施。
</Fragment>
</Infrastructure>

## 步骤 3：在本地运行您的网站和 API

使用以下命令为您的网站及其连接的 API 启动本地开发服务器：

<PackageManagerShortCommand commands={["dev"]} />

您的网站将在 `http://localhost:4200` 上可用。

对网站和 API 的更改都将实时反映，因为本地网站和 API 服务器都将热重载。

## 步骤 4：定义云资源并部署到 AWS

<Infrastructure>
<Fragment slot="cdk">
打开 `packages/infra/src/stacks/application-stack.ts` 并添加以下代码：

```typescript
import { Stack, StackProps } from 'aws-cdk-lib';
import { DemoApi, DemoWebsite, UserIdentity } from '@my-project/common-constructs';
import { Construct } from 'constructs';

export class ApplicationStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props);

    const identity = new UserIdentity(this, 'identity');
    const api = new DemoApi(this, 'api', {
      integrations: DemoApi.defaultIntegrations(this).build(),
    });
    api.grantInvokeAccess(identity.identityPool.authenticatedRole);

    new DemoWebsite(this, 'website');
  }
}
```

这就是我们部署全栈应用程序所需编写的全部 CDK 代码。
</Fragment>
<Fragment slot="terraform">
打开 `packages/infra/src/main.tf` 并添加以下代码：

```hcl
# Include metrics tracking for @aws/nx-plugin usage
module "metrics" {
  source = "../../common/terraform/src/metrics"
}

# Deploy user identity
module "user_identity" {
  source = "../../common/terraform/src/core/user-identity"
}

# Shared asset bucket — stages Lambda deployment zips for every lambda / API module
module "asset_bucket" {
  source = "../../common/terraform/src/core/asset-bucket"
}

# Deploy API
module "demo_api" {
  source = "../../common/terraform/src/app/apis/demo-api"

  asset_bucket_name = module.asset_bucket.bucket_name
}

# Grant authenticated users access to invoke the API
resource "aws_iam_policy" "api_invoke_policy" {
  name        = "DemoApiInvokePolicy"
  description = "Policy to allow authenticated users to invoke the API"

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Action = "execute-api:Invoke"
        Resource = "${module.demo_api.api_execution_arn}/*/*"
      }
    ]
  })
}

resource "aws_iam_role_policy_attachment" "authenticated_api_access" {
  role       = module.user_identity.authenticated_role_name
  policy_arn = aws_iam_policy.api_invoke_policy.arn
}

# Deploy website
provider "aws" {
  alias  = "us_east_1"
  region = "us-east-1"
}

module "demo_website" {
  source = "../../common/terraform/src/app/static-websites/demo-website"

  providers = {
    aws.us_east_1 = aws.us_east_1
  }

  depends_on = [module.user_identity, module.demo_api]
}
```

这就是我们部署全栈应用程序所需编写的全部 Terraform 代码。
</Fragment>
</Infrastructure>

### 构建并部署基础设施

接下来，运行以下命令来构建您的项目：

<PackageManagerShortCommand commands={["build"]} />

:::tip[修复 Lint 错误]
如果遇到任何 lint 错误，您可以运行以下命令自动修复它们。

<PackageManagerShortCommand commands={["lint"]} />
:::

引导您的基础设施：

<Infrastructure>
<Fragment slot="cdk">
<NxCommands commands={['bootstrap infra']} />

:::tip[引导区域]
CDK 引导对于您的目标部署 AWS 区域和 `us-east-1` 都是必需的，以允许为网站部署 AWS WAF WebACL。
:::
</Fragment>
<Fragment slot="terraform">
<NxCommands commands={['bootstrap infra']} />

:::tip[一次性设置]
Terraform 引导会创建一个 S3 存储桶来存储您的 Terraform 状态文件。每个 AWS 账户/区域组合只需执行一次。
:::
</Fragment>
</Infrastructure>

部署您的项目：

<Infrastructure>
<Fragment slot="cdk">
<NxCommands commands={['deploy infra "my-project-infra-sandbox/*"']} />
</Fragment>
<Fragment slot="terraform">
<NxCommands commands={['apply infra']} />

:::tip[应用前先计划]
此命令将首先运行 `terraform plan` 以显示将进行的更改，然后应用这些更改以部署您的基础设施。
:::
</Fragment>
</Infrastructure>

## 步骤 5：使用已部署的云资源测试网站

<Steps>
1. 获取 `runtime-config.json` 文件：

    <NxCommands commands={['load-runtime-config demo-website']} />

2. 启动本地网站服务器

    <NxCommands commands={['serve demo-website']} />
</Steps>

您的网站将在 `http://localhost:4200` 上可用，并将指向您为 API 和身份验证部署的资源。
