## 任务 1：实现游戏 API

我们将在本节中实现以下 API：

1. `saveGame` - 创建或更新游戏。
2. `queryGames` - 返回先前保存的游戏的分页列表。
3. `queryInventory` - 返回玩家库存中物品的分页列表。
4. `queryActions` - 返回给定游戏的对话历史记录。

:::note[每个状态片段的存储位置]
- `games` 和 `inventory` 存储在 **DynamoDB**（通过 ElectroDB）— 游戏 API lambda 和库存 MCP 服务器读写它们。
- `actions`（聊天记录）存储在 **S3** — Story Agent 的 `S3SessionManager` 每回合写入一个 JSON blob，游戏 API 中的 `queryActions` 读取它们，以便 UI 可以在页面重新加载时重放历史记录。没有 `saveAction` 过程；代理是唯一的写入者。
:::

### 实体建模

这是我们应用程序的 ER 图。

```d2
direction: right

game: Game {
  shape: sql_table
  playerName: "string  PK"
  genre: string
  lastUpdated: string
}

item: Item {
  shape: sql_table
  playerName: "string  PK"
  itemName: "string  SK"
  emoji: "string  (optional)"
  lastUpdated: string
  quantity: number
}

game -> item: 1..*
```

`ts#dynamodb` 生成器设置了 [ElectroDB](https://electrodb.dev/en/core-concepts/introduction/)，我们将使用它来建模我们的数据。我们将在 S3 中持久化对话历史记录，因此我们添加对 S3 客户端的依赖：

## 任务 4：在本地测试游戏 API

无需部署到 AWS 即可试用我们的 API — `dev` 目标针对 [DynamoDB Local](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/DynamoDBLocal.html) 运行游戏 API。因为我们在模块 1 中将游戏 API 连接到 `DungeonDb` 项目，所以此目标也会自动启动 DynamoDB Local。

我们刚刚编写的过程和 MCP 服务器导入了 `@dungeon-adventure/dungeon-db`，这是一个新的跨项目导入，因此首先同步工作区：

<NxCommands commands={["sync"]} />

<Aside type="tip" title="为什么需要此步骤">
`nx sync` 在 `game-api` 和 `inventory` 的 `package.json` 文件中声明 `@dungeon-adventure/dungeon-db`，并为您添加匹配的 TypeScript 项目引用，使您无需在声明项目之间的依赖关系时手动添加。
</Aside>

然后修复任何 lint 问题：

<PackageManagerShortCommand commands={["lint"]} />

并构建代码库：

<PackageManagerShortCommand commands={["build"]} />

### 启动本地服务器

使用 `dev` 目标在本地启动游戏 API，这也会启动 DynamoDB Local：

<NxCommands commands={["dev game-api"]} />

<Aside type="tip" title="首次运行">
首次运行会拉取 DynamoDB Local 容器镜像，这可能需要一些时间。让服务器在此终端中保持运行，并打开第二个终端用于下面的 `curl` 命令。
</Aside>

### 测试 API

一旦您的服务器启动并运行，查询（空的）游戏列表：

```bash
curl -X GET 'http://localhost:2022/games.query?input=%7B%7D'
```

:::note[URL 编码]
我们传递给测试 API 的 `%7B%7D` 是 URI 编码的空 JSON 对象（`{}`）。
:::

您将看到一个空列表：

```json
{"result":{"data":{"items":[],"cursor":null}}}
```

现在保存一个游戏：

```bash
curl -X POST 'http://localhost:2022/games.save' \
  -H 'Content-Type: application/json' \
  -d '{"playerName":"Alice","genre":"zombie"}'
```

保存操作返回持久化的游戏（带有实体为您设置的 `lastUpdated` 时间戳）：

```json
{"result":{"data":{"playerName":"Alice","genre":"zombie","lastUpdated":"..."}}}
```

再次查询以确认它已持久化到 DynamoDB Local：

```bash
curl -X GET 'http://localhost:2022/games.query?input=%7B%7D'
```

此响应现在包含已保存的游戏：

```json
{"result":{"data":{"items":[{"playerName":"Alice","genre":"zombie","lastUpdated":"..."}],"cursor":null}}}
```

完成后，您可以停止本地服务器（`Ctrl+C`）。

## 任务 5：在本地测试库存 MCP 服务器

我们可以使用 [MCP Inspector](https://github.com/modelcontextprotocol/inspector) 通过生成的 `mcp-server-inspect` 目标试用 MCP 服务器的工具：

<NxCommands commands={["mcp-server-inspect inventory"]} />

这会在本地提供 MCP 服务器（也会启动 DynamoDB Local）并在 `http://localhost:6274` 启动 MCP Inspector，预配置为连接到它。点击 **Connect**，切换到 **Tools** 选项卡，点击 **List Tools**，然后尝试 `add-to-inventory`（例如 `playerName: Alice`、`itemName: Rusty Sword`、`emoji: ⚔️`），然后使用 `list-inventory-items` 查看它已持久化到 DynamoDB Local。完成后停止服务器（`Ctrl+C`）。
