## 任务 1：实现 Story 代理

Story 代理是一个在<Link path="get_started/tutorials/dungeon-game/1">模块 1</Link>中使用 `--protocol=ag-ui` 生成的 [Strands](https://strandsagents.com/) 代理，因此 UI 可以通过 CopilotKit 使用 [Agent-User Interaction 协议](https://docs.copilotkit.ai/aws-strands/protocol)从中流式传输数据。它使用 Inventory MCP Server 来管理玩家的物品，并且已经通过模块 1 中生成器提供的 `session.py` 持久化对话历史——部署后，这就是 Strands 内置的 [`S3SessionManager`](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/agents/sessions/) 写入到 Game API 的 `queryActions` 读取的同一个 S3 存储桶中，这样浏览器可以在重新访问时重建对话记录。

### 与您的代理聊天

生成的 `agent-chat` 目标会打开一个针对您的代理的交互式 REPL。它独立运行并连接到您本地运行的代理，因此首先在一个终端中启动代理的本地服务器：

<NxCommands commands={["agent-dev story"]} />

然后，在第二个终端中启动聊天：

<NxCommands commands={["agent-chat story"]} />

您的第一条消息应该告诉代理您的英雄的名字和类型（例如：`My name is Alice. Start my zombie adventure.`），故事将流式返回。

<Aside type="caution" title="需要 AWS 凭证">
虽然代理在本地运行，但它会调用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 来使用 LLM。您需要在环境中配置 AWS 凭证，并具有访问 [Strands 默认模型](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/model-providers/amazon-bedrock/)的权限。有关详细信息，请参阅 [Strands 模型提供商文档](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/model-providers/amazon-bedrock/)。
</Aside>
