---
title: 管理员凭证
---
import Infrastructure from '@components/infrastructure.astro';

Aurora 管理员（主）用户的密码由 Aurora 本身在 AWS Secrets Manager 中生成和轮换，使用 [RDS 托管的主用户密码](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/rds-secrets-manager.html)。您的基础设施代码永远不会收到密码，因此它不会泄漏到 CloudFormation 模板或 Terraform 状态文件中。Aurora 每 7 天轮换一次密钥，无需部署或维护任何轮换函数。

该密钥使用与集群相同的客户托管 KMS 密钥进行加密。

您的应用程序永远不会使用这些凭证。它使用 IAM 身份验证以最小权限数据库用户的身份连接——只有迁移和创建数据库用户处理程序读取管理员密钥，并且每个处理程序仅被授予对该密钥及其 KMS 密钥的访问权限。

<Infrastructure>
<Fragment slot="cdk">

管理员密钥在底层集群上作为 `secret.secretArn` 公开，`grantSecretRead` 授予消费者对其的读取访问权限：

```ts title="packages/infra/src/stacks/application-stack.ts"
import { MyDatabase } from '@my-scope/common-constructs';

const db = new MyDatabase(this, 'Db', { ... });

db.grantSecretRead(myFunction);
```
</Fragment>
<Fragment slot="terraform">

管理员密钥的 ARN 作为 `secret_arn` 输出公开，同时还有解密所需的 `kms_key_arn`：

```hcl title="packages/infra/src/main.tf"
module "my_database" {
  source = "../../common/terraform/src/app/dbs/my-database"
  ...
}

output "database_secret_arn" {
  value = module.my_database.secret_arn
}
```

RDS 托管的密钥仅包含一个带有 `username` 和 `password` 的 JSON 对象——没有连接详细信息。从模块的 `writer_endpoint`、`cluster_port` 和 `database_name` 输出中获取主机、端口和数据库名称。
</Fragment>
</Infrastructure>
