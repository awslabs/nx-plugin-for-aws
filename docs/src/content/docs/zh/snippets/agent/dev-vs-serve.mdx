#### `-dev` 与 `-serve`

生成器添加了两个在相同端口上运行相同服务器的目标。它们仅在设置的环境上有所不同：

| 目标 | 环境 | 用途 |
| --- | --- | --- |
| `<your-agent-name>-dev` | `PORT`, `LOCAL_DEV=true` | 本地开发 |
| `<your-agent-name>-serve` | `PORT` | 在本地测试已部署的代码路径 |

**使用 `<your-agent-name>-dev` 进行本地开发。** `LOCAL_DEV=true` 将代理切换到其本地代码路径：会话状态被写入工作区根目录下的 `tmp/agents/` 磁盘，并且任何连接的 MCP 服务器都通过直接 HTTP 访问，而不是通过 AgentCore。它也是项目级 `dev` 目标聚合的目标，以及 `<your-agent-name>-chat` 目标期望找到正在运行的目标。

`<your-agent-name>-serve` 运行与已部署代理相同的代码路径，它从 AppConfig 中的<Link path="guides/runtime-config">运行时配置</Link>解析会话存储和连接的运行时 ARN。这需要将 `RUNTIME_CONFIG_APP_ID` 设置为部署的 AppConfig 应用程序 ID（由已部署的堆栈输出为 `RuntimeConfigApplicationId`），以及允许读取它的 AWS 凭证：

```bash
RUNTIME_CONFIG_APP_ID=<app-id> nx run your-project:agent-serve
```

:::caution[`-serve` 需要已部署的配置]
在没有 `RUNTIME_CONFIG_APP_ID` 的情况下启动，`<your-agent-name>-serve` 接受请求，但每次调用都会失败，并显示 `RUNTIME_CONFIG_APP_ID is not set — cannot resolve connected agent ARNs from AppConfig.`

设置 `LOCAL_DEV=true` 以改用本地代码路径——这正是 `<your-agent-name>-dev` 已经为您做的。
:::
