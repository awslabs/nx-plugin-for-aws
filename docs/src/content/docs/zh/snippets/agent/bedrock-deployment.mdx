### 基础设施即代码

如果您为 `infra` 选择了 `agentcore` 或 `agentcore-ecr`，将生成相关的 CDK 或 Terraform 基础设施，您可以使用它将您的 Agent 部署到 [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html)。

<Infrastructure>
<Fragment slot="cdk">
将为您的 agent 生成一个 CDK 构造，根据您运行生成器时选择的 `name` 命名，或默认为 `<ProjectName>Agent`。

您可以在 CDK 应用程序中使用此 CDK 构造：

```ts
import { MyProjectAgent } from '@my-scope/common-constructs';

export class ExampleStack extends Stack {
  constructor(scope: Construct, id: string) {
    new MyProjectAgent(this, 'MyProjectAgent');
  }
}
```

:::note[CDK 构造]
此构造使用 [`aws-cdk-lib/aws-bedrockagentcore` 模块](https://docs.aws.amazon.com/cdk/api/v2/docs/aws-cdk-lib.aws_bedrockagentcore-readme.html)。
:::
</Fragment>
<Fragment slot="terraform">
将为您生成一个 Terraform 模块，根据您运行生成器时选择的 `name` 命名，或默认为 `<ProjectName>-agent`。

将共享的 <Link path="/zh/guides/runtime-config#writing-configuration">`runtime_config_appconfig`</Link> 模块的输出传递给 agent 模块。在默认的 `agentcore` 打包方式下，agent 的代码会暂存在共享资产存储桶中，因此也需要传递该存储桶 — 像 Lambda 和 API 模块已经做的那样，为每个部署实例化一次 `core/asset-bucket` 模块：

```terraform
module "asset_bucket" {
  source = "../../common/terraform/src/core/asset-bucket"
}

module "my_project_agent" {
  source = "../../common/terraform/src/app/agents/my-project-agent"

  appconfig_application_id  = module.runtime_config_appconfig.application_id
  appconfig_application_arn = module.runtime_config_appconfig.application_arn

  # Only for `agentcore` packaging; `agentcore-ecr` publishes to ECR instead.
  asset_bucket_name = module.asset_bucket.bucket_name
  asset_bucket_arn  = module.asset_bucket.bucket_arn
}
```
</Fragment>
</Infrastructure>

:::note[Bedrock 模型权限]
生成的 agent 构造默认授予调用所有 Bedrock 基础模型和推理配置文件的权限（对 `arn:aws:bedrock:*:*:foundation-model/*` 和 `arn:aws:bedrock:*:*:inference-profile/*` 的 `bedrock:InvokeModel` 和 `bedrock:InvokeModelWithResponseStream`）。

您可能希望将其范围缩小到您的 agent 使用的特定模型。您可以在 [Strands 文档](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/model-providers/amazon-bedrock/#default-model)中找到 Strands agents 使用的默认模型；有关配置不同模型的信息，请参阅 [Strands 模型提供商指南](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/model-providers/)。
:::

### 身份验证

生成器提供了一个 `auth` 选项来配置您的 Agent 的身份验证。在生成 agent 时，您可以选择 `IAM`（默认）或 `Cognito` 身份验证。

#### IAM

默认情况下，您的 Agent 将使用 IAM 身份验证进行保护，只需在不带任何参数的情况下部署它：

<Infrastructure>
<Fragment slot="cdk">
```ts {5}
import { MyProjectAgent } from '@my-scope/common-constructs';

export class ExampleStack extends Stack {
  constructor(scope: Construct, id: string) {
    new MyProjectAgent(this, 'MyProjectAgent');
  }
}
```

您可以使用 `grantInvokeAccess` 方法授予在 Bedrock AgentCore Runtime 上调用您的 agent 的访问权限，例如：

```ts {8}
import { MyProjectAgent } from '@my-scope/common-constructs';

export class ExampleStack extends Stack {
  constructor(scope: Construct, id: string) {
    const agent = new MyProjectAgent(this, 'MyProjectAgent');
    const lambdaFunction = new Function(this, ...);

    agent.grantInvokeAccess(lambdaFunction);
  }
}
```
</Fragment>
<Fragment slot="terraform">
```terraform {9-10}
module "asset_bucket" {
  source = "../../common/terraform/src/core/asset-bucket"
}

# Agent
module "my_project_agent" {
  # Relative path to the generated module in the common/terraform project
  source = "../../common/terraform/src/app/agents/my-project-agent"

  appconfig_application_id  = module.runtime_config_appconfig.application_id
  appconfig_application_arn = module.runtime_config_appconfig.application_arn

  # Only for `agentcore` packaging; `agentcore-ecr` publishes to ECR instead.
  asset_bucket_name = module.asset_bucket.bucket_name
  asset_bucket_arn  = module.asset_bucket.bucket_arn
}
```

要授予调用您的 agent 的访问权限，您需要添加如下策略，引用 `module.my_project_agent.agent_core_runtime_arn` 输出：

```terraform
{
  Effect = "Allow"
  Action = [
    "bedrock-agentcore:InvokeAgentRuntime"
  ]
  Resource = [
    module.my_project_agent.agent_core_runtime_arn,
    "${module.my_project_agent.agent_core_runtime_arn}/*"
  ]
}
```
</Fragment>
</Infrastructure>

#### Cognito 身份验证

当您选择 `Cognito` 身份验证时，生成器会将 agent 配置为使用 Cognito 进行身份验证。

<Infrastructure>
<Fragment slot="cdk">
生成的构造接受一个 `identity` 属性，用于配置 Cognito 身份验证：

```ts {8}
import { MyProjectAgent, UserIdentity } from '@my-scope/common-constructs';

export class ExampleStack extends Stack {
  constructor(scope: Construct, id: string) {
    const identity = new UserIdentity(this, 'Identity');

    new MyProjectAgent(this, 'MyProjectAgent', {
      identity,
    });
  }
}
```

`UserIdentity` 构造可以使用 <Link path="/zh/guides/react-website-auth">`ts#website#auth` 生成器</Link>生成，或者您可以创建自己的 CDK `UserPool` 和 `UserPoolClient`。
</Fragment>
<Fragment slot="terraform">
生成的模块接受 `user_pool_id` 和 `user_pool_client_ids` 变量用于 Cognito 身份验证：

```terraform {11-12}
module "user_identity" {
  source = "../../common/terraform/src/core/user-identity"
}

module "my_project_agent" {
  source = "../../common/terraform/src/app/agents/my-project-agent"

  appconfig_application_id  = module.runtime_config_appconfig.application_id
  appconfig_application_arn = module.runtime_config_appconfig.application_arn

  user_pool_id         = module.user_identity.user_pool_id
  user_pool_client_ids = [module.user_identity.user_pool_client_id]
}
```
</Fragment>
</Infrastructure>

:::note[自定义 OIDC 提供商]
如果您需要使用非 Cognito OIDC 提供商的自定义 JWT 身份验证，您可以直接修改为您的 agent 生成的 CDK 构造或 Terraform 模块。请注意，连接生成器仅支持 `IAM` 或 `Cognito` 身份验证。
:::

:::caution[安全最佳实践]
在实现您的 agent 的业务逻辑时，请查看 [Bedrock AgentCore Runtime 安全最佳实践](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-security-best-practices.html)。
:::
