将 [Amazon Bedrock Guardrail](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html) 附加到 <Link path="guides/ts-agent">TypeScript Agent</Link>。guardrail 是 Amazon Bedrock 应用于您的 agent 发送给模型的消息以及模型答案的一组规则。如果没有 guardrail，用户可以向您的 agent 询问任何主题，模型可以在其答案中重复个人数据（如电子邮件地址）。

该生成器添加一个包含您的规则的策略文件、将 guardrail 应用于您的 agent 模型的代码，以及在您的 AWS 账户中创建 guardrail 的基础设施。

## 工作原理

- 您的 `agent.ts` 旁边的 `guardrail.json` 包含规则：您的 agent 必须拒绝的主题以及必须隐藏或阻止的个人数据类型（PII，个人可识别信息）。
- 您的 CDK construct 或 Terraform 模块在您合成或计划时读取 `guardrail.json`。它创建 guardrail 和一个编号版本。guardrail 版本是规则的只读快照。
- 基础设施将 guardrail 的 ID 和版本号写入 <Link path="guides/runtime-config">runtime config</Link>，即您的基础设施存储已部署资源详细信息的 AWS AppConfig 应用程序。条目为 `agentcore.guardrails.<AgentClass>`，以您的 agent 的类命名，例如 `agentcore.guardrails.MyAgent`。每个受保护的 agent 都有自己的条目。
- `guardrail.ts` 构建您的 `new Agent({...})` 调用使用的 Bedrock 模型。在每次模型调用之前，模型从 runtime config 读取 agent 的条目并应用该 guardrail。

## guardrail 检查什么

guardrail 在每次模型调用时检查两件事：

- 您的 agent 发送给模型的对话，包括用户的最新消息
- 模型的答案，在您的 agent 将其流式传输回用户之前

当 guardrail 阻止用户的消息时，用户会收到 `blockedInputMessaging` 文本，并且不会调用模型。Strands 还会将 agent 对话历史记录中被阻止的消息替换为 `[User input redacted.]`。当它阻止答案时，用户会收到 `blockedOutputsMessaging` 文本。当 `ANONYMIZE` 规则匹配时，答案包含占位符（如 `{EMAIL}`）而不是值。

guardrail 不检查工具定义、模型传递给您的工具的参数或您的工具返回的结果。例如，如果工具从数据库返回客户的电子邮件地址，guardrail 不会将其从模型中隐藏。将工具结果视为不受信任的，如 <Link path="guides/ts-agent">TypeScript Agent 指南</Link>在"保护您的 Agent"下所述。

## 编辑 guardrail.json

提供的策略是为生成的数学 agent 提供的示例。它拒绝投资建议并隐藏或阻止三种类型的个人数据：

```json title="guardrail.json"
{
  "blockedInputMessaging": "Sorry, I can't help with that request.",
  "blockedOutputsMessaging": "Sorry, I can't share that answer.",
  "deniedTopics": [
    {
      "name": "Investment advice",
      "definition": "Recommendations about which specific stocks, funds or other investments to buy or sell.",
      "examples": ["Which stocks should I buy this year?"]
    }
  ],
  "piiEntities": [
    { "type": "EMAIL", "action": "ANONYMIZE" },
    { "type": "PHONE", "action": "ANONYMIZE" },
    { "type": "US_SOCIAL_SECURITY_NUMBER", "action": "BLOCK" }
  ]
}
```

字段为：

- `blockedInputMessaging`：当 guardrail 阻止用户的消息时用户收到的回复。最多 500 个字符。
- `blockedOutputsMessaging`：当 guardrail 阻止模型的答案时用户收到的回复。最多 500 个字符。
- `deniedTopics`：您的 agent 必须拒绝的主题。每个主题都有一个 `name`（最多 100 个字母、数字、空格和字符 `-_!?.`）、一个最多 1000 个字符的 `definition` 来描述主题，以及可选的 `examples`，每个最多 100 个字符。
- `piiEntities`：要采取行动的个人数据类型。`type` 是[敏感信息类型](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-sensitive-filters.html)，如 `EMAIL`、`PHONE` 或 `US_SOCIAL_SECURITY_NUMBER`。`action` 是 `ANONYMIZE` 以用占位符替换值，或 `BLOCK` 以阻止整个消息或答案。

编写描述主题本身的主题 `definition`。例如，"Recommendations about which specific stocks to buy" 比 "Do not give investment advice" 效果更好。

### 为什么版本是编号的

每次您更改 `guardrail.json` 并部署时，基础设施都会创建一个新的编号 guardrail 版本并将其写入 runtime config。版本的描述包含 `guardrail.json` 的 SHA-256 哈希，因此对文件的更改会更改描述，新版本会替换旧版本。使用 CDK construct，哈希还涵盖您传递的任何 guardrail 属性。

您正在运行的 agent 不需要重启。它缓存从 runtime config 读取的内容 5 秒，因此它在 AppConfig 部署后的 5 秒内使用新版本。旧版本在 AppConfig 部署后被删除。CloudFormation 在其清理步骤中删除它，在一次测量中（2026-10-24，us-east-1）在部署完成后约 7 秒开始。CloudFormation 不保证该延迟。Terraform 在部署模块后约 15 秒保留旧版本，因此 5 秒缓存永远不会指向已删除的版本。当您将 guardrail 模块添加到该模块的 `depends_on` 时，这会起作用，如[将 guardrail 连接到您的 agent](#将-guardrail-连接到您的-agent) 中所示。

您的 agent 永远不会使用 `DRAFT` 版本。`DRAFT` 始终包含最新规则，因此在 AWS 控制台中进行的编辑将在没有部署的情况下到达您正在运行的 agent。如果 runtime config 中的版本不是版本号，`guardrail.ts` 会抛出错误。

## 将 guardrail 连接到您的 agent

生成器不会更改您的堆栈或根 Terraform 模块，就像 `ts#agent` 生成器将部署 agent 留给您一样。完成后，它会打印下面的代码，其中填写了您的 agent 的名称。添加它以创建 guardrail、写入其 runtime-config 条目并允许 agent 应用 guardrail：

<Infrastructure>
  <Fragment slot="cdk">
```ts title="packages/infra/src/stacks/application-stack.ts"
import { MyAgent, MyAgentGuardrail } from '@my-scope/common-constructs';

const agent = new MyAgent(this, 'MyAgent');
new MyAgentGuardrail(this, 'MyAgentGuardrail', { agent });
```

construct 将 guardrail 的 ID 和版本写入 runtime config 的 `agentcore.guardrails.MyAgent`，并授予 `agent` 应用 guardrail 的权限。agent construct 已经允许 agent 读取 runtime config。

construct 公开：

- `guardrail`（`CfnGuardrail`）和 `version`（`CfnGuardrailVersion`）
- `guardrailId`、`guardrailArn` 和 `guardrailVersion`
- `grantApply(grantee)`，在 guardrail 上向另一个主体授予 `bedrock:ApplyGuardrail`

它还添加 `GuardrailId` 和 `GuardrailVersion` 堆栈输出。其 props 是 `agent` 和任何 `CfnGuardrail` 属性。`CfnGuardrail` 属性优先于 `guardrail.json`。例如，添加内容过滤器：

```ts
new MyAgentGuardrail(this, 'MyAgentGuardrail', {
  agent,
  contentPolicyConfig: {
    filtersConfig: [
      { type: 'HATE', inputStrength: 'HIGH', outputStrength: 'HIGH' },
    ],
  },
});
```
  </Fragment>
  <Fragment slot="terraform">
如图所示添加 `my_agent_guardrail` 模块，在您部署 agent 的根模块中。将其 `additional_iam_policy_statements` 行添加到您现有的 `my_agent` 模块块中。将 `module.my_agent_guardrail` 添加到您的 `runtime_config_appconfig_deployment` 模块的 `depends_on` 列表中，以便部署包含 guardrail 的 runtime-config 条目，并且 Terraform 仅在部署后删除旧的 guardrail 版本。如果您的根模块尚未部署 agent，请先添加 agent 的模块，如 <Link path="guides/ts-agent#infrastructure-as-code">TypeScript Agent 指南</Link>中所述。

```hcl title="packages/infra/src/main.tf"
module "my_agent_guardrail" {
  source = "../../common/terraform/src/app/guardrails/my-agent"
}

module "my_agent" {
  source = "../../common/terraform/src/app/agents/my-agent"
  # ...existing arguments...
  additional_iam_policy_statements = module.my_agent_guardrail.iam_policy_statements
}

module "runtime_config_appconfig_deployment" {
  # ...existing arguments...
  depends_on = [
    # ...existing modules...
    module.my_agent_guardrail,
  ]
}
```

如果您的 agent 模块已经设置了 `additional_iam_policy_statements`，请组合列表：

```hcl
  additional_iam_policy_statements = concat(module.my_agent_guardrail.iam_policy_statements, local.my_statements)
```

该模块将 guardrail 的 ID 和版本写入 runtime config 的 `agentcore.guardrails.MyAgent`。`agentcore` 命名空间在 runtime-config 模块的默认 `namespaces` 中，因此您不需要添加它。agent 模块已经允许 agent 读取 runtime config。

该模块接受 `tags` 变量并输出 `guardrail_id`、`guardrail_arn`、`guardrail_version` 和 `iam_policy_statements`。要添加其他 guardrail 策略（如内容过滤器），请编辑模块中的 `aws_bedrock_guardrail` 资源。

该模块在 guardrail 版本上设置 `create_before_destroy`，因此 Terraform 在删除旧版本之前创建新版本。来自 `hashicorp/time` 提供程序的 `time_sleep` 资源在 runtime-config 部署后约 15 秒保留旧版本，runtime-config 条目从中读取 guardrail ID 和版本。由于这种等待，`terraform destroy` 也需要约 15 秒更长的时间。
  </Fragment>
</Infrastructure>

### 缺少 runtime-config 条目

如果您忘记了连接，runtime config 没有您的 agent 的条目。然后模型在调用 Bedrock 之前抛出错误，因此 agent 不会在没有其 guardrail 的情况下运行。对于 `MyAgent`，错误是：

```
No guardrail for this agent in runtime config at agentcore.guardrails.MyAgent. Add the MyAgentGuardrail construct (CDK) or the guardrails/my-agent module (Terraform) to your infrastructure.
```

agent 使用每个协议（`http`、`a2a` 和 `ag-ui`）启动，每个请求都会因此错误而失败。

## 本地开发

`<agent>-dev` 目标设置 `LOCAL_DEV=true`。当 `LOCAL_DEV` 为 `true` 且未设置 `RUNTIME_CONFIG_APP_ID` 环境变量时，`guardrail.ts` 不读取 runtime config。它会打印一次警告，agent 在没有 guardrail 的情况下运行：

<NxCommands commands={['agent-dev your-project']} />

要在本地测试您的规则，请先部署 guardrail。然后将 `RUNTIME_CONFIG_APP_ID` 设置为您已部署的 runtime-config 应用程序的 ID，从 `RuntimeConfigApplicationId` 堆栈输出（CDK）或 `module.runtime_config_appconfig.application_id`（Terraform）获取。您的 shell 还需要可以读取 AppConfig 和应用 guardrail 的 AWS 凭证：

<NxCommands commands={['agent-dev your-project']} env={{ RUNTIME_CONFIG_APP_ID: '<application-id>' }} />

然后 agent 只读取自己的条目，因此多个受保护的 agent 可以针对同一应用程序在本地运行。如果 agent 无法读取 runtime config，或者条目缺失，它会打印一次警告并在没有 guardrail 的情况下运行。

`<agent>-serve` 目标不设置 `LOCAL_DEV`，因此它需要 `RUNTIME_CONFIG_APP_ID` 和已部署的条目，否则每个请求都会如上所述失败。`<agent>-chat` 目标连接到正在运行的 agent，本身不需要 runtime config。

## 成本和延迟

Amazon Bedrock 对评估文本的每个 guardrail 策略收费，包括输入和答案。请参阅 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。

每次模型调用也需要更长时间，因为 guardrail 在您的 agent 将答案流式传输给用户之前检查答案。

## 限制

- 此生成器支持使用 `ts#agent` 创建的 agent。它不支持 AgentCore Harness。
- `guardrail.json` 仅包含拒绝的主题和 PII 实体。使用 construct 的 props（CDK）或通过编辑模块（Terraform）添加其他策略，如内容过滤器和单词过滤器。
- guardrail 不检查工具结果，如[guardrail 检查什么](#guardrail-检查什么)中所述。
