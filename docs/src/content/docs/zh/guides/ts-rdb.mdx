## 本地开发

### 数据建模

生成的项目使用 [Prisma ORM](https://www.prisma.io/docs/orm) 来定义您的数据库架构并生成类型安全的客户端。工作流程是模型优先的：在数据库项目的 `prisma/models/` 目录下添加或更新 Prisma 模型文件，然后从这些模型更改生成迁移。

示例 `User` 模型：

```ts title="packages/postgres/prisma/models/user.prisma"
model User {
  id          Int      @id @default(autoincrement()) 
  firstName   String
  lastName    String
}
```

有关更多详细信息，请参阅官方 [Prisma 数据建模指南](https://www.prisma.io/docs/orm/core-concepts/data-modeling#data-modeling-with-prisma-orm)。

### 生成数据库客户端

生成器会自动配置 `generate` 目标，以便在构建项目时创建类型安全的 TypeScript Prisma 客户端。客户端被写入 `generated/prisma`（已添加到 `.gitignore`）。

您也可以随时手动生成客户端：

<NxCommands commands={['run <your-db-project-name>:generate']} />

使用 `prisma` 目标从工作区根目录运行 Prisma CLI 命令：

<NxCommands commands={['run <project>:prisma generate']} />

`src/prisma.ts` 中的运行时包装器导出：

- `getPrisma()` - 从 AWS AppConfig 加载数据库连接设置，并使用 IAM 身份验证创建 Prisma 客户端

客户端自动：
- 使用 `RUNTIME_CONFIG_APP_ID` 环境变量从 AWS AppConfig 检索数据库配置
- 通过 AWS RDS Signer 生成临时身份验证令牌以进行 IAM 身份验证
- 使用证书验证管理 SSL/TLS 连接
- 通过持久数据库连接池处理连接池

### 创建迁移

在 `prisma/models/` 下添加或更新模型后，使用 `migrate dev` 生成迁移文件并同时将它们应用到本地数据库。

生成的 `prisma` 目标在运行前会自动启动本地数据库容器：

<NxCommands commands={['run <project>:prisma migrate dev']} />

如果您只想生成迁移文件而不将它们应用到本地数据库，请添加 `--create-only`：

<NxCommands commands={['run <project>:prisma migrate dev --create-only']} />

每次架构更改时，这会在 `prisma/migrations` 中生成一个新的迁移文件夹：

<FileTree>
  - prisma
    - migrations
      - 20260405013911_initial_migrations
        - migration.sql
      - migration_lock.toml
    - schema.prisma
</FileTree>

当您部署 AWS 堆栈时，生成的基础设施会自动将生成的迁移应用到已部署的数据库。

### 应用现有迁移

当您拉取其他开发人员创建的迁移文件时，使用 `migrate deploy` 将这些现有迁移应用到本地数据库。

<NxCommands commands={['run <project>:prisma migrate deploy']} />

在此本地开发流程中，`migrate deploy` 将迁移文件应用到本地数据库；它不会将数据库部署到 AWS。

### 运行 Prisma 命令

生成的 `prisma` 目标公开了 Prisma CLI，因此您可以使用它对本地数据库运行 Prisma 支持的任何命令。有关可用命令，请参阅 [Prisma CLI 参考](https://www.prisma.io/docs/orm/reference/prisma-cli-reference)。

<NxCommands commands={['run <project>:prisma <prisma-command>']} />

### 使用 Prisma Studio

[Prisma Studio](https://www.prisma.io/studio) 是本地数据库的可视化编辑器。使用它可以浏览表、检查和编辑记录、过滤数据、跟踪关系，并通过内置的 SQL 控制台运行原始 SQL。它对于在开发期间验证迁移和填充测试数据很有用。使用以下命令启动它：

<NxCommands commands={['run <project>:prisma studio']} />

### 停止本地数据库

停止 `dev`（例如使用 `Ctrl+C`）会自动删除本地数据库容器，但保留命名卷，以便您的数据在重启后保持不变。

:::caution[Windows]
由于 Windows 上信号处理的限制，当 `dev` 停止时容器不会自动删除。您需要手动删除它：

```bash
<engine> rm -f <scope>-<db-name>
```

将 `<engine>` 替换为您的容器引擎（`docker` 或 `finch`），将 `<scope>` 替换为您的 Nx 工作区作用域（例如 `proj`），将 `<db-name>` 替换为您的数据库项目名称（例如 `my-db`）。
:::

## 连接到数据库

在任何 TypeScript 项目中，从您的数据库包导入 `getPrisma` 并调用它以获取类型安全的 Prisma 客户端：

```ts
import { getPrisma } from '@my-scope/db';

const prisma = await getPrisma();
const users = await prisma.user.findMany({ orderBy: { id: 'asc' } });
```

`getPrisma()` 返回一个延迟初始化的缓存客户端。在同一个 Lambda 执行上下文中的后续调用会重用现有的连接池，而不是打开新的连接池。

Prisma 客户端公开从您的 `prisma/models/` 架构派生的完全类型化的模型，为您提供从数据库到 API 响应的端到端类型安全。

`getPrisma()` 在运行时从 AWS AppConfig 获取数据库连接设置。

#### 不使用 RDS Proxy 连接时的 SSL 要求

当直接连接到 Aurora 集群（不使用 RDS Proxy）时，调用 `getPrisma()` 的运行时必须信任 Amazon RDS CA 捆绑包。生成的 Prisma 客户端启用证书验证；如何使 CA 捆绑包可用取决于连接到数据库的运行时。

对于 Amazon RDS，使用来自以下位置的全局 CA 捆绑包：

```text
https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem
```

##### 运行时容器镜像

如果您为运行时准备自己的容器镜像，请在 Dockerfile 中下载 RDS CA 捆绑包并将其添加到操作系统信任存储。

<Tabs>
<TabItem label="Amazon Linux">

```dockerfile
RUN curl -fsSL "https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem" \
    -o /etc/pki/ca-trust/source/anchors/rds-bundle.pem && \
    update-ca-trust
```

</TabItem>
<TabItem label="Debian">

```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends curl ca-certificates && \
    rm -rf /var/lib/apt/lists/* && \
    curl -fsSL "https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem" \
    -o /usr/local/share/ca-certificates/rds-bundle.crt && \
    update-ca-certificates
```

</TabItem>
</Tabs>

##### 压缩的 Lambda 函数

对于使用 Node.js 20 或更高版本运行时的压缩 Lambda 函数，通过设置 `NODE_EXTRA_CA_CERTS` 来加载 Amazon RDS CA 捆绑包：

## 限制

<OptionFilter when={{ engine: 'mysql' }}>

### MySQL: API Gateway 流式模式

当将 Aurora MySQL 与 API Gateway 流式响应一起使用时（例如使用 tRPC 的 `httpBatchStreamLink`），Prisma MySQL 客户端在查询完成后会占用 Node.js 事件循环，从而阻止 Lambda 刷新流并结束请求。

要解决此问题，请在每次查询后在 `finally` 块中显式断开客户端连接，以便事件循环可以自由退出并且流式响应可以完成。

**选项 1：每个过程**

```ts
export const listExampleTable = publicProcedure
  .output(z.array(ExampleTableSchema))
  .query(async () => {
    const prisma = await getPrisma();
    try {
      return await prisma.exampleTable.findMany();
    } finally {
      await prisma.$disconnect();
    }
  });
```

**选项 2：tRPC 中间件**

如果您使用的是[中间件模式](#injecting-the-prisma-client-via-middleware)，请将 `$disconnect()` 调用添加到中间件，以便基于它构建的所有过程都会自动覆盖：

```ts title="packages/api/src/middleware/db.ts"
import { getPrisma } from '@my-scope/db';
import { initTRPC } from '@trpc/server';

export interface IDbContext {
  db: Awaited<ReturnType<typeof getPrisma>>;
}

export const createDbPlugin = () => {
  const t = initTRPC.context<IDbContext>().create();
  return t.procedure.use(async (opts) => {
    const db = await getPrisma();
    try {
      return await opts.next({
        ctx: {
          ...opts.ctx,
          db,
        },
      });
    } finally {
      await db.$disconnect();
    }
  });
};
```

:::note
PostgreSQL 不需要这样做。PostgreSQL 适配器使用配置了 `allowExitOnIdle: true` 的 `pg` 连接池，这允许事件循环自然退出而无需显式断开连接。由于此限制，MySQL 的 `getPrisma()` 不会缓存客户端或在温暖的 Lambda 调用之间重用连接。每次调用都会打开一个新连接，这与在模块级别缓存客户端并重用相同连接池的 PostgreSQL 适配器不同。
:::

### MySQL: IAM 令牌过期

RDS IAM 身份验证令牌在 **15 分钟**后过期。MySQL Prisma 客户端在调用 `getPrisma()` 时将 IAM 令牌捕获为静态值。现有的打开连接不受影响，但如果在令牌过期后需要建立新连接，身份验证将失败。PostgreSQL 适配器通过在池每次打开新连接时动态刷新令牌来避免这种情况，但 MySQL 适配器没有等效机制。

:::caution
对于运行时间超过 15 分钟的任务要小心。如果 MySQL 客户端需要在原始 IAM 令牌过期后打开新连接，身份验证将失败。
:::

对于长时间运行的任务（如批处理作业或数据迁移），请在每个工作单元开始时调用 `getPrisma()`，而不是为整个操作调用一次。因为 `getPrisma()` 总是为 MySQL 创建一个新客户端并获取新的 IAM 令牌，这确保每个连接都使用有效的令牌进行身份验证。
