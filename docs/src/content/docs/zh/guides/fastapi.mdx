[FastAPI](https://fastapi.tiangolo.com/) 是一个用于在 Python 中构建 API 的框架。

FastAPI 生成器创建一个新的 FastAPI，并配置 AWS CDK 或 Terraform 基础设施。生成的后端通过 AWS API Gateway API 公开。它设置了 [AWS Lambda Powertools](https://docs.powertools.aws.dev/lambda/python/latest/) 以实现可观测性，包括结构化日志记录和 CloudWatch 指标。

<OptionFilter not when={{ infra: 'http-ecs' }} description="Lambda hosting">
后端使用 AWS Lambda 进行无服务器部署，并且还设置了 AWS X-Ray 追踪。
</OptionFilter>

<OptionFilter when={{ infra: 'http-ecs' }} description="ECS hosting">
您的 API 作为长期运行的 uvicorn 服务器在 Amazon ECS 上的容器中运行，位于 API Gateway HTTP API 后面，而不是在 Lambda 函数中。请参阅<a href="#running-on-amazon-ecs">在 Amazon ECS 上运行</a>了解这会改变什么，包括为什么 X-Ray 追踪在那里不产生追踪。
</OptionFilter>

<OptionFilter when={{ infra: 'http-ecs' }} description="ECS hosting is experimental">
:::caution[实验性]
`http-ecs` 是实验性的。其生成的输出可能会在版本之间发生变化，而不会提供迁移来迁移现有工作区，因此在升级时请自行协调这些变化。

它需要 CDK IaC 提供程序：尚未实现 Terraform 支持。如果工作区解析为 Terraform，生成器会失败并显示一条消息说明修复方法。

`integrationPattern` 在这里始终为 `shared`。在 `http-ecs` 旁边传递 `--integrationPattern=isolated` 不会失败：生成器会警告该选项被忽略并使用 `shared`。以交互方式运行生成器时，它会在 `infra` 之前询问 `integrationPattern`，并预选 `isolated`，因此如果您保持预选不变然后选择 `http-ecs`，您会看到该警告。在此页面的命令构建器中，选择 `http-ecs` 会禁用 `isolated` 并在已选择时清除它，因此它编写的命令永远不会携带该标志。
:::

## 生成器输出

生成器将在 `<directory>/<api-name>` 目录中创建以下项目结构：

<FileTree>

- project.json 项目配置和构建目标
- pyproject.toml Python 项目配置和依赖项
- run.sh Lambda Web Adapter 引导脚本，通过 uvicorn 启动 FastAPI 应用
- \<module_name>
  - \_\_init\_\_.py 模块初始化
  - init.py 设置 FastAPI 应用并配置 powertools 中间件
  - main.py API 实现
- scripts
  - generate_open_api.py 从 FastAPI 应用生成 OpenAPI 架构的脚本

</FileTree>

<FileTree>

    - Dockerfile 容器镜像定义
    - .dockerignore 镜像构建上下文中排除的文件
</FileTree>

您的 `init.py`、`main.py` 以及您添加到它们的操作对于每个 `infra` 值都是相同的。

## 实现您的 FastAPI

主要的 API 实现在 `main.py` 中。这是您定义 API 路由及其实现的地方。以下是一个示例：

```python
from pydantic import BaseModel
from .init import app, tracer

class Item(BaseModel):
  name: str

@app.get("/items/{item_id}")
@tracer.capture_method
def get_item(item_id: int) -> Item:
    return Item(name=f"Item {item_id}")

@app.post("/items")
@tracer.capture_method
def create_item(item: Item) -> Item:
    return item
```

生成器会自动设置几个功能：

1. AWS Lambda Powertools 集成以实现可观测性
2. 错误处理中间件
3. 请求/响应关联
4. 指标收集

<OptionFilter not when={{ infra: 'http-ecs' }} description="Streaming, which needs a REST API">
类型安全的流式传输也已设置，仅适用于 `rest-lambda` 基础设施。
</OptionFilter>

<OptionFilter not when={{ infra: 'http-ecs' }} description="How the Lambda variants serve the app">
应用程序在 Lambda 函数中由运行 uvicorn 的 [Lambda Web Adapter](https://github.com/awslabs/aws-lambda-web-adapter) 提供服务。
</OptionFilter>

<OptionFilter when={{ infra: 'http-ecs' }} description="How the ECS variant serves the app">
应用程序由容器中的 uvicorn 提供服务，没有 Lambda Web Adapter。请参阅<a href="#running-on-amazon-ecs">在 Amazon ECS 上运行</a>。
</OptionFilter>

### 使用 AWS Lambda Powertools 实现可观测性

#### 日志记录

生成器使用 AWS Lambda Powertools 配置结构化日志记录。您可以在路由处理程序中访问日志记录器：

```python
from .init import app, logger

@app.get("/items/{item_id}")
def read_item(item_id: int):
    logger.info("Fetching item", extra={"item_id": item_id})
    return {"item_id": item_id}
```

日志记录器会自动包含：

- 用于请求追踪的关联 ID
- 请求路径、匹配的路由和方法

#### 追踪

AWS X-Ray 追踪会自动配置。您可以向追踪添加自定义子段：

```python
from .init import app, tracer

@app.get("/items/{item_id}")
@tracer.capture_method
def read_item(item_id: int):
    # Creates a new subsegment
    with tracer.provider.in_subsegment("fetch-item-details"):
        # Your logic here
        return {"item_id": item_id}
```

<OptionFilter when={{ infra: 'http-ecs' }} description="X-Ray produces no traces on ECS">
:::caution[ECS 上无追踪]
上面的装饰器和子段在容器中运行时不会出错，但不会产生追踪。Powertools 在不在 Lambda 中运行时会关闭其追踪器。请参阅<a href="#observability">可观测性</a>了解您能获得什么，以及如果需要追踪应该添加什么。
:::
</OptionFilter>

#### 指标

CloudWatch 指标会自动为每个请求收集。您可以添加自定义指标：

```python
from .init import app, metrics
from aws_lambda_powertools.metrics import MetricUnit

@app.get("/items/{item_id}")
def read_item(item_id: int):
    metrics.add_metric(name="ItemViewed", unit=MetricUnit.Count, value=1)
    return {"item_id": item_id}
```

默认指标包括：

- 请求计数
- 成功/失败计数
- 按路由的指标（通过 `<method> <path>` 的 `route` 维度）

### 错误处理

生成器包含全面的错误处理：

```python
from fastapi import HTTPException

@app.get("/items/{item_id}")
def read_item(item_id: int):
    if item_id < 0:
        raise HTTPException(status_code=400, detail="Item ID must be positive")
    return {"item_id": item_id}
```

未处理的异常会被中间件捕获并：

1. 记录完整的异常和堆栈跟踪
2. 记录失败指标
3. 向客户端返回安全的 500 响应
4. 保留关联 ID

:::tip[响应模型]
建议为您的 API 操作指定响应模型，以便在使用 `connection` 生成器时获得更好的代码生成。<Link path="guides/connection/react-fastapi#errors">在此处查看更多详细信息</Link>。
:::

### 访问调用用户

<OptionFilter when={{ infra: 'http-ecs' }} description="Identity on ECS — the authorizer context does not arrive">
在 ECS 上没有 Lambda Web Adapter 和 API Gateway 请求上下文标头：API Gateway 不会将授权器的声明转发到私有负载均衡器集成。授权器仍然决定请求是否到达容器，但您的处理程序无法从请求中读取调用者，如下所述。

要在操作中读取调用者的身份，请将授权器的上下文映射到 API 构造中的请求标头，并从 FastAPI `Request` 中读取该标头。
</OptionFilter>

<OptionFilter not when={{ infra: 'http-ecs' }} description="Identity on the Lambda variants">
当您的 API 受身份验证保护时，您的路由处理程序通常需要知道谁在调用。生成的 FastAPI 通过 [Lambda Web Adapter](https://github.com/awslabs/aws-lambda-web-adapter) 在 AWS Lambda 内运行，它将 API Gateway 请求上下文作为 JSON 转发到 `x-amzn-request-context` 标头。您可以从 FastAPI `Request` 中读取它以提取调用者的身份。

例如，让我们添加一个 `/me` 端点，返回有关调用用户的详细信息。我们将提取实现为 [FastAPI 依赖项](https://fastapi.tiangolo.com/tutorial/dependencies/)，以便可以在路由之间重用。请求上下文的形状——因此您如何提取身份——取决于您选择的 `auth` 方法以及您是否部署了 REST 或 HTTP API。
</OptionFilter>

<OptionFilter when={{ auth: 'iam' }} description="IAM 身份验证 API 的身份提取">
对于 `IAM` 身份验证，我们使用从 API Gateway 请求上下文中提取的 sub 在 Cognito 中查找调用者，这需要 `boto3`。将其添加到您的 API 项目：

<NxCommands commands={[`run my-api:add boto3${PY_VERSIONS.boto3}`]} />

在 `main.py` 旁边创建 `identity.py`：

<Tabs syncKey="http-rest">
<TabItem label="REST API" _filter={{ infra: 'rest-lambda' }}>
```python
import json
import os
from typing import Annotated

from boto3 import client
from fastapi import Depends, HTTPException, Request
from pydantic import BaseModel

cognito = client("cognito-idp")


class Identity(BaseModel):
    sub: str
    username: str


def get_identity(request: Request) -> Identity:
    # The Lambda Web Adapter forwards the API Gateway request context as JSON
    request_context_header = request.headers.get("x-amzn-request-context")
    if not request_context_header:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    request_context = json.loads(request_context_header)
    provider = request_context.get("identity", {}).get("cognitoAuthenticationProvider")

    sub = provider.split(":")[-1] if provider else None
    if not sub:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    users = cognito.list_users(
        # Assumes user pool id is configured in lambda environment
        UserPoolId=os.environ["USER_POOL_ID"],
        Limit=1,
        Filter=f'sub="{sub}"',
    ).get("Users", [])

    if len(users) != 1:
        raise HTTPException(status_code=403, detail=f"No user found with subjectId {sub}")

    return Identity(sub=sub, username=users[0]["Username"])


CurrentUser = Annotated[Identity, Depends(get_identity)]
```
</TabItem>

```python
from boto3 import client
from fastapi import Depends, HTTPException, Request

    username: str

    # The Lambda Web Adapter forwards the API Gateway request context as JSON
    request_context_header = request.headers.get("x-amzn-request-context")
    if not request_context_header:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    request_context = json.loads(request_context_header)
    amr = (
        request_context.get("authorizer", {})
        .get("iam", {})
        .get("cognitoIdentity", {})
        .get("amr", [])

        raise HTTPException(status_code=403, detail="Unable to determine calling user")

        UserPoolId=os.environ["USER_POOL_ID"],
        Limit=1,
        Filter=f'sub="{sub}"',
    ).get("Users", [])

    if len(users) != 1:
        raise HTTPException(status_code=403, detail=f"No user found with subjectId {sub}")

    return Identity(sub=sub, username=users[0]["Username"])
```

```python
import json
from typing import Annotated

from fastapi import Depends, HTTPException, Request
from pydantic import BaseModel


class Identity(BaseModel):
    sub: str
    username: str


def get_identity(request: Request) -> Identity:
    # The Lambda Web Adapter forwards the API Gateway request context as JSON
    request_context_header = request.headers.get("x-amzn-request-context")
    if not request_context_header:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    request_context = json.loads(request_context_header)
    claims = request_context.get("authorizer", {}).get("claims", {})

    sub = claims.get("sub")
    username = claims.get("username")

    if not sub or not username:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    return Identity(sub=sub, username=username)
```

HTTP API 使用 JWT 授权器，它将验证的声明放在 `authorizer.jwt.claims` 下：

```python
import json
from typing import Annotated

from fastapi import Depends, HTTPException, Request
from pydantic import BaseModel


class Identity(BaseModel):
    sub: str
    username: str


def get_identity(request: Request) -> Identity:
    # The Lambda Web Adapter forwards the API Gateway request context as JSON
    request_context_header = request.headers.get("x-amzn-request-context")
    if not request_context_header:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    request_context = json.loads(request_context_header)
    claims = request_context.get("authorizer", {}).get("jwt", {}).get("claims", {})

    sub = claims.get("sub")
    username = claims.get("username")

    if not sub or not username:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    return Identity(sub=sub, username=username)


CurrentUser = Annotated[Identity, Depends(get_identity)]
```

### 流式传输

使用 REST API 时，生成的 FastAPI 开箱即支持流式响应。基础设施配置为使用 [AWS Lambda Web Adapter](https://github.com/awslabs/aws-lambda-web-adapter) 通过 uvicorn 在 Lambda 内运行您的 FastAPI，并在 API Gateway 中为所有 REST API 操作使用 `ResponseTransferMode.STREAM`，这使得流式传输可以与非流式操作一起工作。

#### 使用 `JsonStreamingResponse`

生成的 `init.py` 导出一个 `JsonStreamingResponse` 类，它提供类型安全的流式传输和正确的 OpenAPI 架构生成。这确保 <Link path="guides/connection/react-fastapi">`connection` 生成器</Link> 可以生成正确类型的流式客户端方法。

```python
from pydantic import BaseModel
from .init import app, JsonStreamingResponse

class Chunk(BaseModel):
    message: str

async def generate_chunks():
    for i in range(100):
        yield Chunk(message=f"This is chunk {i}")

@app.post(
    "/stream",
    response_class=JsonStreamingResponse,
    responses={200: JsonStreamingResponse.openapi_response(Chunk, "Stream of chunks")},
)
async def my_stream() -> JsonStreamingResponse:
    return JsonStreamingResponse(generate_chunks())
```

`JsonStreamingResponse` 类：

1. 将 Pydantic 模型序列化为 [JSON Lines](https://jsonlines.org/) 格式（`application/jsonl`）
2. 提供一个 `openapi_response` 辅助函数，生成带有 `itemSchema` 的正确 OpenAPI 架构，使 <Link path="guides/connection/react-fastapi#consuming-a-stream">`connection` 生成器</Link> 能够生成类型安全的流式客户端方法

#### 消费

要消费响应流，您可以使用 <Link path="guides/connection/react-fastapi#consuming-a-stream">`connection` 生成器</Link>，它将提供一个类型安全的方法来迭代您的流式块。
</OptionFilter>

FastAPI 生成器根据您选择的 `iac` 创建 CDK 或 Terraform 基础设施即代码。您可以使用它来部署您的 FastAPI。

<OptionFilter not when={{ infra: 'http-ecs' }} description="CDK usage for the Lambda variants">
用于部署 API 的 CDK 构造在 `common/constructs` 文件夹中。您可以在 CDK 应用程序中使用它：

```ts {6-8}
import { MyApi } from '@my-scope/common-constructs';

export class ExampleStack extends Stack {
  constructor(scope: Construct, id: string) {
    // Add the api to your stack
    const api = new MyApi(this, 'MyApi', {
      integrations: MyApi.defaultIntegrations(this).build(),

  }

```

这会设置：

1. FastAPI 应用程序中每个操作的 AWS Lambda 函数
2. API Gateway HTTP/REST API 作为函数触发器
3. IAM 角色和权限
4. CloudWatch 日志组
5. X-Ray 追踪配置
6. CloudWatch 指标命名空间

<OptionFilter when={{ infra: 'http-ecs' }} description="CDK usage when the API runs on ECS — pass the VPC">
`defaultIntegrations` 接受您的服务运行所在的 VPC，并在其中构建所有内容：ECS 服务、其前面的内部负载均衡器以及 API Gateway 通过其到达该负载均衡器的 VPC 链接。该构造从不创建 VPC，因此您在堆栈中创建或导入一个。

```ts {10,13-15}
import { MyApi } from '@my-scope/common-constructs';
import { Stack } from 'aws-cdk-lib';
import { Vpc } from 'aws-cdk-lib/aws-ec2';
import { Construct } from 'constructs';

export class ExampleStack extends Stack {
  constructor(scope: Construct, id: string) {
    super(scope, id);

    const vpc = new Vpc(this, 'Vpc', { natGateways: 1 });

    const api = new MyApi(this, 'MyApi', {
      integrations: MyApi.defaultIntegrations(this, { vpc }).build(),
    });
  }
}
```

要使用现有 VPC，请使用 `Vpc.fromLookup(this, 'Vpc', { vpcId: '<vpc-id>' })` 查找它并将其作为 `vpc` 传递。

传递 `service` 以更改容器服务本身——其 `cpu`、`memoryLimitMiB`、`desiredCount`、`environment`，或 `grantTaskRole` 以授予任务角色权限：

```ts
MyApi.defaultIntegrations(this, {
  vpc,
  service: {
    cpu: 512,
    memoryLimitMiB: 1024,
    grantTaskRole: (taskRole) => myTable.grantReadWriteData(taskRole),
  },
}).build();
```

这会设置一个基于您选择的 `auth` 方法进行身份验证的 AWS API Gateway HTTP API、运行您的容器的 Amazon ECS 服务、其前面的内部负载均衡器以及 API Gateway 通过其到达该负载均衡器的 VPC 链接。
</OptionFilter>

<OptionFilter when={{ infra: 'http-ecs' }} description="How ECS hosting works, what it costs and what it limits">
## 在 Amazon ECS 上运行

当 `infra` 设置为 `http-ecs` 时，您的 API 作为长期运行的 uvicorn 服务器在容器中运行，而不是在 Lambda Web Adapter 后面的 Lambda 函数中。请求采用以下路径：

1. 调用者对 API Gateway HTTP API 签名请求，这是唯一的公共入口点。每个路由都带有您选择的 `auth` 的授权器，因此未经身份验证的请求会在边缘被拒绝。
2. API Gateway 通过 VPC 链接转发请求，这是它进入您的 VPC 的私有路径。
3. VPC 链接到达内部负载均衡器。负载均衡器没有公共地址，其唯一的入站规则允许 VPC 链接的安全组在侦听器端口上。
4. 负载均衡器将请求转发到任务。任务的唯一入站规则允许负载均衡器的安全组在容器端口上，因此 VPC 中的其他任何东西都无法打开与它们的连接。

任务在私有子网中运行，永远不会获得公共 IP 地址。此路径中没有任何内容允许地址范围入站。

默认情况下，服务、负载均衡器和 VPC 链接位于 VPC 的 `PRIVATE_WITH_EGRESS` 子网中，这些子网通过 NAT 网关到达 AWS。将 `vpcSubnets: { subnetType: SubnetType.PRIVATE_ISOLATED }` 传递给 `defaultIntegrations` 会删除 NAT 网关及其每小时费用，但隔离的子网没有出站路由，因此 VPC 需要四个 VPC 端点才能启动任务：用于拉取镜像的 `ecr.api` 和 `ecr.dkr` 的接口端点，一个 S3 网关端点（因为镜像层是 S3 对象），以及一个用于 `logs` 的接口端点，以便 `awslogs` 驱动程序可以写入。没有它们，任务无法拉取其镜像，ECS 会在断路器上回滚部署而不说明原因。

VPC 链接、负载均衡器、其侦听器、目标组以及负载均衡器将其访问日志写入的存储桶由一个构造创建，即 `common/constructs` 中的 `core/api/ecs-http-endpoint.ts`，每个托管在 ECS 上的 API 都共享它。您的 API 自己的构造命名其容器服务并将每个操作路由到该端点。

### 容器中运行的内容

`<module_name>/<api_name>_container/main.py` 从您的 `main.py` 导入应用程序，因此您编写的每个操作都像在 Lambda 上一样提供服务。它添加了两个自己的东西：

- `GET /health`，负载均衡器的目标组和容器健康检查调用它。它被声明为 `include_in_schema=False`，因此它不会出现在您的 OpenAPI 规范中，因此也不会出现在 API Gateway 路由和生成的客户端中。它也被排除在请求指标之外，因此目标组每 15 秒的调用不会计为 API 请求。
- 一个中间件，写出 API 自己的中间件收集的指标。在 Lambda 上，处理程序在每次调用结束时执行此操作；此服务器跨请求存在，因此它自己刷新它们。

API Gateway 路由仍然来自您的 OpenAPI 规范，因此一旦 `nx build` 重新生成规范，您添加的操作就会被部署。

### 可观测性

日志和指标的工作方式与在 Lambda 上相同：容器写入自己的 CloudWatch 日志组，指标以嵌入式指标格式写入，供 CloudWatch Logs 提取。

关于指标，这里有一点不同，在您阅读仪表板或添加自己的指标之前值得了解。`metrics`，即上面的<a href="#metrics">指标</a>部分告诉您从 `.init` 导入的对象，是一个 Powertools `Metrics`，进程中的每个 `Metrics` 对象共享一个指标存储。在 Lambda 上，一次调用从头到尾拥有该存储。uvicorn 服务器同时处理请求，API 自己的每个请求指标和您添加的任何指标都进入该一个存储，因此同时进行的两个请求可以将它们的指标写入一个文档中，并归因于首先添加的路由。另一个请求的文档可能根本没有 `route` 维度，只保存第一次刷新后添加的指标，当发生这种情况时，Powertools 会记录 `PowertoolsUserWarning: Dimension 'route' has already been added`。在轻流量下，请求很少重叠的地方，您不会看到它。

因此，在 ECS 上将每个路由的 `RequestCount` 和 `Success` 视为近似值。如果您需要将指标精确归因于一个请求，请将其添加到您在请求中创建的 `EphemeralMetrics` 并在返回之前刷新，它保留自己的存储：

```python
from aws_lambda_powertools.metrics import EphemeralMetrics, MetricUnit

@app.get("/items/{item_id}")
def read_item(item_id: int):
    request_metrics = EphemeralMetrics()
    request_metrics.add_metric(name="ItemViewed", unit=MetricUnit.Count, value=1)
    request_metrics.flush_metrics()
    return {"item_id": item_id}
```

AWS X-Ray 追踪则不然。`@tracer.capture_method` 在 Lambda 之外是无操作的，任务中也没有 X-Ray 守护进程来接收段。如果您需要追踪，请在容器服务中添加一个作为 sidecar。

API Gateway HTTP API 的访问日志记录到达 API 的每个请求。负载均衡器将其自己的访问日志写入 `EcsHttpEndpoint` 构造创建的存储桶，您可以在其中查看哪个任务为请求提供服务以及它的响应。

### 镜像构建和扫描

容器生成器提供镜像目标，以您的 API 命名：

- `<api-name>-container-docker` 构建 linux/arm64 镜像，首先运行 bundle，以便镜像包含您的包及其依赖项。
- `<api-name>-container-trivy` 扫描该镜像的漏洞。

请参阅 <Link path="/guides/py-container">Python Container Service</Link> 了解镜像的构建方式，以及 <Link path="/guides/docker-bundling">Docker Bundling</Link> 了解它在部署时的发布方式。

### 限制

- **集成超时。** API Gateway HTTP API 将集成限制在大约 30 秒。无论容器工作多长时间，超过该时间的操作都会在网关处失败。
- **无流式传输。** 流式操作需要 `rest-lambda` 基础设施。HTTP API 无法流式传输响应。
- **有效负载大小。** 请求和响应遵循 API Gateway 的 10 MB 限制。
- **每个操作一个服务。** `integrationPattern` 是 `shared`：有一个容器服务，每个路由都路由到它。该选项始终解析为此基础设施的 `shared`，`isolated` 会被忽略并发出警告。

### 成本

与 Lambda 相比，负载均衡器是新的固定成本，在 Lambda 中您按请求付费，空闲时不付费。us-east-1 中的大致月度数字，数据传输之前：

| 项目 | 大约 |
| --- | --- |
| 内部负载均衡器 | $16 加上负载均衡器容量单位 |
| Fargate 任务，0.25 vCPU / 0.5 GB arm64 | 每个任务 $7 |
| NAT 网关，如果您的 VPC 有一个 | $33 |
| VPC 链接 | 无每小时费用 |
| 负载均衡器访问日志的 S3 存储 | 每月每 GB 几美分 |

因此，一个单任务服务在任何流量之前每月花费大约 $23，如果您传入的 VPC 有 NAT 网关，则更多。访问日志随流量增长：向 `endpoint.accessLogsBucket` 添加生命周期规则以使其过期。查看 [Elastic Load Balancing](https://aws.amazon.com/elasticloadbalancing/pricing/) 和 [AWS Fargate](https://aws.amazon.com/fargate/pricing/) 定价页面以获取您所在区域的当前价格。
