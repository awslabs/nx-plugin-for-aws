[Terraform](https://www.terraform.io/) 是一个开源的基础设施即代码软件工具，使您能够安全且可预测地创建、更改和改进基础设施。

Terraform 基础设施生成器创建一个 Terraform 基础设施项目。生成的应用程序通过 [Checkov](https://www.checkov.io/) 安全检查包含安全最佳实践。

## 生成器输出

生成器根据项目类型创建不同的文件结构：

<OptionFilter when={{ type: 'application' }} description="Application type: full Terraform app with remote state management">
### 应用程序类型

对于应用程序项目（`--type=application`），生成器创建一个完整的 Terraform 应用程序，具有远程状态管理：

<FileTree>

  - src
    - main.tf 主 Terraform 配置文件
    - providers.tf 带有 S3 后端的提供程序配置
    - variables.tf 输入变量定义
    - outputs.tf 输出值定义
    - env 特定环境的变量文件
      - dev.tfvars 开发环境变量
  - bootstrap 远程状态的引导配置
    - main.tf 用于状态存储的 S3 存储桶和策略
    - providers.tf AWS 提供程序配置
    - variables.tf 引导变量定义
  - scripts 由 nx `bootstrap`、`bootstrap-destroy` 和 `init` 目标运行的 Node 辅助程序
    - aws-config.ts 通过 AWS SDK 凭证链解析账户 + 区域
    - bootstrap.ts 拉取/推送引导 tfstate 并运行 `terraform apply`
    - bootstrap-destroy.ts 清空状态存储桶并运行 `terraform destroy`
    - init.ts 使用 S3 后端配置运行 `terraform init`
    - env.ts 将 `terraform init` 指向共享提供程序缓存
  - checkov.yml Checkov 配置，包括要跳过的检查
  - project.json 项目配置和构建目标

</FileTree>


:::note[共享 Terraform 模块]
生成器还会创建一个 `packages/common/terraform` 库，该库最初只添加一个指标模块（创建一个带有元数据的空 Cloudformation 堆栈），该模块会自动进行检测，以便 `nx-plugin-for-aws` 团队可以跟踪使用指标。
:::
</OptionFilter>

<OptionFilter when={{ type: 'library' }} description="Library type: simpler layout for reusable Terraform modules">
### 库类型

对于库项目（`--type=library`），生成器为可重用的 Terraform 模块创建一个更简单的结构：

<FileTree>

  - src
    - main.tf 主 Terraform 模块文件
  - checkov.yml Checkov 配置，包括要跳过的检查
  - project.json 项目配置和构建目标

</FileTree>
</OptionFilter>

:::tip[应用程序与库]
应用程序项目包含具有远程状态管理的完整部署功能，而库项目旨在创建可被其他项目使用的可重用 Terraform 模块。
:::

## 实现您的 Terraform 基础设施

您可以在 `src/main.tf` 中开始编写您的 Terraform 基础设施，例如：

```diff title="src/main.tf" {16-49}
-locals {
-  account_id = data.aws_caller_identity.current.account_id
-  aws_region = data.aws_region.current.id
-}
-
-resource "null_resource" "print_info" {
-  # triggers = {
-  #   always_run = timestamp()
-  # }
-
-  provisioner "local-exec" {
-    command = "echo 'AWS Region: ${local.aws_region}, AWS Account: ${local.account_id}, Environment: ${var.environment}'"
-  }
-}
+
+# Declare your infrastructure here
+resource "aws_s3_bucket" "my_bucket" {
+  #checkov:skip=CKV_AWS_18:Access logging not required for this bucket
+  #checkov:skip=CKV_AWS_144:Cross-region replication not required for this bucket
+  #checkov:skip=CKV_AWS_145:AES256 (S3-managed) encryption is sufficient for this bucket
+  #checkov:skip=CKV2_AWS_61:Lifecycle configuration not required for this bucket
+  #checkov:skip=CKV2_AWS_62:Event notifications not required for this bucket
+  bucket = "my-unique-bucket-name"
+}
+
+resource "aws_s3_bucket_versioning" "my_bucket" {
+  bucket = aws_s3_bucket.my_bucket.id
+  versioning_configuration {
+    status = "Enabled"
+  }
+}
+
+resource "aws_s3_bucket_server_side_encryption_configuration" "my_bucket" {
+  bucket = aws_s3_bucket.my_bucket.id
+
+  rule {
+    apply_server_side_encryption_by_default {
+      sse_algorithm = "AES256"
+    }
+  }
+}
+
+resource "aws_s3_bucket_public_access_block" "my_bucket" {
+  bucket = aws_s3_bucket.my_bucket.id
+
+  block_public_acls       = true
+  block_public_policy     = true
+  ignore_public_acls      = true
+  restrict_public_buckets = true
+}
```

一个简单的 `aws_s3_bucket` 无法通过 `build` 运行的 [Checkov](#安全测试) 扫描，因此示例声明了扫描所期望的版本控制、加密和公共访问阻止资源，并通过 `#checkov:skip` 注释说明原因来抑制每个资源的其余检查。根据您自己的要求审查每个抑制——请参阅[安全测试](#安全测试)了解两种抑制机制。

### 跨项目依赖

如果您想从单独的项目（库）执行模块，可以按如下方式操作：

```
module "lib_module" {
  source = "../../path/to/my-lib/src"
}
```

这将自动更新 Nx 图，在您的使用应用程序和您的库之间添加依赖关系。

### 环境配置

在 `src/env/*.tfvars` 文件中配置特定环境的变量。

要添加新环境，请创建一个新的 `src/env/<environment>.tfvars` 文件，其中包含特定环境的变量，并在 `project.json` 中为新环境配置添加 `apply, destroy, init, plan` 的新条目。例如，假设我们想添加一个 `prod` 环境：

<Tabs>
<TabItem label="src/env/prod.tfvars">
```hcl
# Production environment variables
environment = "prod"
aws_region  = "us-west-2"
```

:::note[变量名称]
您在此处设置的每个名称都必须在 `src/variables.tf` 中声明——脚手架声明了 `aws_region` 和 `environment`。Terraform 只会对未声明变量的值发出警告，因此拼写错误的名称会被静默忽略而不是应用。
:::
</TabItem>
<TabItem label="project.json">
```diff
{
  "targets": {
        "apply": {
            "executor": "nx:run-commands",
            "defaultConfiguration": "dev",
            "configurations": {

                },
+                "prod": {
+                    "command": "terraform apply ../../../dist/packages/infra/terraform/prod.tfplan"
+                }
            },
            "options": {
                "forwardAllArgs": true,
                "cwd": "{projectRoot}/src"
            },
            "dependsOn": ["plan"]
        },
        "destroy": {
            "executor": "nx:run-commands",
            "defaultConfiguration": "dev",
            "configurations": {
                "dev": {
                    "command": "terraform destroy -var-file=env/dev.tfvars"
                },
+                "prod": {
+                    "command": "terraform destroy -var-file=env/prod.tfvars"
+                }
            },
            "options": {
                "forwardAllArgs": true,
                "cwd":"{projectRoot}/src"
            },
            "dependsOn": ["init"]
        },
        "init": {
            "executor": "nx:run-commands",
            "defaultConfiguration": "dev",
            "configurations": {
                "dev": {
                    "env": { "TF_ENV": "dev" }
                },
+                "prod": {
+                    "env": { "TF_ENV": "prod" }
+                }
            },
            "options": {
                "forwardAllArgs": true,
                "commands": ["tsx {projectRoot}/scripts/init.ts {projectRoot}"],
                "cwd": "{workspaceRoot}"
            }

        "plan": {
            "executor": "nx:run-commands",
            "defaultConfiguration": "dev",
            "configurations": {

                },
+                "prod": {
+                    "command": "terraform plan -var-file=env/prod.tfvars -out=../../../dist/packages/infra/terraform/prod.tfplan"
+                }
            },
            "options": {
                "forwardAllArgs": true,
                "cwd": "{projectRoot}/src"
            },
            "dependsOn": ["init"]
        }
    }
}
```
</TabItem>

### 远程状态引导（仅限应用程序项目）

在部署基础设施之前，您需要引导远程状态后端。这将创建一个 S3 存储桶来存储您的 Terraform 状态文件：

<NxCommands commands={['bootstrap tf-infra']} />

:::note[AWS 配置文件配置]
确保您的 AWS CLI 配置文件已配置到您希望部署引导资源的账户/区域。

引导目标仅适用于应用程序类型项目。库项目不需要远程状态管理，因为它们旨在成为可重用的模块。
:::
</OptionFilter>

## 可用目标

可用目标取决于您的项目类型：

### 通用目标（应用程序和库）

#### 验证您的基础设施

您可以使用 `validate` 目标验证您的 Terraform 配置：

<NxCommands commands={['validate tf-infra']} />

与 `test` 类似，这首先运行 `terraform init -backend=false`，因此它会安装验证所需的模块和提供程序，而无需配置 S3 后端。因此，它可以在新项目上运行，在 <Link path="guides/terraform-project#远程状态引导仅限应用程序项目">`bootstrap`</Link> 之前且无需 AWS 凭证，就像 `lint`、`test` 和 `checkov` 一样。

#### Linting

Terraform 项目使用 [`terraform fmt`](https://developer.hashicorp.com/terraform/cli/commands/fmt) 来检查格式。

##### 运行 Linter

要调用 linter 检查您的项目，您可以运行 `lint` 目标。

<NxCommands commands={["lint tf-infra"]} />

##### 修复 Lint 问题

大多数 linting 或格式化问题可以通过使用 `--configuration=fix` 参数运行来自动修复。

<NxCommands commands={["lint tf-infra --configuration=fix"]} />

同样，如果您想修复工作区中所有包的所有 lint 问题，可以运行：

<NxCommands commands={["run-many --target lint --all --configuration=fix"]} />

:::tip[简写命令]
这在您的工作区根目录有一个简写命令：

<PackageManagerShortCommand commands={["lint"]} />
:::

##### 跳过 Lint 问题

为了避免在开发过程中 linting 问题拖慢您的速度（特别是如果您的项目中有无法自动修复的问题），您可以使用 `skip-lint` 配置运行构建：

<NxCommands commands={["run-many --target build --configuration=skip-lint"]} />

这会在构建期间完全跳过格式检查。

:::tip[简写命令]
这在您的工作区根目录有一个简写命令：

<PackageManagerShortCommand commands={["build:skip-lint"]} />
:::

#### 安全测试

使用 Checkov 通过 `checkov` 目标对您的基础设施运行安全检查：

<NxCommands commands={['checkov tf-infra']} />

您将在根 `dist` 文件夹下的 `dist/packages/<my-terraform-project>/checkov` 中找到您的安全测试结果。

Checkov 作为 `build` 的一部分运行。

检查在项目的 `checkov.yml` 中配置。将检查 ID 添加到 `skip-check` 以在整个项目中抑制它：

```yaml title="checkov.yml"
skip-check:
  - CKV_AWS_115 # Concurrent execution limit
  - CKV_AWS_116 # Dead Letter Queue
```

要仅对单个资源抑制检查，请在资源块内添加 `#checkov:skip=<id>:<reason>` 注释：

```hcl
resource "aws_s3_bucket" "example" {
  #checkov:skip=CKV_AWS_18:Access logging not required for this bucket
  bucket = "example"
}
```

#### 运行 Terraform 测试

`test` 目标在项目中的任何 `.tftest.hcl` 文件上运行 [Terraform 的原生测试框架](https://developer.hashicorp.com/terraform/language/tests)：

<NxCommands commands={['test tf-infra']} />

没有测试文件的项目是无操作成功，因此您可以在需要时添加测试。`build` 运行此目标，因此您的测试作为正常构建的一部分运行。

每个 `run` 块评估您的配置。使用 `command = plan` 检查 Terraform _将会_执行的操作（这会展开整个模块图，因此它可以捕获 `validate` 无法捕获的计划时错误），或使用 `command = apply` 创建真实资源并断言其输出。声明 `mock_provider` 意味着不会进行 API 调用，也不需要 AWS 凭证，这使得 `plan` 测试快速且可以安全地在 CI 中运行：

```hcl title="src/main.tftest.hcl"
mock_provider "aws" {
  mock_data "aws_caller_identity" {
    defaults = { account_id = "123456789012" }
  }
  mock_data "aws_region" {
    defaults = { region = "us-east-1" }
  }
}

variables {
  aws_region  = "us-east-1"
  environment = "dev"
}

run "plan_is_valid" {
  command = plan

  assert {
    condition     = data.aws_caller_identity.current.account_id == "123456789012"
    error_message = "Unexpected account id"
  }
}
```

在 `variables` 块中设置配置所需的每个变量，否则运行将失败并显示"has a required variable ... with no set value"。

每个运行 `terraform init` 的目标都在工作区根目录的 `.terraform/plugin-cache` 下重用提供程序缓存，因此提供程序只下载一次而不是每次运行时都下载。每个项目在那里都有自己的目录：两个 `terraform init` 运行同时填充一个缓存时，每个都可能为同一个提供程序计算不同的哈希值，然后 terraform 会根据您的 `.terraform.lock.hcl` 拒绝它。有关更多信息，请参阅 [Terraform 文档](https://developer.hashicorp.com/terraform/cli/config/config-file#provider-plugin-cache)。

在您的环境中设置 `TF_PLUGIN_CACHE_DIR` 以将提供的 `init` 脚本指向您自己管理的缓存——例如在工作区之间共享的卷。这只会影响通过脚本的目标，即应用程序项目的 `init`。其他每个目标都在 `project.json` 中将路径声明为 `env` 条目，而 Nx 的 `env` 块优先于环境变量，因此也要在那里更改它——对于任一项目类型的 `test` 和 `validate`，以及对于库项目的 `init`。

### 仅限应用程序的目标

以下目标仅适用于应用程序类型项目：

#### 规划您的基础设施

在应用更改之前，您可以通过运行 `plan` 目标来查看 Terraform 将执行的操作：

<NxCommands commands={['plan tf-infra']} />

这将在 `dist/packages/<my-terraform-project>/terraform/dev.tfplan` 中创建一个计划文件。

`plan` 依赖于 `assemble`，因此它会生成您的模块引用的工件，例如 Lambda 包和生成的操作元数据，而不运行 lint、test 和 type-check 门控。

:::caution[在您的管道中使用 `build`]
`assemble` 用于开发期间的快速迭代。在您的 CI 管道中运行 `build`，以确保您的项目在生产部署之前通过质量门控。
:::

#### 初始化 Terraform

使用 `init` 目标初始化您的 Terraform 工作目录：

<NxCommands commands={['run tf-infra:init']} />

#### 部署到 AWS

规划后，您可以使用 `apply` 目标将基础设施部署到 AWS：

<NxCommands commands={['apply tf-infra']} />

:::tip[自动批准]
上述命令应用由 `plan` 目标创建的计划。确保先运行 `plan` 以查看更改。
:::

:::note[部署别名]
`deploy` 目标也可作为 `apply` 的别名使用。您可以互换使用 <NxCommands commands={['deploy tf-infra']} /> 或 <NxCommands commands={['apply tf-infra']} />。
:::

#### 获取输出

从您的 Terraform 配置中检索输出值：

<NxCommands commands={['output tf-infra']} />

#### 销毁基础设施

当您需要拆除基础设施时，使用 `destroy` 目标：

<NxCommands commands={['destroy tf-infra']} />

:::caution[破坏性操作]
这将永久删除此 Terraform 配置管理的所有资源。请谨慎使用！
:::

#### 销毁引导资源

要清理引导资源（用于状态存储的 S3 存储桶）：

<NxCommands commands={['bootstrap-destroy tf-infra']} />

这会在销毁状态存储桶之前清空它，并从 AWS SDK 凭证链解析区域，因此它可以在 CI 中无人值守运行。

:::caution[首先销毁您的基础设施]
状态存储桶保存每个环境的状态，因此在此之前为每个环境运行 `destroy`。一旦存储桶消失，Terraform 将不再知道它创建的资源。
:::
</OptionFilter>
