此生成器向现有 Python 项目添加容器化 HTTP 服务。您将获得一个小型 [FastAPI](https://fastapi.tiangolo.com/) 服务器，由 [uvicorn](https://www.uvicorn.org/) Web 服务器运行，带有 `GET /health` 路由和示例路由 `GET /echo`、Dockerfile 以及用于在本地运行服务器、构建镜像和扫描镜像的目标。您还将获得在 [Amazon Elastic Container Service (Amazon ECS)](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/Welcome.html)（运行和扩展容器的 AWS 服务）上运行镜像的 CDK 或 Terraform 代码。

## 工作原理

该服务运行在 [AWS Fargate](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/AWS_Fargate.html) 上，它无需您管理服务器即可运行每个容器。您容器的每个运行副本都是一个 ECS 任务。任务运行在您自己的 VPC（虚拟私有云，AWS 账户中的隔离网络）中。安全组（附加到任务的一组防火墙规则）控制哪些网络流量可以到达它们和离开它们。

该服务是私有的。它没有负载均衡器、没有 API 也没有公共 IP 地址。其安全组没有入站规则，因此在您允许调用者之前，没有任何东西可以打开到服务的连接。该服务仍然可以进行出站调用，例如到数据库或其他 AWS 服务。

## 在本地运行您的服务

`<name>-serve` 目标在您的机器上运行服务器，无需容器：

<NxCommands commands={['run your-project:service-serve']} />

服务器监听 `PORT` 环境变量中的端口。`<name>-serve` 目标将其设置为生成器分配的端口，从 8081 开始，跳过工作区中其他项目已使用的端口。在容器内，服务器监听端口 8080。

服务器监听 `HOST` 环境变量中的地址，默认为 `127.0.0.1`，因此 `<name>-serve` 目标仅接受来自您自己机器的连接。镜像设置 `HOST=0.0.0.0`，因此在任务内部，服务器监听任务自己的网络接口。任务的安全组仍然决定谁可以连接。

使用其健康检查路由检查服务器是否启动，它返回状态 200 和 `{"status":"ok"}`：

```bash
curl http://localhost:<port>/health
```

服务器还有一个示例路由，您可以用自己的路由替换它。`GET /echo?message=<x>` 返回 `{"message":"<x>"}`。`message` 参数是必需的，最多可以有 1024 个字符。没有它的请求或值更长的请求会获得状态 422。

## 构建和扫描镜像

`<name>-docker` 目标构建您服务的 linux/arm64 镜像。它首先运行 `bundle-arm` 目标，将您的代码及其 linux/arm64 依赖项写入 `dist/<project root>/bundle-arm`。聚合的 `bundle` 目标依赖于 `bundle-arm`。然后 `<name>-docker` 目标将该文件夹、`Dockerfile` 和 `.dockerignore` 复制到 `dist/<project root>/docker/<name>`，并使用该文件夹作为构建上下文（镜像构建可以读取的文件）构建镜像。它使用您的工作区设置的容器引擎，`docker` 或 [Finch](https://runfinch.com/)。该目标作为聚合 `docker` 目标的一部分运行，该目标构建项目中的每个镜像。

<NxCommands commands={['run your-project:service-docker']} />

在 ECS 上，健康检查命令在容器内运行，并在容器端口上调用 `GET /health`。它不需要入站访问。ECS 会替换健康检查持续失败的任务。ECS 忽略 Dockerfile 中的 `HEALTHCHECK` 指令。有关如何构建和发布镜像的更多信息，请参阅 <Link path="/guides/docker-bundling">Docker 打包</Link>。

## 部署您的服务

### 将服务添加到您的基础设施

构造和模块从不创建 VPC。您在堆栈或根模块中创建或导入一个并传递它。任务在具有出口的私有子网中运行，通过 NAT 网关（允许私有子网进行出站连接的托管网关）或通过 VPC 端点（从您的 VPC 到 AWS 服务的私有连接）访问 AWS 服务。

<Infrastructure>
<Fragment slot="cdk">
CDK 构造在 `common/constructs` 中创建，并以您的服务命名。使用新 VPC 的示例用法：

```ts title="packages/infra/src/stacks/application-stack.ts"
import { MyService } from '@my-scope/common-constructs';
import { Stack, StackProps } from 'aws-cdk-lib';
import { SubnetType, Vpc } from 'aws-cdk-lib/aws-ec2';
import { Construct } from 'constructs';

export class ApplicationStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props);

    const vpc = new Vpc(this, 'Vpc', { natGateways: 1 });

    new MyService(this, 'MyService', {
      vpc,
      vpcSubnets: { subnetType: SubnetType.PRIVATE_WITH_EGRESS },
    });
  }
}
```

要使用现有 VPC，请使用 `Vpc.fromLookup(this, 'Vpc', { vpcId: '<vpc-id>' })` 查找它并将其作为 `vpc` 传递。
</Fragment>
<Fragment slot="terraform">
Terraform 模块在 `common/terraform` 中创建。服务的镜像发布到共享资产存储库，因此每次部署实例化一次 `core/asset-ecr` 模块，并将其输出传递给每个服务模块。还要传递共享 `runtime_config_appconfig` 模块的输出，其中包含服务从中读取其<Link path="/guides/runtime-config">运行时配置</Link>的 AWS AppConfig 应用程序：

```hcl title="packages/infra/src/main.tf"

}

module "my_service" {
  source = "../../common/terraform/src/app/services/my-service"

  vpc_id     = aws_vpc.main.id
  subnet_ids = aws_subnet.private[*].id

  asset_ecr_repository_url = module.asset_ecr.repository_url
  asset_ecr_repository_arn = module.asset_ecr.repository_arn

  appconfig_application_id  = module.runtime_config_appconfig.application_id
  appconfig_application_arn = module.runtime_config_appconfig.application_arn
}
```

### 在没有 NAT 网关的情况下运行

当您的任务启动时，ECS 代表它们拉取镜像并发送日志。您的服务器代码也可能调用 AWS 服务。在没有 NAT 网关的私有子网中，这些调用中的每一个都需要一个 VPC 端点。如果没有正确的端点，任务将无法启动或在调用 AWS 时超时。

在 VPC 中创建这些端点，将 `<region>` 替换为您的 AWS 区域：

| 端点 | 类型 | 使用者 |
| --- | --- | --- |
| `com.amazonaws.<region>.ecr.api` | 接口 | ECS，用于向 Amazon ECR 进行身份验证并查找镜像 |
| `com.amazonaws.<region>.ecr.dkr` | 接口 | ECS，用于从 Amazon ECR 拉取镜像 |
| `com.amazonaws.<region>.s3` | 网关 | ECS，用于下载镜像层，Amazon ECR 将其存储在 Amazon S3 中 |
| `com.amazonaws.<region>.logs` | 接口 | 容器的日志输出，发送到 Amazon CloudWatch Logs |
| `com.amazonaws.<region>.secretsmanager` | 接口 | ECS，用于读取您在任务启动时传递给容器的密钥 |
| `com.amazonaws.<region>.appconfigdata` | 接口 | 您的代码，用于从 AWS AppConfig 读取<Link path="/guides/runtime-config">运行时配置</Link> |
| `com.amazonaws.<region>.sts` | 接口 | 您的代码，当它从 AWS STS 请求临时凭证时（例如担任另一个角色） |

接口端点需要一个允许来自任务的 HTTPS（端口 443）的安全组。有关 Amazon ECR 端点的详细信息，请参阅 [Amazon ECR 接口 VPC 端点](https://docs.aws.amazon.com/AmazonECR/latest/userguide/vpc-endpoints.html)。

### 安全默认值

生成的基础设施默认应用这些设置：

- 服务的安全组没有入站规则。在您添加规则之前，VPC 内部或外部的任何调用者都无法连接到任务。
- 任务在私有子网中运行，永远不会获得公共 IP 地址。
- 生成器不会在服务前面创建负载均衡器和 API。
- 任务只能在端口 443 上发送出站流量。与数据库的连接会添加数据库端口。
- 任务角色（您的服务器代码运行的角色）只能从 AWS AppConfig 读取运行时配置，直到您或连接授予更多权限。
- 执行角色（ECS 用于启动任务的角色）只能拉取服务的镜像、写入其日志组并读取您列出的密钥。
- 密钥仅作为对 AWS Secrets Manager 或 AWS Systems Manager Parameter Store 的引用到达容器，永远不会作为纯环境值。
- 容器具有只读根文件系统和可写的 `/tmp` 文件夹，并以 uid 1000（非 root 用户）运行。ECS Exec（对运行中任务的 shell 访问）已关闭。
- 健康检查失败的部署会停止并回滚到以前的版本。
- 日志组使用 AWS KMS 密钥加密，日志保留一年。

### 让调用者访问您的服务

生成的服务无法被调用。如果 VPC 中的另一个工作负载需要调用它，例如 Lambda 函数或另一个 ECS 服务，您需要自己向服务的安全组添加入站规则。生成器不添加入站规则。通过其安全组在容器端口上允许一个命名的调用者，永远不要允许地址范围。

<Infrastructure>
<Fragment slot="cdk">
构造实现了 `IConnectable`，因此通过其 `connections` 允许调用者的安全组：

```ts title="packages/infra/src/stacks/application-stack.ts"
import { Port } from 'aws-cdk-lib/aws-ec2';

const svc = new MyService(this, 'MyService', { vpc });
svc.connections.allowFrom(callerSecurityGroup, Port.tcp(8080));
```

如果调用者的安全组在您的 CDK 应用中定义并限制出站流量，`allowFrom` 还会向其添加匹配的出站规则。
</Fragment>
<Fragment slot="terraform">
向服务的安全组添加入站规则，您的服务模块将其输出为 `security_group_id`，以调用者的安全组作为源：

```hcl title="packages/infra/src/main.tf"
resource "aws_vpc_security_group_ingress_rule" "caller_to_my_service" {
  security_group_id            = module.my_service.security_group_id
  referenced_security_group_id = aws_security_group.caller.id
  from_port                    = 8080
  to_port                      = 8080
  ip_protocol                  = "tcp"
}
```

如果调用者的安全组限制出站流量，还要在调用者的组上添加一个 `aws_vpc_security_group_egress_rule` 到服务的安全组。
</Fragment>
</Infrastructure>

调用者连接到任务的私有 IP 地址。生成器不设置服务发现，当 ECS 替换任务时，任务的地址会改变。要为调用者提供稳定的名称，请自己设置服务发现，例如使用 [Amazon ECS Service Connect](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/service-connect.html)。

### 高级配置

生成的服务为您设置其名称和镜像。下面的示例直接使用通用 `EcsService` 构造和 `ecs-service` 模块，用于生成的服务不传递的设置。

在 CDK 中，您的 `common-constructs` 包在您服务的构造旁边导出 `EcsService`，因此您以相同的方式导入它：`import { EcsService } from '@my-scope/common-constructs'`。生成的构造扩展 `EcsService` 并传递所有其他属性，例如 `cluster`、`environment`、`secrets` 和 `grantTaskRole`。其可选的 `image` 属性替换从您的项目构建的镜像。

在 Terraform 中，您的服务模块只允许您设置 `ecs-service` 模块的某些变量：`vpc_id`、`subnet_ids`、`cluster_arn`、`environment`、`secrets`、`task_role_policy_statements` 和 `tags`。要设置任何其他变量，请编辑您服务模块中的 `module "ecs_service"` 块。

#### 大小和扩展

默认情况下，每个任务获得 256 个 CPU 单元（四分之一 vCPU）和 512 MiB 内存。服务启动一个任务，自动扩展保持一到两个任务运行，当平均 CPU 使用率超过 70% 时添加任务。

| 设置 | CDK 属性 | Terraform 变量 | 默认值 |
| --- | --- | --- | --- |
| 每个任务的 CPU 单元 | `cpu` | `cpu` | 256 |
| 每个任务的内存 (MiB) | `memoryLimitMiB` | `memory` | 512 |
| 启动时的任务数 | `desiredCount` | `desired_count` | 1 |
| 最少任务数 | `minCapacity` | `min_capacity` | 1 |
| 最多任务数 | `maxCapacity` | `max_capacity` | 2 |
| 目标平均 CPU (%) | `targetCpuUtilizationPercent` | `target_cpu_utilization` | 70 |

#### 容器用户

任务定义将容器作为 uid 1000（非 root 用户）运行。提供的 Dockerfile 与之匹配：它创建一个 uid 和 gid 为 1000 的用户 `app` 并设置 `USER 1000:1000`。要以另一个用户身份运行，请设置 CDK `user` 属性或 Terraform `container_user` 变量。Terraform 拒绝 `0` 和 `root`。

| 设置 | CDK 属性 | Terraform 变量 | 默认值 |
| --- | --- | --- | --- |
| 容器运行的用户 | `user` | `container_user` | `'1000'` (CDK), `"1000:1000"` (Terraform) |

在 Terraform 中，`container_user` 是 `ecs-service` 模块的变量。您的服务模块不传递它，因此在其 `module "ecs_service"` 块中设置它。

### 成本

容器服务在空闲时计费，不像 Lambda 函数。无论是否有人调用服务，这些部分都按小时计费：

- Fargate 任务，按 vCPU 和每 GB 内存计费。`desiredCount` 和 `minCapacity` 至少保持一个任务运行。
- 接口 VPC 端点，在每个可用区按小时计费，或 NAT 网关，按小时和每 GB 处理的数据计费。
- CloudWatch Logs 中的日志存储和 Amazon ECR 中的镜像存储。

要估算您的区域和流量的成本，请使用 [AWS 定价计算器](https://calculator.aws/)。

### 销毁您的服务
