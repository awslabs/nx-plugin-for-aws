生成一个 TypeScript [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) 服务器，为大型语言模型（LLMs）提供上下文，并可选择将其部署到 [Amazon Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/)。

## 什么是 MCP？

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/) 是一个开放标准，允许 AI 助手与外部工具和资源进行交互。它为 LLMs 提供了一种一致的方式来：

- 执行工具（函数）以执行操作或检索信息
- 访问提供上下文或数据的资源

## 使用您的 MCP Server

### 添加工具

工具是 AI 助手可以调用以执行操作的函数。每个工具都位于 `tools/` 下的独立文件中，该文件导出一个 `register<Name>Tool` 函数，然后您从 `server.ts` 中调用它。例如，添加 `tools/my-tool.ts`：

```typescript title="tools/my-tool.ts"
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';
import { z } from 'zod';

export const registerMyTool = (server: McpServer) => {
  server.registerTool("toolName", {
    description: "tool description",
    inputSchema: { param1: z.string(), param2: z.number() } // Input schema using Zod
  },
    async ({ param1, param2 }) => {
      // Tool implementation
      return {
        content: [{ type: "text", text: "Result" }]
      };
    }
  );
};
```

然后在 `server.ts` 的 `createServer` 中注册它：

```typescript title="server.ts" {6}
import { registerMyTool } from './tools/my-tool.js';

export const createServer = async () => {
  const server = new McpServer({ name: 'my-server', version: '1.0.0' });

  registerMyTool(server);

  return server;
};
```

### 添加资源

资源为 AI 助手提供上下文。与工具类似，每个资源都位于 `resources/` 下的独立文件中，该文件导出一个从 `server.ts` 调用的 `register<Name>Resource` 函数。您可以从文件添加静态资源或动态资源：

```typescript title="resources/my-resource.ts"
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';

export const registerMyResource = (server: McpServer) => {
  const exampleContext = 'some context to return';

  server.registerResource('resource-name', 'example://resource', {}, async (uri) => ({
    contents: [{ uri: uri.href, text: exampleContext }],
  }));

  // Dynamic resource
  server.registerResource('dynamic-resource', 'dynamic://resource', {}, async (uri) => {
    const data = await fetchSomeData();
    return {
      contents: [{ uri: uri.href, text: data }],
    };
  });
};
```

## 运行您的 MCP Server

### 本地开发

要在本地运行您的 MCP 服务器（以及与其连接的所有内容，例如本地数据库），请使用项目的 `dev` 目标：

<NxCommands commands={['dev your-project']} />

如果您已向项目添加了多个组件（MCP 服务器、代理等），这将启动所有组件。要仅运行此 MCP 服务器，请以其 `<your-server-name>-dev` 目标为目标：

<NxCommands commands={['your-server-name-dev your-project']} />

### Inspector

生成器配置了一个名为 `<your-server-name>-inspect` 的目标，它会在本地启动您的 MCP 服务器（通过 `<your-server-name>-dev` 目标，包括任何连接的依赖项，例如本地数据库），并启动预配置为通过 Streamable HTTP 传输连接到它的 [MCP Inspector](https://github.com/modelcontextprotocol/inspector)。

<NxCommands commands={['your-server-name-inspect your-project']} />

这将在 `http://localhost:6274` 启动检查器。点击"Connect"按钮开始使用。

:::tip
要使用 STDIO 传输检查服务器，请使用 `<your-server-name>-inspect-stdio` 目标，它会针对服务器的 STDIO 实例启动检查器。
:::

### STDIO

测试和使用 MCP 服务器的最简单方法是使用检查器或将其配置为 AI 助手（如上所述）。

但是，您可以使用 `<your-server-name>-serve-stdio` 目标直接使用 [STDIO transport](https://modelcontextprotocol.io/docs/concepts/transports#standard-input%2Foutput-stdio) 运行服务器。

<NxCommands commands={['your-server-name-serve-stdio your-project']} />

此命令使用 `tsx --watch` 在文件更改时自动重启服务器。

### Streamable HTTP

如果您想使用 [Streamable HTTP transport](https://modelcontextprotocol.io/docs/concepts/transports#streamable-http) 在本地运行 MCP 服务器，可以使用 `<your-server-name>-serve` 目标。

<NxCommands commands={['your-server-name-serve your-project']} />

此命令使用 `tsx --watch` 在文件更改时自动重启服务器。

### Bundle 目标

<Snippet name="ts-bundle" />

bundle 目标使用 `http.ts` 作为 Streamable HTTP MCP 服务器的入口点，以便在 Bedrock AgentCore Runtime 上托管。

<OptionFilter when={{ infra: 'agentcore' }} description="Code package target">
### Package 目标

生成器配置了一个 `<your-server-name>-package` 目标，它组装可部署的代码包：打包的 `index.js` 加上 AWS Distro for OpenTelemetry 的供应商安装，AgentCore 要求该包中必须存在该组件。生成的基础设施将此目录上传为 `.zip` — 在 CDK 下通过 `AgentRuntimeArtifact.fromCodeAsset`，或在 Terraform 下归档到共享资产存储桶中。
</OptionFilter>

<OptionFilter when={{ infra: 'agentcore-ecr' }} description="Container image build and scan">
### Docker 目标

生成器配置了一个 `<your-server-name>-docker` 目标，它将 `Dockerfile` 从您的 MCP 服务器源目录复制到 bundle 输出目录。这将 `Dockerfile` 与打包的工件放在一起，允许 CDK 使用 `AgentRuntimeArtifact.fromAsset` 直接构建 Docker 镜像。

如果您定义了多个 MCP 服务器，还会生成一个 `docker` 目标，为所有 MCP 服务器准备 docker 上下文。
