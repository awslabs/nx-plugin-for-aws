`connection` 生成器让 <Link path="guides/py-container">Python 容器服务</Link>使用 <Link path="guides/py-rdb">Python 关系数据库</Link>项目。它将数据库包添加为服务项目的依赖项，并为服务的 Docker 镜像准备与 Amazon Aurora 的 SSL 连接。

## 工作原理

使用 `infra=ecs` 的容器服务在您的 VPC 中作为 Amazon ECS（Elastic Container Service）上的任务运行。每个任务以服务的任务角色运行，这是一个在您授予更多权限之前只能读取运行时配置的 IAM 角色，并且位于服务的安全组中，该安全组仅允许端口 443 上的出站流量。要使用数据库，服务需要两个默认情况下不具备的条件：

- `rds-db:connect` 的 IAM 权限，以便它可以使用 IAM 身份验证登录数据库。
- 数据库端口上的安全组规则对：数据库安全组上的入站规则和服务安全组上的出站规则。如果没有出站规则，服务无法访问数据库，因为其安全组仅允许端口 443 出站。

生成器会拒绝使用 `infra=none` 的服务，因为这样的服务没有任务角色可以授予访问权限。

## 前提条件

在使用此生成器之前，请确保您具有：

1. 使用 `infra=ecs` 的容器服务（使用 <Link path="guides/py-container">`py#container`</Link> 生成器生成）
2. 一个 <Link path="guides/py-rdb">`py#rdb`</Link> 项目

## 在服务中使用数据库

从您的数据库包中导入 `session_context` 并在处理请求的地方使用它：

```python title="packages/my_project/my_project/my_service/orders.py"
from sqlmodel import select
from my_scope_my_database import session_context
from my_scope_my_database.models.example import ExampleModel


async def list_examples() -> list[dict]:
    async with session_context() as session:
        items = (await session.execute(select(ExampleModel))).scalars().all()
        return [item.model_dump() for item in items]
```

数据库包使用 `RUNTIME_CONFIG_APP_ID` 环境变量从<Link path="guides/runtime-config">运行时配置</Link>中读取数据库的连接详细信息。

生成的容器服务设置 `RUNTIME_CONFIG_APP_ID` 并授予其任务角色对运行时配置的读取访问权限，因此您无需自己添加这两项。在 Terraform 中，服务的模块块必须传递 `appconfig_application_id` 和 `appconfig_application_arn`，如<Link path="guides/py-container">容器指南</Link>中所示。

## 基础设施

生成器不会更改您的堆栈或根 Terraform 模块。相反，它会打印要添加的代码，下面显示了名为 `my-service` 的服务和名为 `my-database` 的数据库的代码。在您添加它之前，服务无法访问数据库端口，数据库会拒绝其 IAM 身份验证。

<Infrastructure>
<Fragment slot="cdk">

在示例中，`myService` 是您的 `MyService` 构造，`myDatabase` 是您的 `MyDatabase` 构造：

```ts title="packages/infra/src/stacks/application-stack.ts"
myDatabase.allowDefaultPortFrom(myService);
myDatabase.grantConnect(myService.taskRole);
```

`allowDefaultPortFrom` 在数据库的安全组上添加入站规则，在服务的安全组上添加出站规则。`grantConnect` 向服务的任务角色授予 `rds-db:connect` 权限。

<Fragment slot="terraform">

在示例中，`module "my_service"` 部署服务，`module "my_database"` 部署数据库。`data "aws_region" "current"` 和 `data "aws_caller_identity" "current"` 数据源在生成的 `providers.tf` 中声明：

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_role_policy" "my_service_my_database_connect" {
  name = "my-service-my-database-connect"
  role = module.my_service.task_role_name

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = ["rds-db:connect"]
        Resource = ["arn:aws:rds-db:${data.aws_region.current.region}:${data.aws_caller_identity.current.account_id}:dbuser:${module.my_database.connect_resource_id}/${module.my_database.database_runtime_user}"]
      },
    ]
  })
}

resource "aws_vpc_security_group_ingress_rule" "my_service_to_my_database" {
  description                  = "Allow the my-service container service to connect to the database"
  security_group_id            = module.my_database.security_group_id
  referenced_security_group_id = module.my_service.security_group_id
  from_port                    = module.my_database.cluster_port
  to_port                      = module.my_database.cluster_port
  ip_protocol                  = "tcp"
}

resource "aws_vpc_security_group_egress_rule" "my_service_to_my_database" {
  description                  = "Allow the my-service container service to reach the database"
  security_group_id            = module.my_service.security_group_id
  referenced_security_group_id = module.my_database.security_group_id
  from_port                    = module.my_database.cluster_port
  to_port                      = module.my_database.cluster_port
  ip_protocol                  = "tcp"
}
```

### 不使用 RDS Proxy 连接时的 SSL 要求

当服务直接连接到 Aurora 集群而不使用 RDS Proxy 时，它必须信任 Amazon RDS 证书颁发机构。生成器在服务的 Dockerfile 中的 `EXPOSE` 行之前添加这些行，以将 Amazon RDS CA 捆绑包安装到系统信任存储中：

```dockerfile
ADD https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem /usr/local/share/ca-certificates/rds-global-bundle.crt
RUN update-ca-certificates
```

使用 RDS Proxy 时，您不需要 RDS CA 捆绑包。
