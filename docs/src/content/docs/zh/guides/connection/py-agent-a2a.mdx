`connection` 生成器可以将您的 <Link path="guides/py-agent">Python Agent</Link> 连接到远程 [A2A](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-a2a.html) agent——无论是 <Link path="guides/ts-agent">TypeScript</Link> 还是 <Link path="guides/py-agent">Python</Link>——这样您的 agent 就可以将任务委托给另一个 agent 作为工具。

该生成器会设置所有必要的连接，使您的 agent 能够发现和调用远程 A2A agent，无论是部署到 AWS（通过 Bedrock AgentCore）还是在本地运行时。

## 前提条件

在使用此生成器之前，请确保您具备：

1. 一个包含 <Link path="guides/py-agent">Python Agent</Link> 组件的 Python 项目（Strands 或 LangChain）
2. 一个使用 `--protocol=a2a` 和 `--auth=iam` 生成的 Agent 组件项目（<Link path="guides/ts-agent">`ts#agent`</Link> 或 <Link path="guides/py-agent">`py#agent`</Link>）
3. 两个组件都使用 `infra: agentcore` 创建

## 生成器输出

生成器会在 `packages/common/agent_connection/` 创建一个共享的 `agent_connection` Python 项目（如果尚不存在）。每个连接的客户端模块都会生成到这个共享项目中：

<FileTree>

- packages/common/agent\_connection
  - \<scope>\_agent\_connection
    - \_\_init\_\_.py 重新导出每个连接的客户端
    - core
      - \_\_init\_\_.py Python 包初始化
      - agentcore\_endpoints.py 框架无关的 ARN/URL 解析
      - agentcore\_a2a\_client\_config.py 框架无关的 A2A 客户端配置（签名的 `ClientConfig`）
      - agentcore\_a2a\_client\_\<framework>.py 为您的 agent 框架包装配置的 A2A 客户端
      - auth/ 框架无关的 SigV4 / 会话转发 `httpx.Auth`
    - app
      - \_\_init\_\_.py Python 包初始化
      - \<target\_agent\_name>\_client\_\<framework>.py 每个 A2A agent 的连接专用 A2A 客户端

</FileTree>

客户端后缀与您的 agent 框架匹配（`_strands` 或 `_langchain`）。两者都包装相同的框架无关签名 `ClientConfig`：Strands 客户端包装 Strands `A2AAgent`，而 LangChain 客户端直接驱动 [a2a SDK](https://pypi.org/project/a2a-sdk/)。

此外，生成器还会：
- 转换您的 agent 的 `agent.py`，使用 `@tool` 将远程 A2A agent 注册为工具
- 将 `agent_connection` 项目添加为您的 agent 项目的工作区依赖项
- 更新 agent 的 `dev` 目标以依赖于目标 agent 的 `dev` 目标

## 使用已连接的 A2A Agent

生成器会转换您的 agent 的 `agent.py`，将远程 A2A agent 包装为工具。远程 agent 通过 `@tool` 装饰的委托进行注册——装饰器的导入和 agent 构造函数因框架而异：

<Tabs syncKey="agent-framework">
<TabItem label="Strands" _filter={{ framework: 'strands' }}>
```python title="packages/my-project/my_module/agent/agent.py" {4,8-13,15}
from contextlib import contextmanager
from strands import Agent, tool

from my_scope_agent_connection import RemoteAgentClientStrands

@contextmanager
def get_agent():
    remote_agent = RemoteAgentClientStrands.create()

    @tool
    def ask_remote_agent(prompt: str) -> str:
        """Delegate a question to the remote RemoteAgent A2A agent and return its reply."""
        return str(remote_agent(prompt))

    yield Agent(
        system_prompt="...",
        tools=[ask_remote_agent],
    )
```
</TabItem>
<TabItem label="LangChain" _filter={{ framework: 'langchain' }}>
```python title="packages/my-project/my_module/agent/agent.py" {5,8-13,15}
from langchain.agents import create_agent
from langchain_aws import ChatBedrockConverse
from langchain_core.tools import tool

from my_scope_agent_connection import RemoteAgentClientLangChain

def get_agent():
    remote_agent = RemoteAgentClientLangChain.create()

    @tool
    def ask_remote_agent(prompt: str) -> str:
        """Delegate a question to the remote RemoteAgent A2A agent and return its reply."""
        return str(remote_agent(prompt))

    return create_agent(
        model=ChatBedrockConverse(model=MODEL_ID, region_name=REGION),
        system_prompt="...",
        tools=[ask_remote_agent],
    )
```
</TabItem>
</Tabs>

两个客户端都可以直接调用，返回远程 agent 的回复，并包装一个 `httpx.AsyncClient`，该客户端在部署到 AWS 时使用 SigV4 签名请求，在 `LOCAL_DEV=true` 时使用普通的 `http://localhost:<port>/` 端点。Strands 客户端包装 Strands `A2AAgent`；LangChain 客户端直接驱动 a2a SDK。

AgentCore 会话 ID 会通过 `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id` 标头自动传播到远程 agent，无论框架如何：agent 服务器将入站请求的会话绑定到异步上下文中，连接客户端的签名 `httpx.Auth` 会在每个出站调用上标记它——确保 [Bedrock AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html) 的一致性。

## 本地开发

生成器会配置宿主 agent 的 `dev` 目标以：
1. 自动启动已连接的 A2A agent
2. 设置 `LOCAL_DEV=true`，使生成的客户端直接连接到 `http://localhost:<port>/` 而不是 AgentCore

使用以下命令在本地运行 agent：

<NxCommands commands={["<agent-name>-dev <project-name>"]} />

这将启动宿主 agent 和所有已连接的 A2A agent，宿主 agent 通过分配的本地端口通过普通 HTTP 调用远程 agent。
