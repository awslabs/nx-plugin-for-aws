`connection` 生成器让 <Link path="guides/py-agent">Python Agent</Link> 调用使用 <Link path="guides/ts-container">`ts#container`</Link> 或 <Link path="guides/py-container">`py#container`</Link> 创建的容器服务。它向共享的 `agent_connection` 项目添加一个客户端,该客户端从运行时配置中读取服务的 URL,并使用 agent 自己的 AWS 凭证对每个请求进行签名。

## 工作原理

使用 `infra=ecs` 的容器服务在内部应用程序负载均衡器后面的 Amazon ECS (Elastic Container Service) 上运行。使用默认的 `ingress=http-api` 时,Amazon API Gateway HTTP API(托管的 HTTPS 端点)通过 VPC 链接访问该负载均衡器,VPC 链接是 API Gateway 到您的 VPC 的私有连接。agent 调用 HTTP API。

客户端使用 agent 角色的凭证,通过 SigV4(AWS 请求签名过程)对每个请求进行签名。当该角色可以对其调用 `execute-api:Invoke` 时,HTTP API 接受该请求。HTTP API 会结束任何超过 30 秒的请求,因此运行时间较长的路由必须提前返回并在后台完成其工作。

生成器会拒绝无法以这种方式访问的服务。服务必须具有 `infra=ecs`,因为 `infra=none` 不会创建端点。它必须具有 `ingress=http-api`,因为 `private` 服务只能从其 VPC 内部访问。它必须具有 `auth=iam`,因为 agent 使用 IAM 凭证对其请求进行签名,并且没有 Cognito 令牌可发送。

## 前提条件

在使用此生成器之前,请确保您具有:

1. 一个 <Link path="guides/py-agent">`py#agent`</Link> 项目
2. 一个具有 `infra=ecs`、`ingress=http-api` 和 `auth=iam` 的容器服务(使用 <Link path="guides/ts-container">`ts#container`</Link> 或 <Link path="guides/py-container">`py#container`</Link> 生成器生成)

## 生成器输出

生成器在共享的 `agent_connection` 项目中创建以下文件:

<FileTree>

- packages/common/agent\_connection
  - my\_scope\_agent\_connection
    - app
      - \<service\_name>\_client.py 从运行时配置中读取服务 URL 并使用 SigV4 对请求进行签名的客户端
    - \_\_init\_\_.py 导出 `get_<service_name>_client`

</FileTree>

它将 `httpx` 和 `boto3` 添加到 `agent_connection` 项目,将 `agent_connection` 项目添加为您的 agent 项目的依赖项,并使 agent 的 `<agent-name>-dev` 目标启动服务的 `<service-name>-serve` 目标。

## 使用客户端

`get_<service_name>_client()` 从 <Link path="guides/runtime-config">运行时配置</Link> 的 `connection` 命名空间中的 `services.<ServiceName>` 下读取服务的 URL。它返回一个 `httpx.Client`,其路径相对于服务。生成器不会更改您的 agent 代码。要让模型调用服务,请将客户端包装在工具中:

```python title="packages/my_project/my_project/my_agent/agent.py"
from my_scope_agent_connection import get_my_service_client
from strands import tool


@tool
def check_my_service() -> int:
    """Check whether the MyService container service is healthy."""
    with get_my_service_client() as client:
        return client.get("/health").status_code
```

将 `check_my_service` 添加到您的 agent 的 `tools` 列表中。当未设置 `RUNTIME_CONFIG_APP_ID` 时,当它无法找到 AWS 区域(从 `AWS_REGION`、`AWS_DEFAULT_REGION` 或 boto3 会话)来签名请求时,或者当运行时配置没有服务条目时,`get_my_service_client()` 会引发错误。

## 基础设施

agent 的角色需要权限来调用服务的 HTTP API。生成器不会更改您的堆栈或根 Terraform 模块。相反,它会打印要添加的代码,如下所示,针对名为 `my-agent` 的 agent 和名为 `my-service` 的服务。在您添加它之前,HTTP API 会以 403 Forbidden 拒绝 agent 的请求。

<Infrastructure>
<Fragment slot="cdk">

在示例中,`myService` 是您的 `MyService` 构造,`myAgent` 是您的 `MyAgent` 构造:

```ts title="packages/infra/src/stacks/application-stack.ts"
myService.grantInvoke(myAgent);
```

`grantInvoke` 允许 agent 的角色对服务的 HTTP API 调用 `execute-api:Invoke`。

</Fragment>
<Fragment slot="terraform">

将语句添加到 agent 的 `additional_iam_policy_statements` 中,紧邻该块已列出的任何语句。在示例中,`module "my_service"` 部署服务:

```hcl title="packages/infra/src/main.tf"
module "my_agent" {
  source = "../../common/terraform/src/app/agents/my-agent"
  # ...existing arguments...
  additional_iam_policy_statements = [
    {
      Effect   = "Allow"
      Action   = ["execute-api:Invoke"]
      Resource = ["${module.my_service.api_execution_arn}/*"]
    },
  ]
}
```

</Fragment>
</Infrastructure>
