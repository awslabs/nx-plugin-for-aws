`connection` 生成器让 <Link path="guides/ts-agent">TypeScript Agent</Link> 调用使用 <Link path="guides/ts-container">`ts#container`</Link> 或 <Link path="guides/py-container">`py#container`</Link> 创建的容器服务。它向共享的 `agent-connection` 项目添加一个客户端，该客户端从运行时配置中读取服务的 URL，并使用代理自己的 AWS 凭证对每个请求进行签名。

## 工作原理

使用 `infra=ecs` 的容器服务在内部应用程序负载均衡器后面的 Amazon ECS（Elastic Container Service）上运行。使用默认的 `ingress=http-api` 时，Amazon API Gateway HTTP API（托管的 HTTPS 端点）通过 VPC 链接到达该负载均衡器，VPC 链接是 API Gateway 进入您的 VPC 的私有连接。代理调用 HTTP API。

客户端使用代理角色的凭证，通过 SigV4（AWS 请求签名过程）对每个请求进行签名。当该角色可以对其调用 `execute-api:Invoke` 时，HTTP API 接受请求。HTTP API 会终止任何超过 30 秒的请求，因此运行时间较长的路由必须提前返回并在后台完成其工作。

生成器会拒绝无法以这种方式访问的服务。服务必须具有 `infra=ecs`，因为 `infra=none` 不会创建端点。它必须具有 `ingress=http-api`，因为 `private` 服务只能从其 VPC 内部访问。它必须具有 `auth=iam`，因为代理使用 IAM 凭证对其请求进行签名，并且没有 Cognito 令牌可发送。

## 前提条件

在使用此生成器之前，请确保您具有：

1. 一个 <Link path="guides/ts-agent">`ts#agent`</Link> 项目
2. 一个具有 `infra=ecs`、`ingress=http-api` 和 `auth=iam` 的容器服务（使用 <Link path="guides/ts-container">`ts#container`</Link> 或 <Link path="guides/py-container">`py#container`</Link> 生成器生成）

生成器在共享的 `agent-connection` 项目中创建以下文件：

<FileTree>

- packages/common/agent-connection
  - src
    - app
      - \<service-name>-client.ts Client that reads the service's URL from runtime configuration and signs requests with SigV4

它将 `@aws-lambda-powertools/parameters`、`@aws-sdk/credential-providers` 和 `aws4fetch` 添加到 `agent-connection` 项目，并使代理的 `<agent-name>-dev` 目标启动服务的 `<service-name>-serve` 目标。

## 使用客户端

`<ServiceName>Client.create()` 从 <Link path="guides/runtime-config">运行时配置</Link> 的 `connection` 命名空间中读取服务的 URL，位于 `services.<ServiceName>` 下。客户端的 `fetch` 接受相对于服务的路径。生成器不会更改您的代理代码。要让模型调用服务，请将客户端包装在工具中：

```ts title="packages/my-project/src/my-agent/agent.ts"
import { Agent, tool } from '@strands-agents/sdk';
import { MyServiceClient } from '@my-scope/agent-connection';
import { z } from 'zod';

export const getAgent = async () => {
  const myService = await MyServiceClient.create();
  const checkMyService = tool({
    name: 'check_my_service',
    description: 'Check whether the MyService container service is healthy',
    inputSchema: z.object({}),
    callback: async () => (await myService.fetch('/health')).status,
  });

  return new Agent({
    tools: [checkMyService],
  });
};
```

当 `RUNTIME_CONFIG_APP_ID` 未设置或运行时配置中没有服务条目时，`create()` 会抛出异常。

## 基础设施

代理的角色需要调用服务的 HTTP API 的权限。生成器不会更改您的堆栈或根 Terraform 模块。相反，它会打印要添加的代码，如下所示，适用于名为 `my-agent` 的代理和名为 `my-service` 的服务。在您添加它之前，HTTP API 会以 403 Forbidden 拒绝代理的请求。

<Infrastructure>
<Fragment slot="cdk">

在示例中，`myService` 是您的 `MyService` 构造，`myAgent` 是您的 `MyAgent` 构造：

```ts title="packages/infra/src/stacks/application-stack.ts"
myService.grantInvoke(myAgent);
```

`grantInvoke` 允许代理的角色对服务的 HTTP API 调用 `execute-api:Invoke`。

</Fragment>
<Fragment slot="terraform">

将语句添加到代理的 `additional_iam_policy_statements` 中，紧邻该块已列出的任何语句。在示例中，`module "my_service"` 部署服务：

```hcl title="packages/infra/src/main.tf"
module "my_agent" {
  source = "../../common/terraform/src/app/agents/my-agent"
  # ...existing arguments...
  additional_iam_policy_statements = [
    {
      Effect   = "Allow"
      Action   = ["execute-api:Invoke"]
      Resource = ["${module.my_service.api_execution_arn}/*"]
    },
  ]
}
```

</Fragment>
</Infrastructure>
