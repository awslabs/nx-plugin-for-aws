## 什么是 Strands？

[Strands](https://strandsagents.com/docs/user-guide/quickstart/overview/) 是一个用于构建 AI 代理的轻量级框架。主要特性包括：

- **轻量且可定制**：简单的代理循环，不会妨碍您的工作
- **生产就绪**：完整的可观测性、追踪和大规模部署选项
- **模型和提供商无关**：支持来自各种提供商的多种不同模型
- **社区驱动的工具**：强大的社区贡献工具集
- **多代理支持**：高级技术，如代理团队和自主代理
- **灵活的交互模式**：支持对话式、流式和非流式

## 使用您的 Agent

### 协议

您的代理的服务器协议决定了它如何通信。您可以在以下选项之间进行选择：

- **HTTP**（默认）：使用基于 WebSocket 的 [tRPC](https://trpc.io/) 进行实时、类型安全的通信。最适合自定义客户端集成和对代理 API 的细粒度控制。
- **A2A**：使用 [Agent-to-Agent (A2A)](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-a2a.html) 协议进行标准化的代理间通信。最适合您的代理需要被其他兼容 A2A 的代理发现和调用的情况。
- **AG-UI**：通过 [`@ag-ui/aws-strands`](https://www.npmjs.com/package/@ag-ui/aws-strands) 使用 [AG-UI 协议](https://docs.ag-ui.com/)（基于 POST 的 SSE）与 [CopilotKit](https://docs.copilotkit.ai/aws-strands) 直接集成前端。最适合您想要具有流式传输、工具调用可视化和状态管理的丰富聊天 UI 的情况。

协议在 CDK/Terraform 基础设施中设置，并相应地生成应用程序代码。

<OptionFilter when={{ protocol: 'http' }} description="tRPC over WebSocket details">
### 基于 WebSocket 的 tRPC（HTTP 协议）

TypeScript Agent 使用基于 WebSocket 的 [tRPC](https://trpc.io/)，利用 [AgentCore 的双向流支持](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-websocket.html)，在客户端和您的代理之间实现实时、类型安全的通信。

由于 tRPC 支持通过 WebSocket 进行 Query、Mutation 和 Subscription 过程，您可以定义任意数量的过程。默认情况下，在 `router.ts` 中为您定义了一个名为 `invoke` 的单个订阅过程。
</OptionFilter>

### 添加工具

工具是 AI 代理可以调用以执行操作的函数。您可以在 `agent.ts` 文件中添加新工具：

```typescript
import { Agent, tool } from '@strands-agents/sdk';
import { z } from 'zod';

const letterCounter = tool({
  name: 'letter_counter',
  description: 'Count occurrences of a specific letter in a word',
  inputSchema: z.object({
    word: z.string().describe('The input word to search in'),
    letter: z.string().length(1).describe('The specific letter to count'),
  }),
  callback: (input) => {
    const { word, letter } = input;
    const count = word.toLowerCase().split(letter.toLowerCase()).length - 1;
    return `The letter '${letter}' appears ${count} time(s) in '${word}'`;
  },
});

// Add tools to your agent
export const getAgent = async () => {
  return new Agent({
    systemPrompt: 'You are a helpful assistant with access to various tools.',
    tools: [letterCounter],
  });
};
```

Strands 框架会自动处理：
- 使用 Zod 模式进行输入验证
- 为工具调用生成 JSON 模式
- 错误处理和响应格式化

### 模型配置

默认情况下，Strands 代理使用 Claude 4 Sonnet，但您可以轻松地在模型提供商之间切换：

```typescript
import { Agent } from '@strands-agents/sdk';
import { BedrockModel } from '@strands-agents/sdk/models/bedrock';
import { OpenAIModel } from '@strands-agents/sdk/models/openai';

// Use Bedrock
const bedrockModel = new BedrockModel({
  modelId: 'anthropic.claude-sonnet-4-20250514-v1:0',
});
let agent = new Agent({ model: bedrockModel });
let response = await agent.invoke('What can you help me with?');

// Alternatively, use OpenAI by just switching model provider
const openaiModel = new OpenAIModel({
  apiKey: process.env.OPENAI_API_KEY,
  modelId: 'gpt-4o',
});
agent = new Agent({ model: openaiModel });
response = await agent.invoke('What can you help me with?');
```

有关更多配置选项，请参阅 [Strands 关于模型提供商的文档](https://strandsagents.com/docs/user-guide/concepts/model-providers/)。

### 会话管理

`session` 选项控制您的代理如何在调用之间持久化对话状态（消息历史、工具状态等），使用 Strands SDK 的 [SessionManager](https://strandsagents.com/docs/user-guide/concepts/agents/session-management/)：

- **`s3`**（默认）：CDK/Terraform 基础设施为会话数据配置一个专用的 S3 存储桶，使用专用的 KMS 密钥加密并阻止所有公共访问；服务器访问日志通过相同的密钥传送到 CloudWatch Logs 日志组。代理的 IAM 角色被授予对存储桶的读/写/列表/删除访问权限以及对密钥的解密/生成数据密钥访问权限，存储桶名称与代理的 ARN 一起注册在 AppConfig 运行时配置中。
- **`in-memory`**：不配置存储桶。对话状态仅在运行进程的生命周期内保存在内存中，不会在重启或缩容后保留。

这在生成的 `session.ts` 中实现，它导出一个 `getSessionManager()` 函数，为当前会话解析 `SessionManager`。

会话 ID 本身来自 AgentCore Runtime 会话（对于 A2A/AG-UI 通过 `x-amzn-bedrock-agentcore-runtime-session-id` 标头传播，或对于 HTTP/tRPC 通过 WebSocket 连接上下文传播），并绑定到基于 [`AsyncLocalStorage`](https://nodejs.org/api/async_context.html#class-asynclocalstorage) 的上下文，因此 `getCurrentSessionId()` 可以在请求的任何地方解析它 — 包括通过 <Link path="/guides/connection">`connection` 生成器</Link>连接的任何下游 MCP 或 A2A 客户端，因此整个调用链共享一致的会话。

:::note[AG-UI：会话和线程]
AG-UI 协议在请求体中有自己的对话标识符 `threadId`。`@ag-ui/aws-strands` 为每个 `threadId` 缓存一个 Strands 代理，并**每个线程调用一次** `sessionManagerProvider` — 即第一次看到该线程时。

因此，生成的 `index.ts` 传递 `sessionManagerProvider: (input) => getSessionManager(input.threadId)`，将对话状态键控在同一个线程 ID 上，以便提供程序和适配器的缓存始终一致。

当不带参数调用时，`getSessionManager()` 会回退到当前的 AgentCore 会话 ID，这是 HTTP 和 A2A 协议使用它的方式。
:::

:::caution[会话隔离]
会话 ID 和 `threadId` 都由调用者提供，因此它们本身都无法识别对话属于谁。AgentCore Runtime 针对代理运行时资源 ARN 而不是针对单个会话授权调用，并验证会话 ID 的格式而不将其与调用身份绑定 — [将会话范围限定到用户是代理的责任](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-instances-security.html)。

使用 `auth=cognito` 时，生成的基础设施设置 `requestHeaderConfiguration.allowlistedHeaders: ['Authorization']`，因此调用者的 JWT — 已由 AgentCore 授权器验证 — 作为普通请求标头到达您的代理代码。服务器入口点读取其 `sub` 声明并为请求绑定它，`session.ts` 通过 `getSessionStorageKey()` 从中构建存储键，生成 `u-<sub>-<conversationId>`。

没有可用声明的请求会被拒绝并返回 401，而不是回退到无范围的命名空间。在 `nx dev` 下，代理前面没有授权器，因此未经身份验证的请求会回退到单个本地用户 — 该回退受 `LOCAL_DEV` 限制，只有 `-dev` 目标才会设置它。解码声明时会跳过签名验证，因为 AgentCore Runtime 已经[在入站授权期间验证了令牌](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-oauth.html)。

在 AG-UI 路径上，中间件还会在将协议的 `thread_id` 别名折叠到 `threadId` 后删除它。适配器在解析正文时将 `thread_id` 映射到 `threadId`（首键优先），因此将别名保留在原位会让客户端绕过重写偷运无范围的线程 ID — 如果您自定义此功能，请将这两个步骤放在一起。

使用 `auth=iam` 时，SigV4 向 AgentCore Runtime 而不是向您的代理代码标识调用主体，因此对话状态仅键控在会话 ID 上，`bedrock-agentcore:InvokeAgentRuntime` 是边界 — 将其授予受信任的后端，或使用每个用户的 IAM 主体，以便 IAM 强制执行范围限定。

`getSessionStorageKey()` 还会展平路径分隔符，因此对话 ID 无法遍历出其命名空间。
:::

#### 替代方案：将会话限制为其所有者

命名空间为每个调用者键控存储，因此一个用户的对话永远不会返回给另一个用户。会话 ID 本身仍然是客户端发送的任何内容，这在两种情况下很重要：

- 会话 ID 选择服务请求的 [microVM](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-how-it-works.html)，因此其文件系统、`/tmp` 和进程内缓存由解析到该会话的每个请求共享。两个调用者发送相同的 ID 会共享这些内容，即使使用单独的存储键。
- 命名空间对对话进行分区；它不决定允许用户恢复哪些会话。

如果其中任何一个对您很重要，请让您的应用程序拥有会话 ID：从 API 发出它，记录它属于谁，并在代理中检查该所有权。

**1. 通过您的 API 创建会话**

添加一个启动对话的过程。它生成会话 ID，从其自己的请求上下文解析调用者，并存储该对 — 例如在使用 <Link path="guides/ts-dynamodb">`ts#dynamodb`</Link> 生成器创建的表中：

| Attribute | Example | Notes |
| --- | --- | --- |
| `sessionId` | `a5f1…` | 分区键 — 代理从给定的会话 ID 查找所有者 |
| `userId` | `<sub>` | 拥有会话的经过身份验证的调用者 |
| `createdAt`, `title` | … | UI 列出对话所需的任何内容 |

如果您还想列出用户自己的会话，请在 `userId` 上添加二级索引。

```ts
export const createSession = publicProcedure
  .output(z.object({ sessionId: z.string() }))
  .mutation(async ({ ctx }) => {
    const sessionId = randomUUID().replaceAll('-', '');
    await sessionEntity.put({ sessionId, userId: callerSub(ctx.event) }).go();
    return { sessionId };
  });
```

从经过验证的请求上下文而不是从输入字段解析调用者，因此它不能由浏览器提供。<Link path="guides/trpc">实现自定义中间件</Link>展示了如何为 IAM 和 Cognito 身份验证的 API 执行此操作。查询索引的第二个过程让 UI 向用户提供他们自己的对话，而不会看到其他人的对话。

**2. 在代理中验证所有权**

代理接收会话 ID，并且使用 `auth=cognito` 时接收调用者的 JWT。查找会话，将其所有者与调用者进行比较，如果它们不同则拒绝请求：

```ts
const session = await getSession(sessionId);
if (session?.userId !== getCurrentUserId()) {
  res.status(403).json({ error: 'Session does not belong to the caller' });
  return;
}
```

API 决定谁拥有会话；代理强制执行它。在两个地方检查意味着泄露的会话 ID 在下次调用时仍会被拒绝，并且代理的任何未来客户端都会继承相同的规则。

:::caution
生成不透明的随机会话 ID 并存储映射。从用户提供的值（对话名称、电子邮件）派生一个是可预测的，因此调用者可以落在未给它的会话上。
:::

:::note[本地开发]
在本地运行时（`LOCAL_DEV=true`，由 `-dev` 目标自动设置），无论配置的 `session` 选项如何，会话数据始终存储在工作区根目录的 `tmp/agents/strands/<agent-name>` 下的磁盘上，以方便使用。
:::
</OptionFilter>

### 调用已部署的 Agent

<Snippet name="agent/runtime-arn" parentHeading="调用已部署的 Agent" />

#### NodeJS

生成的 `client.ts` 文件包含一个类型安全的客户端工厂，可用于调用已部署的代理。

:::caution[HTTP 标头身份验证]
客户端工厂在 WebSocket 握手中使用 HTTP 标头对 Bedrock AgentCore Runtime 的请求进行身份验证。这在浏览器中是不可能的，因此此客户端不适合浏览器环境。有关从浏览器调用的详细信息，请参阅下面的"浏览器"部分。
:::

<Tabs syncKey="auth">
<TabItem label="IAM" _filter={{ auth: 'iam' }}>
##### IAM 身份验证

您可以通过将其 ARN 传递给 `withIamAuth` 工厂方法来调用已部署的代理：

```typescript
import { AgentClient } from './agent/client.js';

const client = AgentClient.withIamAuth({
  agentRuntimeArn: 'arn:aws:bedrock-agentcore:us-west-2:123456789012:runtime/my-agent',
});

client.invoke.subscribe({ prompt: 'what is 1 plus 1?' }, {
  onData: (message) => console.log(message),
  onError: (error) => console.error(error),
  onComplete: () => console.log('Done'),
});
```

:::note[AWS 凭证]
这将使用默认的 AWS 凭证提供程序链对请求进行身份验证，因此运行上述代码的环境必须配置了 AWS 凭证，并有权调用运行时。
:::
</TabItem>

<TabItem label="Cognito" _filter={{ auth: 'cognito' }}>
##### JWT / Cognito 身份验证

使用 `withJwtAuth` 工厂方法通过 JWT / Cognito 访问令牌进行身份验证。

```typescript
const client = AgentClient.withJwtAuth({
  agentRuntimeArn: 'arn:aws:bedrock-agentcore:us-west-2:123456789012:runtime/my-agent',
  accessTokenProvider: async () => `<access-token>`,
});

client.invoke.subscribe({ prompt: 'what is 1 plus 1?' }, {
  onData: console.log,
});
```

`accessTokenProvider` 必须返回用于对请求进行身份验证的令牌。例如，您可以在此方法中获取令牌，以确保在 tRPC 重启 WebSocket 连接时重用新鲜的凭证。下面演示了使用 AWS SDK 从 Cognito 获取令牌：

```typescript
import { CognitoIdentityProvider } from "@aws-sdk/client-cognito-identity-provider";

const cognito = new CognitoIdentityProvider();

const jwtClient = AgentClient.withJwtAuth({
  agentRuntimeArn: 'arn:aws:bedrock-agentcore:us-west-2:123456789012:runtime/my-agent',
  accessTokenProvider: async () => {
    const response = await cognito.adminInitiateAuth({
      UserPoolId: '<user-pool-id>',
      ClientId: '<user-pool-client-id>',
      AuthFlow: 'ADMIN_NO_SRP_AUTH',
      AuthParameters: {
        USERNAME: '<username>',
        PASSWORD: '<password>',
      },
    });
    return response.AuthenticationResult!.AccessToken!;
  },
});
```
