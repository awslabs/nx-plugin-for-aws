## 编写 Python 源代码

在 `<module-name>` 目录中添加您的 Python 源代码。

### 在其他项目中导入您的库代码

使用 `add` 目标向 Python 项目添加依赖项。

假设我们创建了两个 Python 项目，`my_app` 和 `my_lib`。它们的完全限定项目名称将是 `my_scope.my_app` 和 `my_scope.my_lib`，默认情况下，它们的模块名称分别为 `my_scope_my_app` 和 `my_scope_my_lib`。

要让 `my_app` 依赖于 `my_lib`，我们可以运行以下命令：

<NxCommands commands={['run my_scope.my_app:add my_scope.my_lib']} />

:::note[完全限定名称]
我们对依赖项和被依赖项都使用完全限定的项目名称。我们可以对要添加依赖项的项目使用简写语法，但必须完全限定要依赖的项目名称。
:::

然后您可以导入您的库代码：

```python title="packages/my_app/my_scope_my_app/main.py"
from my_scope_my_lib.my_module import my_function
```

上面，`my_scope_my_lib` 是库的模块名称，`my_module` 对应于 Python 源文件 `my_module.py`，`my_function` 是该文件中定义的方法。

### 依赖项

要向您的项目添加依赖项，您可以在 Python 项目中运行 `add` 目标，例如：

<NxCommands commands={['run my_scope.my_library:add some-pip-package']} />

这将把依赖项添加到您项目的 `pyproject.toml` 文件中，并更新根目录的 `uv.lock`。

#### 运行时代码

当您将 Python 项目用作运行时代码（例如作为 AWS lambda 函数的处理程序）时，您需要创建源代码及其所有依赖项的捆绑包。您可以通过向 `project.json` 文件添加如下目标来实现：

```json title="project.json"
{
  ...
  "targets": {
    ...
    "bundle": {
      "cache": true,
      "executor": "nx:run-commands",
      "outputs": ["{workspaceRoot}/dist/packages/my_library/bundle"],
      "options": {
        "commands": [
          "uv export --frozen --no-dev --no-editable --project packages/my_library --package my_scope.my_library -o dist/packages/my_library/bundle/requirements.txt",
          "uv pip install -n --no-deps --no-installer-metadata --no-compile-bytecode --python-platform x86_64-manylinux_2_28 --python `uv python pin` --target dist/packages/my_library/bundle -r dist/packages/my_library/bundle/requirements.txt"
        ],
        "parallel": false
      },
      "dependsOn": ["compile"]
    },
  },
}
```

### 安装

使用以下命令安装 Python 依赖项：

```bash
uv sync
```

### 构建

您的 Python 项目配置了 `build` 目标（在 `project.json` 中定义），您可以通过以下方式运行：

<NxCommands commands={['build <project-name>']} />

其中 `<project-name>` 是您项目的完全限定名称。

`build` 目标将编译、检查、测试和类型检查您的项目。

构建输出可以在工作空间根目录的 `dist` 文件夹中找到，位于您的包和目标的目录中，例如 `dist/packages/<my-library>/build`

要构建工作空间中的所有项目，请运行：

<NxCommands commands={['run-many --target build']} />

或使用简写命令：

<PackageManagerShortCommand commands={["build"]} />

### 组装

您的项目还有一个 `assemble` 目标，它是 `build` 的仅生成构件的同级目标：它生成项目对部署的贡献（其编译输出，以及它声明的任何捆绑包、容器镜像或生成的规范），而不运行代码检查、测试或类型检查关卡。

<NxCommands commands={['assemble <project-name>']} />

部署目标依赖于 `assemble` 而不是 `build`，因此部署仅构建即将部署的内容。`build` 保持不变，仍然执行所有操作，因此它仍然是您运行以检查项目的目标——也是您应该在 CI 中运行的目标。

:::caution
因为 `assemble` 跳过了质量关卡，所以部署不再因代码检查错误、失败的单元测试或类型错误而失败。运行 `build`（或您的 CI 流水线）来检查您的代码。
:::

## 测试

[pytest](https://docs.pytest.org/en/stable/) 已配置用于测试您的项目。

### 编写测试

测试应该写在项目中的 `test` 目录中，在以 `test_` 为前缀的 Python 文件中，例如：

<FileTree>
  - my_library
    - my_module.py
  - tests
    - test_my_module.py Tests for my_module.py
</FileTree>

测试是以 `test_` 开头并进行断言以验证预期的方法，例如：

```python title="tests/test_my_module.py"
from my_library.my_module import say_hello

def test_say_hello():
  assert say_hello("Darth Vader") == "Hello, Darth Vader!"
```

有关如何编写测试的更多详细信息，请参阅 [pytest 文档](https://docs.pytest.org/en/stable/how-to/assert.html#)。

### 运行测试

测试将作为项目的 `build` 目标的一部分运行，但您也可以通过运行 `test` 目标单独运行它们：

<NxCommands commands={['test <project-name>']} />

您可以使用 `-k` 标志运行单个测试或测试套件，指定测试文件或方法的名称：

<NxCommands commands={["test <project-name> -k 'test_say_hello'"]} />

## 类型检查

Python 项目使用 [ty](https://docs.astral.sh/ty/) 进行类型检查。

### 运行类型检查器

类型检查作为项目的 `build` 目标的一部分运行，但您也可以通过 `typecheck` 目标单独运行它：

<NxCommands commands={['run <project-name>:typecheck']} />

### 抑制类型错误

要抑制单行的特定诊断，请在行尾添加 `# ty: ignore[<rule>]` 注释，例如：

```python
value: int = "not an int"  # ty: ignore[invalid-assignment]
```

要在整个项目中配置类型检查行为，请在项目的 `pyproject.toml` 中添加 `[tool.ty]` 部分。有关可用选项，请参阅 [ty 配置参考](https://docs.astral.sh/ty/reference/configuration/)。

## 代码检查

Python 项目使用 [Ruff](https://docs.astral.sh/ruff/) 进行代码检查。

### 运行代码检查器

要调用代码检查器检查您的项目，您可以运行 `lint` 目标。

<NxCommands commands={["lint <project-name>"]} />

### 修复代码检查问题

大多数代码检查或格式化问题可以自动修复。您可以通过使用 `--configuration=fix` 参数运行来告诉 Ruff 修复代码检查问题。

<NxCommands commands={["lint <project-name> --configuration=fix"]} />

同样，如果您想修复工作空间中所有包的所有代码检查问题，您可以运行：

<NxCommands commands={["run-many --target lint --all --configuration=fix"]} />

:::tip[简写命令]
这在工作空间根目录有一个简写命令：

<PackageManagerShortCommand commands={["lint"]} />
:::

### 跳过代码检查问题

为了避免代码检查问题在开发过程中拖慢您的速度（特别是如果您的项目中有无法自动修复的问题），您可以使用 `skip-lint` 配置运行构建：

<NxCommands commands={["run-many --target build --configuration=skip-lint"]} />

这仍然会在构建过程中运行 Ruff，但代码检查目标将始终被视为成功。

:::tip[简写命令]
这在工作空间根目录有一个简写命令：

<PackageManagerShortCommand commands={["build:skip-lint"]} />
:::
