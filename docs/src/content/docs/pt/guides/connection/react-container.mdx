O gerador `connection` permite que seu site React chame um serviço de container criado com <Link path="guides/ts-container">`ts#container`</Link> ou <Link path="guides/py-container">`py#container`</Link>. Ele adiciona um hook React que lê a URL do serviço da configuração de runtime e adiciona a autenticação que o serviço espera a cada requisição.

## Como isso funciona

Um serviço de container com `infra=ecs` é executado no Amazon ECS (Elastic Container Service) atrás de um Application Load Balancer interno. Com o padrão `ingress=http-api`, uma Amazon API Gateway HTTP API (um endpoint HTTPS gerenciado) alcança esse load balancer através de um VPC link, que é a conexão privada do API Gateway para dentro da sua VPC. O site chama a HTTP API.

A opção `auth` do serviço decide como a HTTP API verifica cada requisição:

- `iam` (padrão): a requisição deve ser assinada com SigV4, o processo de assinatura de requisições da AWS. O hook a assina com as credenciais temporárias da AWS que o identity pool do Cognito do seu site fornece a um usuário autenticado.
- `cognito`: a requisição deve conter o token de acesso do Cognito do usuário autenticado como um bearer token.
- `none`: a HTTP API aceita todas as requisições.

A HTTP API encerra qualquer requisição que demore mais de 30 segundos, então uma rota que executa por mais tempo deve retornar cedo e finalizar seu trabalho em segundo plano.

O gerador rejeita um serviço que não pode alcançar. O serviço deve ter `infra=ecs`, porque `infra=none` não cria nenhum endpoint. Ele também deve ter `ingress=http-api`, porque um serviço `private` é acessível apenas de dentro da sua VPC.

## Pré-requisitos

Antes de usar este gerador, certifique-se de ter:

1. Um site React (gerado usando o <Link path="guides/react-website">gerador `ts#website`</Link>)
2. Um serviço de container com `infra=ecs` e `ingress=http-api` (gerado usando o gerador <Link path="guides/ts-container">`ts#container`</Link> ou <Link path="guides/py-container">`py#container`</Link>)
3. Cognito Auth adicionado via o <Link path="guides/react-website-auth">gerador `ts#website#auth`</Link>, se o `auth` do serviço for `iam` ou `cognito`

## Saída do Gerador

O gerador cria os seguintes arquivos no seu site React:

<FileTree>

- src
  - hooks
    - use\<ServiceName>.tsx Hook retornando a URL do serviço e um `fetch` que adiciona a autenticação do serviço
    - useSigV4.tsx Hook para assinar requisições com SigV4 (apenas `iam`)
  - components
    - RuntimeConfig/index.tsx Aponta o hook para o serviço local no desenvolvimento local

</FileTree>

`<ServiceName>` é o nome da classe do serviço, por exemplo `useOrders` para um serviço chamado `orders`. O gerador também adiciona estas dependências ao site:

- `aws4fetch`, `oidc-client-ts`, `@aws-sdk/credential-provider-cognito-identity`, `react-oidc-context`, e a dependência de desenvolvimento `@smithy/types` (`iam`)
- `react-oidc-context` (`cognito`)

## Usando o Hook

O hook retorna a `url` do serviço e uma função `fetch`. `fetch` recebe um caminho relativo ao serviço e as opções usuais de `fetch`:

```tsx
import { useEffect, useState } from 'react';
import { useMyService } from './hooks/useMyService';

export const ServiceStatus = () => {
  const myService = useMyService();
  const [status, setStatus] = useState<number>();

  useEffect(() => {
    myService.fetch('/health').then((response) => setStatus(response.status));
  }, [myService.fetch]);

  return <p>Service status: {status ?? 'loading'}</p>;
};
```

O serviço implantado escreve sua URL na <Link path="guides/runtime-config">configuração de runtime</Link> sob `connection.services.<ServiceName>`, que o site lê de `runtime-config.json`.

O site chama a HTTP API do navegador, então as configurações de CORS (cross-origin resource sharing) da HTTP API devem permitir a origem do site. O gerador não as altera. Por padrão, a HTTP API aceita requisições de qualquer origem, com os cabeçalhos `authorization`, `content-type` e SigV4 que o hook envia. Para aceitar requisições apenas do seu site, chame `myService.restrictCorsTo('https://<seu domínio do site>')` no CDK. No Terraform, defina `cors_allow_origins` no bloco `module "ecs_service"` do módulo do seu serviço. Para detalhes, veja <Link path="guides/ts-container#cors-and-throttling">CORS and Throttling</Link>.

## Infraestrutura

Para `auth=iam`, os usuários autenticados do site precisam de permissão para chamar a HTTP API do serviço. O gerador não altera sua stack ou módulo raiz do Terraform. Em vez disso, ele imprime o código a ser adicionado, que é mostrado abaixo para um serviço chamado `my-service`. Até que você o adicione, a HTTP API rejeita as requisições do site com 403 Forbidden. Para `cognito` e `none` não há nada a adicionar.

<Infrastructure>
<Fragment slot="cdk">

No exemplo, `myService` é seu construto `MyService` e `identity` é seu construto `UserIdentity`:

```ts title="packages/infra/src/stacks/application-stack.ts"
myService.grantInvoke(identity.identityPool.authenticatedRole);
```

`grantInvoke` permite que a role autenticada do identity pool chame `execute-api:Invoke` na HTTP API do serviço.

</Fragment>
<Fragment slot="terraform">

No exemplo, `module "my_service"` implanta o serviço e `module "user_identity"` implanta o identity pool do seu site:

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_role_policy" "authenticated_my_service_invoke" {
  name = "authenticated-my-service-invoke"
  role = module.user_identity.authenticated_role_name

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = ["execute-api:Invoke"]
        Resource = ["${module.my_service.api_execution_arn}/*"]
      },
    ]
  })
}
```

## Desenvolvimento Local

<NxCommands commands={["dev <website-project-name>"]} />

O target `dev` do site também inicia o target `<service-name>-serve` do serviço, e o hook chama o serviço em `http://localhost:<port>`. A porta é aquela que o gerador de container atribuiu ao serviço. No desenvolvimento local, o hook `useSigV4` não assina requisições quando `runtime-config.json` não tem configurações do Cognito.
