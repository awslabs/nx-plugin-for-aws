O gerador `connection` pode conectar seu <Link path="guides/ts-agent">TypeScript Agent</Link> a um agente [A2A](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-a2a.html) remoto — seja <Link path="guides/ts-agent">TypeScript</Link> ou <Link path="guides/py-agent">Python</Link> — para que seu agente possa delegar a outro agente como uma ferramenta.

O gerador configura toda a estrutura necessária para que seu agente possa descobrir e invocar o agente A2A remoto, tanto quando implantado na AWS (via Bedrock AgentCore) quanto quando executado localmente.

## Pré-requisitos

Antes de usar este gerador, certifique-se de ter:

1. Um projeto TypeScript com um componente <Link path="guides/ts-agent">Strands Agent</Link> (qualquer protocolo)
2. Um projeto com um componente Agent gerado com `--protocol=a2a` e `--auth=iam` (seja <Link path="guides/ts-agent">`ts#agent`</Link> ou <Link path="guides/py-agent">`py#agent`</Link>)
3. Ambos os componentes criados com `infra: agentcore`

## Saída do Gerador

O gerador cria um pacote compartilhado `agent-connection` e modifica o código do seu agente:

<FileTree>

- packages/common/agent-connection
  - src
    - app
      - \<target-agent-name>-client-strands.ts High-level Strands client for the connected A2A agent
    - core
      - agentcore-endpoints.ts Framework-agnostic ARN/URL resolution
      - agentcore-fetch.ts Framework-agnostic SigV4 / JWT / session-forwarding fetch
      - agentcore-a2a-client-config.ts Framework-agnostic A2A client config (signed `clientFactory`)
      - agentcore-a2a-client-strands.ts Strands A2A client wrapping the config
    - index.ts Exports all clients
  - project.json
  - tsconfig.json

</FileTree>

Além disso, ele:
- Transforma o `agent.ts` do seu agente para registrar o agente A2A remoto como uma `tool` do Strands
- Atualiza o target `dev` do agente para depender do target `dev` do agente de destino
- Instala as dependências necessárias

## Usando o A2A Agent Conectado

O gerador transforma o `agent.ts` do seu agente para encapsular o agente A2A remoto como uma ferramenta:

```ts title="packages/example/src/my-agent/agent.ts" {2,5-12,15}
import { Agent, tool } from '@strands-agents/sdk';
import { RemoteAgentClientStrands } from '@my-scope/agent-connection';
import { z } from 'zod';

export const getAgent = async () => {
  const remoteAgent = await RemoteAgentClientStrands.create();
  const remoteAgentTool = tool({
    name: 'askRemoteAgent',
    description: 'Delegate a question to the remote RemoteAgent A2A agent and return its reply.',
    inputSchema: z.object({ prompt: z.string() }),
    callback: async ({ prompt }) => (await remoteAgent.invoke(prompt)).toString(),
  });
  return new Agent({
    systemPrompt: '...',
    tools: [remoteAgentTool],
  });
};
```

O ID de sessão do AgentCore é propagado para o agente remoto automaticamente através do cabeçalho `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id`, então `create()` não recebe argumentos: o servidor do agente vincula a sessão da requisição de entrada em um contexto [`AsyncLocalStorage`](https://nodejs.org/api/async_context.html#class-asynclocalstorage) (`enterSessionContext` no `router.ts` gerado, ou `runWithSessionId` no middleware de sessão A2A/AG-UI), e o fetch do cliente de conexão em `agentcore-fetch.ts` o carimba em cada chamada de saída — garantindo consistência para a [Bedrock AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html).

Internamente, `RemoteAgentClientStrands.create()` retorna um `A2AAgent` do Strands configurado com um `clientFactory` que assina com SigV4 quando implantado na AWS, e um endpoint simples `http://localhost:<port>/` quando `LOCAL_DEV=true`. A assinatura e a resolução de endpoint residem no `agentcore-a2a-client-config.ts` agnóstico de framework; apenas o fino `agentcore-a2a-client-strands.ts` depende do Strands.

## Desenvolvimento Local

O gerador configura o target `dev` do agente host para:
1. Iniciar o(s) agente(s) A2A conectado(s) automaticamente
2. Definir `LOCAL_DEV=true` para que o cliente gerado se conecte diretamente a `http://localhost:<port>/` em vez do AgentCore

Execute o agente localmente com:

<NxCommands commands={["<agent-name>-dev <project-name>"]} />

Isso iniciará tanto o agente host quanto todos os agentes A2A conectados, com o agente host chamando os agentes remotos via HTTP simples em suas portas locais atribuídas.
