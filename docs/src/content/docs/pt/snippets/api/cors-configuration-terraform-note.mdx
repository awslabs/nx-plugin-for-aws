:::note[Configuração CORS no Terraform]
Se sua solução incluir um módulo de website Terraform, você pode usar seu nome de domínio CloudFront para restringir o CORS.
Dado um nome de domínio CloudFront `<domain_name>`, dentro do módulo Terraform para implantar sua API, adicione
- uma propriedade `cors_allow_origins`, definida como `["http://localhost:4200", "http://localhost:4300", "https://<domain name>"]`, para APIs HTTP. Isso restringe o CORS do API gateway a esta distribuição e ao host local.
- uma variável de ambiente `ALLOWED_ORIGINS`, definida como `"https://<domain_name>"`, para APIs REST. Isso define a distribuição CloudFront como a única origem CORS permitida (além do host local) nas integrações AWS Lambda. Note que essa restrição não é aplicada ao preflight OPTIONS - por favor, dê +1 [nesta issue do GitHub](https://github.com/awslabs/nx-plugin-for-aws/issues/377) para ajudar a priorizar a resolução disso.

```hcl {6,9}
module "my_api" {
  source = "../../common/terraform/src/app/apis/my-api"

  asset_bucket_name = module.asset_bucket.bucket_name

  cors_allow_origins = ["http://localhost:4200", "http://localhost:4300", "https://<domain name>"] // Only required for HTTP API

  env = {
    ALLOWED_ORIGINS = "https://<domain name>" // Only required for REST API
    ENVIRONMENT = var.environment
    LOG_LEVEL   = "INFO"
  }
}
```
O construtor `MyWebsite` pode ser gerado usando o <Link path="/guides/react-website">gerador `ts#website`</Link>. Este exemplo assume que as portas locais do website são `4200`/`4300` - verifique seu `project.json` (ou `vite.config.mts`) para as portas realmente atribuídas a ele, já que cada website gerado dessa forma recebe as suas próprias.
:::
