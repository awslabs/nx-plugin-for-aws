[CDK Graph](https://aws.github.io/aws-pdk/developer_guides/cdk-graph/index.html) constrói grafos dos seus recursos CDK conectados e fornecia dois plugins:

#### Diagram Plugin

O [CDK Graph Diagram Plugin](https://aws.github.io/aws-pdk/developer_guides/cdk-graph-plugin-diagram/index.html) gera diagramas de arquitetura AWS a partir da sua infraestrutura CDK.

Para uma abordagem determinística similar, uma alternativa viável é [CDK-Dia](https://github.com/pistazie/cdk-dia).

Com os avanços em IA Generativa, muitos modelos de fundação são capazes de criar diagramas de alta qualidade a partir da sua infraestrutura CDK. Recomendamos experimentar o [AWS Diagram MCP Server](https://github.com/awslabs/mcp/tree/main/src/aws-diagram-mcp-server). Confira [este post do blog](https://aws.amazon.com/blogs/machine-learning/build-aws-architecture-diagrams-using-amazon-q-cli-and-mcp/) para um passo a passo.

#### Threat Composer Plugin

O [CDK Graph Threat Composer Plugin](https://aws.github.io/aws-pdk/developer_guides/cdk-graph-plugin-threat-composer/index.html) gera um [Threat Composer](https://github.com/awslabs/threat-composer/) inicial de modelo de ameaças a partir do seu código CDK.

Este plugin funcionava simplesmente filtrando um [modelo de ameaças base](https://github.com/aws/aws-pdk/tree/mainline/packages/cdk-graph-plugin-threat-composer/src/model-generator/base-model) contendo exemplos de ameaças, e filtrando-os com base nos recursos que sua stack utilizava.

Se você está interessado nesses exemplos específicos de ameaças, você pode copiar e filtrar o modelo de ameaças base, ou usá-lo como contexto para ajudar um modelo de fundação a gerar um similar.
