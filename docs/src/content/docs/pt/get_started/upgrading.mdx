Tanto o Nx quanto o `@aws/nx-plugin` fornecem migrações que atualizam seu workspace automaticamente quando você os atualiza, usando [`nx migrate`](https://nx.dev/docs/features/automate-updating-dependencies). Este guia explica como atualizar cada um.

<Aside type="tip">
Você pode usar sua ferramenta de codificação agêntica de escolha para atualizar seu workspace para você, usando o <Link path="get_started/building-with-ai">servidor MCP</Link>. Experimente o prompt:

> Upgrade Nx and the Nx Plugin for AWS in this workspace.
</Aside>

`nx migrate <package>@<version>` tem como alvo qualquer pacote que você nomear — então atualizar o próprio Nx e atualizar o `@aws/nx-plugin` são atualizações separadas, cada uma seguindo o mesmo ciclo:

<Steps>

1. **Gerar** — `nx migrate <package>@latest` atualiza as versões do pacote no `package.json` e escreve um `migrations.json` listando as migrações a serem executadas. Nada é instalado e nenhum outro arquivo é tocado ainda, então você pode revisar as mudanças de versão primeiro.

2. **Instalar** — instale as novas versões com seu gerenciador de pacotes (por exemplo, `pnpm install --no-frozen-lockfile`).

3. **Executar** — `nx migrate --run-migrations` aplica cada migração pendente ao seu workspace, uma de cada vez.

4. **Commit** — verifique se seu workspace compila, então delete `migrations.json` e faça commit.

</Steps>

<Aside type="caution" title="Um pacote de cada vez">
Complete o ciclo completo para um pacote antes de iniciar o próximo: cada `nx migrate <package>` **sobrescreve** `migrations.json`, então executar `nx migrate @aws/nx-plugin@latest` seguido imediatamente por `nx migrate latest` descarta as migrações pendentes do plugin antes que elas sejam executadas.
</Aside>

## Atualizando @aws/nx-plugin

Inicie o ciclo tendo como alvo o plugin:

<NxCommands commands={['migrate @aws/nx-plugin@latest']} />

```
 NX   The migrate command has run successfully.

- package.json has been updated.
- migrations.json has been generated.
- 1 AI migration prompt(s) have been written to tools/ai-migrations/.

 NX   Next steps:

- Make sure package.json changes make sense and then run 'pnpm install --no-frozen-lockfile',
- Review and tweak the AI migration prompts in tools/ai-migrations/ as needed.
- Run 'pnpm exec nx migrate --run-migrations'
- To learn more go to https://nx.dev/features/automate-updating-dependencies
```

Revise as mudanças no `package.json`, instale e então execute as migrações:

<NxCommands commands={['migrate --run-migrations']} />

### Migrações determinísticas

A maioria das migrações são codemods determinísticos — eles são executados sem supervisão e relatam qualquer coisa que deliberadamente pularam:

```
 NX   Running migrations from 'migrations.json'

Running the following migrations:
- @aws/nx-plugin: update-vitest-workspace-config — Add a coverage reporter to vitest configs
- @aws/nx-plugin: update-custom-api-handlers — Update custom API handlers for the new middleware signature

── Migration 1 of 2 · @aws/nx-plugin:update-vitest-workspace-config ─────
→ Running generator…
Changes:
  UPDATE packages/api/vite.config.mts

...

 NX   Successfully finished running migrations from 'migrations.json'.

2 migrations applied, 0 commits created.

 NX   Some migrations have additional information, see below.

- packages/website/vite.config.mts has a customised shape; add a coverage reporter manually.
```

Preste atenção às **informações adicionais** no final: quando uma migração encontra um arquivo que você personalizou além do que ela pode atualizar com segurança, ela deixa suas mudanças intactas e relata o acompanhamento manual lá.

### Migrações agênticas

Algumas migrações têm como alvo código que você possui, onde a edição correta depende do que você construiu — essas são fornecidas como prompts aplicados pelo seu agente de codificação de IA local (Claude Code, Codex ou OpenCode). Quando alguma estiver pendente, o Nx pede consentimento antes de envolver um agente:

```
? Enable the agentic flow? …
❯ Yes, just this time      Apply 1 prompt migration and validate generator output with an AI agent
  Yes, always              Saved to nx.json so Nx won't ask again
  No, just this time       Skip prompts and run generators without AI validation
  No, never                Saved to nx.json so Nx won't ask again
```

Se você aceitar, o agente aplica cada migração de prompt no local e resume o que mudou:

```
── Migration 2 of 2 · @aws/nx-plugin:update-custom-api-handlers ─────────
→ Running prompt with Claude Code…
✓ update-custom-api-handlers: Updated 3 API handlers to the new middleware signature.
```

Se você recusar — ou nenhum agente estiver instalado, ou a execução for não interativa (por exemplo, CI) — as migrações de prompt são puladas e salvas para você aplicar manualmente:

```
── Migration 2 of 2 · @aws/nx-plugin:update-custom-api-handlers ─────────
↷ Skipped — agentic flow disabled. Listed in next steps.

 NX   Successfully finished running migrations from 'migrations.json'.

1 migration applied, 0 commits created, 1 prompt migration skipped.

 NX   Some migrations have additional information, see below.

- Some prompt migrations were skipped. Review and apply each of the following
  prompt files to the workspace, in the listed order:
  - tools/ai-migrations/@aws/nx-plugin/2.0.0/prompt.md
```

Cada prompt pulado é um arquivo de instrução markdown autocontido em `tools/ai-migrations/` — cole-o em seu agente de codificação, ou siga suas etapas manualmente.

Finalmente, verifique se tudo ainda compila, então delete `migrations.json` e faça commit:

<NxCommands commands={['run-many --target build --all']} />

## Atualizando Nx

Atualizar o próprio Nx (e seus plugins `@nx/*`) é o mesmo ciclo, tendo como alvo `nx`:

<NxCommands commands={['migrate latest']} />

Então instale, execute as migrações, verifique e faça commit como antes:

<NxCommands commands={['migrate --run-migrations']} />

<Aside type="tip">
Ao pular várias versões principais do Nx, atualize uma versão principal de cada vez — veja [Automate Updating Dependencies](https://nx.dev/docs/features/automate-updating-dependencies) para detalhes.
</Aside>

<Aside type="note" title="pnpm build scripts">
Se `nx migrate latest` falhar com `ERR_PNPM_IGNORED_BUILDS`, o pnpm bloqueou o script de pós-instalação do pacote `nx`. Permita-o em `pnpm-workspace.yaml` e execute novamente:

```yaml
# pnpm-workspace.yaml
allowBuilds:
  nx: true
```
</Aside>
