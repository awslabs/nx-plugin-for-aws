L'immagine Docker costruita per questo progetto può essere scansionata per vulnerabilità utilizzando [Trivy](https://trivy.dev/), eseguito dall'[immagine Trivy ospitata su ECR](https://gallery.ecr.aws/aquasecurity/trivy).

Un target `trivy` viene aggiunto al tuo progetto che scansiona l'immagine costruita ed **esce con codice diverso da zero** se viene trovata qualsiasi vulnerabilità di gravità `HIGH` o `CRITICAL`. Il `Dockerfile` generato utilizza un'immagine base senza vulnerabilità risolvibili note di queste gravità al momento della generazione, e aggiorna gli strumenti inclusi (come `npm`) per mantenerla tale.

La scansione utilizza lo stesso motore container della tua build dell'immagine (`docker` o `finch`), quindi non sono richiesti strumenti aggiuntivi. La scansione non è memorizzata in cache, poiché l'immagine che legge risiede nel motore container anziché su disco — quindi scansiona sempre l'immagine reale e fallisce in modo evidente anziché riportare un successo memorizzato in cache per un'immagine che non è più presente. Ogni esecuzione richiede quindi decine di secondi per immagine e aggiorna il database delle vulnerabilità di Trivy, quindi necessita di accesso alla rete. Lo script root `trivy` fornito scansiona ogni immagine nel workspace:

<PackageManagerShortCommand commands={['trivy']} />

:::tip[Esegui Trivy in CI]
La scansione non è intenzionalmente collegata a `build` poiché questo può introdurre attriti non necessari durante l'iterazione in fase di sviluppo, dato che il database delle vulnerabilità di Trivy viene continuamente aggiornato con nuovi CVE.

Invece raccomandiamo di eseguire il comando sopra come passaggio dedicato nella tua pipeline CI prima del deployment agli stage di produzione.
:::

:::caution[Le vulnerabilità non risolvibili vengono ignorate]
La scansione viene eseguita con `--ignore-unfixed`, quindi le vulnerabilità senza una correzione disponibile non fanno fallire la build, poiché non possono essere risolte aggiornando gli strumenti nel tuo `Dockerfile` — non vengono riportate nell'output della scansione della build. Man mano che vengono divulgate nuove vulnerabilità, il risultato delle scansioni può cambiare nel tempo, quindi rivedi periodicamente l'immagine eseguendo `trivy image <your-image>` senza il flag, e ricostruisci contro un'immagine base più recente (o aggiungi passaggi container per applicare le patch disponibili) una volta che viene pubblicata una correzione.
:::

#### Soppressione dei Risultati di Trivy

Potrebbero esserci casi in cui desideri sopprimere una vulnerabilità specifica, ad esempio quando non è ancora disponibile una correzione e hai valutato il rischio come accettabile.

Aggiungi l'ID della vulnerabilità (uno per riga) al file `.trivyignore` nella root del tuo progetto (cioè accanto al tuo `project.json`):

```gitignore
# .trivyignore
# node-tar arbitrary file write - not exploitable in our usage
CVE-2024-XXXXX
```

Per maggiori dettagli sul filtraggio dei risultati, consulta la [documentazione sul filtraggio di Trivy](https://trivy.dev/latest/docs/configuration/filtering/#by-finding-ids).
