Questa guida ti accompagna attraverso le basi dell'installazione e dell'utilizzo di `@aws/nx-plugin` per costruire rapidamente progetti su AWS.

:::tip[Tutorial Full-Stack]
Per un tutorial più approfondito sulla costruzione di un'applicazione full-stack, consulta il <Link path="get_started/tutorials/dungeon-game/overview">Tutorial Dungeon Adventure</Link>.
:::

## Prerequisiti

Le seguenti dipendenze globali sono necessarie prima di procedere:

<Snippet name="prerequisites" />

## Passaggio 1: Inizializzare un Nuovo Workspace Nx

Esegui il seguente comando per creare un <Link path="guides/workspace">workspace Nx</Link> con il package manager di tua scelta:

<CreateNxWorkspaceCommand workspace="my-project" />

:::tip[Scegliere un Provider IaC]
Ti verrà richiesto di scegliere il tuo provider di infrastructure as code (IaC) preferito, [CDK](https://docs.aws.amazon.com/cdk/) o [Terraform](https://developer.hashicorp.com/terraform). Puoi saltare il prompt eseguendo il comando con `--iac`, ad esempio:

<Infrastructure>
<Fragment slot="cdk">
<CreateNxWorkspaceCommand workspace="my-project" iac="cdk" />
</Fragment>
<Fragment slot="terraform">
<CreateNxWorkspaceCommand workspace="my-project" iac="terraform" />
</Fragment>
</Infrastructure>

Ti verrà anche richiesto di scegliere il motore di container utilizzato dai generatori che costruiscono immagini container. Accetta il valore predefinito (`infer`) per selezionare Docker se è installato, altrimenti Finch.
:::

Una volta completato, naviga nella directory del progetto:

```sh
cd my-project
```

## Passaggio 2: Utilizzare i Generatori per Strutturare il Progetto

Aggiungeremo un'API tRPC, un sito web React, l'autenticazione Cognito e l'infrastruttura CDK o Terraform in questa guida rapida. A seconda del tipo di progetto che stai costruendo, puoi scegliere qualsiasi combinazione di generatori per avviare rapidamente il tuo progetto. Consulta i __Generatori__ nella barra di navigazione a sinistra per vedere l'elenco completo delle opzioni, oppure prova il <Link path="get_started/graph-builder">graph builder</Link> per costruire il tuo workspace visivamente.

Come scorciatoia, puoi utilizzare il pulsante qui sotto per copiare i comandi per strutturare l'applicazione completa.

<EmbeddedGraph preset="quick-start" workspace="my-project" iac="cdk" orientation="horizontal" skipWorkspace />

:::tip[Costruire con l'AI]
Il <Link path="get_started/building-with-ai">Nx Plugin for AWS MCP Server</Link> è già configurato nel tuo workspace, quindi puoi chiedere al tuo agente di codifica AI preferito come Kiro o Claude di costruire questi progetti per te invece di digitare i comandi CLI tu stesso.
:::

Altrimenti, segui i passaggi seguenti per eseguire ogni generatore da solo.

<RunGenerator generator="ts#api" requiredParameters={{ name: 'demo-api', framework: 'trpc', auth: 'iam' }} noInteractive />

Questo creerà l'API all'interno della cartella `packages/demo-api`.

### Aggiungere un Sito Web React

<RunGenerator generator="ts#website" requiredParameters={{ name: 'demo-website' }} noInteractive />

Questo crea un nuovo sito web React in `packages/demo-website`.

<RunGenerator generator="ts#website#auth" requiredParameters={{ project: '@my-project/demo-website', cognitoDomain: 'my-demo' }} noInteractive />

Questo configura l'infrastruttura necessaria e il codice React per aggiungere l'autenticazione Cognito al tuo sito web.

Questo configura i provider necessari per garantire che il tuo sito web possa chiamare la tua API tRPC.

Questo configura un progetto Terraform che puoi utilizzare per distribuire la tua infrastruttura su AWS.

## Passaggio 3: Eseguire il Sito Web e l'API Localmente

Utilizza il seguente comando per avviare i server di sviluppo locali per il tuo sito web e le sue API connesse:

<PackageManagerShortCommand commands={["dev"]} />

Il tuo sito web sarà disponibile all'indirizzo `http://localhost:4200`.

Le modifiche sia al tuo sito web che all'API si rifletteranno in tempo reale poiché sia il sito web locale che i server API si ricaricheranno automaticamente.

## Passaggio 4: Definire le Risorse Cloud e Distribuire su AWS

<Infrastructure>
<Fragment slot="cdk">
Apri `packages/infra/src/stacks/application-stack.ts` e aggiungi il seguente codice:

```typescript
import {
  DemoApi,
  DemoWebsite,
  UserIdentity,
} from '@my-project/common-constructs';
import { Stack, StackProps } from 'aws-cdk-lib';
import { Construct } from 'constructs';

export class ApplicationStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props);

    const identity = new UserIdentity(this, 'identity');
    const api = new DemoApi(this, 'api', {
      integrations: DemoApi.defaultIntegrations(this).build(),
    });
    api.grantInvokeAccess(identity.identityPool.authenticatedRole);

    new DemoWebsite(this, 'website');
  }
}
```

Questo è tutto il CDK che dobbiamo scrivere per distribuire la nostra applicazione full-stack.
</Fragment>
<Fragment slot="terraform">
Apri `packages/infra/src/main.tf` e aggiungi il seguente codice:

```hcl
# Include metrics tracking for @aws/nx-plugin usage
module "metrics" {
  source = "../../common/terraform/src/metrics"
}

# Deploy user identity
module "user_identity" {
  source = "../../common/terraform/src/core/user-identity"
}

# Shared asset bucket — stages Lambda deployment zips for every lambda / API module
module "asset_bucket" {
  source = "../../common/terraform/src/core/asset-bucket"
}

# Deploy API
module "demo_api" {
  source = "../../common/terraform/src/app/apis/demo-api"

  asset_bucket_name = module.asset_bucket.bucket_name
}

# Grant authenticated users access to invoke the API
resource "aws_iam_policy" "api_invoke_policy" {
  name        = "DemoApiInvokePolicy"
  description = "Policy to allow authenticated users to invoke the API"

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = "execute-api:Invoke"
        Resource = "${module.demo_api.api_execution_arn}/*/*"
      }
    ]
  })
}

resource "aws_iam_role_policy_attachment" "authenticated_api_access" {
  role       = module.user_identity.authenticated_role_name
  policy_arn = aws_iam_policy.api_invoke_policy.arn
}

# Deploy website
provider "aws" {
  alias  = "us_east_1"
  region = "us-east-1"
}

module "demo_website" {
  source = "../../common/terraform/src/app/static-websites/demo-website"

  providers = {
    aws.us_east_1 = aws.us_east_1
  }

  depends_on = [module.user_identity, module.demo_api]
}
```

Questo è tutto il Terraform che dobbiamo scrivere per distribuire la nostra applicazione full-stack.
</Fragment>
</Infrastructure>

### Costruire e Distribuire l'Infrastruttura

Successivamente, esegui il seguente comando per costruire il tuo progetto:

<PackageManagerShortCommand commands={["build"]} />

:::tip[Correggere gli Errori di Lint e Formattazione]
Se riscontri errori di lint o formattazione, puoi eseguire il seguente comando per correggerli automaticamente.

<PackageManagerShortCommand commands={["lint"]} />
:::

:::tip[Il workspace non è sincronizzato]
Se la build riporta `The workspace is out of sync`, accetta il prompt per sincronizzare il workspace oppure esegui direttamente il seguente comando di sincronizzazione prima di riprovare la build:

<NxCommands commands={["sync"]} />

Questo scrive i riferimenti del progetto TypeScript e le voci di dipendenza `package.json` richieste dalle tue importazioni.
:::

Esegui il bootstrap della tua infrastruttura:

<Infrastructure>
<Fragment slot="cdk">
<NxCommands commands={['bootstrap infra']} />

:::tip[Regioni di Bootstrap]
Il bootstrap di CDK è richiesto sia per la regione AWS di distribuzione di destinazione, sia per `us-east-1` per consentire la distribuzione del WebACL AWS WAF per il sito web.
:::
</Fragment>
<Fragment slot="terraform">
<NxCommands commands={['bootstrap infra']} />

:::tip[Configurazione Una Tantum]
Il bootstrap di Terraform crea un bucket S3 per memorizzare i file di stato di Terraform. Questo deve essere fatto solo una volta per ogni combinazione di account AWS/regione.
:::
</Fragment>
</Infrastructure>

Distribuisci il tuo progetto:

<Infrastructure>
<Fragment slot="cdk">
<NxCommands commands={['deploy-sandbox infra']} />
</Fragment>
<Fragment slot="terraform">
<NxCommands commands={['apply infra']} />

:::tip[Plan Prima di Apply]
Questo comando eseguirà prima `terraform plan` per mostrarti quali modifiche verranno apportate, quindi applicherà tali modifiche per distribuire la tua infrastruttura.
:::
</Fragment>
</Infrastructure>

## Passaggio 5: Creare un Utente

Il tuo sito web è protetto da Amazon Cognito e la registrazione autonoma è disabilitata per impostazione predefinita, quindi crea il tuo primo utente nel pool di utenti che hai distribuito. Puoi trovare l'ID del pool di utenti negli output della distribuzione o nella [console Amazon Cognito](https://console.aws.amazon.com/cognito/):

```sh
aws cognito-idp admin-create-user \
  --user-pool-id <user pool id> \
  --username <username> \
  --user-attributes Name=email,Value=<email> Name=email_verified,Value=true Name=given_name,Value=<first name> Name=family_name,Value=<last name> \
  --temporary-password '<temporary password>' \
  --message-action SUPPRESS
```

Rimuovi `--message-action SUPPRESS` per fare in modo che Cognito invii la password temporanea via email all'indirizzo che hai fornito, invece di condividerla tu stesso con l'utente. Puoi anche creare utenti dalla scheda **Users** del tuo pool di utenti nella console Cognito.

La prima volta che accedi come questo utente ti verrà richiesto di scegliere una nuova password, quindi di configurare l'autenticazione a più fattori con un codice inviato tramite SMS o una password monouso basata sul tempo da un'app di autenticazione.

:::tip[Registrazione Autonoma]
Esegui il generatore <Link path="guides/react-website-auth">`ts#website#auth`</Link> con `--allowSignup=true` se preferisci che gli utenti si registrino autonomamente dalla pagina di accesso anziché creare ogni utente manualmente.
:::

## Passaggio 6: Testare il Sito Web con le Risorse Cloud Distribuite

<Steps>
1. Recupera il file `runtime-config.json`:

    <NxCommands commands={['load-runtime-config demo-website']} />

2. Avvia il server del sito web locale

    <NxCommands commands={['serve demo-website']} />
</Steps>

Il tuo sito web sarà disponibile all'indirizzo `http://localhost:4200` e punterà alle risorse che hai distribuito per l'API e l'autenticazione. Accedi con l'utente che hai creato per vederlo in azione.

Il tuo sito web è anche servito da CloudFront — apri il nome di dominio della sua distribuzione per utilizzare la versione in esecuzione interamente su AWS.

## Passaggio 7: Pulizia

Quando hai finito, elimina le risorse che hai distribuito per evitare costi continui:

<Infrastructure>
<Fragment slot="cdk">
<NxCommands commands={['destroy-sandbox infra']} />
</Fragment>
<Fragment slot="terraform">
<NxCommands commands={['destroy infra']} />
</Fragment>
</Infrastructure>

:::note[Risorse Conservate]
Il pool di utenti Cognito viene creato con la protezione dall'eliminazione abilitata, quindi non viene rimosso automaticamente. Eliminalo (e il ruolo IAM che Cognito utilizza per inviare messaggi SMS) manualmente se non ne hai più bisogno.
:::
