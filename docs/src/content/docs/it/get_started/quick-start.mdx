Questa guida ti accompagna attraverso le basi dell'installazione e dell'utilizzo di `@aws/nx-plugin` per costruire rapidamente progetti su AWS.

## Prerequisiti

Le seguenti dipendenze globali sono necessarie prima di procedere:

<Snippet name="prerequisites" />

## Passaggio 1: Creare un Workspace

Crea un <Link path="guides/workspace">workspace Nx</Link> con il package manager di tua scelta e apri la directory che crea:

<CreateNxWorkspaceCommand workspace="my-project" />

```sh
cd my-project
```

Ti viene richiesto di scegliere il tuo provider di infrastructure as code, [CDK](https://docs.aws.amazon.com/cdk/) o [Terraform](https://developer.hashicorp.com/terraform), e il motore di container utilizzato dai generatori che costruiscono immagini container.

## Passaggio 2: Costruire la Tua Applicazione

Costruiremo un'applicazione full-stack: un'API tRPC, un sito web React, l'autenticazione Cognito e l'infrastruttura CDK o Terraform. Chiedi a un assistente AI di strutturarla per te, oppure esegui tu stesso i generatori — entrambi i percorsi portano allo stesso workspace.

### Con l'AI

<Steps>
1. Apri il workspace nel tuo assistente di codifica AI.

    I nuovi workspace vengono forniti con il <Link path="get_started/building-with-ai">server MCP</Link> del plugin già configurato per Kiro, Claude Code, Cursor, Gemini CLI, GitHub Copilot e OpenAI Codex, quindi il tuo assistente può cercare i generatori del plugin ed eseguirli senza alcuna configurazione.

2. Chiedi l'applicazione:

    <Prompt>
    Create a tRPC API called demo-api, and a React website called demo-website. Add Cognito authentication to the website, connect the website to the API, and add an infrastructure project called infra. Then instantiate the generated infrastructure components so the website and API deploy, granting authenticated users access to the API.
    </Prompt>

    Il tuo assistente scopre i generatori attraverso il server MCP e li esegue, nell'ordine richiesto dalle loro dipendenze. Rivedi le modifiche che apporta, quindi continua al Passaggio 3.
</Steps>

## Passaggio 3: Eseguire il Sito Web e l'API Localmente

Utilizza il seguente comando per avviare i server di sviluppo locali per il tuo sito web e le sue API connesse:

<PackageManagerShortCommand commands={["dev"]} />

Il tuo sito web sarà disponibile all'indirizzo `http://localhost:4200`.

Le modifiche sia al tuo sito web che all'API si rifletteranno in tempo reale poiché sia il sito web locale che i server API si ricaricheranno automaticamente.

<Drawer title="Chiamare l'API dal tuo sito web" trigger="Provalo: chiama l'API dal tuo sito web">

Connettere il sito web all'API ha aggiunto un hook `useDemoApi`, che restituisce un [tRPC options proxy](https://trpc.io/docs/client/tanstack-react-query): ogni procedura sulla tua API offre `queryOptions` e `mutationOptions` da passare a [TanStack Query](https://tanstack.com/query/latest).

Aggiorna `packages/demo-website/src/routes/index.tsx` per chiamare la procedura `echo` dell'API, mostrando uno spinner mentre la richiesta è in corso:

<Diff lang="tsx" before={`import { createFileRoute } from '@tanstack/react-router';

export const Route = createFileRoute('/')({
  component: RouteComponent,
});

function RouteComponent() {
  return (
    <div className="text-center">
      <header>
        <h1>Welcome</h1>
        <p>Welcome to your new React website!</p>
      </header>
    </div>
  );
}
`} after={`import { useQuery } from '@tanstack/react-query';
import { createFileRoute } from '@tanstack/react-router';
import { Spinner } from '../components/spinner';
import { useDemoApi } from '../hooks/useDemoApi';

export const Route = createFileRoute('/')({
  component: RouteComponent,
});

function RouteComponent() {
  const trpc = useDemoApi();
  const echo = useQuery(
    trpc.echo.queryOptions({ message: 'Hello from the API!' }),
  );

  return (
    <div className="text-center">
      <header>
        <h1>Welcome</h1>
        <p>Welcome to your new React website!</p>
      </header>
      {echo.isLoading ? (
        <Spinner />
      ) : echo.error ? (
        <p>Error: {echo.error.message}</p>
      ) : (
        <p>{echo.data?.message}</p>
      )}
    </div>
  );
}
`} />

Salva il file e la pagina si ricarica con il messaggio che la tua API ha restituito. La chiamata è type-safe end-to-end — rinomina `message` in `packages/demo-api/src/schema/echo.ts` e il tuo sito web smette di compilare finché non segui la modifica.

Consulta la <Link path="guides/connection/react-trpc">guida alla connessione React a tRPC</Link> per mutazioni, sottoscrizioni, gestione degli errori e aggiornamenti ottimistici.

</Drawer>

## Passaggio 4: Definire le Risorse Cloud e Distribuire su AWS

<Infrastructure>
<Fragment slot="cdk">
Apri `packages/infra/src/stacks/application-stack.ts` e aggiungi il seguente codice:

```typescript
import {
  DemoApi,
  DemoWebsite,
  UserIdentity,
} from '@my-project/common-constructs';
import { Stack, StackProps } from 'aws-cdk-lib';
import { Construct } from 'constructs';

export class ApplicationStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props);

    const identity = new UserIdentity(this, 'identity');
    const api = new DemoApi(this, 'api', {
      integrations: DemoApi.defaultIntegrations(this).build(),
    });
    api.grantInvokeAccess(identity.identityPool.authenticatedRole);

    new DemoWebsite(this, 'website');
  }
}
```

Questo è tutto il CDK che dobbiamo scrivere per distribuire la nostra applicazione full-stack.
</Fragment>
<Fragment slot="terraform">
Apri `packages/infra/src/main.tf` e aggiungi il seguente codice:

```hcl
# Deploy user identity
module "user_identity" {
  source = "../../common/terraform/src/core/user-identity"
}

# Shared asset bucket — stages Lambda deployment zips for every lambda / API module
module "asset_bucket" {
  source = "../../common/terraform/src/core/asset-bucket"
}

# Deploy API
module "demo_api" {
  source = "../../common/terraform/src/app/apis/demo-api"

  asset_bucket_name = module.asset_bucket.bucket_name
}

# Grant authenticated users access to invoke the API
resource "aws_iam_policy" "api_invoke_policy" {
  name        = "DemoApiInvokePolicy"
  description = "Policy to allow authenticated users to invoke the API"

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = "execute-api:Invoke"
        Resource = "${module.demo_api.api_execution_arn}/*/*"
      }
    ]
  })
}

resource "aws_iam_role_policy_attachment" "authenticated_api_access" {
  role       = module.user_identity.authenticated_role_name
  policy_arn = aws_iam_policy.api_invoke_policy.arn
}

# Deploy website
provider "aws" {
  alias  = "us_east_1"
  region = "us-east-1"
}

module "demo_website" {
  source = "../../common/terraform/src/app/static-websites/demo-website"

  providers = {
    aws.us_east_1 = aws.us_east_1
  }

  depends_on = [module.user_identity, module.demo_api]
}

# Print the website URL and user pool id when the deployment finishes
output "website_url" {
  value = module.demo_website.website_url
}

output "user_pool_id" {
  value = module.user_identity.user_pool_id
}
```

Questo è tutto il Terraform che dobbiamo scrivere per distribuire la nostra applicazione full-stack.
</Fragment>
</Infrastructure>

### Costruire e Distribuire l'Infrastruttura

Successivamente, esegui il seguente comando per costruire il tuo progetto:

<PackageManagerShortCommand commands={["build"]} />

:::tip[Correggere gli Errori di Lint e Formattazione]
Se riscontri errori di lint o formattazione, puoi eseguire il seguente comando per correggerli automaticamente.

<PackageManagerShortCommand commands={["lint"]} />
:::

:::note[Il workspace non è sincronizzato]
Se la build riporta `The workspace is out of sync`, accetta il prompt per sincronizzare il workspace oppure esegui direttamente il seguente comando di sincronizzazione prima di riprovare la build:

<NxCommands commands={["sync"]} />

Questo scrive i riferimenti del progetto TypeScript e le voci di dipendenza `package.json` richieste dalle tue importazioni.
:::

Esegui il bootstrap della tua infrastruttura:

<Infrastructure>
<Fragment slot="cdk">
<NxCommands commands={['bootstrap infra']} />

:::tip[Regioni di Bootstrap]
Il bootstrap di CDK è richiesto sia per la regione AWS di distribuzione di destinazione, sia per `us-east-1` per consentire la distribuzione del WebACL AWS WAF per il sito web. Se stai distribuendo altrove, esegui il bootstrap anche di `us-east-1`:

<NxCommands commands={['run infra:bootstrap --args="aws://<account-id>/us-east-1"']} />
:::
</Fragment>
<Fragment slot="terraform">
<NxCommands commands={['bootstrap infra']} />

:::tip[Configurazione Una Tantum]
Il bootstrap di Terraform crea un bucket S3 per memorizzare i file di stato di Terraform. Questo deve essere fatto solo una volta per ogni combinazione di account AWS/regione.
:::
</Fragment>
</Infrastructure>

Distribuisci il tuo progetto:

<Infrastructure>
<Fragment slot="cdk">
<NxCommands commands={['deploy-sandbox infra']} />
</Fragment>
<Fragment slot="terraform">
<NxCommands commands={['apply infra']} />

:::tip[Plan Prima di Apply]
Questo comando eseguirà prima `terraform plan` per mostrarti quali modifiche verranno apportate, quindi applicherà tali modifiche per distribuire la tua infrastruttura.
:::
</Fragment>
</Infrastructure>

## Passaggio 5: Testare il Sito Web con le Risorse Cloud Distribuite

<Steps>
1. Recupera il file `runtime-config.json`:

    <NxCommands commands={['load-runtime-config demo-website']} />

2. Avvia il server del sito web locale

    <NxCommands commands={['serve demo-website']} />
</Steps>

Il tuo sito web sarà disponibile all'indirizzo `http://localhost:4200` e punterà alle risorse che hai distribuito per l'API e l'autenticazione.

Per accedere, dovrai [creare un utente nel pool di utenti Cognito](https://docs.aws.amazon.com/cognito/latest/developerguide/how-to-create-user-accounts.html).

<Drawer title="Creare un utente con AWS CLI" trigger="Clicca qui per le istruzioni usando AWS CLI">

Il seguente comando crea un utente in un pool di utenti. Puoi trovare l'ID del pool di utenti negli output della distribuzione o nella [console Amazon Cognito](https://console.aws.amazon.com/cognito/). Sostituisci i valori per username, email, nome e cognome e la password temporanea.

```sh
aws cognito-idp admin-create-user \
  --user-pool-id <user pool id> \
  --username <username> \
  --user-attributes Name=email,Value=<email> Name=email_verified,Value=true Name=given_name,Value=<first name> Name=family_name,Value=<last name> \
  --temporary-password '<temporary password>' \
  --message-action SUPPRESS
```

La prima volta che accedi come questo utente ti verrà richiesto di scegliere una nuova password, quindi di configurare l'autenticazione a più fattori con un codice inviato tramite SMS o una password monouso basata sul tempo da un'app di autenticazione.

</Drawer>

Il tuo sito web è anche servito da CloudFront. Apri il nome di dominio della sua distribuzione (che viene stampato sul tuo terminale dopo la distribuzione) per utilizzare la versione in esecuzione interamente su AWS.

Congratulazioni! 🎉 Hai costruito e distribuito con successo un'applicazione full-stack utilizzando `@aws/nx-plugin`!

## Passaggio 6: Pulizia

Quando hai finito, elimina le risorse che hai distribuito per evitare costi continui:

<Infrastructure>
<Fragment slot="cdk">
<NxCommands commands={['destroy-sandbox infra']} />

:::note[Risorse Conservate]
Il pool di utenti Cognito viene creato con la protezione dall'eliminazione abilitata, quindi non viene rimosso automaticamente. Eliminalo (insieme al ruolo IAM che Cognito utilizza per inviare messaggi SMS) manualmente se non ne hai più bisogno.
:::
</Fragment>
<Fragment slot="terraform">
<NxCommands commands={['destroy infra']} />

:::note[Risorse Conservate]
Il pool di utenti Cognito viene creato con la protezione dall'eliminazione abilitata, quindi non viene rimosso automaticamente (il comando destroy segnalerà un errore). Eliminalo (insieme al ruolo IAM che Cognito utilizza per inviare messaggi SMS) manualmente se non ne hai più bisogno.
:::
</Fragment>
</Infrastructure>

Per rimuovere le risorse di bootstrap, segui le istruzioni qui sotto:

<Infrastructure>
<Fragment slot="cdk">
Elimina lo stack di bootstrap in ogni regione di cui hai eseguito il bootstrap, inclusa `us-east-1`. Questo rimuove i ruoli di bootstrap e il repository delle immagini container:

```sh
aws cloudformation delete-stack --stack-name CDKToolkit --region <region>
```

:::note[Asset Bucket]
Il bucket degli asset viene conservato di proposito, quindi eliminalo separatamente.
:::
</Fragment>
<Fragment slot="terraform">
<NxCommands commands={['bootstrap-destroy infra']} />

:::caution[Anche il Tuo Stato Terraform Viene Eliminato]
Questo svuota ed elimina il bucket S3 che contiene il tuo stato Terraform, quindi eseguilo solo una volta che hai smantellato tutta l'infrastruttura distribuita.
:::
</Fragment>
</Infrastructure>
