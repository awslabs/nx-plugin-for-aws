Questo generatore aggiunge un servizio HTTP containerizzato a un progetto TypeScript esistente. Ottieni un piccolo server HTTP con una route `GET /health`, un Dockerfile e target per eseguire il server localmente, costruire la sua immagine e scansionare l'immagine. Ottieni anche codice CDK o Terraform che esegue l'immagine su [Amazon Elastic Container Service (Amazon ECS)](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/Welcome.html), il servizio AWS che esegue e scala i container.

Il servizio viene eseguito su [AWS Fargate](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/AWS_Fargate.html), che esegue ogni container senza server da gestire. Viene eseguito nel tuo VPC (virtual private cloud, una rete isolata nel tuo account AWS), dietro un [Application Load Balancer](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html) (ALB) interno che solo gli indirizzi all'interno del VPC possono raggiungere. Per impostazione predefinita, un'[Amazon API Gateway HTTP API](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api.html) riceve le richieste dai chiamanti e le passa all'ALB attraverso un VPC link (la connessione privata di API Gateway in un VPC). I chiamanti ottengono un endpoint HTTPS autenticato e il load balancer non è mai esposto a Internet.

## Eseguire il Servizio Localmente

Il target `<name>-serve` esegue il server sulla tua macchina, senza un container:

<NxCommands commands={['run your-project:service-serve']} />

Il server ascolta sulla porta nella variabile d'ambiente `PORT`. Il target `<name>-serve` la imposta su una porta che il generatore assegna, partendo da 8081 e saltando le porte che altri progetti nel tuo workspace già utilizzano. All'interno del container il server ascolta sulla porta 8080.

Verifica che il server sia attivo con la sua route di health, che restituisce lo stato 200 e `{"status":"ok"}`:

```bash
curl http://localhost:<port>/health
```

Il server ha anche una route di esempio che sostituisci con le tue route. `GET /hello?name=<x>` restituisce `{"message":"Hello, <x>!"}`, e `name` ha come valore predefinito `world`. Qualsiasi altro percorso restituisce lo stato 404.

## Costruire e Scansionare l'Immagine

Il target `<name>-docker` costruisce un'immagine linux/arm64 del tuo servizio. Esegue prima il target `bundle`, quindi l'immagine contiene il server in bundle. Quindi copia il `Dockerfile` e `.dockerignore` nella cartella di output del bundle, `dist/<project root>/bundle/container/<name>`, e costruisce l'immagine con quella cartella come contesto di build (i file che la build dell'immagine può leggere). Utilizza il motore di container con cui è configurato il tuo workspace, `docker` o [Finch](https://runfinch.com/). Il target viene eseguito come parte del target aggregato `docker`, che costruisce ogni immagine nel progetto.

<NxCommands commands={['run your-project:service-docker']} />

Solo il target group del load balancer (l'elenco dei task a cui il load balancer invia le richieste) controlla `GET /health`, per decidere se un task è pronto per il traffico. ECS ignora un'istruzione `HEALTHCHECK` nel Dockerfile. Per maggiori informazioni su come vengono costruite e pubblicate le immagini, vedi <Link path="/guides/docker-bundling">Docker Bundling</Link>.

## Deployment del Servizio

### Aggiungere il Servizio alla Tua Infrastruttura

Il costrutto e il modulo non creano mai un VPC. Ne crei o importi uno nel tuo stack o modulo root e lo passi. I task e il load balancer vengono eseguiti in subnet private con egress, che raggiungono i servizi AWS attraverso un NAT gateway (un gateway gestito che consente alle subnet private di effettuare connessioni in uscita) o attraverso VPC endpoint (connessioni private dal tuo VPC ai servizi AWS).

<Infrastructure>
<Fragment slot="cdk">
Il costrutto CDK viene creato in `common/constructs` e prende il nome dal tuo servizio. Esempio di utilizzo con un nuovo VPC:

```ts title="packages/infra/src/stacks/application-stack.ts"
import { MyService } from '@my-scope/common-constructs';
import { Stack, StackProps } from 'aws-cdk-lib';
import { SubnetType, Vpc } from 'aws-cdk-lib/aws-ec2';
import { Construct } from 'constructs';

export class ApplicationStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props);

    const vpc = new Vpc(this, 'Vpc', { natGateways: 1 });

    new MyService(this, 'MyService', {
      vpc,
      vpcSubnets: { subnetType: SubnetType.PRIVATE_WITH_EGRESS },
    });
  }
}
```

Per utilizzare un VPC esistente, cercalo con `Vpc.fromLookup(this, 'Vpc', { vpcId: '<vpc-id>' })` e passalo come `vpc`.
</Fragment>
<Fragment slot="terraform">
Il modulo Terraform viene creato in `common/terraform`. L'immagine del servizio viene pubblicata nel repository di asset condiviso, quindi istanzia il modulo `core/asset-ecr` una volta per deployment e passa i suoi output a ogni modulo di servizio. Passa anche gli output del modulo condiviso `runtime_config_appconfig`, che contengono l'applicazione AWS AppConfig da cui il servizio legge la sua <Link path="/guides/runtime-config">configurazione runtime</Link>:

```hcl title="packages/infra/src/main.tf"
module "asset_ecr" {
  source = "../../common/terraform/src/core/asset-ecr"
}

module "my_service" {
  source = "../../common/terraform/src/app/services/my-service"

  vpc_id     = aws_vpc.main.id
  subnet_ids = aws_subnet.private[*].id

  asset_ecr_repository_url = module.asset_ecr.repository_url
  asset_ecr_repository_arn = module.asset_ecr.repository_arn

  appconfig_application_id  = module.runtime_config_appconfig.application_id
  appconfig_application_arn = module.runtime_config_appconfig.application_arn
}
```
</Fragment>
</Infrastructure>

### Limiti delle Richieste

API Gateway smette di attendere il tuo servizio dopo 30 secondi e restituisce un errore al chiamante. Non puoi aumentare questo timeout di integrazione. Il payload di richiesta più grande che l'HTTP API accetta è 10 MB e non puoi aumentare neanche questo limite. Entrambi i valori provengono dalla pagina [Amazon API Gateway quotas for HTTP APIs](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-quotas.html).

Quindi le richieste che durano più di 30 secondi e le risposte che trasmettono dati per un lungo periodo non funzionano attraverso l'HTTP API. Per quelle, imposta `ingress` su `private` e chiama il load balancer interno dall'interno del VPC.
</OptionFilter>

<OptionFilter when={{ infra: 'ecs' }} description="Networking, sicurezza, chiamate, configurazione avanzata, costi e distruzione">
### Esecuzione Senza un NAT Gateway

Quando i tuoi task si avviano, ECS estrae l'immagine e invia i log per loro conto. Il codice del tuo server potrebbe anche chiamare i servizi AWS. Nelle subnet private senza NAT gateway, ognuna di queste chiamate necessita di un VPC endpoint. Senza gli endpoint giusti, i task non riescono ad avviarsi o vanno in timeout quando chiamano AWS.

Crea questi endpoint nel VPC, sostituendo `<region>` con la tua Regione AWS:

| Endpoint | Tipo | Chi lo usa |
| --- | --- | --- |
| `com.amazonaws.<region>.ecr.api` | Interface | ECS, per autenticarsi con Amazon ECR e cercare l'immagine |
| `com.amazonaws.<region>.ecr.dkr` | Interface | ECS, per estrarre l'immagine da Amazon ECR |
| `com.amazonaws.<region>.s3` | Gateway | ECS, per scaricare i layer dell'immagine, che Amazon ECR memorizza in Amazon S3 |
| `com.amazonaws.<region>.logs` | Interface | L'output dei log del container, inviato ad Amazon CloudWatch Logs |
| `com.amazonaws.<region>.secretsmanager` | Interface | ECS, per leggere i segreti che passi al container quando un task si avvia |
| `com.amazonaws.<region>.appconfigdata` | Interface | Il tuo codice, per leggere la <Link path="/guides/runtime-config">configurazione runtime</Link> da AWS AppConfig |
| `com.amazonaws.<region>.sts` | Interface | Il tuo codice, quando richiede credenziali temporanee da AWS STS (ad esempio per assumere un altro ruolo) |

Gli endpoint di interfaccia necessitano di un security group che consenta HTTPS (porta 443) dai task. Per i dettagli sugli endpoint Amazon ECR, vedi [Amazon ECR interface VPC endpoints](https://docs.aws.amazon.com/AmazonECR/latest/userguide/vpc-endpoints.html).

### Impostazioni di Sicurezza Predefinite

L'infrastruttura generata applica queste impostazioni per impostazione predefinita:

- Il load balancer è interno. Nessun security group consente il traffico in entrata da `0.0.0.0/0` o `::/0`.
- I task vengono eseguiti in subnet private e non ottengono mai un indirizzo IP pubblico.
- Il load balancer accetta traffico solo dal VPC link (`http-api`) o dall'intervallo di indirizzi del VPC (`private`). I task accettano traffico solo dal load balancer, sulla porta del container.
- I task possono inviare traffico in uscita solo sulla porta 443. Le connessioni ai database aggiungono la porta del database.
- Il task role (il ruolo con cui viene eseguito il codice del tuo server) può solo leggere la configurazione runtime da AWS AppConfig finché tu o una connessione non concedete di più.
- L'execution role (il ruolo che ECS utilizza per avviare il tuo task) può solo estrarre l'immagine del servizio, scrivere nel suo log group e leggere i segreti che elenchi.
- I segreti raggiungono il container solo come riferimenti ad AWS Secrets Manager o AWS Systems Manager Parameter Store, mai come valori di ambiente in chiaro.
- Il container ha un file system root di sola lettura e viene eseguito come uid 1000, un utente non root. ECS Exec (accesso shell in un task in esecuzione) è disattivato.
- Un deployment che non supera i controlli di salute si ferma e torna alla versione precedente.
- L'HTTP API scrive log di accesso e limita le richieste. Si autentica con IAM a meno che tu non scelga diversamente.
- I log vengono conservati per un anno.

Il codice generato sopprime questi controlli [Checkov](https://www.checkov.io/) (Checkov scansiona il codice dell'infrastruttura per impostazioni non sicure) e indica il motivo accanto a ogni soppressione:

- `CKV_AWS_91` richiede i log di accesso del load balancer. I log di accesso dell'HTTP API, o i log del tuo servizio, registrano invece le richieste.
- `CKV_AWS_2` e `CKV_AWS_103` richiedono un listener HTTPS con TLS. Il load balancer ascolta su HTTP semplice perché è interno e solo i chiamanti all'interno del VPC possono raggiungerlo. Con `http-api`, TLS termina su API Gateway.

Il modulo Terraform salta anche `CKV2_AWS_20` e `CKV_AWS_378` per lo stesso motivo del listener HTTP, e `CKV_AWS_150` perché la protezione dalla cancellazione del load balancer è disattivata in modo che il servizio possa essere distrutto.

### Chiamare il Tuo Servizio

L'URL del servizio viene scritto nella <Link path="/guides/runtime-config">configurazione runtime</Link> come `connection.services.<NameClassName>`, dove `<NameClassName>` è il nome del servizio in PascalCase. Per `--name=orders` la chiave è `Orders`. Senza un nome, il nome del servizio è `<project>-service`, quindi per un progetto chiamato `my-project` la chiave è `MyProjectService`. La cartella sorgente e il prefisso del target sono ancora `service` in quel caso.

<Tabs syncKey="auth">
<TabItem label="IAM" _filter={{ ingress: 'http-api', auth: 'iam' }}>
I chiamanti firmano ogni richiesta con [AWS Signature Version 4 (SigV4)](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_sigv.html) per il servizio `execute-api`, utilizzando credenziali AWS che possono chiamare l'API. API Gateway rifiuta una richiesta senza una firma valida prima che raggiunga il tuo servizio.

<Infrastructure>
<Fragment slot="cdk">
Concedi a un ruolo o a una funzione il permesso di chiamare il servizio con `grantInvoke`:

```ts title="packages/infra/src/stacks/application-stack.ts"
const service = new MyService(this, 'MyService', { vpc });
service.grantInvoke(myFunction);
```
</Fragment>
<Fragment slot="terraform">
Concedi a un ruolo il permesso di chiamare il servizio con una policy `execute-api:Invoke` sull'ARN di esecuzione dell'API, che il modulo del tuo servizio restituisce come `api_execution_arn`:

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_role_policy" "invoke_my_service" {
  role = aws_iam_role.caller.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["execute-api:Invoke"]
      Resource = ["${module.my_service.api_execution_arn}/*"]
    }]
  })
}
```
</Fragment>
</Infrastructure>
</TabItem>
<TabItem label="Cognito" _filter={{ ingress: 'http-api', auth: 'cognito' }}>
I chiamanti inviano un JSON Web Token (JWT) emesso dal tuo pool di utenti Amazon Cognito nell'header `Authorization`. L'HTTP API verifica che il token provenga dal pool di utenti e sia stato emesso per uno dei client app accettati.

<Infrastructure>
<Fragment slot="cdk">
Il costrutto generato per un servizio Cognito non accetta una prop `auth`. Passa invece il pool di utenti e il client app nella sua prop `identity` richiesta:

```ts title="packages/infra/src/stacks/application-stack.ts"
new MyService(this, 'MyService', {
  vpc,
  identity: { userPool, userPoolClient },
});
```
</Fragment>
<Fragment slot="terraform">
Imposta le variabili richieste `user_pool_id` e `user_pool_client_ids` del modulo del tuo servizio, `app/services/<name>/<name>.tf`. Il modulo le passa al modulo `ecs-service`.
</Fragment>
</Infrastructure>
</TabItem>
<TabItem label="None" _filter={{ ingress: 'http-api', auth: 'none' }}>
L'HTTP API accetta richieste senza autenticazione. Chiunque conosca l'URL può chiamare il tuo servizio, quindi controlla i chiamanti nel tuo codice.
</TabItem>
<TabItem label="Private" _filter={{ ingress: 'private' }}>
Un servizio `private` non ha un'HTTP API. Il suo URL è l'indirizzo del load balancer interno, che solo i chiamanti all'interno del VPC possono raggiungere. Il load balancer accetta traffico dall'intervallo di indirizzi del VPC sulla sua porta di ascolto. Ad esempio, chiamalo da una funzione Lambda o da un altro servizio ECS nello stesso VPC.
</TabItem>

### Configurazione Avanzata

Il servizio generato imposta il suo nome, `ingress` e `auth` per te. Gli esempi seguenti utilizzano direttamente il costrutto generico `EcsService` e il modulo `ecs-service`, per impostazioni che il servizio generato non passa o per scegliere `ingress` e `auth` per istanza.

In CDK, il tuo package `common-constructs` esporta `EcsService` accanto al costrutto del tuo servizio, quindi lo importi allo stesso modo: `import { EcsService } from '@my-scope/common-constructs'`. Il costrutto generato estende `EcsService` e passa ogni altra prop, ad esempio `cluster`, `loadBalancer`, `environment`, `secrets` e `grantTaskRole`. La sua prop opzionale `image` sostituisce l'immagine costruita dal tuo progetto. Non ha una prop `auth`. Un servizio Cognito prende invece `identity` e altri servizi utilizzano sempre l'`auth` con cui sono stati generati.

In Terraform, il modulo del tuo servizio ti consente di impostare solo alcune delle variabili del modulo `ecs-service`: `vpc_id`, `subnet_ids`, `cluster_arn`, `environment`, `secrets`, `task_role_policy_statements` e `tags`, più `user_pool_id` e `user_pool_client_ids` per un servizio Cognito. Per impostare qualsiasi altra variabile, modifica il blocco `module "ecs_service"` nel modulo del tuo servizio.

#### Immagine Precostruita

Per eseguire un'immagine già costruita, ad esempio da un registro pubblico, passa il suo URI. Nulla viene costruito localmente. Per un'immagine in un repository Amazon ECR privato, CDK concede all'execution role l'accesso pull su quel repository. Terraform concede l'accesso pull solo quando passi anche l'ARN del repository come `image_repository_arn`.

<Infrastructure>
<Fragment slot="cdk">

```ts
new EcsService(this, 'Prebuilt', {
  serviceName: 'Prebuilt',
  vpc,
  image: { imageUri: 'public.ecr.aws/my-org/my-image@sha256:<digest>' },
});
```

</Fragment>
<Fragment slot="terraform">

```hcl
module "prebuilt" {
  source = "../../common/terraform/src/core/container/ecs-service"

  service_name = "Prebuilt"
  vpc_id       = aws_vpc.main.id
  subnet_ids   = aws_subnet.private[*].id
  image_uri    = "public.ecr.aws/my-org/my-image@sha256:<digest>"
  # For an image in a private Amazon ECR repository, also pass:
  # image_repository_arn = aws_ecr_repository.my_image.arn
}
```

</Fragment>
</Infrastructure>

#### Worker Senza Load Balancer

Un worker legge da una coda o esegue lavori in background e nulla lo chiama. Disattiva il load balancer per ottenere un servizio senza load balancer, senza HTTP API e senza URL.

<Infrastructure>
<Fragment slot="cdk">

```ts
new EcsService(this, 'Worker', {
  serviceName: 'Worker',
  vpc,
  image: { directory: '<path to the folder with the Dockerfile>' },
  loadBalancer: false,
});
```

</Fragment>
<Fragment slot="terraform">
Come con un'immagine precostruita, Terraform concede l'accesso pull su un repository Amazon ECR privato solo quando passi `image_repository_arn`.

```hcl
module "worker" {
  source = "../../common/terraform/src/core/container/ecs-service"

  service_name  = "Worker"
  vpc_id        = aws_vpc.main.id
  subnet_ids    = aws_subnet.private[*].id
  image_uri     = "<image uri pinned by digest>"
  load_balancer = false
  # For an image in a private Amazon ECR repository, also pass:
  # image_repository_arn = aws_ecr_repository.my_image.arn
}
```

</Fragment>
</Infrastructure>

#### Diversi Servizi in Uno Stack

Ogni servizio crea il proprio cluster ECS a meno che tu non ne passi uno. Per eseguire diversi servizi in un cluster, passa lo stesso cluster a ciascuno.

Ogni servizio HTTP API crea il proprio VPC link, anche quando i servizi condividono un cluster. API Gateway consente 10 VPC link per account per Regione per impostazione predefinita e puoi richiedere un aumento.

<Infrastructure>
<Fragment slot="cdk">

```ts
const cluster = new Cluster(this, 'Cluster', { vpc });

new MyService(this, 'MyService', { vpc, cluster });
new MyOtherService(this, 'MyOtherService', { vpc, cluster });
```

</Fragment>
<Fragment slot="terraform">
Passa lo stesso `cluster_arn` a ogni modulo `ecs-service`. L'output `cluster_arn` del primo servizio te ne fornisce uno:

```hcl
cluster_arn = module.my_service.cluster_arn
```

</Fragment>
</Infrastructure>

#### Variabili d'Ambiente e Segreti

Le impostazioni semplici vanno in `environment`. Non mettere mai valori segreti lì, perché chiunque possa leggere la definizione del task può leggerli. Passa invece i segreti come riferimenti. L'execution role può leggere solo i segreti che elenchi.

<Infrastructure>
<Fragment slot="cdk">

```ts
new EcsService(this, 'MyService', {
  // ...
  environment: { LOG_LEVEL: 'info' },
  secrets: { API_KEY: Secret.fromSecretsManager(apiKeySecret) },
});
```

</Fragment>
<Fragment slot="terraform">

```hcl
environment = { LOG_LEVEL = "info" }
secrets     = { API_KEY = aws_secretsmanager_secret.api_key.arn }
```

</Fragment>
</Infrastructure>

#### Dimensionamento e Scaling

Ogni task ottiene 256 unità CPU (un quarto di una vCPU) e 512 MiB di memoria per impostazione predefinita. Il servizio avvia un task e l'autoscaling mantiene tra uno e due task in esecuzione, aggiungendo task quando l'uso medio della CPU supera il 70%.

| Impostazione | Prop CDK | Variabile Terraform | Predefinito |
| --- | --- | --- | --- |
| Unità CPU per task | `cpu` | `cpu` | 256 |
| Memoria per task (MiB) | `memoryLimitMiB` | `memory` | 512 |
| Task all'avvio | `desiredCount` | `desired_count` | 1 |
| Minimo di task | `minCapacity` | `min_capacity` | 1 |
| Massimo di task | `maxCapacity` | `max_capacity` | 2 |
| CPU media target (%) | `targetCpuUtilizationPercent` | `target_cpu_utilization` | 70 |

#### Permessi del Task Role

#### Utente del Container

La definizione del task esegue il container come uid 1000, un utente non root. Questo corrisponde all'utente `node` che il Dockerfile fornito imposta. Per eseguire come un altro utente, imposta la prop CDK `user` o la variabile Terraform `container_user`. Terraform rifiuta `0` e `root`.

| Impostazione | Prop CDK | Variabile Terraform | Predefinito |
| --- | --- | --- | --- |
| Utente con cui viene eseguito il container | `user` | `container_user` | `'1000'` (CDK), `"1000:1000"` (Terraform) |

#### CORS e Throttling

Queste impostazioni si applicano solo con `ingress` impostato su `http-api`. CORS (cross-origin resource sharing) decide quali siti web possono chiamare il tuo servizio da un browser. Per impostazione predefinita, l'HTTP API accetta richieste del browser da qualsiasi origine, con qualsiasi metodo e con gli header `authorization`, `content-type`, `x-amz-content-sha256`, `x-amz-date` e `x-amz-security-token`. Gli ultimi tre sono gli header che una firma SigV4 aggiunge. L'HTTP API limita anche le richieste a una velocità costante di 10.000 al secondo, con burst fino a 5.000.

| Impostazione | CDK | Variabile Terraform | Predefinito |
| --- | --- | --- | --- |
| Origini CORS consentite | Metodo `restrictCorsTo(...origins)`, o prop `corsPreflight` | `cors_allow_origins` | qualsiasi origine (`["*"]`) |
| Altre impostazioni CORS | Prop `corsPreflight` | none | qualsiasi metodo e gli header sopra |
| Throttling | Prop `throttle` | none | `{ rateLimit: 10000, burstLimit: 5000 }` |

Una prop `corsPreflight` sostituisce l'intero valore predefinito, quindi elenca ogni header che i tuoi chiamanti inviano. Il metodo `restrictCorsTo` mantiene le altre impostazioni CORS e cambia solo le origini consentite:

```ts
const service = new MyService(this, 'MyService', { vpc });
service.restrictCorsTo('https://app.example.com');
```

In Terraform, `cors_allow_origins` e `container_user` sono variabili del modulo `ecs-service`. Il modulo del tuo servizio non le passa, quindi impostale nel suo blocco `module "ecs_service"`. I valori di throttling sono fissi in `ecs-service.tf`.

### Costi

Un container service fattura mentre è inattivo, a differenza di una funzione Lambda. Queste parti fatturano all'ora indipendentemente dal fatto che qualcuno chiami o meno il servizio:

- Task Fargate, per vCPU e per GB di memoria. `desiredCount` e `minCapacity` mantengono almeno un task in esecuzione.
- L'Application Load Balancer, per ora e per unità di capacità del load balancer.
- Endpoint VPC di interfaccia, per ora in ogni Availability Zone, o un NAT gateway, per ora e per GB di dati che elabora.
- Archiviazione dei log in CloudWatch Logs e archiviazione delle immagini in Amazon ECR.

L'HTTP API fattura per richiesta. Per stimare il costo per la tua Regione e il tuo traffico, usa il [AWS Pricing Calculator](https://calculator.aws/).
