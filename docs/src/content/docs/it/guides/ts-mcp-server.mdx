Genera un server TypeScript [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) per fornire contesto ai Large Language Model (LLM), e opzionalmente distribuiscilo su [Amazon Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/).

## Cos'è MCP?

Il [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) è uno standard aperto che consente agli assistenti AI di interagire con strumenti e risorse esterne. Fornisce un modo coerente per gli LLM di:

- Eseguire strumenti (funzioni) che eseguono azioni o recuperano informazioni
- Accedere a risorse che forniscono contesto o dati

## Lavorare con il Tuo MCP Server

### Aggiungere Strumenti

Gli strumenti sono funzioni che l'assistente AI può chiamare per eseguire azioni. Ogni strumento risiede nel proprio file sotto `tools/` che esporta una funzione `register<Name>Tool`, che poi chiami da `server.ts`. Ad esempio, aggiungi `tools/my-tool.ts`:

```typescript title="tools/my-tool.ts"
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';
import { z } from 'zod';

export const registerMyTool = (server: McpServer) => {
  server.registerTool("toolName", {
    description: "tool description",
    inputSchema: { param1: z.string(), param2: z.number() } // Input schema using Zod
  },
    async ({ param1, param2 }) => {
      // Tool implementation
      return {
        content: [{ type: "text", text: "Result" }]
      };
    }
  );
};
```

Poi registralo in `server.ts`:

```typescript title="server.ts"
import { registerMyTool } from './tools/my-tool.js';

registerMyTool(server);
```

### Delimitare i Dati degli Strumenti per Chiamante

`createServer` riceve un `McpRequestContext` che descrive la richiesta corrente. Su HTTP Streamable questo include l'id di sessione AgentCore Runtime del chiamante, che un <Link path="guides/ts-agent">agent</Link> inoltra automaticamente su ogni chiamata MCP in uscita.

Passalo a uno strumento che memorizza dati per chiamante:

```typescript title="server.ts"
export const createServer = async (context: McpRequestContext = {}) => {
  // ...
  registerMyTool(server, context);
};
```

```typescript title="tools/my-tool.ts"
export const registerMyTool = (
  server: McpServer,
  context: McpRequestContext,
) => {
  server.registerTool('my-tool', { /* ... */ }, async ({ itemName }) => {
    if (!context.sessionId) {
      throw new Error('No caller session — cannot resolve the owner.');
    }
    // Key stored data on the caller's session, not on a tool argument.
    await save({ owner: context.sessionId, itemName });
    // ...
  });
};
```

:::caution
Delimita i dati memorizzati sul contesto della richiesta piuttosto che su un argomento dello strumento. Un modello può essere persuaso a passare qualsiasi valore desideri, quindi argomenti come un nome utente o giocatore non sono un confine di fiducia. Il contesto è assente su STDIO, dove non c'è richiesta.
:::

### Aggiungere Risorse

Le risorse forniscono contesto all'assistente AI. Come gli strumenti, ogni risorsa risiede nel proprio file sotto `resources/` che esporta una funzione `register<Name>Resource` chiamata da `server.ts`. Puoi aggiungere risorse statiche da file o risorse dinamiche:

```typescript title="resources/my-resource.ts"
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';

export const registerMyResource = (server: McpServer) => {
  const exampleContext = 'some context to return';

  server.registerResource('resource-name', 'example://resource', {}, async (uri) => ({
    contents: [{ uri: uri.href, text: exampleContext }],
  }));

  // Dynamic resource
  server.registerResource('dynamic-resource', 'dynamic://resource', {}, async (uri) => {
    const data = await fetchSomeData();
    return {
      contents: [{ uri: uri.href, text: data }],
    };
  });
};
```

## Eseguire il Tuo MCP Server

### Sviluppo Locale

Per eseguire il tuo server MCP (e tutto ciò che è connesso ad esso, come un database locale) localmente, usa il target `dev` del progetto:

<NxCommands commands={['dev your-project']} />

Se hai aggiunto più componenti al tuo progetto (server MCP, agenti, ecc.), questo li avvia tutti. Per eseguire solo questo server MCP, punta al suo target `<your-server-name>-dev`:

<NxCommands commands={['your-server-name-dev your-project']} />

### Inspector

Il generatore configura un target denominato `<your-server-name>-inspect`, che avvia il tuo server MCP localmente (tramite il target `<your-server-name>-dev`, incluse eventuali dipendenze connesse come un database locale) e lancia l'[MCP Inspector](https://github.com/modelcontextprotocol/inspector) preconfigurato per connettersi ad esso tramite trasporto HTTP Streamable.

<NxCommands commands={['your-server-name-inspect your-project']} />

Questo avvierà l'inspector su `http://localhost:6274`. Inizia cliccando sul pulsante "Connect".

:::tip
Per ispezionare il server utilizzando il trasporto STDIO invece, usa il target `<your-server-name>-inspect-stdio`, che lancia l'inspector contro un'istanza STDIO del tuo server.
:::

### STDIO

Il modo più semplice per testare e utilizzare un server MCP è utilizzare l'inspector o configurarlo con un assistente AI (come sopra).

Puoi tuttavia eseguire il tuo server con [trasporto STDIO](https://modelcontextprotocol.io/docs/concepts/transports#standard-input%2Foutput-stdio) direttamente utilizzando il target `<your-server-name>-serve-stdio`.

<NxCommands commands={['your-server-name-serve-stdio your-project']} />

Questo comando utilizza `tsx --watch` per riavviare automaticamente il server quando i file cambiano.

### Streamable HTTP

Se desideri eseguire il tuo server MCP localmente utilizzando [trasporto HTTP Streamable](https://modelcontextprotocol.io/docs/concepts/transports#streamable-http), puoi utilizzare il target `<your-server-name>-serve`.

<NxCommands commands={['your-server-name-serve your-project']} />

Questo comando utilizza `tsx --watch` per riavviare automaticamente il server quando i file cambiano.

### Target Bundle

<Snippet name="ts-bundle" />

Il target bundle utilizza `http.ts` come punto di ingresso per il server MCP HTTP Streamable da ospitare su Bedrock AgentCore Runtime.

### Target Docker

Il generatore configura un target `<your-server-name>-docker` che copia il `Dockerfile` dalla directory sorgente del tuo server MCP nella directory di output del bundle. Questo co-localizza il `Dockerfile` con gli artefatti del bundle, consentendo a CDK di costruire l'immagine Docker direttamente utilizzando `AgentRuntimeArtifact.fromAsset`.

Viene anche generato un target `docker` che prepara il contesto docker per tutti i server MCP se ne hai definiti più di uno.
