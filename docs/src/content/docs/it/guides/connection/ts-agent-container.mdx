Il generatore `connection` consente a un <Link path="guides/ts-agent">TypeScript Agent</Link> di chiamare un container service creato con <Link path="guides/ts-container">`ts#container`</Link> o <Link path="guides/py-container">`py#container`</Link>. Aggiunge un client al progetto condiviso `agent-connection` che legge l'URL del servizio dalla configurazione runtime e firma ogni richiesta con le credenziali AWS dell'agent stesso.

## Come funziona

Un container service con `infra=ecs` viene eseguito su Amazon ECS (Elastic Container Service) dietro un Application Load Balancer interno. Con il valore predefinito `ingress=http-api`, un'API HTTP di Amazon API Gateway (un endpoint HTTPS gestito) raggiunge quel load balancer attraverso un VPC link, che è la connessione privata di API Gateway nella tua VPC. L'agent chiama l'API HTTP.

Il client firma ogni richiesta con SigV4, il processo di firma delle richieste AWS, utilizzando le credenziali del ruolo dell'agent. L'API HTTP accetta la richiesta quando quel ruolo può chiamare `execute-api:Invoke` su di essa. L'API HTTP termina qualsiasi richiesta che impiega più di 30 secondi, quindi una route che viene eseguita più a lungo deve restituire un risultato anticipatamente e completare il suo lavoro in background.

Il generatore rifiuta un servizio che non può raggiungere in questo modo. Il servizio deve avere `infra=ecs`, perché `infra=none` non crea alcun endpoint. Deve avere `ingress=http-api`, perché un servizio `private` è raggiungibile solo dall'interno della sua VPC. Deve avere `auth=iam`, perché l'agent firma le sue richieste con credenziali IAM e non ha alcun token Cognito da inviare.

## Prerequisiti

Prima di utilizzare questo generatore, assicurati di avere:

1. Un progetto <Link path="guides/ts-agent">`ts#agent`</Link>
2. Un container service con `infra=ecs`, `ingress=http-api` e `auth=iam` (generato utilizzando il generatore <Link path="guides/ts-container">`ts#container`</Link> o <Link path="guides/py-container">`py#container`</Link>)

## Output del generatore

Il generatore crea i seguenti file nel progetto condiviso `agent-connection`:

<FileTree>

- packages/common/agent-connection
  - src
    - app
      - \<service-name>-client.ts Client che legge l'URL del servizio dalla configurazione runtime e firma le richieste con SigV4
    - index.ts Esporta il client

</FileTree>

Aggiunge `@aws-lambda-powertools/parameters`, `@aws-sdk/credential-providers` e `aws4fetch` al progetto `agent-connection`, e fa in modo che il target `<agent-name>-dev` dell'agent avvii il target `<service-name>-serve` del servizio.

## Utilizzo del client

`<ServiceName>Client.create()` legge l'URL del servizio dal namespace `connection` della <Link path="guides/runtime-config">configurazione runtime</Link>, sotto `services.<ServiceName>`. Il `fetch` del client accetta un percorso relativo al servizio. Il generatore non modifica il codice del tuo agent. Per consentire al modello di chiamare il servizio, avvolgi il client in un tool:

```ts title="packages/my-project/src/my-agent/agent.ts"
import { Agent, tool } from '@strands-agents/sdk';
import { MyServiceClient } from '@my-scope/agent-connection';
import { z } from 'zod';

export const getAgent = async () => {
  const myService = await MyServiceClient.create();
  const checkMyService = tool({
    name: 'check_my_service',
    description: 'Check whether the MyService container service is healthy',
    inputSchema: z.object({}),
    callback: async () => (await myService.fetch('/health')).status,
  });

  return new Agent({
    tools: [checkMyService],
  });
};
```

`create()` genera un'eccezione quando `RUNTIME_CONFIG_APP_ID` non è impostato o quando la configurazione runtime non ha alcuna voce per il servizio.

## Infrastruttura

Il ruolo dell'agent necessita del permesso per chiamare l'API HTTP del servizio. Il generatore non modifica il tuo stack o il modulo Terraform root. Invece stampa il codice da aggiungere, che è mostrato di seguito per un agent denominato `my-agent` e un servizio denominato `my-service`. Fino a quando non lo aggiungi, l'API HTTP rifiuta le richieste dell'agent con 403 Forbidden.

<Infrastructure>
<Fragment slot="cdk">

Nell'esempio, `myService` è il tuo costrutto `MyService` e `myAgent` è il tuo costrutto `MyAgent`:

```ts title="packages/infra/src/stacks/application-stack.ts"
myService.grantInvoke(myAgent);
```

`grantInvoke` consente al ruolo dell'agent di chiamare `execute-api:Invoke` sull'API HTTP del servizio.

</Fragment>
<Fragment slot="terraform">

Aggiungi l'istruzione agli `additional_iam_policy_statements` dell'agent, accanto a qualsiasi istruzione che il blocco già elenca. Nell'esempio, `module "my_service"` distribuisce il servizio:

```hcl title="packages/infra/src/main.tf"
module "my_agent" {
  source = "../../common/terraform/src/app/agents/my-agent"
  # ...existing arguments...
  additional_iam_policy_statements = [
    {
      Effect   = "Allow"
      Action   = ["execute-api:Invoke"]
      Resource = ["${module.my_service.api_execution_arn}/*"]
    },
  ]
}
```

</Fragment>
</Infrastructure>

## Sviluppo locale

<NxCommands commands={["<agent-name>-dev <project-name>"]} />

Questo avvia l'agent e il target `<service-name>-serve` del servizio. Il target dev dell'agent imposta `LOCAL_DEV=true`, quindi il client chiama il servizio su `http://localhost:<port>` senza firmare. La porta è quella che il generatore di container ha assegnato al servizio.
