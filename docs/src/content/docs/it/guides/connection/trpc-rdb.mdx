Il generatore `connection` collega un'<Link path="guides/trpc">API tRPC</Link> a un progetto <Link path="guides/ts-rdb">Database Relazionale</Link>, generando un plugin middleware tRPC type-safe che rende disponibile un client Prisma nel contesto delle tue procedure.

## Prerequisiti

Prima di utilizzare questo generatore, assicurati di avere:

1. Un progetto <Link path="guides/trpc">API tRPC</Link> (generato con `ts#api`)
2. Un progetto <Link path="guides/ts-rdb">`ts#rdb`</Link>

## Output del Generatore

Il generatore crea un file middleware nel tuo progetto API tRPC e amplia il contesto radice in `init.ts`:

<FileTree>

- packages/api/src
  - middleware
    - \<db-name>.ts plugin tRPC che espone il client Prisma nel contesto delle procedure
  - init.ts L'interfaccia di contesto del database aggiunta a `Context`

</FileTree>

```ts title="packages/api/src/init.ts" {1,3}
import { IMyDbContext } from './middleware/my-db.js';

export type Context = IMiddlewareContext & IMyDbContext;

export const t = initTRPC.context<Context>().create();
```

Ampliare `Context` è ciò che consente alle procedure di comporre il plugin — senza di esso, `concat()` rifiuta il plugin con un errore di tipo `"Context mismatch"`.

Inoltre, aggiorna il target `dev` della tua API tRPC per avviare automaticamente il database quando viene eseguito localmente.

## Utilizzo del Middleware

### Registrare il Plugin

Aggiungi il plugin generato al tuo router tRPC in modo che tutte le procedure che lo utilizzano ottengano accesso al database:

```ts title="packages/api/src/router.ts" {2,4}
import { t } from './init.js';
import { createMyDbPlugin } from './middleware/my-db.js';

export const dbProcedure = t.procedure.concat(createMyDbPlugin());
```

### Accedere al Database nelle Procedure

Il plugin unisce `IMyDbContext` nel contesto delle tue procedure, rendendo `myDb` disponibile come proprietà opzionale:

```ts title="packages/api/src/procedures/users.ts" {7-8}
import { z } from 'zod';
import { dbProcedure } from '../router.js';

export const listUsers = dbProcedure
  .output(z.array(z.object({ id: z.string(), name: z.string() })))
  .query(async ({ ctx }) => {
    // ctx.myDb is the Prisma client — typed as Awaited<ReturnType<typeof getPrisma>>
    return await ctx.myDb!.user.findMany();
  });
```

### MySQL: Disconnettersi Dopo Ogni Richiesta

Quando il database di destinazione utilizza il motore MySQL, il middleware generato avvolge `opts.next()` in un blocco `try/finally` che chiama `$disconnect()`:

```ts title="packages/api/src/middleware/my-db.ts" {6}
return t.procedure.use(async (opts) => {
  const myDb = await getPrisma();
  try {
    return await opts.next({ ctx: { ...opts.ctx, myDb } });
  } finally {
    await myDb.$disconnect();
  }
});
```

Questo risolve il problema dell'adapter MySQL che mantiene aperto il ciclo degli eventi di Node.js dopo una query, il che altrimenti impedirebbe a Lambda di svuotare le risposte in streaming. Disconnettersi in `finally` rilascia il ciclo degli eventi in modo che la risposta possa completarsi. Vedi <Link path="guides/ts-rdb#mysql-api-gateway-streaming-mode">MySQL: API Gateway Streaming Mode</Link> per i dettagli.

PostgreSQL non richiede questo — il suo adapter utilizza un pool di connessioni configurato con `allowExitOnIdle: true`.

:::caution[MySQL: Scadenza del Token IAM]
I token IAM di RDS scadono dopo **15 minuti**. L'adapter MySQL cattura il token al momento della connessione. Se la tua Lambda rimane attiva abbastanza a lungo da far scadere il token, i nuovi tentativi di connessione potrebbero fallire. Controlla gli errori di connessione e chiama di nuovo `getPrisma()` per ottenere un nuovo client con un nuovo token. Vedi <Link path="guides/ts-rdb#mysql-iam-token-expiry">MySQL: IAM Token Expiry</Link> per i dettagli e le soluzioni alternative.
:::

## Database Multipli

Puoi connettere database aggiuntivi eseguendo nuovamente il generatore con una destinazione diversa. Ogni database ottiene il proprio plugin e interfaccia di contesto, e ciascuno viene aggiunto a `Context`:

```ts title="packages/api/src/init.ts"
export type Context = IMiddlewareContext & IMyDbContext & IOtherDbContext;
```

```ts title="packages/api/src/router.ts"
export const dbProcedure = t.procedure
  .concat(createMyDbPlugin())
  .concat(createOtherDbPlugin());
```

## Sviluppo Locale

Il generatore configura il target `dev` della tua API tRPC per dipendere dal target `dev` del database, quindi eseguendo:

<NxCommands commands={["dev <api-project-name>"]} />

avvierà automaticamente il database locale insieme alla tua API.
