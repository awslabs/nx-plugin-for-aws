Il generatore `connection` consente a un <Link path="guides/ts-container">servizio container TypeScript</Link> di utilizzare un progetto <Link path="guides/ts-dynamodb">TypeScript DynamoDB</Link>. Configura lo sviluppo locale in modo che il servizio e DynamoDB Local si avviino insieme e stampa le autorizzazioni di cui il servizio ha bisogno.

## Come funziona

Un servizio container con `infra=ecs` viene eseguito come task su Amazon ECS (Elastic Container Service). Ogni task viene eseguito con il task role del servizio, un ruolo IAM che può solo leggere la configurazione di runtime finché non concedi ulteriori autorizzazioni. Per leggere e scrivere nella tabella, il task role necessita delle azioni DynamoDB sulla tabella e sui suoi indici, e dell'uso della chiave di crittografia AWS KMS della tabella.

Il generatore rifiuta un servizio con `infra=none`, perché tale servizio non ha un task role a cui concedere l'accesso.

## Prerequisiti

Prima di utilizzare questo generatore, assicurati di avere:

1. Un servizio container con `infra=ecs` (generato utilizzando il generatore <Link path="guides/ts-container">`ts#container`</Link>)
2. Un progetto <Link path="guides/ts-dynamodb">`ts#dynamodb`</Link>

## Output del Generatore

Il generatore aggiorna il target `<service-name>-serve` del servizio in `project.json` per dipendere dal target `dev` del progetto DynamoDB. Nessun file sorgente viene modificato.

## Utilizzo di DynamoDB nel Servizio

Importa le factory di entità dal pacchetto DynamoDB e usale dove gestisci una richiesta:

```ts title="packages/my-project/src/my-service/examples.ts"
import { createExampleEntity } from '@my-scope/my-table';

export const listExamples = async () => {
  const entity = await createExampleEntity();
  const result = await entity.scan.go();
  return result.data;
};
```

## Infrastruttura

Il generatore non modifica il tuo stack o il modulo Terraform root. Invece stampa il codice da aggiungere, che è mostrato di seguito per un servizio chiamato `my-service` e una tabella chiamata `my-table`. Finché non lo aggiungi, le richieste del servizio alla tabella vengono negate.

<Infrastructure>
<Fragment slot="cdk">

Nell'esempio, `myService` è il tuo costrutto `MyService` e `myTable` è il tuo costrutto `MyTable`:

```ts title="packages/infra/src/stacks/application-stack.ts"
myTable.grantReadWriteData(myService.taskRole);
```

`grantReadWriteData` concede sia le autorizzazioni DynamoDB che KMS al task role del servizio.

</Fragment>
<Fragment slot="terraform">

Nell'esempio, `module "my_service"` distribuisce il servizio e `module "my_table"` distribuisce la tabella:

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_role_policy" "my_service_my_table_access" {
  name = "my-service-my-table-access"
  role = module.my_service.task_role_name

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Action = [
          "dynamodb:GetItem", "dynamodb:PutItem", "dynamodb:UpdateItem",
          "dynamodb:DeleteItem", "dynamodb:Query", "dynamodb:Scan",
          "dynamodb:BatchGetItem", "dynamodb:BatchWriteItem",
        ]
        Resource = [
          module.my_table.table_arn,
          "${module.my_table.table_arn}/index/*",
        ]
      },
      {
        Effect = "Allow"
        Action = [
          "kms:Encrypt",
          "kms:Decrypt",
          "kms:ReEncrypt*",
          "kms:GenerateDataKey*",
          "kms:DescribeKey",
        ]
        Resource = [module.my_table.kms_key_arn]
      },
    ]
  })
}
```

## Sviluppo Locale

<NxCommands commands={["<service-name>-serve <project-name>"]} />

Questo avvia il servizio e DynamoDB Local. Con `LOCAL_DEV=true` impostato, `getDynamoDBClient()` e `resolveTableName()` si connettono a DynamoDB Local invece che ad AWS.
