Il generatore `connection` può connettere il tuo <Link path="guides/ts-agent">TypeScript Agent</Link> a un agente [A2A](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-a2a.html) remoto — sia <Link path="guides/ts-agent">TypeScript</Link> che <Link path="guides/py-agent">Python</Link> — in modo che il tuo agente possa delegare a un altro agente come strumento.

Il generatore configura tutto il cablaggio necessario affinché il tuo agente possa scoprire e invocare l'agente A2A remoto, sia quando viene distribuito su AWS (tramite Bedrock AgentCore) sia quando viene eseguito localmente.

## Prerequisiti

Prima di utilizzare questo generatore, assicurati di avere:

1. Un progetto TypeScript con un componente <Link path="guides/ts-agent">Strands Agent</Link> (qualsiasi protocollo)
2. Un progetto con un componente Agent generato con `--protocol=a2a` e `--auth=iam` (sia <Link path="guides/ts-agent">`ts#agent`</Link> che <Link path="guides/py-agent">`py#agent`</Link>)
3. Entrambi i componenti creati con `infra: agentcore`

## Output del Generatore

Il generatore crea un pacchetto condiviso `agent-connection` e modifica il codice del tuo agente:

<FileTree>

- packages/common/agent-connection
  - src
    - app
      - \<target-agent-name>-client-strands.ts High-level Strands client for the connected A2A agent
    - core
      - agentcore-endpoints.ts Framework-agnostic ARN/URL resolution
      - agentcore-fetch.ts Framework-agnostic SigV4 / JWT / session-forwarding fetch
      - agentcore-a2a-client-config.ts Framework-agnostic A2A client config (signed `clientFactory`)
      - agentcore-a2a-client-strands.ts Strands A2A client wrapping the config
    - index.ts Exports all clients
  - project.json
  - tsconfig.json

</FileTree>

Inoltre:
- Trasforma il file `agent.ts` del tuo agente per registrare l'agente A2A remoto come `tool` di Strands
- Aggiorna il target `dev` dell'agente per dipendere dal target `dev` dell'agente di destinazione
- Installa le dipendenze richieste

## Utilizzo dell'Agente A2A Connesso

Il generatore trasforma il file `agent.ts` del tuo agente per avvolgere l'agente A2A remoto come strumento:

```ts title="packages/example/src/my-agent/agent.ts" {2,5-12,15}
import { Agent, tool } from '@strands-agents/sdk';
import { RemoteAgentClientStrands } from '@my-scope/agent-connection';
import { z } from 'zod';

export const getAgent = async (sessionId: string) => {
  const remoteAgent = await RemoteAgentClientStrands.create(sessionId);
  const remoteAgentTool = tool({
    name: 'askRemoteAgent',
    description: 'Delegate a question to the remote RemoteAgent A2A agent and return its reply.',
    inputSchema: z.object({ prompt: z.string() }),
    callback: async ({ prompt }) => (await remoteAgent.invoke(prompt)).toString(),
  });
  return new Agent({
    systemPrompt: '...',
    tools: [remoteAgentTool],
  });
};
```

Il parametro `sessionId` viene propagato dal chiamante, garantendo coerenza per [Bedrock AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html).

Internamente, `RemoteAgentClientStrands.create(sessionId)` restituisce un `A2AAgent` di Strands configurato con un `clientFactory` che firma con SigV4 quando distribuito su AWS, e un semplice endpoint `http://localhost:<port>/` quando `LOCAL_DEV=true`. La firma e la risoluzione degli endpoint risiedono nel file framework-agnostic `agentcore-a2a-client-config.ts`; solo il sottile `agentcore-a2a-client-strands.ts` dipende da Strands.

## Sviluppo Locale

Il generatore configura il target `dev` dell'agente host per:
1. Avviare automaticamente gli agenti A2A connessi
2. Impostare `LOCAL_DEV=true` in modo che il client generato si connetta direttamente a `http://localhost:<port>/` invece che ad AgentCore

Esegui l'agente localmente con:

<NxCommands commands={["<agent-name>-dev <project-name>"]} />

Questo avvierà sia l'agente host che tutti gli agenti A2A connessi, con l'agente host che chiama gli agenti remoti tramite HTTP semplice sulle loro porte locali assegnate.
