#### `-dev` so với `-serve`

Generator thêm hai target chạy cùng một server trên cùng một cổng. Chúng chỉ khác nhau ở môi trường mà chúng thiết lập:

| Target | Môi trường | Sử dụng cho |
| --- | --- | --- |
| `<your-agent-name>-dev` | `PORT`, `LOCAL_DEV=true` | Phát triển cục bộ |
| `<your-agent-name>-serve` | `PORT` | Thực thi đường dẫn code đã triển khai ở cục bộ |

**Sử dụng `<your-agent-name>-dev` cho phát triển cục bộ.** `LOCAL_DEV=true` chuyển agent sang các đường dẫn code cục bộ của nó: trạng thái phiên được ghi vào đĩa dưới `tmp/agents/` tại thư mục gốc workspace, và bất kỳ MCP server được kết nối nào đều được truy cập qua HTTP trực tiếp thay vì thông qua AgentCore. Đây cũng là target mà target `dev` cấp dự án tổng hợp, và là target mà target `<your-agent-name>-chat` mong đợi tìm thấy đang chạy.

`<your-agent-name>-serve` chạy cùng đường dẫn code như agent đã triển khai của bạn, giải quyết session storage và các ARN runtime được kết nối từ <Link path="guides/runtime-config">Runtime Configuration</Link> trong AppConfig. Điều đó yêu cầu `RUNTIME_CONFIG_APP_ID` được đặt thành AppConfig application id của một deployment (được xuất ra dưới dạng `RuntimeConfigApplicationId` bởi stack đã triển khai), cùng với các thông tin xác thực AWS được phép đọc nó:

```bash
RUNTIME_CONFIG_APP_ID=<app-id> nx run your-project:agent-serve
```

:::caution[`-serve` cần cấu hình đã triển khai]
Khởi động mà không có `RUNTIME_CONFIG_APP_ID`, `<your-agent-name>-serve` chấp nhận các yêu cầu nhưng mọi lời gọi đều thất bại với `RUNTIME_CONFIG_APP_ID is not set — cannot resolve connected agent ARNs from AppConfig.`

Đặt `LOCAL_DEV=true` để sử dụng các đường dẫn code cục bộ thay thế — đó là những gì `<your-agent-name>-dev` đã làm cho bạn.
:::
