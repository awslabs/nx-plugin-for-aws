## Nhiệm vụ 1: Chạy mọi thứ ở local

Khởi động toàn bộ stack local — máy chủ dev game-ui cùng với Game API local và AG-UI Story Agent local (lần lượt khởi động máy chủ Inventory MCP) — bằng một lệnh duy nhất:

<NxCommands commands={["dev game-ui"]} />

Target `dev` trên `game-ui` có `dependsOn` trên `game-api:dev` và `dungeon_adventure.story:agent-dev`, vì vậy Nx khởi động máy chủ local của mọi dự án song song. Thông qua các kết nối mà chúng ta thiết lập trong Module 1, chúng lần lượt khởi động máy chủ Inventory MCP và DynamoDB Local. Đảm bảo container engine của bạn đang chạy, sau đó mở máy chủ dev tại `http://localhost:4200/` trong trình duyệt.

<Aside type="tip" title="Không cần đăng nhập ở local">
Trong chế độ `local-dev`, component `CognitoAuth` bỏ qua luồng đăng nhập Cognito (không có user pool chạy ở local), vì vậy bạn sẽ vào thẳng trò chơi mà không cần đăng nhập. Bạn sẽ tạo tài khoản thực khi chúng ta triển khai lên AWS ở cuối module này.
</Aside>

<Aside type="caution" title="Giữ Dev Server chạy">
Để máy chủ dev chạy trong suốt phần còn lại của module này — nó hot-reload mọi thay đổi bên dưới.
</Aside>

## Nhiệm vụ 2: Nơi CopilotKit đã được kết nối

Khi bạn chạy generator `connection` cho `game-ui → story` trong <Link path="get_started/tutorials/dungeon-game/1">Module 1</Link>, tích hợp AG-UI của website Shadcn đã được tạo cho bạn. Đáng để xem qua nhanh:

<FileTree>
- packages/game-ui/src/
  - components/
    - AguiProvider.tsx Single `CopilotKitProvider` registered with every AG-UI agent.
    - copilot/
      - index.tsx Re-exports themed `CopilotChat` / `CopilotSidebar` / `CopilotPopup`.
      - ShadcnAssistantMessage.tsx, ShadcnUserMessage.tsx, ShadcnChatInput.tsx, ShadcnCursor.tsx, copilot.css
    - story-agent-chat.tsx A `CopilotChat` pre-bound to the Story Agent's `agentId`.
  - hooks/
    - useAguiStoryAgent.tsx Instantiates an `@ag-ui/client` `HttpAgent` pointing at the deployed Story Agent and pads `threadId` to AgentCore's 33-character minimum session id.
  - main.tsx Wraps `<App />` in `<AguiProvider>`
</FileTree>

Tất cả những gì chúng ta cần làm là thả một `<CopilotChat agentId="agent" threadId={...} />` vào một route. Để biết thêm chi tiết về cách tích hợp được kết hợp, xem <Link path="guides/connection/react-agui">hướng dẫn kết nối React → AG-UI</Link>.

## Nhiệm vụ 4: Tạo các route của trò chơi

Chúng ta cần hai route — một để chọn hero, một để chơi. Cả hai đều sử dụng các component shadcn và chat CopilotKit; không có giao diện chat tự tạo.

<TabItem label="routes/game/$playerName.tsx">

Đây là route chơi. Nó xây dựng `threadId` xác định (``{player}-{genre}`` được đệm đến 33 ký tự — hook AG-UI sẽ gửi nó nguyên văn làm session id của AgentCore), render `<CopilotChat agentId="agent" threadId={threadId} />`, và phủ inventory từ `useGameApi().inventory.query` lên trên. Khi mount, `useGameApi().actions.query({ sessionId: threadId })` đọc lịch sử hội thoại mà agent đã lưu trữ trong S3 và — nếu có — gọi `agent.setMessages(...)` để rehydrate chat; nếu không nó gửi một user message priming để khởi động câu chuyện. `agent.messages` được subscribe thông qua `useAgent({ updates: [OnMessagesChanged] })` vì vậy mỗi lượt mới cũng refetch inventory query (các lời gọi MCP tool mutate DynamoDB trực tiếp).

<Aside type="tip" title="Đợi `isFetching`, không phải `isLoading`">
Cache mặc định của React Query giữ lại kết quả đầu tiên trong 5 phút, vì vậy một lần truy cập trở lại ban đầu sẽ thấy danh sách trống cũ từ lần load đầu tiên. Chúng ta đặt `staleTime: 0` + `refetchOnMount: 'always'` và bảo vệ `useEffect` hydration trên `!isFetching && isSuccess` để đường dẫn re-prime chỉ kích hoạt trên một thread thực sự trống.
</Aside>

<Aside type="tip" title="threadIds xác định làm cho /game/$playerName?genre=... có thể chia sẻ">
Truy cập lại cùng một URL — cho dù sau khi reload, redeploy, hoặc trên thiết bị khác — sẽ resolve thành cùng một `threadId`, vì vậy agent tiếp tục kể cùng một câu chuyện.
</Aside>

<Aside type="tip" title="Path Parameters">
Cú pháp `$playerName` cho `@tanstack/react-router` biết coi `playerName` là một [path param](https://tanstack.com/router/v1/docs/framework/react/guide/path-params). `validateSearch` làm cho `genre` được type mạnh so với enum của chúng ta.
</Aside>

## Nhiệm vụ 5: Triển khai lên AWS

Trò chơi của bạn đã hoàn thành và bạn đã kiểm tra mọi phần ở local. Bây giờ hãy triển khai nó lên AWS để bạn có thể chơi từ bất kỳ đâu.

### Build code của bạn

<PackageManagerShortCommand commands={["build"]} />

### Triển khai ứng dụng của bạn

<NxCommands commands={['deploy-sandbox infra']} />

:::caution[Yêu cầu Bootstrap]
Nếu đây là lần triển khai CDK đầu tiên trong tài khoản/khu vực AWS của bạn, hãy bootstrap nó trước:

<NxCommands commands={['bootstrap infra']} />
:::

Target `deploy-sandbox` triển khai stage sandbox được định nghĩa trong `packages/infra/src/main.ts`.

Target `deploy-sandbox` sử dụng [CloudFormation express mode](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/cloudformation-express-mode.html), hoàn thành mỗi thao tác tài nguyên ngay khi cấu hình của nó được áp dụng thay vì đợi ổn định hoàn toàn. Lần triển khai đầu tiên của bạn sẽ mất khoảng 4 phút để hoàn thành, và một số tài nguyên (chẳng hạn như CloudFront distribution) có thể tiếp tục provisioning ở chế độ nền trong một thời gian ngắn sau đó. Các lần triển khai tiếp theo sẽ nhanh hơn.

Vì express mode trả về trước khi các tài nguyên ổn định hoàn toàn, `deploy-sandbox` chỉ dành cho phát triển. Sử dụng target `deploy-ci` cho các triển khai CI/CD và production, luôn đợi ổn định hoàn toàn.

## Nhiệm vụ 6: Kết hợp các component local và đã triển khai

Bạn đã thấy hai đầu của phổ: mọi thứ local (`dev`) và mọi thứ đã triển khai. Trong quá trình phát triển hàng ngày, thường hữu ích khi kết hợp cả hai — ví dụ, lặp lại code website với API và agent *thực* đã triển khai, hoặc chạy API ở local với bảng DynamoDB *thực*.

Chìa khóa là biến môi trường `RUNTIME_CONFIG_APP_ID`. Khi một dự án chạy **không có** `LOCAL_DEV=true`, các tra cứu runtime config lấy cấu hình của chúng từ AWS AppConfig sử dụng application id này — giá trị `RuntimeConfigApplicationId` từ CDK outputs của bạn.

Mỗi website có một target `load-runtime-config` tải xuống `runtime-config.json` đã triển khai (Cognito pool, API endpoints, agent ARN) vào máy chủ dev local. Một số kết hợp hữu ích:

- **Website local → backend đã triển khai.** Pull config đã triển khai một lần, sau đó chạy target `serve` thuần túy để UI giao tiếp với API và agent đã triển khai:

  <NxCommands commands={["load-runtime-config game-ui"]} />
  <NxCommands commands={["serve game-ui"]} />

- **API local → bảng DynamoDB thực.** Chạy target `serve` thuần túy với `RUNTIME_CONFIG_APP_ID` được đặt thành application id đã triển khai:

  <NxCommands env={{RUNTIME_CONFIG_APP_ID:"<RuntimeConfigApplicationId from CDK outputs>"}} commands={["serve game-api"]} />

Tính linh hoạt này cho phép bạn kiểm tra chính xác phần bạn đang làm việc, với bất kỳ component nào — local hoặc đã triển khai — có ý nghĩa.
