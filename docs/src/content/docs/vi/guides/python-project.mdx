Trình tạo dự án Python có thể được sử dụng để tạo một thư viện hoặc ứng dụng [Python](https://www.python.org/) hiện đại được cấu hình với các phương pháp hay nhất, được quản lý bằng [UV](https://docs.astral.sh/uv/), một lockfile và môi trường ảo duy nhất trong [UV workspace](https://docs.astral.sh/uv/concepts/projects/workspaces/), [pytest](https://docs.pytest.org/en/stable/) để chạy các bài kiểm tra, [Ruff](https://docs.astral.sh/ruff/) để phân tích tĩnh, và [ty](https://docs.astral.sh/ty/) để kiểm tra kiểu.

## Kết quả của Trình tạo

Trình tạo sẽ tạo cấu trúc dự án sau trong thư mục `<directory>/<name>`:

<FileTree>

  - \<module-name>
    - \_\_init\_\_.py Module initialisation
  - tests
    - \_\_init\_\_.py Module initialisation
    - conftest.py Test configuration
    - test_noop.py Placeholder test
  - project.json Project configuration and build targets
  - pyproject.toml Packaging configuration file used by UV
  - .python-version Contains the project's Python version

</FileTree>

Bạn cũng có thể nhận thấy các tệp sau được tạo/cập nhật ở thư mục gốc của workspace của bạn:

<FileTree>

  - pyproject.toml Workspace level packaging configuration for UV
  - .python-version Contains the workspace Python version
  - uv.lock Lockfile for Python dependencies

</FileTree>

## Viết Mã nguồn Python

Thêm mã nguồn Python của bạn vào thư mục `<module-name>`.

### Import Mã Thư viện của bạn trong Các Dự án Khác

Sử dụng target `add` để thêm một dependency vào một dự án Python.

Giả sử chúng ta đã tạo hai dự án python, `my_app` và `my_lib`. Chúng sẽ có tên dự án đầy đủ là `my_scope.my_app` và `my_scope.my_lib`, và theo mặc định mỗi cái sẽ có tên module là `my_scope_my_app` và `my_scope_my_lib`.

Để `my_app` phụ thuộc vào `my_lib`, chúng ta có thể chạy lệnh sau:

<NxCommands commands={['run my_scope.my_app:add my_scope.my_lib']} />

:::note[Tên Đầy đủ]
Chúng ta sử dụng tên dự án đầy đủ cho cả dependant và dependee. Chúng ta có thể sử dụng cú pháp viết tắt cho dự án mà chúng ta muốn thêm dependency vào, nhưng phải đầy đủ tên của dự án cần phụ thuộc.
:::

Sau đó bạn có thể import mã thư viện của bạn:

```python title="packages/my_app/my_scope_my_app/main.py"
from my_scope_my_lib.my_module import my_function
```

Ở trên, `my_scope_my_lib` là tên module cho lib, `my_module` tương ứng với một tệp mã nguồn Python `my_module.py`, và `my_function` là một phương thức được định nghĩa trong tệp đó.

### Dependencies

Để thêm dependencies vào dự án của bạn, bạn có thể chạy target `add` trong dự án Python của bạn, ví dụ:

<NxCommands commands={['run my_scope.my_library:add some-pip-package']} />

Điều này sẽ thêm dependency vào tệp `pyproject.toml` của dự án của bạn, và cập nhật `uv.lock` ở thư mục gốc.

#### Mã Runtime

Khi bạn sử dụng dự án Python của bạn làm mã runtime (ví dụ như handler cho một hàm AWS lambda), bạn sẽ cần tạo một bundle của mã nguồn và tất cả các dependencies của nó. Bạn có thể đạt được điều này bằng cách thêm một target như sau vào tệp `project.json` của bạn:

```json title="project.json"
{
  ...
  "targets": {
    ...
    "bundle": {
      "cache": true,
      "inputs": ["production", "^production"],
      "executor": "nx:run-commands",
      "outputs": ["{workspaceRoot}/dist/packages/my_library/bundle"],
      "options": {
        "commands": [
          "uv export --frozen --no-dev --no-editable --project packages/my_library --package my_scope.my_library -o dist/packages/my_library/bundle/requirements.txt",
          "uv pip install -n --no-deps --no-installer-metadata --no-compile-bytecode --python-platform x86_64-manylinux_2_28 --python `uv python pin` --target dist/packages/my_library/bundle -r dist/packages/my_library/bundle/requirements.txt"
        ],
        "parallel": false
      },
      "dependsOn": ["compile"]
    },
  },
}
```

### Cài đặt

Cài đặt các dependencies Python bằng lệnh sau:

```bash
uv sync
```

### Xây dựng

Dự án Python của bạn được cấu hình với một target `build` (được định nghĩa trong `project.json`), mà bạn có thể chạy thông qua:

<NxCommands commands={['build <project-name>']} />

Trong đó `<project-name>` là tên đầy đủ của dự án của bạn.

Target `build` sẽ biên dịch, lint, kiểm tra và kiểm tra kiểu cho dự án của bạn.

Kết quả xây dựng có thể được tìm thấy trong thư mục `dist` ở thư mục gốc trong workspace của bạn, bên trong một thư mục cho package và target của bạn, ví dụ `dist/packages/<my-library>/build`

Để xây dựng tất cả các dự án trong workspace của bạn, chạy:

<NxCommands commands={['run-many --target build']} />

Hoặc sử dụng lệnh viết tắt:

<PackageManagerShortCommand commands={["build"]} />

## Kiểm tra

[pytest](https://docs.pytest.org/en/stable/) được cấu hình để kiểm tra dự án của bạn.

### Viết Các Bài kiểm tra

Các bài kiểm tra nên được viết trong thư mục `test` trong dự án của bạn, trong các tệp python có tiền tố `test_`, ví dụ:

<FileTree>
  - my_library
    - my_module.py
  - tests
    - test_my_module.py Tests for my_module.py
</FileTree>

Các bài kiểm tra là các phương thức bắt đầu bằng `test_` và thực hiện các khẳng định để xác minh kỳ vọng, ví dụ:

```python title="tests/test_my_module.py"
from my_library.my_module import say_hello

def test_say_hello():
  assert say_hello("Darth Vader") == "Hello, Darth Vader!"
```

Để biết thêm chi tiết về cách viết các bài kiểm tra, vui lòng tham khảo [tài liệu pytest](https://docs.pytest.org/en/stable/how-to/assert.html#).

### Chạy Các Bài kiểm tra

Các bài kiểm tra sẽ chạy như một phần của target `build` cho dự án của bạn, nhưng bạn cũng có thể chạy chúng riêng biệt bằng cách chạy target `test`:

<NxCommands commands={['test <project-name>']} />

Bạn có thể chạy một bài kiểm tra riêng lẻ hoặc một bộ bài kiểm tra bằng cách sử dụng cờ `-k`, chỉ định tên của tệp kiểm tra hoặc phương thức:

<NxCommands commands={["test <project-name> -k 'test_say_hello'"]} />

### Tệp Kiểm tra và Bộ nhớ đệm

Thư mục `tests` của dự án của bạn được loại trừ khỏi named input `production` trong `nx.json`.

Các target có đầu ra không thể chứa tệp kiểm tra - chẳng hạn như `compile` và bất kỳ target bundle nào - đọc `production` thay vì `default`, vì vậy việc chỉnh sửa một bài kiểm tra không làm vô hiệu hóa chúng hoặc bất kỳ tác vụ nào trong một dự án phụ thuộc vào dự án của bạn.

Việc loại trừ được giới hạn có chủ ý trong thư mục `tests`. Một tệp `test_*.py` bên trong thư mục package của bạn được coi là mã production, vì nó được đóng gói vào bản phân phối đã xây dựng của bạn, và do đó vẫn làm vô hiệu hóa bản build.

Các target `test`, `lint`, `format` và `typecheck` đọc `default` và do đó vẫn chạy lại khi bạn chỉnh sửa một bài kiểm tra. Lưu ý rằng `typecheck` cũng kiểm tra kiểu cho các bài kiểm tra của bạn, vì vậy lỗi kiểu trong một bài kiểm tra vẫn được báo cáo.

## Kiểm tra Kiểu

Các dự án Python sử dụng [ty](https://docs.astral.sh/ty/) để kiểm tra kiểu.

### Chạy Trình Kiểm tra Kiểu

Kiểm tra kiểu chạy như một phần của target `build` cho dự án của bạn, nhưng bạn cũng có thể chạy nó riêng biệt thông qua target `typecheck`:

<NxCommands commands={['run <project-name>:typecheck']} />

### Loại bỏ Lỗi Kiểu

Để loại bỏ một chẩn đoán cụ thể cho một dòng duy nhất, thêm một comment `# ty: ignore[<rule>]` ở cuối dòng, ví dụ:

```python
value: int = "not an int"  # ty: ignore[invalid-assignment]
```

Để cấu hình hành vi kiểm tra kiểu trên toàn dự án của bạn, thêm một phần `[tool.ty]` vào `pyproject.toml` của dự án của bạn. Tham khảo [tài liệu tham khảo cấu hình ty](https://docs.astral.sh/ty/reference/configuration/) để biết các tùy chọn có sẵn.

## Linting

Các dự án Python sử dụng [Ruff](https://docs.astral.sh/ruff/) để linting.

### Chạy Linter

Để gọi linter để kiểm tra dự án của bạn, bạn có thể chạy target `lint`.

<NxCommands commands={["lint <project-name>"]} />

### Sửa Các Vấn đề Lint

Phần lớn các vấn đề linting hoặc formatting có thể được sửa tự động. Bạn có thể yêu cầu Ruff sửa các vấn đề lint bằng cách chạy với tham số `--configuration=fix`.

<NxCommands commands={["lint <project-name> --configuration=fix"]} />

Tương tự, nếu bạn muốn sửa tất cả các vấn đề lint trong tất cả các package trong workspace của bạn, bạn có thể chạy:

<NxCommands commands={["run-many --target lint --all --configuration=fix"]} />

:::tip[Lệnh Viết tắt]
Điều này có một lệnh viết tắt từ thư mục gốc của workspace của bạn:

<PackageManagerShortCommand commands={["lint"]} />
:::

### Bỏ qua Các Vấn đề Lint

Để tránh các vấn đề linting làm chậm bạn trong quá trình phát triển (đặc biệt nếu bạn có các vấn đề không thể tự động sửa trong dự án của bạn), bạn có thể chạy một bản build với cấu hình `skip-lint`:

<NxCommands commands={["run-many --target build --configuration=skip-lint"]} />

Điều này vẫn sẽ chạy Ruff như một phần của bản build, nhưng target lint sẽ luôn được coi là thành công.

:::tip[Lệnh Viết tắt]
Điều này có một lệnh viết tắt từ thư mục gốc của workspace của bạn:

<PackageManagerShortCommand commands={["build:skip-lint"]} />
:::
