Tạo một dự án [Amazon Bedrock AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html). AgentCore Gateway là một điểm vào được quản lý đặt trước các MCP server hoặc agent của bạn, xác thực các yêu cầu đến (IAM hoặc Cognito) và ký lưu lượng đi đến các target của nó bằng IAM SigV4.

Tùy chọn `protocol` chọn những gì Gateway đứng trước:

- **`mcp`** (mặc định) — tổng hợp một hoặc nhiều MCP server target đằng sau một endpoint MCP duy nhất, và đánh giá mọi lời gọi tool dựa trên [Cedar policy engine](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy.html).
- **`http`** — proxy các yêu cầu trực tiếp đến [AgentCore Runtime targets](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-http-runtime.html) (các agent của bạn) thông qua định tuyến dựa trên đường dẫn (`/<targetName>/invocations`), không có tổng hợp hoặc chuyển đổi giao thức. Sử dụng điều này để đặt các agent trước một endpoint được quản lý duy nhất — ví dụ để một trang web có thể truy cập các agent được triển khai bên trong VPC thông qua Gateway.

Construct được tạo tạo ra các tài nguyên AWS sau:

- Một `AgentCore::Gateway` với xác thực IAM đến (mặc định) hoặc xác thực Cognito JWT (xem <a href="#authentication">Xác thực</a>). Gateway `mcp` được cấu hình cho giao thức MCP; gateway `http` không có loại giao thức, điều mà AgentCore yêu cầu cho các runtime target của nó

## Xác thực

Tùy chọn `auth` cấu hình cách Gateway xác thực các yêu cầu đến. Chọn giữa `iam` (mặc định) và `cognito`.

### IAM

Theo mặc định, Gateway được cấu hình với `GatewayAuthorizer.usingAwsIam()`. Các caller ký yêu cầu bằng SigV4, và danh tính IAM của caller có sẵn cho các Cedar policy dưới dạng principal `AgentCore::IamEntity`. Đây là tùy chọn được khuyến nghị khi các caller của bạn là các agent hoặc dịch vụ chạy trong AWS — ví dụ một <Link path="/guides/ts-agent">agent</Link> được kết nối qua <Link path="guides/connection/ts-agent-gateway">agent to Gateway connection generator</Link>, ký các lời gọi của nó bằng execution role riêng của nó.

### Cognito

Khi bạn chọn `cognito`, Gateway được cấu hình với Custom JWT authorizer trỏ đến một Cognito user pool. Các caller xác thực bằng cách trình bày JWT bearer token, và claim `sub` của token có sẵn cho các Cedar policy dưới dạng principal `AgentCore::OAuthUser`. Sử dụng điều này khi các caller của bạn xác thực thông qua Cognito — ví dụ một trang web hoặc một coding agent kết nối qua <Link path="guides/ts-dcr-proxy">`ts#dcr-proxy` generator</Link>.

Cơ sở hạ tầng được tạo sử dụng một Cognito user pool và client hiện có — nó không tạo chúng. Bạn có thể tạo một `UserIdentity` bằng cách sử dụng <Link path="/guides/react-website-auth">`ts#website#auth` generator</Link>, hoặc cung cấp của riêng bạn.

## Viết Policies

<OptionFilter when={{ cedarPolicy: true }} description="Cedar policies — chỉ cedarPolicy: true">

Cedar là ngôn ngữ policy được AgentCore Gateway sử dụng để ủy quyền các lời gọi tool. Mọi yêu cầu `tools/list` và `tools/call` chảy qua Gateway đều được đánh giá dựa trên tập policy đã gắn, và caller phải có ít nhất một câu lệnh `permit` khớp (và không có `forbid` khớp) để yêu cầu thành công.

Tham khảo [tài liệu AWS về AgentCore Gateway policies](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy.html) để biết tài liệu tham khảo đầy đủ, bao gồm [các mẫu policy phổ biến](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy-common-patterns.html).

### Thêm một policy

Để thêm một policy, tạo một file `.cedar` mới bên cạnh `permit-all.cedar`. Mỗi file `.cedar` trong `policies/` phải chứa chính xác **một** câu lệnh `permit` hoặc `forbid` và được triển khai dưới dạng một tài nguyên `AWS::BedrockAgentCore::Policy` duy nhất. Tên của tài nguyên policy được lấy từ tên file: `permit-all.cedar` trở thành `PermitAll` (kebab/snake-case được chuyển đổi thành PascalCase). Các file chứa nhiều câu lệnh tạo ra lỗi `unexpected token 'forbid'` tại thời điểm triển khai — tách chúng thành các file riêng biệt.

Ví dụ, để chỉ cho phép một agent role cụ thể gọi một tool cụ thể, tạo:

```cedar title="packages/<name>/policies/ts-agent-divide.cedar"
permit (
  principal == AgentCore::IamEntity::"arn:aws:sts::<%= accountId %>:assumed-role/<%= tsAgentRoleName %>",
  action == AgentCore::Action::"ts-mcp___divide",
  resource == AgentCore::Gateway::"<%= gatewayArn %>"
);
```

Truyền tên role vào dưới dạng biến template (xem <a href="#template-variables">Biến template</a> bên dưới) thay vì hard-code nó. Chạy lại synth hoặc plan để triển khai policy mới.

### Biến template

Các policy là các template [EJS](https://ejs.co/) được render tại thời điểm synth/plan để chúng có thể di chuyển được qua các tài khoản và triển khai lại Gateway:

| Biến                 | Được thay thế bằng                                  |
| -------------------- | --------------------------------------------------- |
| `<%= gatewayArn %>`  | ARN của Gateway đã triển khai                       |
| `<%= accountId %>`   | Tài khoản AWS mà Gateway này được triển khai vào    |

Luôn tham chiếu các biến này thay vì hard-code các giá trị.

### Chế độ ENFORCE và default-deny

`PolicyEngine` chạy ở chế độ `ENFORCE`, có nghĩa là ngữ nghĩa **default-deny** được áp dụng: nếu không có câu lệnh `permit` nào khớp với tuple (principal, action, resource), yêu cầu bị từ chối. Các lời gọi tool bị từ chối trả về:

```
Tool Execution Denied: Tool call not allowed due to policy enforcement
[No policy applies to the request (denied by default).]
```

Ngoài ra, Gateway lọc phản hồi của `tools/list` để các caller chỉ thấy các tool mà họ có ít nhất một `permit` khớp: nếu một agent thiếu quyền cho một tool nhất định, tool đó bị ẩn hoàn toàn thay vì xuất hiện và thất bại tại thời điểm gọi.

### `permit-all.cedar` mặc định

Generator cung cấp một policy mặc định được giới hạn theo loại xác thực của Gateway.

Đối với Gateway **IAM**, nó cho phép bất kỳ IAM caller nào từ tài khoản AWS mà Gateway được triển khai vào:

```cedar title="packages/<name>/policies/permit-all.cedar"
permit (
  principal is AgentCore::IamEntity,
  action,
  resource == AgentCore::Gateway::"<%= gatewayArn %>"
) when {
  principal.id like "arn:aws:*::<%= accountId %>:*"
};
```

Đối với Gateway **Cognito**, nó cho phép bất kỳ OAuth user đã xác thực nào (JWT authorizer đã xác thực user pool và client của token trước khi các policy được đánh giá):

```cedar title="packages/<name>/policies/permit-all.cedar"
permit (
  principal is AgentCore::OAuthUser,
  action,
  resource == AgentCore::Gateway::"<%= gatewayArn %>"
);
```

Để khóa chặt hơn, thêm các policy hẹp hơn bên cạnh nó. Luôn giữ ít nhất một `permit` khớp trong tập policy, nếu không default-deny sẽ chặn mọi lời gọi.

### Tài liệu tham khảo phạm vi policy

Loại principal phụ thuộc vào cách Gateway xác thực các caller (xem <a href="#authentication">Xác thực</a>).

Đối với Gateway **IAM**, các caller là các IAM principal:

```
principal is AgentCore::IamEntity
```

Các caller được đánh giá dưới dạng ARN assumed-role STS với tên session bị loại bỏ, vì vậy một role có thể được khớp chính xác — không cần ký tự đại diện:

```cedar
principal == AgentCore::IamEntity::"arn:aws:sts::<%= accountId %>:assumed-role/<%= myAgentRoleName %>"
```

Cùng một giá trị có sẵn dưới dạng `principal.id` cho các mệnh đề `when`. Dành `like` cho các mẫu thực sự, chẳng hạn như khớp toàn tài khoản trong `permit-all.cedar` mặc định.

Đối với Gateway **Cognito**, các caller là các OAuth user được xây dựng từ claim `sub` của JWT token, và các claim JWT (username, scope, v.v.) có sẵn dưới dạng principal tag:

```
principal is AgentCore::OAuthUser
```

Khớp các claim riêng lẻ trong các mệnh đề `when` — ví dụ để yêu cầu một scope:

```cedar
permit (
  principal is AgentCore::OAuthUser,
  action,
  resource == AgentCore::Gateway::"<%= gatewayArn %>"
) when {
  principal.scope == "gateway/invoke"
};
```

Các lời gọi tool đến policy engine dưới dạng các action với dạng:

```
AgentCore::Action::"<target-name>___<tool-name>"
```

trong đó `<target-name>` là tên Gateway target (mặc định là `mcpServerName` của MCP server khi sử dụng `gateway.addMcpServer(...)`, được lấy từ tên class của dự án MCP ở dạng kebab-case — ví dụ `TsMcp` → `ts-mcp`), `<tool-name>` là tên của MCP tool, và dấu phân cách là `___` (ba dấu gạch dưới). Cedar không hỗ trợ ký tự đại diện trên các action — khớp các action chính xác, hoặc bỏ qua `action ==` để khớp tất cả các action.

Resource luôn là chính Gateway:

```cedar
resource == AgentCore::Gateway::"<%= gatewayArn %>"
```

### Cân nhắc về xác thực

Cơ sở hạ tầng được tạo tạo các policy với `IGNORE_ALL_FINDINGS`: Cedar analyzer của AgentCore (`FAIL_ON_ANY_FINDINGS`, mặc định của dịch vụ) từ chối nhiều policy hợp lệ — ví dụ, một `forbid` vô hiệu hóa một tool duy nhất cho mọi caller bị từ chối là "Overly Restrictive", ngay cả khi được giới hạn bằng mệnh đề `when`. Việc thực thi không bị ảnh hưởng; nó được cấu hình bởi chế độ `ENFORCE` của policy engine.

Một ràng buộc về thứ tự vẫn áp dụng: một policy tham chiếu `AgentCore::Action::"<target>___<tool>"` chỉ xác thực khi target đã đăng ký tool đó với Gateway, đó là lý do tại sao cơ sở hạ tầng được tạo tạo các policy sau Gateway target.

Nếu một policy không triển khai được, CloudFormation hiển thị việc từ chối dưới dạng lỗi `Resource stabilization failed` mơ hồ — chạy `aws bedrock-agentcore-control list-policies --policy-engine-id <id>` để lấy `statusReasons` của validator, chứa lý do thực sự.

### Ví dụ: forbid một tool trong khi giữ permit rộng hơn

Ghép một `forbid` hẹp với một `permit` rộng hơn (Cedar đánh giá `forbid` trước `permit`):

```cedar title="packages/<name>/policies/forbid-divide-for-py-agent.cedar"
forbid (
  principal == AgentCore::IamEntity::"arn:aws:sts::<%= accountId %>:assumed-role/<%= pyAgentRoleName %>",
  action == AgentCore::Action::"ts-mcp___divide",
  resource == AgentCore::Gateway::"<%= gatewayArn %>"
);
```

Điều này từ chối Python agent role gọi `ts-mcp___divide` trong khi để `permit-all.cedar` rộng hơn tại chỗ cho tất cả các caller khác.

## Triển khai AgentCore Gateway của bạn

AgentCore Gateway generator tạo mã cơ sở hạ tầng CDK hoặc Terraform dựa trên `iac` đã chọn của bạn. Bạn có thể sử dụng điều này để triển khai Gateway của bạn.

```ts {7} title="packages/infra/src/stacks/application-stack.ts"
import { MyGateway } from '@my-scope/common-constructs';

}
```

Điều này thiết lập cơ sở hạ tầng Gateway của bạn, bao gồm `AgentCore::Gateway`, Cedar `PolicyEngine` của nó, và AWS WAF Web ACL (xem [AWS WAF](#aws-waf) bên dưới). Đăng ký các MCP server target với `gateway.addMcpServer(...)` — xem <Link path="guides/connection/agentcore-gateway-mcp">hướng dẫn kết nối MCP server</Link>.
</Fragment>
<Fragment slot="terraform">
Terraform module để triển khai Gateway của bạn nằm trong thư mục `common/terraform`. Bạn có thể sử dụng điều này trong một cấu hình Terraform, ví dụ:

```hcl title="packages/infra/src/main.tf"
module "my_gateway" {
  source = "../../common/terraform/src/app/gateways/my-gateway"
}
```

Điều này thiết lập cơ sở hạ tầng Gateway của bạn, bao gồm `aws_bedrockagentcore_gateway`, Cedar policy engine của nó, và AWS WAF Web ACL (xem [AWS WAF](#aws-waf) bên dưới). Đăng ký các MCP server target với một tài nguyên `aws_bedrockagentcore_gateway_target` — xem <Link path="guides/connection/agentcore-gateway-mcp">hướng dẫn kết nối MCP server</Link>.
</Fragment>
</Infrastructure>

### AWS WAF

Theo mặc định, construct được tạo liên kết một [AWS WAFv2](https://docs.aws.amazon.com/waf/latest/developerguide/waf-chapter.html) Web ACL với Gateway. AWS WAF kiểm tra mọi yêu cầu đến inline _trước khi_ nó đến target, bảo vệ Gateway của bạn khỏi các khai thác web, lưu lượng bot và các cuộc tấn công volumetric. Web ACL sử dụng bộ quy tắc mặc định được quản lý bởi AWS ([`AWSManagedRulesCommonRuleSet`](https://docs.aws.amazon.com/waf/latest/developerguide/aws-managed-rule-groups-baseline.html#aws-managed-rule-groups-baseline-crs) và [`AWSManagedRulesKnownBadInputsRuleSet`](https://docs.aws.amazon.com/waf/latest/developerguide/aws-managed-rule-groups-baseline.html#aws-managed-rule-groups-baseline-known-bad-inputs)), cung cấp bảo vệ chống lại các khai thác web phổ biến bao gồm OWASP Top 10. Log yêu cầu WAF được ghi vào một CloudWatch Logs group.

Web ACL là `REGIONAL` và được tạo trong region của Gateway, như yêu cầu cho các liên kết AgentCore Gateway.

:::caution[Sai lệch SizeRestrictions_BODY so với mặc định]
Quy tắc `SizeRestrictions_BODY` từ `AWSManagedRulesCommonRuleSet` được ghi đè thành `Count` thay vì `Block`, vì giới hạn 8 KB của quy tắc quá hạn chế cho các payload tool MCP điển hình. Các yêu cầu quá khổ vẫn sẽ được ghi lại dưới dạng metric để bạn có thể giám sát chúng. Xem hướng dẫn [AWS WAF body size limits](https://docs.aws.amazon.com/waf/latest/developerguide/waf-rule-statement-oversize-handling.html) để biết thêm chi tiết.
:::

Bạn có thể chỉnh sửa Gateway construct được tạo để thêm, xóa hoặc điều chỉnh các quy tắc (ví dụ, để thêm [rate-based rules](https://docs.aws.amazon.com/waf/latest/developerguide/waf-rule-statement-type-rate-based.html) hoặc các nhóm quy tắc được quản lý bổ sung).

<Infrastructure>
<Fragment slot="cdk">
Để từ chối (ví dụ, để gắn Web ACL của riêng bạn), đặt `enableWaf` thành `false` khi bạn khởi tạo Gateway construct:

```ts {2}
new MyGateway(this, 'MyGateway', {
  enableWaf: false,
});
```

Construct hiển thị Web ACL đã tạo dưới dạng `webAcl` để cấu hình thêm.
</Fragment>
<Fragment slot="terraform">
Để từ chối (ví dụ, để gắn Web ACL của riêng bạn), đặt `enable_waf` thành `false` trên Gateway module:

```hcl {2}
module "my_gateway" {
  enable_waf = false
}
```

Module xuất ARN của Web ACL đã tạo dưới dạng `waf_web_acl_arn` để cấu hình thêm.
</Fragment>
</Infrastructure>
