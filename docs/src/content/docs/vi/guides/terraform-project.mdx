[Terraform](https://www.terraform.io/) là một công cụ phần mềm mã nguồn mở cho infrastructure as code, cho phép bạn tạo, thay đổi và cải thiện hạ tầng một cách an toàn và dự đoán được.

Trình tạo hạ tầng Terraform tạo ra một dự án hạ tầng Terraform. Ứng dụng được tạo ra bao gồm các phương pháp bảo mật tốt nhất thông qua kiểm tra bảo mật [Checkov](https://www.checkov.io/).

## Kết quả của Trình tạo

Trình tạo tạo ra các cấu trúc tệp khác nhau tùy thuộc vào loại dự án:

<OptionFilter when={{ type: 'application' }} description="Application type: full Terraform app with remote state management">
### Loại Application

Đối với các dự án application (`--type=application`), trình tạo tạo ra một ứng dụng Terraform hoàn chỉnh với quản lý trạng thái từ xa:

<FileTree>

  - src
    - main.tf Tệp cấu hình Terraform chính
    - providers.tf Cấu hình Provider với S3 backend
    - variables.tf Định nghĩa biến đầu vào
    - outputs.tf Định nghĩa giá trị đầu ra
    - env Tệp biến cụ thể cho môi trường
      - dev.tfvars Biến môi trường Development
  - bootstrap Cấu hình Bootstrap cho trạng thái từ xa
    - main.tf S3 bucket và policies cho lưu trữ state
    - providers.tf Cấu hình AWS provider
    - variables.tf Định nghĩa biến Bootstrap
  - scripts Node helpers chạy bởi các target nx `bootstrap` và `init`
    - aws-config.ts Phân giải account + region thông qua chuỗi thông tin xác thực AWS SDK
    - bootstrap.ts Pull/push bootstrap tfstate và chạy `terraform apply`
    - init.ts Chạy `terraform init` với cấu hình S3 backend
  - project.json Cấu hình dự án và build targets

</FileTree>


:::note[Shared Terraform Modules]
Trình tạo cũng tạo ra một thư viện `packages/common/terraform` ban đầu chỉ thêm một module metrics (tạo một Cloudformation stack trống với metadata) được tự động đo lường để nhóm `nx-plugin-for-aws` có thể theo dõi số liệu sử dụng.
:::
</OptionFilter>

<OptionFilter when={{ type: 'library' }} description="Library type: simpler layout for reusable Terraform modules">
### Loại Library

Đối với các dự án library (`--type=library`), trình tạo tạo ra một cấu trúc đơn giản hơn cho các module Terraform có thể tái sử dụng:

<FileTree>

  - src
    - main.tf Tệp module Terraform chính
  - project.json Cấu hình dự án và build targets

</FileTree>
</OptionFilter>

:::tip[Application vs Library]
Các dự án Application bao gồm khả năng triển khai đầy đủ với quản lý trạng thái từ xa, trong khi các dự án library được thiết kế để tạo các module Terraform có thể tái sử dụng mà các dự án khác có thể sử dụng.
:::

## Triển khai Hạ tầng Terraform của bạn

Bạn có thể bắt đầu viết hạ tầng Terraform của mình bên trong `src/main.tf`, ví dụ:

```diff title="src/main.tf" {16-19}
-locals {
-  account_id = data.aws_caller_identity.current.account_id
-  aws_region = data.aws_region.current.id
-}
-
-resource "null_resource" "print_info" {
-  # triggers = {
-  #   always_run = timestamp()
-  # }
-
-  provisioner "local-exec" {
-    command = "echo 'AWS Region: ${local.aws_region}, AWS Account: ${local.account_id}, Environment: ${var.environment}'"
-  }
-}
+
+# Declare your infrastructure here
+resource "aws_s3_bucket" "my_bucket" {
+  bucket = "my-unique-bucket-name"
+}
```

### Phụ thuộc giữa các dự án

Nếu bạn muốn thực thi một module từ một dự án riêng biệt (lib), bạn có thể làm như sau:

```
module "lib_module" {
  source = "../../path/to/my-lib/src"
}
```

Điều này sẽ tự động cập nhật đồ thị Nx để thêm phụ thuộc giữa ứng dụng sử dụng của bạn và lib của bạn.

### Cấu hình Môi trường

Cấu hình các biến cụ thể cho môi trường trong các tệp `src/env/*.tfvars`.

Để thêm môi trường mới, tạo một tệp `src/env/<environment>.tfvars` mới với các biến cụ thể cho môi trường và thêm các mục mới cho `apply, destroy, init, plan` trong `project.json` cho cấu hình env mới. Ví dụ, giả sử chúng ta muốn thêm một env `prod`:

<Tabs>
<TabItem label="src/env/prod.tfvars">
```hcl
# Production environment variables
environment = "prod"
region      = "us-west-2"
```
</TabItem>
<TabItem label="project.json">

:::tip[Default Environment]
Theo mặc định, tất cả các target giả định môi trường `dev`, tuy nhiên bạn có thể nhắm đến một môi trường cụ thể như sau: <NxCommands commands={['apply tf-infra --configuration=prod']} />

Bạn cũng có thể chuyển đổi môi trường bất cứ lúc nào vì state tự động phân đoạn tfstate giữa các môi trường.
:::

### Bootstrap Trạng thái Từ xa (Chỉ Dự án Application)

Trước khi triển khai hạ tầng của bạn, bạn sẽ cần bootstrap backend trạng thái từ xa. Điều này tạo ra một S3 bucket để lưu trữ các tệp trạng thái Terraform của bạn:

<NxCommands commands={['bootstrap tf-infra']} />

:::note[AWS Profile Configuration]
Đảm bảo AWS CLI profile của bạn được cấu hình cho account/region mà bạn muốn triển khai các tài nguyên bootstrap vào.

Target bootstrap chỉ khả dụng cho các dự án loại application. Các dự án Library không yêu cầu quản lý trạng thái từ xa vì chúng được thiết kế để trở thành các module có thể tái sử dụng.
:::
</OptionFilter>

## Các Target Khả dụng

Các target khả dụng phụ thuộc vào loại dự án của bạn:

### Các Target Chung (Cả Application và Library)

#### Xác thực Hạ tầng của bạn

Bạn có thể xác thực cấu hình Terraform của mình bằng cách sử dụng target `validate`:

<NxCommands commands={['validate tf-infra']} />

#### Định dạng Code của bạn

Định dạng code Terraform của bạn bằng cách sử dụng target `fmt`:

<NxCommands commands={['fmt tf-infra']} />

#### Kiểm tra Bảo mật

Chạy kiểm tra bảo mật trên hạ tầng của bạn bằng cách sử dụng Checkov với target `test`:

<NxCommands commands={['test tf-infra']} />

Bạn sẽ tìm thấy kết quả kiểm tra bảo mật của mình trong thư mục `dist` gốc, dưới `dist/packages/<my-terraform-project>/checkov`.

<OptionFilter when={{ type: 'application' }} description="Application-only targets: plan / apply / destroy / etc.">
### Các Target Chỉ dành cho Application

Các target sau chỉ khả dụng cho các dự án loại application:

#### Lập kế hoạch Hạ tầng của bạn

Trước khi áp dụng các thay đổi, bạn có thể xem Terraform sẽ làm gì bằng cách chạy target `plan`:

<NxCommands commands={['plan tf-infra']} />

Điều này sẽ tạo một tệp plan trong `dist/packages/<my-terraform-project>/terraform/dev.tfplan`.

#### Khởi tạo Terraform

Khởi tạo thư mục làm việc Terraform của bạn với target `init`:

<NxCommands commands={['run tf-infra:init']} />

#### Triển khai lên AWS

Sau khi lập kế hoạch, bạn có thể triển khai hạ tầng của mình lên AWS bằng cách sử dụng target `apply`:

<NxCommands commands={['apply tf-infra']} />

:::tip[Auto-Approve]
Lệnh trên áp dụng plan được tạo bởi target `plan`. Đảm bảo chạy `plan` trước để xem xét các thay đổi.
:::

:::note[Deploy Alias]
Một target `deploy` cũng khả dụng như một bí danh cho `apply`. Bạn có thể sử dụng <NxCommands commands={['deploy tf-infra']} /> hoặc <NxCommands commands={['apply tf-infra']} /> thay thế cho nhau.
:::

#### Lấy Outputs

Truy xuất các giá trị output từ cấu hình Terraform của bạn:

<NxCommands commands={['output tf-infra']} />

#### Hủy Hạ tầng

Khi bạn cần phá bỏ hạ tầng của mình, sử dụng target `destroy`:

<NxCommands commands={['destroy tf-infra']} />

:::caution[Destructive Operation]
Điều này sẽ xóa vĩnh viễn tất cả các tài nguyên được quản lý bởi cấu hình Terraform này. Sử dụng cẩn thận!
:::

#### Hủy Tài nguyên Bootstrap

Để dọn dẹp các tài nguyên bootstrap (S3 bucket cho lưu trữ state):

<NxCommands commands={['bootstrap-destroy tf-infra']} />
</OptionFilter>
