Generator này thêm một dịch vụ HTTP được đóng gói container vào dự án TypeScript hiện có. Bạn sẽ có một HTTP server nhỏ với route `GET /health`, một Dockerfile, và các target để chạy server cục bộ, build image và quét image. Bạn cũng nhận được mã CDK hoặc Terraform chạy image trên [Amazon Elastic Container Service (Amazon ECS)](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/Welcome.html), dịch vụ AWS chạy và mở rộng quy mô container.

Dịch vụ chạy trên [AWS Fargate](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/AWS_Fargate.html), chạy mỗi container mà không cần server để bạn quản lý. Nó chạy trong VPC của riêng bạn (virtual private cloud, một mạng cô lập trong tài khoản AWS của bạn), đằng sau một [Application Load Balancer](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html) (ALB) nội bộ mà chỉ các địa chỉ bên trong VPC mới có thể truy cập. Theo mặc định, một [Amazon API Gateway HTTP API](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api.html) nhận yêu cầu từ người gọi và chuyển chúng đến ALB thông qua VPC link (kết nối riêng tư của API Gateway vào VPC). Người gọi nhận được một endpoint HTTPS được xác thực, và load balancer không bao giờ đối mặt với internet.

## Đầu ra của Generator

Generator thêm các file sau vào dự án của bạn. Thư mục nguồn được đặt tên theo tùy chọn `name`, hoặc `service` nếu bạn bỏ qua nó:

<FileTree>
  - your-project/
    - src/
      - service/ (hoặc tên bạn đã chọn)
        - server.ts HTTP routes: `GET /health` và route mẫu `GET /hello`
        - index.ts Entry point đọc `PORT` và khởi động server. Bundle và target `<name>-serve` bắt đầu từ file này
        - Dockerfile Định nghĩa container image
        - .dockerignore Các file bị bỏ qua khỏi build context của image
    - rolldown.config.ts Được cập nhật với bundle entry cho `index.ts`
    - project.json Được cập nhật với target `bundle` và các target `<name>-serve`, `<name>-docker` và `<name>-trivy` cho dịch vụ của bạn
</FileTree>

Tên target bắt đầu bằng tùy chọn `name`, hoặc bằng `service` nếu bạn bỏ qua nó. Ví dụ, các target là `service-serve`, `service-docker` và `service-trivy` khi không có tên, và `orders-serve`, `orders-docker` và `orders-trivy` cho `--name=orders`. Target `bundle` được chia sẻ bởi mọi entry point được bundle trong dự án.

## Chạy Dịch vụ của Bạn Cục bộ

Target `<name>-serve` chạy server trên máy của bạn, không có container:

<NxCommands commands={['run your-project:service-serve']} />

Server lắng nghe trên cổng trong biến môi trường `PORT`. Target `<name>-serve` đặt nó thành một cổng mà generator chỉ định, bắt đầu từ 8081 và bỏ qua các cổng mà các dự án khác trong workspace của bạn đã sử dụng. Bên trong container, server lắng nghe trên cổng 8080.

Kiểm tra xem server đã hoạt động chưa với health route của nó, trả về status 200 và `{"status":"ok"}`:

```bash
curl http://localhost:<port>/health
```

Server cũng có một route mẫu mà bạn thay thế bằng các route của riêng bạn. `GET /hello?name=<x>` trả về `{"message":"Hello, <x>!"}`, và `name` mặc định là `world`. Bất kỳ đường dẫn nào khác trả về status 404.

## Build và Quét Image

Target `<name>-docker` build một linux/arm64 image của dịch vụ của bạn. Nó chạy target `bundle` trước, vì vậy image chứa server đã được bundle. Sau đó nó sao chép `Dockerfile` và `.dockerignore` vào thư mục đầu ra bundle, `dist/<project root>/bundle/container/<name>`, và build image với thư mục đó làm build context (các file mà image build có thể đọc). Nó sử dụng container engine mà workspace của bạn được thiết lập, `docker` hoặc [Finch](https://runfinch.com/). Target chạy như một phần của target tổng hợp `docker`, build mọi image trong dự án.

<NxCommands commands={['run your-project:service-docker']} />

Chỉ target group của load balancer (danh sách các task mà load balancer gửi yêu cầu đến) kiểm tra `GET /health`, để quyết định xem một task đã sẵn sàng cho traffic chưa. ECS bỏ qua chỉ thị `HEALTHCHECK` trong Dockerfile. Để biết thêm về cách image được build và xuất bản, xem <Link path="/guides/docker-bundling">Docker Bundling</Link>.

## Triển khai Dịch vụ của Bạn

### Thêm Dịch vụ vào Infrastructure của Bạn

Construct và module không bao giờ tạo VPC. Bạn tạo hoặc import một VPC trong stack hoặc root module của bạn và truyền nó vào. Các task và load balancer chạy trong private subnet với egress, tiếp cận các dịch vụ AWS thông qua NAT gateway (một gateway được quản lý cho phép private subnet thực hiện kết nối outbound) hoặc thông qua VPC endpoint (kết nối riêng tư từ VPC của bạn đến các dịch vụ AWS).

<Infrastructure>
<Fragment slot="cdk">
CDK construct được tạo trong `common/constructs` và được đặt tên theo dịch vụ của bạn. Ví dụ sử dụng với VPC mới:

```ts title="packages/infra/src/stacks/application-stack.ts"
import { MyService } from '@my-scope/common-constructs';
import { Stack, StackProps } from 'aws-cdk-lib';
import { SubnetType, Vpc } from 'aws-cdk-lib/aws-ec2';
import { Construct } from 'constructs';

export class ApplicationStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props);

    const vpc = new Vpc(this, 'Vpc', { natGateways: 1 });

    new MyService(this, 'MyService', {
      vpc,
      vpcSubnets: { subnetType: SubnetType.PRIVATE_WITH_EGRESS },
    });
  }
}
```

Để sử dụng VPC hiện có, tra cứu nó với `Vpc.fromLookup(this, 'Vpc', { vpcId: '<vpc-id>' })` và truyền nó làm `vpc`.
</Fragment>

Image của dịch vụ được xuất bản vào shared asset repository, vì vậy hãy khởi tạo module `core/asset-ecr` một lần cho mỗi deployment và truyền đầu ra của nó cho mọi service module. Cũng truyền đầu ra của shared `runtime_config_appconfig` module, chứa ứng dụng AWS AppConfig mà dịch vụ đọc <Link path="/guides/runtime-config">runtime configuration</Link> của nó từ đó:

  asset_ecr_repository_url = module.asset_ecr.repository_url
  asset_ecr_repository_arn = module.asset_ecr.repository_arn

### Giới hạn Yêu cầu

API Gateway ngừng chờ dịch vụ của bạn sau 30 giây và trả về lỗi cho người gọi. Bạn không thể tăng integration timeout này. Payload yêu cầu lớn nhất mà HTTP API chấp nhận là 10 MB, và bạn cũng không thể tăng giới hạn này. Cả hai giá trị đều đến từ trang [Amazon API Gateway quotas for HTTP APIs](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-quotas.html).

Vì vậy, các yêu cầu chạy lâu hơn 30 giây và các phản hồi stream dữ liệu trong thời gian dài không hoạt động thông qua HTTP API. Đối với những trường hợp đó, hãy đặt `ingress` thành `private` và gọi internal load balancer từ bên trong VPC.
</OptionFilter>

### Chạy Không có NAT Gateway

Khi các task của bạn khởi động, ECS pull image và gửi log thay mặt cho chúng. Mã server của bạn cũng có thể gọi các dịch vụ AWS. Trong private subnet không có NAT gateway, mỗi lệnh gọi này cần một VPC endpoint. Không có endpoint phù hợp, các task sẽ không khởi động được hoặc timeout khi chúng gọi AWS.

Tạo các endpoint này trong VPC, thay thế `<region>` bằng AWS Region của bạn:

| Endpoint | Loại | Cái gì sử dụng nó |
| --- | --- | --- |
| `com.amazonaws.<region>.ecr.api` | Interface | ECS, để xác thực với Amazon ECR và tra cứu image |
| `com.amazonaws.<region>.ecr.dkr` | Interface | ECS, để pull image từ Amazon ECR |
| `com.amazonaws.<region>.s3` | Gateway | ECS, để tải xuống các image layer, mà Amazon ECR lưu trữ trong Amazon S3 |
| `com.amazonaws.<region>.logs` | Interface | Đầu ra log của container, được gửi đến Amazon CloudWatch Logs |
| `com.amazonaws.<region>.secretsmanager` | Interface | ECS, để đọc các secret bạn truyền vào container khi một task khởi động |
| `com.amazonaws.<region>.appconfigdata` | Interface | Mã của bạn, để đọc <Link path="/guides/runtime-config">runtime configuration</Link> từ AWS AppConfig |
| `com.amazonaws.<region>.sts` | Interface | Mã của bạn, khi nó yêu cầu temporary credential từ AWS STS (ví dụ để assume một role khác) |

Interface endpoint cần một security group cho phép HTTPS (cổng 443) từ các task. Để biết chi tiết về các Amazon ECR endpoint, xem [Amazon ECR interface VPC endpoints](https://docs.aws.amazon.com/AmazonECR/latest/userguide/vpc-endpoints.html).

### Mặc định Bảo mật

Infrastructure được tạo áp dụng các cài đặt này theo mặc định:

- Load balancer là nội bộ. Không có security group nào cho phép inbound traffic từ `0.0.0.0/0` hoặc `::/0`.
- Các task chạy trong private subnet và không bao giờ nhận địa chỉ IP công khai.
- Load balancer chỉ chấp nhận traffic từ VPC link (`http-api`) hoặc từ dải địa chỉ của VPC (`private`). Các task chỉ chấp nhận traffic từ load balancer, trên container port.
- Các task chỉ có thể gửi outbound traffic trên cổng 443. Kết nối đến database thêm database port.
- Task role (role mà mã server của bạn chạy với) chỉ có thể đọc runtime configuration từ AWS AppConfig cho đến khi bạn hoặc một kết nối cấp thêm.
- Execution role (role mà ECS sử dụng để khởi động task của bạn) chỉ có thể pull image của dịch vụ, ghi vào log group của nó và đọc các secret bạn liệt kê.
- Các secret chỉ đến container dưới dạng tham chiếu đến AWS Secrets Manager hoặc AWS Systems Manager Parameter Store, không bao giờ là giá trị môi trường thuần túy.
- Container có hệ thống file gốc chỉ đọc và chạy với uid 1000, một người dùng không phải root. ECS Exec (truy cập shell vào một task đang chạy) bị tắt.
- Một deployment thất bại health check sẽ dừng và rollback về phiên bản trước đó.
- HTTP API ghi access log và throttle yêu cầu. Nó xác thực với IAM trừ khi bạn chọn cách khác.
- Log được giữ trong một năm.

Mã được tạo bỏ qua các kiểm tra [Checkov](https://www.checkov.io/) này (Checkov quét mã infrastructure để tìm cài đặt không an toàn), và nêu lý do bên cạnh mỗi suppression:

- `CKV_AWS_91` yêu cầu load balancer access log. HTTP API access log, hoặc log của chính dịch vụ của bạn, ghi lại các yêu cầu thay thế.
- `CKV_AWS_2` và `CKV_AWS_103` yêu cầu HTTPS listener với TLS. Load balancer lắng nghe trên HTTP thuần túy vì nó là nội bộ và chỉ người gọi bên trong VPC mới có thể truy cập nó. Với `http-api`, TLS kết thúc tại API Gateway.

Terraform module cũng bỏ qua `CKV2_AWS_20` và `CKV_AWS_378` vì cùng lý do HTTP listener, và `CKV_AWS_150` vì load balancer deletion protection bị tắt để dịch vụ có thể bị hủy.

### Gọi Dịch vụ của Bạn

URL của dịch vụ được ghi vào <Link path="/guides/runtime-config">runtime configuration</Link> dưới dạng `connection.services.<NameClassName>`, trong đó `<NameClassName>` là tên dịch vụ ở dạng PascalCase. Đối với `--name=orders`, key là `Orders`. Không có tên, tên dịch vụ là `<project>-service`, vì vậy đối với dự án có tên `my-project`, key là `MyProjectService`. Thư mục nguồn và tiền tố target vẫn là `service` trong trường hợp đó.

### Cấu hình Nâng cao

Dịch vụ được tạo đặt tên, `ingress` và `auth` của nó cho bạn. Các ví dụ dưới đây sử dụng construct `EcsService` generic và module `ecs-service` trực tiếp, cho các cài đặt mà dịch vụ được tạo không truyền hoặc để chọn `ingress` và `auth` cho mỗi instance.

Trong CDK, package `common-constructs` của bạn xuất `EcsService` bên cạnh construct của dịch vụ của bạn, vì vậy bạn import nó theo cùng một cách: `import { EcsService } from '@my-scope/common-constructs'`. Construct được tạo mở rộng `EcsService` và truyền mọi prop khác qua, ví dụ `cluster`, `loadBalancer`, `environment`, `secrets` và `grantTaskRole`. Prop `image` tùy chọn của nó thay thế image được build từ dự án của bạn. Nó không có prop `auth`. Dịch vụ Cognito nhận `identity` thay thế, và các dịch vụ khác luôn sử dụng `auth` mà chúng được tạo với.

Trong Terraform, module của dịch vụ của bạn chỉ cho phép bạn đặt một số biến của module `ecs-service`: `vpc_id`, `subnet_ids`, `cluster_arn`, `environment`, `secrets`, `task_role_policy_statements` và `tags`, cộng với `user_pool_id` và `user_pool_client_ids` cho dịch vụ Cognito. Để đặt bất kỳ biến nào khác, hãy chỉnh sửa block `module "ecs_service"` trong module của dịch vụ của bạn.

#### Image Được Build Sẵn

Để chạy một image đã được build, ví dụ từ registry công khai, hãy truyền URI của nó. Không có gì được build cục bộ. Đối với image trong Amazon ECR repository riêng tư, CDK cấp quyền pull access cho execution role trên repository đó. Terraform chỉ cấp quyền pull access khi bạn cũng truyền ARN của repository dưới dạng `image_repository_arn`.

<Infrastructure>
<Fragment slot="cdk">

```ts
new EcsService(this, 'Prebuilt', {
  serviceName: 'Prebuilt',
  vpc,
  image: { imageUri: 'public.ecr.aws/my-org/my-image@sha256:<digest>' },
});
```

</Fragment>
<Fragment slot="terraform">

```hcl
module "prebuilt" {
  source = "../../common/terraform/src/core/container/ecs-service"

  service_name = "Prebuilt"
  vpc_id       = aws_vpc.main.id
  subnet_ids   = aws_subnet.private[*].id
  image_uri    = "public.ecr.aws/my-org/my-image@sha256:<digest>"
  # For an image in a private Amazon ECR repository, also pass:
  # image_repository_arn = aws_ecr_repository.my_image.arn
}
```

</Fragment>
</Infrastructure>

#### Kích thước và Mở rộng

Mỗi task nhận 256 CPU unit (một phần tư vCPU) và 512 MiB bộ nhớ theo mặc định. Dịch vụ khởi động một task, và autoscaling giữ từ một đến hai task đang chạy, thêm task khi mức sử dụng CPU trung bình vượt quá 70%.

| Cài đặt | CDK prop | Terraform variable | Mặc định |
| --- | --- | --- | --- |
| CPU unit mỗi task | `cpu` | `cpu` | 256 |
| Bộ nhớ mỗi task (MiB) | `memoryLimitMiB` | `memory` | 512 |
| Task khi khởi động | `desiredCount` | `desired_count` | 1 |
| Ít task nhất | `minCapacity` | `min_capacity` | 1 |
| Nhiều task nhất | `maxCapacity` | `max_capacity` | 2 |
| CPU trung bình mục tiêu (%) | `targetCpuUtilizationPercent` | `target_cpu_utilization` | 70 |

Task role của construct hoặc module dịch vụ của bạn bắt đầu chỉ với quyền đọc runtime configuration. Thêm các quyền mà mã của bạn cần:

#### Container User

Task definition chạy container với uid 1000, một người dùng không phải root. Điều này khớp với user `node` mà Dockerfile được cung cấp đặt. Để chạy với user khác, hãy đặt CDK prop `user` hoặc Terraform variable `container_user`. Terraform từ chối `0` và `root`.

| Cài đặt | CDK prop | Terraform variable | Mặc định |
| --- | --- | --- | --- |
| User mà container chạy với | `user` | `container_user` | `'1000'` (CDK), `"1000:1000"` (Terraform) |

#### CORS và Throttling

Các cài đặt này chỉ áp dụng khi `ingress` được đặt thành `http-api`. CORS (cross-origin resource sharing) quyết định website nào có thể gọi dịch vụ của bạn từ trình duyệt. Theo mặc định, HTTP API chấp nhận yêu cầu trình duyệt từ bất kỳ origin nào, với bất kỳ method nào, và với các header `authorization`, `content-type`, `x-amz-content-sha256`, `x-amz-date` và `x-amz-security-token`. Ba header cuối cùng là các header mà chữ ký SigV4 thêm vào. HTTP API cũng throttle yêu cầu đến tốc độ ổn định 10.000 mỗi giây, với burst lên đến 5.000.

| Cài đặt | CDK | Terraform variable | Mặc định |
| --- | --- | --- | --- |
| CORS origin được cho phép | method `restrictCorsTo(...origins)`, hoặc prop `corsPreflight` | `cors_allow_origins` | bất kỳ origin nào (`["*"]`) |
| Cài đặt CORS khác | prop `corsPreflight` | none | bất kỳ method nào, và các header ở trên |
| Throttling | prop `throttle` | none | `{ rateLimit: 10000, burstLimit: 5000 }` |

Prop `corsPreflight` thay thế toàn bộ mặc định, vì vậy hãy liệt kê mọi header mà người gọi của bạn gửi. Method `restrictCorsTo` giữ các cài đặt CORS khác và chỉ thay đổi các origin được cho phép:

```ts
const service = new MyService(this, 'MyService', { vpc });
service.restrictCorsTo('https://app.example.com');
```

Trong Terraform, `cors_allow_origins` và `container_user` là các biến của module `ecs-service`. Module của dịch vụ của bạn không truyền chúng, vì vậy hãy đặt chúng trong block `module "ecs_service"` của nó. Các giá trị throttling được cố định trong `ecs-service.tf`.

### Chi phí

Container service tính phí khi nó nhàn rỗi, không giống như Lambda function. Các phần này tính phí theo giờ cho dù có ai gọi dịch vụ hay không:

- Fargate task, mỗi vCPU và mỗi GB bộ nhớ. `desiredCount` và `minCapacity` giữ ít nhất một task đang chạy.
- Application Load Balancer, mỗi giờ và mỗi load balancer capacity unit.
- Interface VPC endpoint, mỗi giờ trong mỗi Availability Zone, hoặc NAT gateway, mỗi giờ và mỗi GB dữ liệu nó xử lý.
- Lưu trữ log trong CloudWatch Logs, và lưu trữ image trong Amazon ECR.

HTTP API tính phí mỗi yêu cầu. Để ước tính chi phí cho Region và traffic của bạn, hãy sử dụng [AWS Pricing Calculator](https://calculator.aws/).
