Trình tạo `connection` cho phép một <Link path="guides/ts-container">dịch vụ container TypeScript</Link> sử dụng một dự án <Link path="guides/ts-dynamodb">TypeScript DynamoDB</Link>. Nó cấu hình phát triển cục bộ để dịch vụ và DynamoDB Local khởi động cùng nhau, và in ra các quyền mà dịch vụ cần.

## Cách hoạt động

Một dịch vụ container với `infra=ecs` chạy dưới dạng các tác vụ trên Amazon ECS (Elastic Container Service). Mỗi tác vụ chạy với vai trò tác vụ của dịch vụ, một vai trò IAM chỉ có thể đọc cấu hình thời gian chạy cho đến khi bạn cấp thêm quyền. Để đọc và ghi bảng, vai trò tác vụ cần các hành động DynamoDB trên bảng và các chỉ mục của nó, và sử dụng khóa mã hóa AWS KMS của bảng.

Trình tạo từ chối một dịch vụ với `infra=none`, vì dịch vụ như vậy không có vai trò tác vụ để cấp quyền truy cập.

## Điều kiện tiên quyết

Trước khi sử dụng trình tạo này, hãy đảm bảo bạn có:

1. Một dịch vụ container với `infra=ecs` (được tạo bằng trình tạo <Link path="guides/ts-container">`ts#container`</Link>)
2. Một dự án <Link path="guides/ts-dynamodb">`ts#dynamodb`</Link>

## Kết quả của Trình tạo

Trình tạo cập nhật mục tiêu `<service-name>-serve` của dịch vụ trong `project.json` để phụ thuộc vào mục tiêu `dev` của dự án DynamoDB. Không có tệp nguồn nào được sửa đổi.

## Sử dụng DynamoDB trong Dịch vụ

Import các factory thực thể từ gói DynamoDB và sử dụng chúng ở nơi bạn xử lý một yêu cầu:

```ts title="packages/my-project/src/my-service/examples.ts"
import { createExampleEntity } from '@my-scope/my-table';

export const listExamples = async () => {
  const entity = await createExampleEntity();
  const result = await entity.scan.go();
  return result.data;
};
```

## Cơ sở hạ tầng

Trình tạo không thay đổi stack hoặc mô-đun Terraform gốc của bạn. Thay vào đó, nó in ra mã cần thêm, được hiển thị bên dưới cho một dịch vụ có tên `my-service` và một bảng có tên `my-table`. Cho đến khi bạn thêm nó, các yêu cầu của dịch vụ đến bảng sẽ bị từ chối.

<Infrastructure>
<Fragment slot="cdk">

Trong ví dụ, `myService` là construct `MyService` của bạn và `myTable` là construct `MyTable` của bạn:

```ts title="packages/infra/src/stacks/application-stack.ts"
myTable.grantReadWriteData(myService.taskRole);
```

`grantReadWriteData` cấp cả quyền DynamoDB và KMS cho vai trò tác vụ của dịch vụ.

Trong ví dụ, `module "my_service"` triển khai dịch vụ và `module "my_table"` triển khai bảng:

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_role_policy" "my_service_my_table_access" {
  name = "my-service-my-table-access"
  role = module.my_service.task_role_name

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Action = [
          "dynamodb:GetItem", "dynamodb:PutItem", "dynamodb:UpdateItem",
          "dynamodb:DeleteItem", "dynamodb:Query", "dynamodb:Scan",
          "dynamodb:BatchGetItem", "dynamodb:BatchWriteItem",
        ]
        Resource = [
          module.my_table.table_arn,
          "${module.my_table.table_arn}/index/*",
        ]
      },
      {
        Effect = "Allow"
        Action = [
          "kms:Encrypt",
          "kms:Decrypt",
          "kms:ReEncrypt*",
          "kms:GenerateDataKey*",
          "kms:DescribeKey",
        ]
        Resource = [module.my_table.kms_key_arn]
      },
    ]
  })
}
```
