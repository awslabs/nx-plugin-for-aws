Generator `connection` có thể kết nối <Link path="guides/ts-agent">TypeScript Agent</Link> của bạn với <Link path="guides/agentcore-gateway">AgentCore Gateway</Link>.

Generator này kết nối agent để nó xác thực với Gateway bằng IAM SigV4 khi triển khai, và kết nối với gateway cục bộ được khởi động bởi dự án Gateway khi chạy cục bộ.

## Điều kiện tiên quyết

Trước khi sử dụng generator này, hãy đảm bảo bạn có:

1. Một dự án TypeScript với thành phần <Link path="guides/ts-agent">Agent</Link> (`infra: agentcore`)
2. Một dự án <Link path="guides/agentcore-gateway">`agentcore-gateway`</Link> với `protocol: mcp` và `auth: iam`

Gateway phải phục vụ giao thức `mcp` — agent tiếp cận nó như một MCP client, vì vậy các target của nó được hiển thị dưới dạng công cụ. Gateway cũng phải sử dụng xác thực IAM: agent ký các yêu cầu của nó bằng SigV4 sử dụng vai trò thực thi của chính nó. Generator sẽ từ chối các gateway được xác thực bằng Cognito.

:::note[Một hướng cho mỗi Gateway]
Một Gateway duy nhất không thể vừa được gọi bởi một agent vừa đứng trước một agent. Đứng trước các agent runtime cần `protocol: http` (xem <Link path="guides/connection/agentcore-gateway-agent">Gateway to Agent</Link>), trong khi được gọi bởi một agent cần `protocol: mcp`. Sử dụng một Gateway riêng biệt cho mỗi hướng.
:::

## Kết quả của Generator

Generator tạo ra các tệp client core dùng chung vào package `agent-connection` của bạn, cộng với một wrapper cho mỗi Gateway, và sửa đổi agent của bạn:

<FileTree>

- packages/common/agent-connection
  - src
    - core/
      - agentcore-endpoints.ts Framework-agnostic ARN/URL resolution
      - agentcore-gateway-mcp-transport.ts Framework-agnostic Gateway MCP transport
      - agentcore-gateway-mcp-client-strands.ts Strands MCP client for the deployed Gateway
    - app/
      - \<gateway-kebab>-client-strands.ts Per-Gateway Strands client wrapper
    - index.ts Re-exports the Gateway client

</FileTree>

Ngoài ra, generator:

- Sửa đổi `agent.ts` của agent để import lớp Gateway client, gọi `<Gateway>ClientStrands.create()`, và đăng ký client được trả về trong mảng `tools`
- Kết nối target `<agent>-dev` của agent để phụ thuộc vào target `dev` của Gateway
- Cài đặt các dependency SigV4 / MCP cần thiết

## Sử dụng Gateway đã kết nối

Generator chuyển đổi `agent.ts` của agent để sử dụng Gateway client:

```ts title="packages/example/src/my-agent/agent.ts" {2,5,8}
import { Agent } from '@strands-agents/sdk';
import { MyGatewayClientStrands } from '@my-scope/agent-connection';

export const getAgent = async () => {
  const myGateway = await MyGatewayClientStrands.create();
  return new Agent({
    systemPrompt: '...',
    tools: [myGateway],
  });
};
```

Khi được triển khai (`LOCAL_DEV` không được đặt), client trỏ đến điểm cuối MCP của Gateway và xác thực bằng SigV4. Khi `LOCAL_DEV=true`, nó trỏ đến gateway cục bộ được khởi động bởi target `dev` của dự án Gateway, vì vậy cùng một `agent.ts` hoạt động đồng nhất trong cả hai chế độ.

Session ID được truyền tự động đến các MCP server downstream thông qua header `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id`.

## Cơ sở hạ tầng

Sau khi chạy generator, bạn phải cấp quyền cho agent để gọi Gateway.

<Infrastructure>
<Fragment slot="cdk">
```ts title="packages/infra/src/stacks/application-stack.ts" {5}
const gateway = new MyGateway(this, 'MyGateway');
const myAgent = new MyAgent(this, 'MyAgent');

// Grant the agent permissions to invoke the Gateway
gateway.grantInvokeAccess(myAgent);
```

URL của Gateway được tự động đăng ký trong namespace `agentcore.gateways.<ClassName>` của <Link path="guides/runtime-config">Runtime Configuration</Link> bởi CDK construct được tạo, vì vậy agent có thể khám phá nó tại runtime.

## Phát triển cục bộ

Generator cấu hình target `dev` của agent để:

1. Khởi động gateway cục bộ của Gateway đã kết nối và mọi MCP server được đính kèm
2. Đặt `LOCAL_DEV=true` để client được tạo trỏ đến gateway cục bộ thay vì Gateway đã triển khai

Chạy agent cục bộ với:

<NxCommands commands={["<agent-name>-dev <project-name>"]} />

Để chạy agent cục bộ **với Gateway đã triển khai** thay vào đó (ví dụ, để thực thi các chính sách Cedar), hãy sử dụng target `serve` của agent. Không có `LOCAL_DEV` được đặt, client sẽ phân giải URL Gateway đã triển khai từ runtime configuration và ký các yêu cầu bằng SigV4 với thông tin xác thực AWS cục bộ của bạn:

<NxCommands commands={["<agent-name>-serve <project-name>"]} />

### Độ chính xác cục bộ

Gateway cục bộ thay thế cho Gateway đã triển khai, vì vậy:

- **Không có đánh giá chính sách Cedar.** Mọi công cụ đều hiển thị với agent bất kể chính sách. Sử dụng target `serve` để thực thi các chính sách với Gateway đã triển khai.
- **Tiền tố tên công cụ được giữ nguyên.** Các công cụ của mỗi MCP server cục bộ được bọc để hiển thị tên có dạng `<target-name>___<tool-name>`, khớp với những gì Gateway đã triển khai phát ra. Điều này giữ cho system prompt của agent và tên action Cedar mà bạn tham chiếu nhất quán giữa các lần chạy cục bộ và đã triển khai.
