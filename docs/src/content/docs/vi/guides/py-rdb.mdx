Generator này tạo một dự án cơ sở dữ liệu quan hệ Python mới được hỗ trợ bởi [Amazon Aurora](https://aws.amazon.com/rds/aurora/) (PostgreSQL hoặc MySQL), [SQLModel](https://sqlmodel.tiangolo.com/) để mô hình hóa dữ liệu, và [Alembic](https://alembic.sqlalchemy.org/) để di chuyển schema. Nó tạo ra mã ứng dụng và cơ sở hạ tầng cần thiết để cung cấp và quản lý cơ sở dữ liệu bằng AWS CDK hoặc Terraform, với định nghĩa schema khai báo, triển khai migration tự động, và một database client.

## Kết quả của Generator

Generator tạo cấu trúc dự án sau trong thư mục `<directory>/<name>`:

<FileTree>
  - \<name>
    - \_\_init\_\_.py Package exports (`get_engine`, `session_context`)
    - connection.py Database engine and session factory with IAM authentication
    - utils.py Runtime config and local development helpers
    - migration_handler.py Lambda handler that runs Alembic migrations during deployment
    - create_db_user_handler.py Lambda handler that creates the application database user during deployment
    - models
      - example.py Example SQLModel table definition
  - migrations
    - versions Alembic-generated migration scripts
    - env.py Alembic environment (connects to the database)
    - script.py.mako Alembic migration script template
  - alembic.ini Alembic configuration
  - config.json Local development connection details and runtime config key
  - Dockerfile.migration Container image for the migration handler
  - Dockerfile.create-db-user Container image for the create-db-user handler
  - project.json Project configuration and build targets
</FileTree>

Các script phát triển cục bộ được chia sẻ trên tất cả các dự án cơ sở dữ liệu và được tạo vào `packages/common/scripts/`:

<FileTree>
  - packages/common/scripts/src/rdb
    - pull-image.ts Pulls the database container image
    - start-container.ts Starts a local database container
    - wait-for-postgres-db.ts Waits for the local database to be ready (PostgreSQL)
    - wait-for-mysql-db.ts Waits for the local database to be ready (MySQL)
</FileTree>

## Phát triển cục bộ

### Mô hình hóa dữ liệu

Dự án được tạo sử dụng [SQLModel](https://sqlmodel.tiangolo.com/) để định nghĩa schema cơ sở dữ liệu của bạn. Quy trình làm việc là model-first: thêm hoặc cập nhật các lớp bảng SQLModel trong thư mục `<name>/models/` của dự án cơ sở dữ liệu của bạn, sau đó tạo một migration từ những thay đổi model đó.

Ví dụ về model:

```python title="packages/my_db/my_db/models/example.py"
from sqlalchemy import Column, String
from sqlmodel import Field, SQLModel


class ExampleModel(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str = Field(sa_column=Column(String(255), nullable=False))
    description: str | None = Field(default=None, sa_column=Column(String(255), nullable=True))
```

Import các model của bạn trong `<name>/models/__init__.py` để Alembic có thể phát hiện chúng trong quá trình tự động tạo.

### Tạo Migrations

Sau khi thêm hoặc cập nhật models, sử dụng Alembic để tạo và áp dụng các script migration. Target `alembic` được tạo tự động khởi động một container cơ sở dữ liệu cục bộ trước khi chạy:

<NxCommands commands={['run <project>:alembic revision --autogenerate -m "describe your change"']} />

Điều này tạo một script migration mới trong `migrations/versions/`. Xem xét script được tạo trước khi áp dụng nó.

Áp dụng migration vào cơ sở dữ liệu cục bộ của bạn:

<NxCommands commands={['run <project>:migrate']} />

Khi bạn triển khai AWS stack, cơ sở hạ tầng được tạo tự động áp dụng các migration đã tạo vào cơ sở dữ liệu đã triển khai.

### Áp dụng Migrations hiện có

Khi bạn pull các file migration được tạo bởi các nhà phát triển khác, áp dụng chúng vào cơ sở dữ liệu cục bộ của bạn:

<NxCommands commands={['run <project>:migrate']} />

### Chạy các lệnh Alembic

Target `alembic` được tạo cung cấp Alembic CLI, vì vậy bạn có thể chạy bất kỳ lệnh Alembic nào đối với cơ sở dữ liệu cục bộ. Xem [tài liệu tham khảo lệnh Alembic](https://alembic.sqlalchemy.org/en/latest/ops.html) để biết các lệnh có sẵn.

<NxCommands commands={['run <project>:alembic <alembic-command>']} />

### Dừng Cơ sở dữ liệu cục bộ

Dừng `dev` (ví dụ: với `Ctrl+C`) tự động xóa container cơ sở dữ liệu cục bộ, nhưng giữ lại named volume để dữ liệu của bạn tồn tại qua các lần khởi động lại.

:::caution[Windows]
Do hạn chế với xử lý tín hiệu trên Windows, container không được tự động xóa khi `dev` bị dừng. Bạn sẽ cần xóa nó thủ công:

```bash
<engine> rm -f <scope>-<db-name>
```

Thay thế `<engine>` bằng container engine của bạn (`docker` hoặc `finch`), `<scope>` bằng scope của Nx workspace của bạn (ví dụ: `proj`), và `<db-name>` bằng tên dự án cơ sở dữ liệu của bạn (ví dụ: `my-db`).
:::

## Kết nối đến Cơ sở dữ liệu

Import `session_context` từ package cơ sở dữ liệu của bạn và sử dụng nó như một async context manager để có được một `AsyncSession`:

```python
from sqlmodel import select

from my_scope.my_db import session_context
from my_scope.my_db.models.example import ExampleModel

async def example():
    async with session_context() as session:
        results = (await session.execute(select(ExampleModel))).all()
```

Database client tự động:
- Lấy cấu hình cơ sở dữ liệu từ AWS AppConfig tại runtime
- Tạo các token xác thực tạm thời thông qua `boto3` RDS Signer cho xác thực IAM
- Thiết lập kết nối TLS bằng cách sử dụng `ssl.create_default_context()`

#### Yêu cầu SSL khi kết nối không có RDS Proxy

Amazon RDS CA bundle phải có trong system trust store của runtime.

##### Container Runtimes

<Tabs>
<TabItem label="Amazon Linux">

```dockerfile
ADD https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem /etc/pki/ca-trust/source/anchors/global-bundle.pem
RUN update-ca-trust
```

</TabItem>
<TabItem label="Debian">

```dockerfile
ADD https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem /usr/local/share/ca-certificates/rds-global-bundle.crt
RUN update-ca-certificates
```

</TabItem>
</Tabs>

##### Zip Lambda Functions

Đối với các hàm Lambda được triển khai bằng zip (chẳng hạn như <Link path="guides/fastapi">`py#api` FastAPI</Link>), CA trust store tích hợp của môi trường thực thi Lambda Amazon Linux 2023 bao gồm các Amazon Root CA được sử dụng bởi RDS.

Khi sử dụng RDS Proxy, bạn không cần cấu hình RDS CA bundle trong runtime kết nối đến cơ sở dữ liệu.
