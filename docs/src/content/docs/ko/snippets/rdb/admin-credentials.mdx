---
title: 관리자 자격 증명
---
import Infrastructure from '@components/infrastructure.astro';

Aurora 관리자(마스터) 사용자의 비밀번호는 [RDS 관리형 마스터 사용자 비밀번호](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/rds-secrets-manager.html)를 사용하여 Aurora 자체가 AWS Secrets Manager에서 생성하고 교체합니다. 인프라 코드는 비밀번호를 받지 않으므로 CloudFormation 템플릿이나 Terraform 상태 파일로 유출될 수 없습니다. Aurora는 배포하거나 유지 관리할 교체 함수 없이 7일마다 시크릿을 교체합니다.

시크릿은 클러스터와 동일한 고객 관리형 KMS 키로 암호화됩니다.

애플리케이션은 이러한 자격 증명을 사용하지 않습니다. IAM 인증을 사용하여 최소 권한 데이터베이스 사용자로 연결합니다. 마이그레이션 및 create-db-user 핸들러만 관리자 시크릿을 읽으며, 각각은 해당 시크릿과 KMS 키에만 액세스 권한이 부여됩니다.

<Infrastructure>
<Fragment slot="cdk">

관리자 시크릿은 기본 클러스터에서 `secret.secretArn`으로 노출되며, `grantSecretRead`는 소비자에게 읽기 액세스 권한을 부여합니다:

```ts title="packages/infra/src/stacks/application-stack.ts"
import { MyDatabase } from '@my-scope/common-constructs';

const db = new MyDatabase(this, 'Db', { ... });

db.grantSecretRead(myFunction);
```
</Fragment>
<Fragment slot="terraform">

관리자 시크릿의 ARN은 `secret_arn` 출력으로 노출되며, 복호화에 필요한 `kms_key_arn`과 함께 제공됩니다:

```hcl title="packages/infra/src/main.tf"
module "my_database" {
  source = "../../common/terraform/src/app/dbs/my-database"
  ...
}

output "database_secret_arn" {
  value = module.my_database.secret_arn
}
```

RDS 관리형 시크릿은 `username`과 `password`만 포함하는 JSON 객체를 보유하며 연결 세부 정보는 포함하지 않습니다. 호스트, 포트 및 데이터베이스 이름은 모듈의 `writer_endpoint`, `cluster_port` 및 `database_name` 출력에서 가져옵니다.
</Fragment>
</Infrastructure>
