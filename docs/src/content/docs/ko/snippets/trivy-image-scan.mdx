이 프로젝트를 위해 빌드된 Docker 이미지는 [ECR 호스팅 Trivy 이미지](https://gallery.ecr.aws/aquasecurity/trivy)에서 실행되는 [Trivy](https://trivy.dev/)를 사용하여 취약점을 스캔할 수 있습니다.

`trivy` 타겟이 프로젝트에 추가되어 빌드된 이미지를 스캔하고 `HIGH` 또는 `CRITICAL` 심각도의 취약점이 발견되면 **0이 아닌 값으로 종료**합니다. 생성된 `Dockerfile`은 생성 시점에 이러한 심각도의 알려진 수정 가능한 취약점이 없는 베이스 이미지를 사용하며, 번들된 도구(예: `npm`)를 업그레이드하여 이를 유지합니다.

스캔은 이미지 빌드와 동일한 컨테이너 엔진(`docker` 또는 `finch`)을 사용하므로 추가 도구가 필요하지 않습니다. 스캔은 캐시되지 않습니다. 읽는 이미지가 디스크가 아닌 컨테이너 엔진에 있기 때문입니다. 따라서 항상 실제 이미지를 스캔하며, 더 이상 존재하지 않는 이미지에 대해 캐시된 통과를 보고하는 대신 명확하게 실패합니다. 제공되는 `trivy` 루트 스크립트는 워크스페이스의 모든 이미지를 스캔합니다:

:::tip[CI에서 Trivy 실행]
Trivy의 취약점 데이터베이스가 새로운 CVE로 지속적으로 업데이트되므로, 개발 중 반복 작업 시 불필요한 마찰을 초래할 수 있어 스캔은 의도적으로 `build`에 연결되지 않았습니다.

대신 프로덕션 스테이지에 배포하기 전에 CI 파이프라인에서 위 명령을 전용 단계로 실행하는 것을 권장합니다.
:::

:::caution[수정 불가능한 취약점은 무시됨]
스캔은 `--ignore-unfixed`로 실행되므로 사용 가능한 수정 사항이 없는 취약점은 빌드를 실패시키지 않습니다. 이러한 취약점은 `Dockerfile`에서 도구를 업그레이드하여 조치할 수 없으므로 빌드의 스캔 출력에 보고되지 않습니다. 새로운 취약점이 공개됨에 따라 스캔 결과가 시간이 지남에 따라 변경될 수 있으므로, 플래그 없이 `trivy image <your-image>`를 실행하여 주기적으로 이미지를 검토하고, 수정 사항이 게시되면 더 새로운 베이스 이미지에 대해 재빌드하거나 (또는 사용 가능한 패치를 적용하기 위해 컨테이너 단계를 추가하세요).
:::

#### Trivy 결과 억제

특정 취약점을 억제하고 싶은 경우가 있을 수 있습니다. 예를 들어 아직 수정 사항이 없고 위험을 허용 가능한 것으로 평가한 경우입니다.

프로젝트 루트의 `.trivyignore` 파일(즉, `project.json` 옆)에 취약점 ID를 한 줄에 하나씩 추가하세요:

```gitignore
# .trivyignore
# node-tar arbitrary file write - not exploitable in our usage
CVE-2024-XXXXX
```

결과 필터링에 대한 자세한 내용은 [Trivy 필터링 문서](https://trivy.dev/latest/docs/configuration/filtering/#by-finding-ids)를 참조하세요.
