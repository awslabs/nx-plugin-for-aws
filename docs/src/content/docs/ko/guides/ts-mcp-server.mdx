대규모 언어 모델(LLM)에 컨텍스트를 제공하기 위한 TypeScript [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) 서버를 생성하고, 선택적으로 [Amazon Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/)에 배포합니다.

## MCP란 무엇인가요?

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/)는 AI 어시스턴트가 외부 도구 및 리소스와 상호 작용할 수 있도록 하는 개방형 표준입니다. LLM이 다음을 수행할 수 있는 일관된 방법을 제공합니다:

- 작업을 수행하거나 정보를 검색하는 도구(함수) 실행
- 컨텍스트 또는 데이터를 제공하는 리소스 액세스

## 제너레이터 출력

제너레이터는 기존 TypeScript 프로젝트에 다음 파일을 추가합니다:

<FileTree>
  - your-project/
    - src/
      - mcp-server/ (or custom name if specified)
        - index.ts Exports your server
        - server.ts Main server definition
        - stdio.ts Entry point for STDIO transport, useful for simple local MCP servers
        - http.ts Entry point for Streamable HTTP transport, useful for hosting your MCP server
        - tools/
          - divide.ts Sample tool
        - resources/
          - sample-guidance.ts Sample resource

</FileTree>

## MCP Server 작업하기

### 도구 추가

도구는 AI 어시스턴트가 작업을 수행하기 위해 호출할 수 있는 함수입니다. 각 도구는 `tools/` 아래의 자체 파일에 있으며 `register<Name>Tool` 함수를 내보내고, 이를 `server.ts`에서 호출합니다. 예를 들어, `tools/my-tool.ts`를 추가합니다:

```typescript title="tools/my-tool.ts"
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';
import { z } from 'zod';

export const registerMyTool = (server: McpServer) => {
  server.registerTool("toolName", {
    description: "tool description",
    inputSchema: { param1: z.string(), param2: z.number() } // Input schema using Zod
  },
    async ({ param1, param2 }) => {
      // Tool implementation
      return {
        content: [{ type: "text", text: "Result" }]
      };
    }
  );
};
```

그런 다음 `server.ts`의 `createServer` 내부에 등록합니다:

```typescript title="server.ts" {6}
import { registerMyTool } from './tools/my-tool.js';

export const createServer = async () => {
  const server = new McpServer({ name: 'my-server', version: '1.0.0' });

  registerMyTool(server);

  return server;
};
```

### 리소스 추가

리소스는 AI 어시스턴트에게 컨텍스트를 제공합니다. 도구와 마찬가지로 각 리소스는 `resources/` 아래의 자체 파일에 있으며 `register<Name>Resource` 함수를 내보내고 `server.ts`에서 호출됩니다. 파일의 정적 리소스 또는 동적 리소스를 추가할 수 있습니다:

```typescript title="resources/my-resource.ts"
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';

export const registerMyResource = (server: McpServer) => {
  const exampleContext = 'some context to return';

  server.registerResource('resource-name', 'example://resource', {}, async (uri) => ({
    contents: [{ uri: uri.href, text: exampleContext }],
  }));

  // Dynamic resource
  server.registerResource('dynamic-resource', 'dynamic://resource', {}, async (uri) => {
    const data = await fetchSomeData();
    return {
      contents: [{ uri: uri.href, text: data }],
    };
  });
};
```

## MCP Server 실행

### 로컬 개발

MCP 서버(및 로컬 데이터베이스와 같이 연결된 모든 것)를 로컬에서 실행하려면 프로젝트의 `dev` 타겟을 사용합니다:

<NxCommands commands={['dev your-project']} />

프로젝트에 여러 구성 요소(MCP 서버, 에이전트 등)를 추가한 경우 이 명령은 모두 시작합니다. 이 MCP 서버만 실행하려면 `<your-server-name>-dev` 타겟을 대상으로 지정합니다:

<NxCommands commands={['your-server-name-dev your-project']} />

### Inspector

제너레이터는 `<your-server-name>-inspect`라는 타겟을 구성하며, 이는 MCP 서버를 로컬에서 시작하고(`<your-server-name>-dev` 타겟을 통해, 로컬 데이터베이스와 같은 연결된 종속성 포함) Streamable HTTP 전송을 통해 연결하도록 사전 구성된 [MCP Inspector](https://github.com/modelcontextprotocol/inspector)를 시작합니다.

<NxCommands commands={['your-server-name-inspect your-project']} />

이렇게 하면 `http://localhost:6274`에서 인스펙터가 시작됩니다. "Connect" 버튼을 클릭하여 시작하세요.

:::tip
대신 STDIO 전송을 사용하여 서버를 검사하려면 `<your-server-name>-inspect-stdio` 타겟을 사용하세요. 이는 서버의 STDIO 인스턴스에 대해 인스펙터를 시작합니다.
:::

### STDIO

MCP 서버를 테스트하고 사용하는 가장 쉬운 방법은 인스펙터를 사용하거나 AI 어시스턴트와 구성하는 것입니다(위 참조).

그러나 `<your-server-name>-serve-stdio` 타겟을 사용하여 [STDIO 전송](https://modelcontextprotocol.io/docs/concepts/transports#standard-input%2Foutput-stdio)으로 서버를 직접 실행할 수 있습니다.

<NxCommands commands={['your-server-name-serve-stdio your-project']} />

이 명령은 `tsx --watch`를 사용하여 파일이 변경될 때 서버를 자동으로 다시 시작합니다.

### Streamable HTTP

[Streamable HTTP 전송](https://modelcontextprotocol.io/docs/concepts/transports#streamable-http)을 사용하여 MCP 서버를 로컬에서 실행하려면 `<your-server-name>-serve` 타겟을 사용할 수 있습니다.

<NxCommands commands={['your-server-name-serve your-project']} />

이 명령은 `tsx --watch`를 사용하여 파일이 변경될 때 서버를 자동으로 다시 시작합니다.

<OptionFilter when={{ infra: 'agentcore' }} description="Code package target">
### Package 타겟

제너레이터는 배포 가능한 코드 패키지를 조립하는 `<your-server-name>-package` 타겟을 구성합니다: 번들된 `index.js`와 AgentCore가 패키지에 존재해야 하는 AWS Distro for OpenTelemetry의 벤더 설치가 포함됩니다. 생성된 인프라는 이 디렉터리를 `.zip`으로 업로드합니다 — CDK에서는 `AgentRuntimeArtifact.fromCodeAsset`을 통해, Terraform에서는 공유 자산 버킷에 아카이브됩니다.
</OptionFilter>

<OptionFilter when={{ infra: 'agentcore-ecr' }} description="Container image build and scan">
### Docker 타겟

제너레이터는 MCP 서버 소스 디렉터리에서 번들 출력 디렉터리로 `Dockerfile`을 복사하는 `<your-server-name>-docker` 타겟을 구성합니다. 이렇게 하면 `Dockerfile`이 번들된 아티팩트와 함께 배치되어 CDK가 `AgentRuntimeArtifact.fromAsset`을 사용하여 Docker 이미지를 직접 빌드할 수 있습니다.

여러 MCP 서버가 정의된 경우 모든 MCP 서버에 대한 docker 컨텍스트를 준비하는 `docker` 타겟도 생성됩니다.
