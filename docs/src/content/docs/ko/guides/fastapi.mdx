[FastAPI](https://fastapi.tiangolo.com/)는 Python으로 API를 구축하기 위한 프레임워크입니다.

FastAPI 생성기는 AWS CDK 또는 Terraform 인프라 설정과 함께 새로운 FastAPI를 생성합니다. 생성된 백엔드는 AWS API Gateway API를 통해 노출됩니다. 구조화된 로깅 및 CloudWatch 메트릭을 포함한 관찰성을 위해 [AWS Lambda Powertools](https://docs.powertools.aws.dev/lambda/python/latest/)를 설정합니다.

<OptionFilter not when={{ infra: 'http-ecs' }} description="Lambda 호스팅">
백엔드는 서버리스 배포를 위해 AWS Lambda를 사용하며, AWS X-Ray 추적도 설정됩니다.
</OptionFilter>

<OptionFilter when={{ infra: 'http-ecs' }} description="ECS 호스팅">
API는 Lambda 함수가 아닌 Amazon ECS의 컨테이너에서 장기 실행 uvicorn 서버로 실행되며, API Gateway HTTP API 뒤에 있습니다. X-Ray 추적이 거기서 추적을 생성하지 않는 이유를 포함하여 변경 사항은 <a href="#running-on-amazon-ecs">Running on Amazon ECS</a>를 참조하세요.
</OptionFilter>

`integrationPattern`은 여기서 항상 `shared`입니다. 하나의 컨테이너 서비스가 모든 작업에 응답하기 때문입니다. `http-ecs`와 함께 `--integrationPattern=isolated`를 전달해도 실패하지 않습니다: 생성기는 옵션이 무시되고 `shared`를 사용한다고 경고합니다. 생성기를 대화식으로 실행하면 `infra` 전에 `integrationPattern`을 묻고 `isolated`이 미리 선택되어 있으므로, 미리 선택을 그대로 두고 `http-ecs`를 선택하면 해당 경고가 표시됩니다.
:::

## 생성기 출력

생성기는 `<directory>/<api-name>` 디렉토리에 다음과 같은 프로젝트 구조를 생성합니다:

<FileTree>

- project.json 프로젝트 구성 및 빌드 타겟
- pyproject.toml Python 프로젝트 구성 및 종속성
- run.sh uvicorn을 통해 FastAPI 앱을 시작하는 Lambda Web Adapter 부트스트랩 스크립트
- \<module_name>
  - \_\_init\_\_.py 모듈 초기화
  - init.py FastAPI 앱을 설정하고 powertools 미들웨어를 구성
  - main.py API 구현
- scripts
  - generate_open_api.py FastAPI 앱에서 OpenAPI 스키마를 생성하는 스크립트

</FileTree>

<OptionFilter when={{ infra: 'http-ecs' }} description="API가 ECS에서 실행될 때 다른 파일">
`infra`가 `http-ecs`로 설정되면 API는 Lambda Web Adapter 뒤가 아닌 자체 HTTP 서버로 실행되므로 `run.sh`는 생성되지 않습니다. 대신 API 이름을 따서 명명된 모듈 내부에 컨테이너 폴더가 생성됩니다:

<FileTree>
- \<module_name>
  - \<api_name>_container
    - main.py 진입점: `GET /health`를 추가하고, API가 수집하는 메트릭을 작성하며, `HOST` 및 `PORT`에서 uvicorn을 시작합니다. 번들, 이미지 및 `serve` 타겟은 모두 이 파일에서 시작됩니다
    - Dockerfile 컨테이너 이미지 정의
    - .dockerignore 이미지 빌드 컨텍스트에서 제외된 파일
</FileTree>

`init.py`, `main.py` 및 추가하는 작업은 모든 `infra` 값에 대해 동일합니다.
</OptionFilter>

## FastAPI 구현

주요 API 구현은 `main.py`에 있습니다. 여기에서 API 라우트와 그 구현을 정의합니다. 다음은 예시입니다:

```python
from pydantic import BaseModel
from .init import app, tracer

class Item(BaseModel):
  name: str

@app.get("/items/{item_id}")
@tracer.capture_method
def get_item(item_id: int) -> Item:
    return Item(name=f"Item {item_id}")

@app.post("/items")
@tracer.capture_method
def create_item(item: Item) -> Item:
    return item
```

생성기는 여러 기능을 자동으로 설정합니다:

1. 관찰성을 위한 AWS Lambda Powertools 통합
2. 오류 처리 미들웨어
3. 요청/응답 상관관계
4. 메트릭 수집

<OptionFilter not when={{ infra: 'http-ecs' }} description="REST API가 필요한 스트리밍">
타입 안전 스트리밍도 설정되며, `rest-lambda` 인프라에만 해당됩니다.
</OptionFilter>

<OptionFilter not when={{ infra: 'http-ecs' }} description="Lambda 변형이 앱을 제공하는 방법">
앱은 [Lambda Web Adapter](https://github.com/awslabs/aws-lambda-web-adapter)가 uvicorn을 실행하여 Lambda 함수에서 제공됩니다.
</OptionFilter>

<OptionFilter when={{ infra: 'http-ecs' }} description="ECS 변형이 앱을 제공하는 방법">
앱은 Lambda Web Adapter 없이 컨테이너의 uvicorn에 의해 제공됩니다. <a href="#running-on-amazon-ecs">Running on Amazon ECS</a>를 참조하세요.
</OptionFilter>

### AWS Lambda Powertools를 사용한 관찰성

#### 로깅

생성기는 AWS Lambda Powertools를 사용하여 구조화된 로깅을 구성합니다. 라우트 핸들러에서 로거에 액세스할 수 있습니다:

```python
from .init import app, logger

@app.get("/items/{item_id}")
def read_item(item_id: int):
    logger.info("Fetching item", extra={"item_id": item_id})
    return {"item_id": item_id}
```

로거는 자동으로 다음을 포함합니다:

- 요청 추적을 위한 상관관계 ID
- 요청 경로, 일치하는 라우트 및 메서드

#### 추적

AWS X-Ray 추적이 자동으로 구성됩니다. 추적에 사용자 정의 하위 세그먼트를 추가할 수 있습니다:

```python
from .init import app, tracer

@app.get("/items/{item_id}")
@tracer.capture_method
def read_item(item_id: int):
    # Creates a new subsegment
    with tracer.provider.in_subsegment("fetch-item-details"):
        # Your logic here
        return {"item_id": item_id}
```

<OptionFilter when={{ infra: 'http-ecs' }} description="X-Ray는 ECS에서 추적을 생성하지 않습니다">
:::caution[ECS에서 추적 없음]
위의 데코레이터와 하위 세그먼트는 컨테이너에서 오류 없이 실행되지만 추적을 생성하지 않습니다. Powertools는 Lambda에서 실행되지 않을 때 추적기를 끕니다. 얻을 수 있는 것과 추적이 필요한 경우 추가할 사항은 <a href="#observability">Observability</a>를 참조하세요.
:::
</OptionFilter>

#### 메트릭

CloudWatch 메트릭은 각 요청에 대해 자동으로 수집됩니다. 사용자 정의 메트릭을 추가할 수 있습니다:

```python
from .init import app, metrics
from aws_lambda_powertools.metrics import MetricUnit

@app.get("/items/{item_id}")
def read_item(item_id: int):
    metrics.add_metric(name="ItemViewed", unit=MetricUnit.Count, value=1)
    return {"item_id": item_id}
```

기본 메트릭에는 다음이 포함됩니다:

- 요청 수
- 성공/실패 수
- 라우트별 메트릭 (`<method> <path>`의 `route` 차원을 통해)

### 오류 처리

생성기는 포괄적인 오류 처리를 포함합니다:

```python
from fastapi import HTTPException

@app.get("/items/{item_id}")
def read_item(item_id: int):
    if item_id < 0:
        raise HTTPException(status_code=400, detail="Item ID must be positive")
    return {"item_id": item_id}
```

처리되지 않은 예외는 미들웨어에 의해 포착되어:

1. 스택 추적과 함께 전체 예외를 로깅
2. 실패 메트릭 기록
3. 클라이언트에 안전한 500 응답 반환
4. 상관관계 ID 보존

:::tip[응답 모델]
`connection` 생성기를 사용할 때 더 나은 코드 생성을 위해 API 작업에 대한 응답 모델을 지정하는 것이 좋습니다. <Link path="guides/connection/react-fastapi#errors">자세한 내용은 여기를 참조하세요</Link>.
:::

### 호출 사용자 액세스

<OptionFilter when={{ infra: 'http-ecs' }} description="ECS의 신원 — 권한 부여자 컨텍스트가 도착하지 않습니다">
ECS에는 Lambda Web Adapter가 없고 API Gateway 요청 컨텍스트 헤더도 없습니다: API Gateway는 권한 부여자의 클레임을 프라이빗 로드 밸런서 통합으로 전달하지 않습니다. 권한 부여자는 여전히 요청이 컨테이너에 도달할지 여부를 결정하지만, 핸들러는 아래에 작성된 대로 요청에서 호출자를 읽을 수 없습니다.

작업에서 호출자의 신원을 읽으려면 API 구성체에서 권한 부여자의 컨텍스트를 요청 헤더에 매핑하고 FastAPI `Request`에서 해당 헤더를 읽으세요.
</OptionFilter>

<OptionFilter not when={{ infra: 'http-ecs' }} description="Lambda 변형의 신원">
API가 인증으로 보호되는 경우, 라우트 핸들러는 종종 누가 호출하는지 알아야 합니다. 생성된 FastAPI는 [Lambda Web Adapter](https://github.com/awslabs/aws-lambda-web-adapter)를 통해 AWS Lambda 내부에서 실행되며, API Gateway 요청 컨텍스트를 `x-amzn-request-context` 헤더에 JSON으로 전달합니다. FastAPI `Request`에서 이를 읽어 호출자의 신원을 추출할 수 있습니다.

예를 들어, 호출 사용자에 대한 세부 정보를 반환하는 `/me` 엔드포인트를 추가해 보겠습니다. 라우트 간에 재사용할 수 있도록 추출을 [FastAPI dependency](https://fastapi.tiangolo.com/tutorial/dependencies/)로 구현하겠습니다. 요청 컨텍스트의 형태 — 따라서 신원을 추출하는 방법 — 는 선택한 `auth` 메서드와 REST 또는 HTTP API를 배포했는지 여부에 따라 달라집니다.
</OptionFilter>

<OptionFilter when={{ auth: 'iam' }} description="IAM 인증 API에 대한 신원 추출">
`IAM` 인증의 경우, API Gateway 요청 컨텍스트에서 추출한 sub를 사용하여 Cognito에서 호출자를 조회합니다. 이를 위해서는 `boto3`가 필요합니다. API 프로젝트에 추가하세요:

<NxCommands commands={[`run my-api:add boto3${PY_VERSIONS.boto3}`]} />

`main.py` 옆에 `identity.py`를 생성하세요:

<Tabs syncKey="http-rest">
<TabItem label="REST API" _filter={{ infra: 'rest-lambda' }}>
```python
import json
import os
from typing import Annotated

from boto3 import client
from fastapi import Depends, HTTPException, Request
from pydantic import BaseModel

cognito = client("cognito-idp")


class Identity(BaseModel):
    sub: str
    username: str


def get_identity(request: Request) -> Identity:
    # The Lambda Web Adapter forwards the API Gateway request context as JSON
    request_context_header = request.headers.get("x-amzn-request-context")
    if not request_context_header:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    request_context = json.loads(request_context_header)
    provider = request_context.get("identity", {}).get("cognitoAuthenticationProvider")

    sub = provider.split(":")[-1] if provider else None
    if not sub:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    users = cognito.list_users(
        # Assumes user pool id is configured in lambda environment
        UserPoolId=os.environ["USER_POOL_ID"],
        Limit=1,
        Filter=f'sub="{sub}"',
    ).get("Users", [])

    if len(users) != 1:
        raise HTTPException(status_code=403, detail=f"No user found with subjectId {sub}")

    return Identity(sub=sub, username=users[0]["Username"])


CurrentUser = Annotated[Identity, Depends(get_identity)]
```
</TabItem>

```python
    username: str

    if not request_context_header:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    request_context = json.loads(request_context_header)
    amr = (
        request_context.get("authorizer", {})
        .get("iam", {})
        .get("cognitoIdentity", {})
        .get("amr", [])

        Limit=1,
        Filter=f'sub="{sub}"',

    if len(users) != 1:
        raise HTTPException(status_code=403, detail=f"No user found with subjectId {sub}")

    return Identity(sub=sub, username=users[0]["Username"])
```

<TabItem label="REST API" _filter={{ infra: 'rest-lambda' }}>
```python
import json
from typing import Annotated

from fastapi import Depends, HTTPException, Request
from pydantic import BaseModel


class Identity(BaseModel):
    sub: str
    username: str


def get_identity(request: Request) -> Identity:
    # The Lambda Web Adapter forwards the API Gateway request context as JSON
    request_context_header = request.headers.get("x-amzn-request-context")
    if not request_context_header:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    request_context = json.loads(request_context_header)
    claims = request_context.get("authorizer", {}).get("claims", {})

    sub = claims.get("sub")
    username = claims.get("username")

    if not sub or not username:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    return Identity(sub=sub, username=username)


CurrentUser = Annotated[Identity, Depends(get_identity)]
```

<TabItem label="HTTP API" _filter={{ infra: 'http-lambda' }}>
HTTP API는 확인된 클레임을 `authorizer.jwt.claims` 아래에 배치하는 JWT 권한 부여자를 사용합니다:

```python
import json
from typing import Annotated

from fastapi import Depends, HTTPException, Request
from pydantic import BaseModel


class Identity(BaseModel):
    sub: str
    username: str


def get_identity(request: Request) -> Identity:
    # The Lambda Web Adapter forwards the API Gateway request context as JSON
    request_context_header = request.headers.get("x-amzn-request-context")
    if not request_context_header:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    request_context = json.loads(request_context_header)
    claims = request_context.get("authorizer", {}).get("jwt", {}).get("claims", {})

    sub = claims.get("sub")
    username = claims.get("username")

    if not sub or not username:
        raise HTTPException(status_code=403, detail="Unable to determine calling user")

    return Identity(sub=sub, username=username)


CurrentUser = Annotated[Identity, Depends(get_identity)]
```

:::
</OptionFilter>

그런 다음 호출자의 신원이 필요한 모든 라우트에 `CurrentUser` 종속성을 주입할 수 있습니다:

```python
from .identity import CurrentUser, Identity
from .init import app, tracer

@app.get("/me")
@tracer.capture_method
def me(identity: CurrentUser) -> Identity:
    return identity
```

<OptionFilter when={{ infra: 'rest-lambda' }} description="스트리밍 — REST API만 해당">
### 스트리밍

생성된 FastAPI는 REST API를 사용할 때 기본적으로 스트리밍 응답을 지원합니다. 인프라는 [AWS Lambda Web Adapter](https://github.com/awslabs/aws-lambda-web-adapter)를 사용하여 Lambda 내부에서 uvicorn을 통해 FastAPI를 실행하도록 구성되며, 모든 REST API 작업에 대해 API Gateway에서 `ResponseTransferMode.STREAM`을 사용하여 스트리밍이 비스트리밍 작업과 함께 작동할 수 있도록 합니다.

#### `JsonStreamingResponse` 사용

생성된 `init.py`는 적절한 OpenAPI 스키마 생성과 함께 타입 안전 스트리밍을 제공하는 `JsonStreamingResponse` 클래스를 내보냅니다. 이를 통해 <Link path="guides/connection/react-fastapi">`connection` 생성기</Link>가 올바르게 타입이 지정된 스트리밍 클라이언트 메서드를 생성할 수 있습니다.

```python
from pydantic import BaseModel
from .init import app, JsonStreamingResponse

class Chunk(BaseModel):
    message: str

async def generate_chunks():
    for i in range(100):
        yield Chunk(message=f"This is chunk {i}")

@app.post(
    "/stream",
    response_class=JsonStreamingResponse,
    responses={200: JsonStreamingResponse.openapi_response(Chunk, "Stream of chunks")},
)
async def my_stream() -> JsonStreamingResponse:
    return JsonStreamingResponse(generate_chunks())
```

`JsonStreamingResponse` 클래스는:

1. Pydantic 모델을 [JSON Lines](https://jsonlines.org/) 형식(`application/jsonl`)으로 직렬화
2. `itemSchema`와 함께 올바른 OpenAPI 스키마를 생성하는 `openapi_response` 헬퍼를 제공하여 <Link path="guides/connection/react-fastapi#consuming-a-stream">`connection` 생성기</Link>가 타입 안전 스트리밍 클라이언트 메서드를 생성할 수 있도록 함

#### 소비

응답 스트림을 소비하려면 <Link path="guides/connection/react-fastapi#consuming-a-stream">`connection` 생성기</Link>를 사용할 수 있으며, 이는 스트리밍된 청크를 반복하기 위한 타입 안전 메서드를 제공합니다.
</OptionFilter>

FastAPI 생성기는 선택한 `iac`에 따라 CDK 또는 Terraform 인프라 코드를 생성합니다. 이를 사용하여 FastAPI를 배포할 수 있습니다.

<OptionFilter not when={{ infra: 'http-ecs' }} description="Lambda 변형에 대한 CDK 사용">
`common/constructs` 폴더에 API를 배포하기 위한 CDK 구성체가 있습니다. CDK 애플리케이션에서 이를 사용할 수 있습니다:

```ts {6-8}
import { MyApi } from '@my-scope/common-constructs';

export class ExampleStack extends Stack {
  constructor(scope: Construct, id: string) {
    // Add the api to your stack
    const api = new MyApi(this, 'MyApi', {
      integrations: MyApi.defaultIntegrations(this).build(),
    });
  }
}
```

이는 다음을 설정합니다:

1. FastAPI 애플리케이션의 각 작업에 대한 AWS Lambda 함수
2. 함수 트리거로서의 API Gateway HTTP/REST API
3. IAM 역할 및 권한
4. CloudWatch 로그 그룹
5. X-Ray 추적 구성
6. CloudWatch 메트릭 네임스페이스
</OptionFilter>

<OptionFilter when={{ infra: 'http-ecs' }} description="API가 ECS에서 실행될 때 CDK 사용 — VPC 전달">
`defaultIntegrations`는 서비스가 실행되는 VPC를 가져와 그 안에 모든 것을 빌드합니다: ECS 서비스, 그 앞의 내부 로드 밸런서, 그리고 API Gateway가 해당 로드 밸런서에 도달하는 VPC 링크. 구성체는 VPC를 생성하지 않으므로 스택에서 VPC를 생성하거나 가져와야 합니다.

```ts {10,13-15}
import { MyApi } from '@my-scope/common-constructs';
import { Stack } from 'aws-cdk-lib';
import { Vpc } from 'aws-cdk-lib/aws-ec2';
import { Construct } from 'constructs';

export class ExampleStack extends Stack {
  constructor(scope: Construct, id: string) {
    super(scope, id);

    const vpc = new Vpc(this, 'Vpc', { natGateways: 1 });

    const api = new MyApi(this, 'MyApi', {
      integrations: MyApi.defaultIntegrations(this, { vpc }).build(),
    });
  }
}
```

기존 VPC를 사용하려면 `Vpc.fromLookup(this, 'Vpc', { vpcId: '<vpc-id>' })`로 조회하고 `vpc`로 전달하세요.

컨테이너 서비스 자체를 변경하려면 `service`를 전달하세요 — `cpu`, `memoryLimitMiB`, `desiredCount`, `environment` 또는 태스크 역할에 권한을 부여하는 `grantTaskRole`:

```ts
MyApi.defaultIntegrations(this, {
  vpc,
  service: {
    cpu: 512,
    memoryLimitMiB: 1024,
    grantTaskRole: (taskRole) => myTable.grantReadWriteData(taskRole),
  },
}).build();
```

이는 선택한 `auth` 메서드를 기반으로 한 인증이 있는 AWS API Gateway HTTP API, 컨테이너를 실행하는 Amazon ECS 서비스, 그 앞의 내부 로드 밸런서, 그리고 API Gateway가 해당 로드 밸런서에 도달하는 VPC 링크를 설정합니다.
</OptionFilter>

<Snippet name="api/cors-configuration-cdk-note" />

<OptionFilter when={{ auth: 'cognito' }} description="Cognito 신원 구성체 연결">

`Cognito` 인증을 사용하도록 선택한 경우, API 구성체에 `identity` 속성을 제공해야 합니다:

```ts {9}
import { MyApi, UserIdentity } from '@my-scope/common-constructs';

export class ExampleStack extends Stack {
  constructor(scope: Construct, id: string) {
    const identity = new UserIdentity(this, 'Identity');

    const api = new MyApi(this, 'MyApi', {

```

`UserIdentity` 구성체는 <Link path="/guides/react-website-auth">`ts#website#auth` 생성기</Link>를 사용하여 생성할 수 있습니다
:::
</OptionFilter>

`Custom` 인증을 사용할 때, 구성체는 생성된 `authorizer.py` 파일에서 내부적으로 Lambda 권한 부여자를 생성하며, **기본적으로 모든 요청을 거부합니다**. API가 트래픽을 수락하기 전에 해당 파일에 권한 부여 로직을 구현해야 합니다.

:::

### 액세스 권한 부여 (IAM만 해당)

`IAM` 인증을 사용하도록 선택한 경우, `grantInvokeAccess` 메서드를 사용하여 API에 대한 액세스 권한을 부여할 수 있습니다:

```ts
api.grantInvokeAccess(myIdentityPool.authenticatedRole);
```

<Fragment slot="terraform">
```hcl
# Create an IAM policy to allow invoking the API
resource "aws_iam_policy" "api_invoke_policy" {
  name        = "MyApiInvokePolicy"
  description = "Policy to allow invoking the FastAPI"

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Action = "execute-api:Invoke"
        Resource = "${module.my_api.api_execution_arn}/*/*"
      }
    ]
  })
}

# Attach the policy to an IAM role (e.g., for authenticated users)
resource "aws_iam_role_policy_attachment" "api_invoke_access" {
  role       = aws_iam_role.authenticated_user_role.name
  policy_arn = aws_iam_policy.api_invoke_policy.arn
}

# Or attach to an existing role by name
resource "aws_iam_role_policy_attachment" "api_invoke_access_existing" {
  role       = "MyExistingRole"
  policy_arn = aws_iam_policy.api_invoke_policy.arn
}
```

IAM 정책에 사용할 수 있는 API 모듈의 주요 출력은 다음과 같습니다:

- `module.my_api.api_execution_arn` - execute-api:Invoke 권한 부여용
- `module.my_api.api_arn` - API Gateway ARN

- `GET /health`, 로드 밸런서에 대해 응답하는 것처럼 응답
- `/docs` 또는 `/redoc`에서 대화형 API 문서
- `/openapi.json`에서 OpenAPI 스키마

서버는 `127.0.0.1`에 바인딩되므로 자신의 머신에서만 응답합니다. 아무것도 리로드하지 않습니다: 코드 변경을 적용하려면 다시 시작하세요. 다른 머신, VM 또는 컨테이너에서 도달하려면 `serve` 타겟에 `HOST=0.0.0.0`을 설정하세요 — 이렇게 하면 머신에 도달할 수 있는 모든 것이 인증 없이 API에 도달할 수 있습니다.
</OptionFilter>

:::note[프로젝트 이름]
Python 프로젝트 이름은 밑줄을 사용하므로, `--name=MyApi`로 생성된 API는 `my_api`(또는 정규화된 이름 `<scope>.my_api`)로 지정됩니다. 서버가 수신하는 포트는 프로젝트별로 할당됩니다 — 프로젝트의 `project.json`에 있는 `serve` 타겟에서 읽으세요.
:::

## Running on Amazon ECS

`infra`가 `http-ecs`로 설정되면, API는 Lambda Web Adapter 뒤의 Lambda 함수가 아닌 컨테이너에서 장기 실행 uvicorn 서버로 실행됩니다. 요청은 다음 경로를 따릅니다:

1. 호출자는 유일한 공개 진입점인 API Gateway HTTP API에 요청을 서명합니다. 모든 라우트는 선택한 `auth`에 대한 권한 부여자를 전달하므로 인증되지 않은 요청은 엣지에서 거부됩니다.
2. API Gateway는 VPC 링크를 통해 요청을 전달하며, 이는 VPC로의 프라이빗 경로입니다.
3. VPC 링크는 내부 로드 밸런서에 도달합니다. 로드 밸런서에는 공개 주소가 없으며, 유일한 인바운드 규칙은 리스너 포트에서 VPC 링크의 보안 그룹을 허용합니다.
4. 로드 밸런서는 태스크로 요청을 전달합니다. 태스크의 유일한 인바운드 규칙은 컨테이너 포트에서 로드 밸런서의 보안 그룹을 허용하므로 VPC의 다른 어떤 것도 연결을 열 수 없습니다.

태스크는 프라이빗 서브넷에서 실행되며 공개 IP 주소를 얻지 않습니다. 이 경로의 어떤 것도 주소 범위 인바운드를 허용하지 않습니다.

기본적으로 서비스, 로드 밸런서 및 VPC 링크는 NAT 게이트웨이를 통해 AWS에 도달하는 VPC의 `PRIVATE_WITH_EGRESS` 서브넷에 배치됩니다. `defaultIntegrations`에 `vpcSubnets: { subnetType: SubnetType.PRIVATE_ISOLATED }`를 전달하면 NAT 게이트웨이와 시간당 요금이 제거되지만, 격리된 서브넷에는 외부 경로가 없으므로 VPC는 태스크가 시작되기 위해 4개의 VPC 엔드포인트가 필요합니다: 이미지를 가져오기 위한 `ecr.api` 및 `ecr.dkr`에 대한 인터페이스 엔드포인트, 이미지 레이어가 S3 객체이기 때문에 S3 게이트웨이 엔드포인트, 그리고 `awslogs` 드라이버가 쓸 수 있도록 `logs`에 대한 인터페이스 엔드포인트. 이것들이 없으면 태스크는 이미지를 가져올 수 없고 ECS는 이유를 말하지 않고 회로 차단기에서 배포를 롤백합니다.

VPC 링크, 로드 밸런서, 리스너, 타겟 그룹 및 로드 밸런서가 액세스 로그를 작성하는 버킷은 `common/constructs`의 `core/api/ecs-http-endpoint.ts` 구성체 하나에 의해 생성되며, ECS에서 호스팅되는 모든 API가 공유합니다. API 자체의 구성체는 컨테이너 서비스의 이름을 지정하고 모든 작업을 해당 엔드포인트로 라우팅합니다.

### 컨테이너에서 실행되는 것

`<module_name>/<api_name>_container/main.py`는 `main.py`에서 앱을 가져오므로 작성하는 모든 작업은 Lambda에서와 정확히 동일하게 제공됩니다. 자체적으로 두 가지를 추가합니다:

- `GET /health`, 로드 밸런서의 타겟 그룹과 컨테이너 상태 확인이 호출합니다. `include_in_schema=False`로 선언되어 OpenAPI 사양에서 제외되므로 API Gateway 라우트 및 생성된 클라이언트에서도 제외됩니다. 또한 요청 메트릭에서도 제외되므로 타겟 그룹의 15초마다 호출은 API 요청으로 계산되지 않습니다.
- API 자체 미들웨어가 수집하는 메트릭을 작성하는 미들웨어. Lambda에서는 핸들러가 각 호출이 끝날 때 이를 수행합니다. 이 서버는 요청 간에 존재하므로 스스로 플러시합니다.

API Gateway 라우트는 여전히 OpenAPI 사양에서 가져오므로 추가하는 작업은 `nx build`가 사양을 재생성하면 배포됩니다.

### 관찰성

로그 및 메트릭은 Lambda에서와 동일하게 작동합니다: 컨테이너는 자체 CloudWatch 로그 그룹에 쓰고, 메트릭은 CloudWatch Logs가 추출할 수 있도록 임베디드 메트릭 형식으로 작성됩니다.

메트릭에 대한 한 가지는 여기서 다르며, 대시보드를 읽거나 자체 메트릭을 추가하기 전에 알아두면 좋습니다. 위의 <a href="#metrics">Metrics</a> 섹션에서 `.init`에서 가져오라고 알려주는 객체인 `metrics`는 Powertools `Metrics`이며, 프로세스의 모든 `Metrics` 객체는 하나의 메트릭 저장소를 공유합니다. Lambda에서는 하나의 호출이 처음부터 끝까지 해당 저장소를 소유합니다. uvicorn 서버는 동시에 요청을 처리하며, API 자체의 요청별 메트릭과 추가하는 모든 메트릭이 해당 하나의 저장소로 이동하므로 함께 진행 중인 두 요청의 메트릭이 하나의 문서에 작성되고 먼저 추가된 라우트에 귀속될 수 있습니다. 다른 요청의 문서는 `route` 차원이 전혀 없이 나올 수 있으며, 첫 번째 플러시 후에 추가된 메트릭만 보유하고, 이런 일이 발생하면 Powertools는 `PowertoolsUserWarning: Dimension 'route' has already been added`를 로깅합니다. 요청이 거의 겹치지 않는 가벼운 트래픽에서는 이를 볼 수 없습니다.

따라서 ECS에서 라우트별 `RequestCount` 및 `Success`를 대략적인 것으로 취급하세요. 정확히 하나의 요청에 귀속되는 메트릭이 필요한 경우, 요청에서 생성하고 반환하기 전에 플러시하는 `EphemeralMetrics`에 추가하세요. 이는 자체 저장소를 유지합니다:

```python
from aws_lambda_powertools.metrics import EphemeralMetrics, MetricUnit

@app.get("/items/{item_id}")
def read_item(item_id: int):
    request_metrics = EphemeralMetrics()
    request_metrics.add_metric(name="ItemViewed", unit=MetricUnit.Count, value=1)
    request_metrics.flush_metrics()
    return {"item_id": item_id}
```

AWS X-Ray 추적은 그렇지 않습니다. `@tracer.capture_method`는 Lambda 외부에서 no-op이며, 세그먼트를 수신할 태스크에 X-Ray 데몬도 없습니다. 추적이 필요한 경우 컨테이너 서비스에 사이드카로 추가하세요.

API Gateway HTTP API의 액세스 로그는 API에 도달하는 모든 요청을 기록합니다. 로드 밸런서는 `EcsHttpEndpoint` 구성체가 생성하는 버킷에 자체 액세스 로그를 작성하며, 여기서 어떤 태스크가 요청을 제공했는지와 무엇을 응답했는지 확인할 수 있습니다.

### 이미지 빌드 및 스캔

컨테이너 생성기는 API 이름을 따서 명명된 이미지 타겟을 제공합니다:

- `<api-name>-container-docker`는 linux/arm64 이미지를 빌드하며, 먼저 번들을 실행하여 이미지가 패키지와 종속성을 보유하도록 합니다.
- `<api-name>-container-trivy`는 해당 이미지의 취약점을 스캔합니다.

이미지가 빌드되는 방법은 <Link path="/guides/py-container">Python Container Service</Link>를 참조하고, 배포 시 게시되는 방법은 <Link path="/guides/docker-bundling">Docker Bundling</Link>을 참조하세요.

### 제한 사항

- **통합 타임아웃.** API Gateway HTTP API는 통합을 약 30초로 제한합니다. 그보다 오래 걸리는 작업은 컨테이너가 얼마나 오래 작동하든 게이트웨이에서 실패합니다.
- **스트리밍 없음.** 스트리밍 작업에는 `rest-lambda` 인프라가 필요합니다. HTTP API는 응답을 스트리밍할 수 없습니다.
- **페이로드 크기.** 요청 및 응답은 API Gateway의 10 MB 제한을 따릅니다.
- **모든 작업에 대한 하나의 서비스.** `integrationPattern`은 `shared`입니다: 하나의 컨테이너 서비스가 있고 모든 라우트가 여기로 라우팅됩니다. 이 인프라에 대해 옵션은 항상 `shared`로 해결되며, `isolated`는 경고와 함께 무시됩니다.

### 비용

로드 밸런서는 Lambda와 비교하여 새로운 고정 비용입니다. Lambda에서는 요청당 비용을 지불하고 유휴 상태일 때는 아무것도 지불하지 않습니다. 데이터 전송 전 us-east-1의 대략적인 월별 수치:

| 항목 | 대략 |
| --- | --- |
| 내부 로드 밸런서 | $16 + 로드 밸런서 용량 단위 |
| Fargate 태스크, 0.25 vCPU / 0.5 GB arm64 | 태스크당 $7 |
| NAT 게이트웨이, VPC에 있는 경우 | $33 |
| VPC 링크 | 시간당 요금 없음 |
| 로드 밸런서의 액세스 로그를 위한 S3 스토리지 | 월 GB당 센트 |

따라서 단일 태스크 서비스는 트래픽이 없을 때 월 약 $23의 비용이 들며, 전달하는 VPC에 NAT 게이트웨이가 있으면 더 많이 듭니다. 액세스 로그는 트래픽과 함께 증가합니다: `endpoint.accessLogsBucket`에 수명 주기 규칙을 추가하여 만료시키세요. 리전의 현재 가격은 [Elastic Load Balancing](https://aws.amazon.com/elasticloadbalancing/pricing/) 및 [AWS Fargate](https://aws.amazon.com/fargate/pricing/) 가격 페이지를 확인하세요.
