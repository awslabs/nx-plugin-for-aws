기존 `py#agent`에 Langfuse 트레이스 보기를 추가하여 로컬 개발 중과 배포 후 모두 사용할 수 있습니다. 이 실험적 컴포넌트 생성기는 **Python Strands, HTTP, AgentCore zip 배포(`infra: agentcore`), CDK, IAM 인증**을 지원합니다. 에이전트의 모델, 도구 및 구성된 세션 스토리지를 보존합니다.

다른 언어, 프레임워크, 프로토콜, MCP 서버, 컨테이너, Terraform 및 `infra: none`은 거부됩니다. Langfuse 내보내기는 AgentCore 플랫폼 V1을 선택하며 V2에 대한 CDK 검증에 실패합니다: 자격 증명과 내보내기 연결은 비정규화된 시작 스냅샷에 캡처되어서는 안 됩니다. 생성기는 Langfuse를 배포하거나 시크릿을 생성하지 않습니다.

기존 에이전트는 이 생성기를 실행하지 않는 한 생성된 트레이싱 설정을 계속 사용합니다. Langfuse는 다음 로컬 `dev` 실행 시 시작되며, 배포된 에이전트는 재빌드 및 재배포 후 전환됩니다. 실험적 생성기로서 출력은 업그레이드 마이그레이션 없이 변경될 수 있으며, 사용자는 이러한 변경 사항을 직접 검토하고 조정해야 합니다.

## CloudWatch 영향

:::caution[애플리케이션 트레이스가 Langfuse로 이동]
배포된 에이전트의 경우 Langfuse를 활성화하면 ADOT가 비활성화되고 zip 진입점이 변경됩니다. **에이전트, 모델 호출 및 도구의 새 애플리케이션 스팬이 CloudWatch 대신 Langfuse로 이동합니다.** CloudWatch GenAI Observability 및 Transaction Search에서 사라집니다. **이중 내보내기는 지원되지 않습니다.** 로컬 호출도 Langfuse로 내보내지며, stdout/stderr는 로컬 터미널에 유지됩니다.
:::

| 신호 또는 기능 | Langfuse 활성화 시 효과 |
| --- | --- |
| 에이전트/모델/도구 애플리케이션 스팬 | Langfuse로 내보내집니다. 이러한 스팬은 더 이상 `aws/spans` 또는 런타임의 애플리케이션 스팬 스트림으로 전달되지 않습니다. |
| 런타임 서비스 메트릭 | Invocations, Latency, UserErrors 및 SystemErrors는 CloudWatch에서 계속 사용할 수 있습니다. |
| 에이전트 stdout/stderr | Uvicorn 로그 및 애플리케이션 출력은 여전히 런타임의 CloudWatch 로그 그룹으로 이동합니다. 앱에서 출력한 프롬프트나 도구 결과도 AWS 로그에 남을 수 있습니다. |
| ADOT 구조화된 텔레메트리 로그 | ADOT와 함께 비활성화됩니다. 일반 애플리케이션 로그는 독립적으로 계속됩니다. ADOT를 복원하면 구조화된 텔레메트리 로그가 복원됩니다. |
| 별도로 전달되는 AgentCore 서비스 스팬 | 이 애플리케이션 내보내기에 의해 리디렉션되지 않습니다. Memory, Gateway, Identity 및 내장 도구에 대한 별도의 전달 구성을 확인하세요. 이 통합은 전달을 구성하거나 보장하지 않습니다. |
| AgentCore Evaluations | CloudWatch 기반 온라인/배치 평가 및 `CloudWatchAgentSpanCollector`는 이 에이전트의 새 애플리케이션 스팬을 잃습니다. 온디맨드 Evaluate API는 호출자가 제공한 스팬을 수락할 수 있지만, 이 생성기는 대체 수집기를 제공하지 않습니다. |
| 애플리케이션 테스트, 대시보드 및 평가 작업 | 생성된 애플리케이션 테스트는 CloudWatch 트레이스가 필요하지 않습니다. CloudWatch에서 애플리케이션 스팬을 읽는 대시보드, 알람 또는 평가 작업은 해당 새 스팬을 잃습니다. Langfuse를 활성화하기 전에 각 통합에서 사용하는 트레이스 소스를 확인하세요. |

서비스 전달 및 평가 요구 사항에 대해서는 AWS의 [지원되는 평가 텔레메트리](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/supported-frameworks-telemetry.html) 및 [관찰 가능성 구성](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-configure.html)을 참조하세요.

### 데이터 거주지 및 비용

**로컬 및 배포된 호출**의 프롬프트, 완료, 모델 사용량 및 도구 입력/출력이 구성된 Langfuse 엔드포인트로 전송됩니다. Langfuse Cloud를 사용하면 이 데이터가 노트북이나 AWS 환경을 벗어나 타사 서비스로 이동합니다. 자체 호스팅 Langfuse를 사용하면 선택한 호스트로 이동합니다. 내보내기를 활성화하기 전에 데이터 처리 요구 사항에 대해 엔드포인트, 리전, 보존 및 액세스 제어를 확인하세요. 이 생성기는 트레이스 콘텐츠를 수정하지 않습니다.

전환된 애플리케이션 트레이스와 관련된 CloudWatch/X-Ray 사용 요금은 감소하지만, 런타임 메트릭 및 로그 요금은 유지됩니다. Langfuse에는 자체 플랜 또는 호스팅 비용이 있으며, Secrets Manager 및 아웃바운드 전송으로 인해 요금이 추가될 수 있습니다. 이 버전에는 이중 내보내기 비용이 없습니다.

내보내기는 스팬을 일괄 처리하고 각 호출의 최종 응답 프레임 전에 플러시를 시도하며, 10초 가드 내에서 8초 플러시 타임아웃이 있습니다. 이로 인해 최종 응답 프레임 전에 최대 10초의 지연이 추가될 수 있습니다. 내보내기 실패 또는 중단된 프로세스는 여전히 텔레메트리를 잃을 수 있습니다. 트레이스는 영구적인 감사 로그가 아닙니다.

### 시크릿 및 엔드포인트 준비

트레이스 데이터를 보관할 위치를 선택할 때 [AWS에서 Langfuse 자체 호스팅](https://langfuse.com/self-hosting)을 권장합니다. 기존의 보안된 HTTPS 설치를 사용하세요. 이 생성기는 프로비저닝하지 않습니다. 엔드포인트를 명시적으로 선택하면 Langfuse Cloud도 지원됩니다.

에이전트의 AWS 계정 및 리전에 Secrets Manager 시크릿을 생성하세요. JSON에는 Langfuse 프로젝트의 키가 포함된 문자열 필드 `LANGFUSE_PUBLIC_KEY` 및 `LANGFUSE_SECRET_KEY`가 포함되어야 합니다. Secrets Manager 콘솔 또는 승인된 시크릿 관리 프로세스를 사용하세요. 생성기 플래그, 소스 파일, 셸 히스토리 또는 런타임 환경 변수에 키를 넣지 마세요.

이 첫 번째 버전에는 AWS 관리형 Secrets Manager 암호화 키를 사용하세요. 고객 관리형 KMS 키로 암호화된 시크릿에는 이 생성기가 생성하지 않는 추가적이고 명시적으로 범위가 지정된 복호화 권한이 필요합니다.

6자 접미사를 포함한 시크릿의 **전체 ARN**과 AWS에서 이미 호스팅하는 것과 같은 기존 Langfuse 배포의 HTTPS 기본 URL을 전달하세요. 엔드포인트는 **개발 머신과 배포된 에이전트 모두에서** 연결할 수 있어야 합니다. **기본 대상이 없습니다. 첫 사용 시 `--host`가 필요합니다.** 이 실험적 생성기는 `aws`, `aws-us-gov` 및 `aws-cn` 파티션의 ARN을 허용합니다. ISO 파티션은 지원되지 않습니다.

```sh
pnpm nx g @aws/nx-plugin:observability#langfuse \
  --project=my_agent \
  --secretArn="$LANGFUSE_SECRET_ARN" \
  --host=https://langfuse.example.com
```

여기서 `LANGFUSE_SECRET_ARN`에는 키가 아닌 ARN만 포함됩니다. CDK는 정확히 해당 ARN에 대해 `secretsmanager:GetSecretValue`를 부여합니다. 애플리케이션은 프로세스 시작 시 두 키를 한 번 로드하고 메모리에서 Basic 인증을 구성합니다. 키를 교체할 때 런타임 재시작을 준비하세요. 변경되지 않은 CDK 배포는 실행 중인 프로세스를 새로 고치지 않습니다.

CDK 헬퍼는 호스트와 시크릿 ARN을 `agentcore.langfuse.<AgentClass>`의 AppConfig에 작성하여 다른 에이전트의 항목을 보존합니다. 배포된 시작은 에이전트의 기존 AppConfig 읽기 권한을 사용하여 `get_agentcore_runtime_config()`를 통해 이 항목을 읽습니다. 생성된 런타임은 `DISABLE_ADOT_OBSERVABILITY=true`를 설정하여 AgentCore의 관리형 ADOT 파이프라인이 트레이싱을 애플리케이션에 맡기도록 합니다. 호스트와 시크릿 ARN은 런타임 환경 변수가 아닙니다.

`https://langfuse.example.com`을 기존 엔드포인트로 바꾸세요. Langfuse Cloud를 사용하려면 EU의 경우 `https://cloud.langfuse.com` 또는 US의 경우 `https://us.cloud.langfuse.com`과 같은 지역 기본 URL을 명시적으로 전달하세요. 경로 접두사가 지원됩니다. `/api/public/otel` 없이 기본 URL을 제공하세요. URL의 자격 증명, 쿼리 매개변수 및 프래그먼트는 거부됩니다. 반복 실행은 대체를 제공하지 않는 한 이전 호스트와 시크릿을 유지합니다. 입력을 비워두면 저장된 값이 유지됩니다.

내보내기는 `x-langfuse-ingestion-version: 4`와 함께 OTLP/HTTP를 사용합니다. 자체 호스팅 설치는 해당 수집 계약을 지원해야 합니다. 엔드포인트를 선택할 때 Langfuse의 [OpenTelemetry 통합](https://langfuse.com/integrations/native/opentelemetry) 및 [v4 마이그레이션 가이드](https://langfuse.com/integrations/native/opentelemetry/migration-to-v4)를 참조하세요.

### 로컬 실행

`AWS_PROFILE`로 선택한 인증된 AWS 프로필과 같은 일반 AWS 개발 자격 증명을 사용하세요. 해당 ID는 에이전트가 모델 및 도구에 일반적으로 필요한 권한 외에 선택한 시크릿에 대한 `secretsmanager:GetSecretValue`가 필요합니다. 생성된 실행 역할 권한은 배포된 에이전트를 다루지만 개발자 ID에 권한을 부여하지 않습니다.

```sh
pnpm nx run my_agent:dev
```

에이전트의 `dev` 및 `serve` 대상은 자동 리로드와 함께 Uvicorn을 통해 `langfuse_dev.py`를 실행합니다. 호스트와 시크릿 ARN만 저장하고, Secrets Manager에서 키를 읽고, 에이전트를 가져오기 전에 트레이싱을 초기화합니다. **로컬 트레이싱을 시작하는 데 배포된 AppConfig 애플리케이션이 필요하지 않습니다.** 할당된 로컬 포트는 보존됩니다. 키는 로컬 `.env` 파일이나 Langfuse 환경 변수에서 읽지 않습니다.

**로컬 개발은 Langfuse 시크릿 액세스 없이 실행할 수 있습니다.** 구성 또는 자격 증명을 로드할 수 없는 경우 시작 시 경고를 기록하고 로컬 에이전트는 Langfuse 내보내기 없이 계속됩니다. 요청은 시크릿 조회를 재시도하지 않습니다. AWS 자격 증명, 시크릿 읽기 권한 또는 구성을 수정한 다음 `dev`/`serve`를 다시 시작하여 트레이싱을 활성화하세요. 에이전트는 여전히 일반 모델 및 도구 권한이 필요합니다. 배포된 에이전트는 Langfuse 자격 증명을 로드할 수 없을 때 시작 실패를 계속합니다.

생성된 채팅 클라이언트 또는 HTTP 엔드포인트를 사용하여 로컬 에이전트를 호출하세요. 로컬 및 배포된 호출 모두 동일한 Langfuse 대상 및 세션 매핑을 사용합니다. 에이전트의 로컬 HTTP 서버는 정상적인 동작을 유지합니다. HTTPS 요구 사항은 Langfuse 대상에 적용됩니다. `http://localhost:3000`과 같은 노트북 전용 Langfuse 엔드포인트는 지원되지 않습니다.

빌드, OpenAPI 생성 및 생성된 테스트는 Langfuse 키를 가져오지 않습니다. 생성된 오프라인 Python 테스트는 합성 자격 증명과 인메모리 내보내기를 사용하여 로컬 구성과 AppConfig 구성을 모두 확인합니다.

### 빌드, 배포 및 트레이스 확인

<Link path="guides/py-agent">Python 에이전트 가이드</Link>에 설명된 대로 워크스페이스를 빌드하세요. 생성기는 배포 파일을 변경하지만 배포하지는 않습니다.

:::caution[구성 변경에 롤백 가능 배포 사용]
기존 스택에서 Langfuse를 활성화하거나, 호스트 또는 시크릿 ARN을 변경하거나, 통합을 되돌리면 불변 AppConfig 구성 버전이 교체됩니다. 생성된 `deploy-sandbox` 대상은 기본적으로 롤백이 비활성화된 익스프레스 모드를 사용하며, 이는 리소스 교체를 거부하고 스택을 `UPDATE_FAILED` 상태로 남길 수 있습니다.

이러한 변경에는 롤백이 활성화된 표준 배포를 사용하세요. `my_infra`를 인프라 프로젝트 이름으로 바꾸세요:

```sh
pnpm nx run my_infra:deploy-sandbox --no-express --rollback
```

다른 스테이지의 경우 <Link path="guides/typescript-infrastructure">인프라 가이드</Link>에 설명된 대로 명시적 스테이지 또는 스택 선택기와 롤백이 활성화된 `deploy` 대상을 사용하세요.

이전 배포가 이미 스택을 `UPDATE_FAILED` 상태로 남긴 경우 배포 모드를 전환하기 전에 복구하세요. CloudFormation은 스택이 완전한 상태에 도달할 때까지 후속 작업이 동일한 익스프레스 구성을 사용하도록 요구할 수 있습니다. AWS의 [실패한 스택 복구 지침](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/stack-failure-options.html)을 따르세요. 배포 플래그만 변경해도 실패한 스택이 복구되지 않습니다.
:::

도구를 호출하는 프롬프트로 로컬 또는 배포된 에이전트를 호출하세요. Langfuse UI에서 트레이스 세부 정보 보기를 열고 호출 루트, 에이전트/모델/도구 자식 및 입력/출력 콘텐츠를 확인하세요. 모델(생성) 관찰을 선택하여 토큰 사용량을 확인하세요. 트레이스의 세션을 열어 AgentCore 세션 ID를 확인한 다음 해당 세션에서 짧은 요청을 반복하여 플러싱 및 그룹화를 확인하세요.

애플리케이션 루트는 업스트림 AWS 트레이스 및 부모 ID를 유지합니다. Langfuse SDK는 AWS 서비스 부모가 Langfuse로 내보내지지 않더라도 논리적 애플리케이션 루트로 표시합니다.

33자에서 200자 사이의 세션 ID는 Langfuse에서 변경되지 않고 나타납니다. 더 긴 ID는 64자 SHA-256 16진수 다이제스트를 Langfuse 세션 ID로 사용하므로 반복된 요청이 여전히 동일한 세션에 나타납니다. 이 매핑은 Langfuse 그룹화만 변경합니다. 애플리케이션으로 전송된 AgentCore 세션 ID는 변경되지 않습니다. 누락된 ID 또는 33자 미만의 ID는 해당 호출에 대해 새 UUID를 가져옵니다. 생성된 클라이언트는 이러한 제한 내에서 UUID를 사용합니다.

## 생성된 파일 및 반복 실행

생성기는 에이전트 옆에 `langfuse_telemetry.py` 및 `langfuse_dev.py`, 별도의 `package/<agent>/langfuse_main.py` 진입점 및 Python 내보내기 테스트를 추가합니다. 기존 CDK 구성을 `langfuse-observability.ts`에 연결하고, 배포 진입점을 zip에 복사하고, 종속성을 선언합니다. 스톡 ADOT 런처는 패키지로 유지됩니다.

Langfuse 진입점은 에이전트를 가져오기 전에 하나의 공급자를 생성합니다. FastAPI의 중복 트레이싱은 해당 프로세스에서만 비활성화됩니다. 네이티브 Strands 스팬은 동일한 공급자를 사용합니다. Langfuse SDK의 공개 관찰 API는 애플리케이션 루트 및 세션 속성을 제공합니다. 호출 입력/출력 캡처는 각각 1MiB로 제한됩니다. 루트는 해당 제한을 초과할 때 `content_truncated`를 기록합니다.

종속성 세트는 Langfuse 4.18.0 및 ADOT 0.24.0을 사용합니다. 제공된 OpenTelemetry 핀은 API/SDK/HTTP 내보내기 1.45.2를 포함하여 ADOT의 요구 사항과 일치하며 해당 호환성을 유지하기 위해 유지됩니다. ADOT 및 Langfuse는 리포지토리의 정기적인 종속성 업데이트 대상으로 유지됩니다. 업그레이드할 때 호환성을 확인하고 OpenTelemetry 핀을 조정하세요. Starlette는 FastAPI의 종속성 요구 사항을 따릅니다.

동일한 입력으로 생성기를 반복해도 배선이 중복되거나 런타임 편집을 덮어쓰지 않습니다. 여전히 종속성 설치 기본 설정을 존중하므로 실패하거나 연기된 설치를 재시도하기 위해 다시 실행할 수 있습니다. 호스트 또는 시크릿을 변경하면 로컬 진입점과 CDK 구성이 모두 업데이트됩니다. 로컬 개발을 다시 시작하고, 재빌드하고, [롤백 가능 배포 명령](#build-deploy-and-check-a-trace)을 사용하여 두 환경 모두에 변경 사항을 적용하세요. 구성을 편집하거나 로컬 시작 명령을 사용자 지정하는 경우 생성기는 옵션을 변경하기 전에 조정하도록 요청합니다. 이렇게 하면 옵션 변경이 사용자 지정 배선을 자동으로 교체하는 것을 방지합니다.

`langfuse_dev.py` 없이 이전 실험적 설정은 되돌리고 업데이트된 생성기로 재생성해야 합니다. 사용자 지정을 별도로 보존하고 다시 적용하세요.

## CloudWatch로 다시 전환

Langfuse 생성기의 변경 사항이 포함된 전용 커밋을 되돌리세요:

```sh
git revert <langfuse-setup-commit>
```

후속 에이전트 변경과의 충돌에 대해 되돌리기를 검토하세요. 다른 생성기가 `packages/common/constructs/src/core/app.ts`의 동일한 배열에 사용량 메트릭 태그를 추가했을 수 있습니다. 충돌을 해결할 때 해당 태그를 보존하세요. 다른 에이전트가 여전히 Langfuse를 사용하지 않는 경우에만 Langfuse 태그(`g79`)를 제거하고 나머지 통합에 필요한 공유 종속성을 보존하세요.

워크스페이스 종속성을 다시 설치하고, 재빌드한 다음 [롤백 가능 배포 명령](#build-deploy-and-check-a-trace)을 사용하여 재배포하세요. AppConfig 항목을 제거하려면 리소스 교체도 필요합니다. 이 단계에서는 기본 익스프레스 명령을 사용하지 마세요. 전체 설정을 되돌리면 스톡 ADOT 진입점과 로컬 시작 명령이 복원되고 Langfuse 배선, 파일, 종속성 추가, 런타임 설정 및 시크릿 읽기 권한이 제거됩니다. 실행 중인 로컬 `dev` 프로세스를 다시 시작하세요. 새 세션으로 배포된 에이전트를 호출하고 CloudWatch에서 새 애플리케이션 트레이스를 확인하세요.

생성기에는 롤백 플래그가 없습니다. 되돌릴 때 제거되지 않도록 관련 없는 변경 사항을 설정 커밋에서 제외하세요.

기존 시크릿은 사용자가 관리해야 합니다. 통합을 되돌려도 백엔드 간에 기록 트레이스를 복사, 삭제 또는 이동하지 않습니다. Langfuse를 다시 활성화하려면 호스트 및 시크릿 ARN으로 생성기를 실행하세요.
