이 생성기는 기존 TypeScript 프로젝트에 컨테이너화된 HTTP 서비스를 추가합니다. `GET /health` 라우트가 있는 작은 HTTP 서버, Dockerfile, 그리고 서버를 로컬에서 실행하고 이미지를 빌드하고 스캔하는 타겟을 얻게 됩니다. 또한 [Amazon Elastic Container Service (Amazon ECS)](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/Welcome.html)에서 이미지를 실행하는 CDK 또는 Terraform 코드를 얻게 됩니다. Amazon ECS는 컨테이너를 실행하고 확장하는 AWS 서비스입니다.

서비스는 [AWS Fargate](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/AWS_Fargate.html)에서 실행되며, 관리할 서버 없이 각 컨테이너를 실행합니다. 자체 VPC(가상 프라이빗 클라우드, AWS 계정의 격리된 네트워크) 내에서 실행되며, VPC 내부 주소만 접근할 수 있는 내부 [Application Load Balancer](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html) (ALB) 뒤에 있습니다. 기본적으로 [Amazon API Gateway HTTP API](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api.html)가 호출자로부터 요청을 받아 VPC 링크(API Gateway의 VPC로의 프라이빗 연결)를 통해 ALB로 전달합니다. 호출자는 인증된 HTTPS 엔드포인트를 얻으며, 로드 밸런서는 인터넷에 노출되지 않습니다.

### 옵션

<GeneratorParameters generator="ts#container" />

`infra`, `ingress`, `auth` 옵션은 서로 의존적입니다. `infra`가 `none`으로 설정되면 생성기는 인프라를 생성하지 않으며, 경고와 함께 `ingress`와 `auth`를 무시합니다. `ingress`는 `infra`가 `ecs`로 설정된 경우에만 적용됩니다. `auth`는 `ingress`가 `http-api`로 설정된 경우에만 적용됩니다. `private` 서비스는 인증할 HTTP API가 없기 때문입니다.

## 생성기 출력

생성기는 프로젝트에 다음 파일을 추가합니다. 소스 폴더는 `name` 옵션의 이름을 따르거나, 생략하면 `service`로 명명됩니다:

<FileTree>
  - your-project/
    - src/
      - service/ (또는 선택한 이름)
        - server.ts HTTP 라우트: `GET /health` 및 샘플 라우트 `GET /hello`
        - index.ts `PORT`를 읽고 서버를 시작하는 진입점. 번들과 `<name>-serve` 타겟이 이 파일에서 시작됩니다
        - Dockerfile 컨테이너 이미지 정의
        - .dockerignore 이미지 빌드 컨텍스트에서 제외되는 파일
    - rolldown.config.ts `index.ts`에 대한 번들 엔트리로 업데이트됨
    - project.json `bundle` 타겟과 서비스를 위한 `<name>-serve`, `<name>-docker`, `<name>-trivy` 타겟으로 업데이트됨
</FileTree>

타겟 이름은 `name` 옵션으로 시작하거나, 생략하면 `service`로 시작합니다. 예를 들어, 이름 없이는 타겟이 `service-serve`, `service-docker`, `service-trivy`이고, `--name=orders`의 경우 `orders-serve`, `orders-docker`, `orders-trivy`입니다. `bundle` 타겟은 프로젝트의 모든 번들된 진입점에서 공유됩니다.

## 로컬에서 서비스 실행하기

`<name>-serve` 타겟은 컨테이너 없이 머신에서 서버를 실행합니다:

<NxCommands commands={['run your-project:service-serve']} />

서버는 `PORT` 환경 변수의 포트에서 수신합니다. `<name>-serve` 타겟은 생성기가 할당한 포트로 설정하며, 8081부터 시작하여 워크스페이스의 다른 프로젝트가 이미 사용 중인 포트는 건너뜁니다. 컨테이너 내부에서 서버는 포트 8080에서 수신합니다.

상태 200과 `{"status":"ok"}`를 반환하는 헬스 라우트로 서버가 실행 중인지 확인하세요:

```bash
curl http://localhost:<port>/health
```

서버에는 자체 라우트로 교체할 샘플 라우트도 있습니다. `GET /hello?name=<x>`는 `{"message":"Hello, <x>!"}`를 반환하며, `name`의 기본값은 `world`입니다. 다른 경로는 상태 404를 반환합니다.

## 이미지 빌드 및 스캔

`<name>-docker` 타겟은 서비스의 linux/arm64 이미지를 빌드합니다. 먼저 `bundle` 타겟을 실행하므로 이미지에는 번들된 서버가 포함됩니다. 그런 다음 `Dockerfile`과 `.dockerignore`를 번들 출력 폴더 `dist/<project root>/bundle/container/<name>`에 복사하고, 해당 폴더를 빌드 컨텍스트(이미지 빌드가 읽을 수 있는 파일)로 사용하여 이미지를 빌드합니다. 워크스페이스에 설정된 컨테이너 엔진인 `docker` 또는 [Finch](https://runfinch.com/)를 사용합니다. 이 타겟은 프로젝트의 모든 이미지를 빌드하는 집계 `docker` 타겟의 일부로 실행됩니다.

<NxCommands commands={['run your-project:service-docker']} />

로드 밸런서의 대상 그룹(로드 밸런서가 요청을 보내는 작업 목록)만 `GET /health`를 확인하여 작업이 트래픽을 받을 준비가 되었는지 결정합니다. ECS는 Dockerfile의 `HEALTHCHECK` 명령을 무시합니다. 이미지가 빌드되고 게시되는 방법에 대한 자세한 내용은 <Link path="/guides/docker-bundling">Docker Bundling</Link>을 참조하세요.

## 서비스 배포하기

### 인프라에 서비스 추가하기

구성과 모듈은 VPC를 생성하지 않습니다. 스택이나 루트 모듈에서 VPC를 생성하거나 가져와서 전달합니다. 작업과 로드 밸런서는 송신이 가능한 프라이빗 서브넷에서 실행되며, NAT 게이트웨이(프라이빗 서브넷이 아웃바운드 연결을 할 수 있게 하는 관리형 게이트웨이) 또는 VPC 엔드포인트(VPC에서 AWS 서비스로의 프라이빗 연결)를 통해 AWS 서비스에 도달합니다.

<Infrastructure>
<Fragment slot="cdk">
CDK 구성은 `common/constructs`에 생성되며 서비스 이름을 따릅니다. 새 VPC를 사용한 예제:

```ts title="packages/infra/src/stacks/application-stack.ts"
import { MyService } from '@my-scope/common-constructs';
import { Stack, StackProps } from 'aws-cdk-lib';
import { SubnetType, Vpc } from 'aws-cdk-lib/aws-ec2';
import { Construct } from 'constructs';

export class ApplicationStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props);

    const vpc = new Vpc(this, 'Vpc', { natGateways: 1 });

    new MyService(this, 'MyService', {
      vpc,
      vpcSubnets: { subnetType: SubnetType.PRIVATE_WITH_EGRESS },
    });
  }
}
```

기존 VPC를 사용하려면 `Vpc.fromLookup(this, 'Vpc', { vpcId: '<vpc-id>' })`로 조회하고 `vpc`로 전달하세요.
</Fragment>
<Fragment slot="terraform">
Terraform 모듈은 `common/terraform`에 생성됩니다. 서비스의 이미지는 공유 자산 리포지토리에 게시되므로, 배포당 한 번 `core/asset-ecr` 모듈을 인스턴스화하고 그 출력을 모든 서비스 모듈에 전달합니다. 또한 서비스가 <Link path="/guides/runtime-config">런타임 구성</Link>을 읽는 AWS AppConfig 애플리케이션을 보유한 공유 `runtime_config_appconfig` 모듈의 출력도 전달합니다:

```hcl title="packages/infra/src/main.tf"
module "asset_ecr" {
  source = "../../common/terraform/src/core/asset-ecr"
}

module "my_service" {
  source = "../../common/terraform/src/app/services/my-service"

  vpc_id     = aws_vpc.main.id
  subnet_ids = aws_subnet.private[*].id

  asset_ecr_repository_url = module.asset_ecr.repository_url
  asset_ecr_repository_arn = module.asset_ecr.repository_arn

  appconfig_application_id  = module.runtime_config_appconfig.application_id
  appconfig_application_arn = module.runtime_config_appconfig.application_arn
}
```

### 요청 제한

API Gateway는 30초 후 서비스 대기를 중지하고 호출자에게 오류를 반환합니다. 이 통합 타임아웃은 늘릴 수 없습니다. HTTP API가 허용하는 최대 요청 페이로드는 10MB이며, 이 제한도 늘릴 수 없습니다. 두 값 모두 [Amazon API Gateway quotas for HTTP APIs](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-quotas.html) 페이지에서 확인할 수 있습니다.

따라서 30초보다 오래 실행되는 요청과 오랜 시간 동안 데이터를 스트리밍하는 응답은 HTTP API를 통해 작동하지 않습니다. 이러한 경우 `ingress`를 `private`로 설정하고 VPC 내부에서 내부 로드 밸런서를 호출하세요.
</OptionFilter>

<OptionFilter when={{ infra: 'ecs' }} description="Networking, security, calling, advanced configuration, cost and destroy">
### NAT Gateway 없이 실행하기

작업이 시작되면 ECS는 이미지를 가져오고 대신 로그를 전송합니다. 서버 코드도 AWS 서비스를 호출할 수 있습니다. NAT 게이트웨이가 없는 프라이빗 서브넷에서는 이러한 각 호출에 VPC 엔드포인트가 필요합니다. 올바른 엔드포인트가 없으면 작업이 시작에 실패하거나 AWS를 호출할 때 타임아웃됩니다.

VPC에 다음 엔드포인트를 생성하고, `<region>`을 AWS 리전으로 교체하세요:

| 엔드포인트 | 유형 | 사용처 |
| --- | --- | --- |
| `com.amazonaws.<region>.ecr.api` | Interface | ECS, Amazon ECR로 인증하고 이미지 조회 |
| `com.amazonaws.<region>.ecr.dkr` | Interface | ECS, Amazon ECR에서 이미지 가져오기 |
| `com.amazonaws.<region>.s3` | Gateway | ECS, Amazon ECR이 Amazon S3에 저장하는 이미지 레이어 다운로드 |
| `com.amazonaws.<region>.logs` | Interface | 컨테이너의 로그 출력, Amazon CloudWatch Logs로 전송 |
| `com.amazonaws.<region>.secretsmanager` | Interface | ECS, 작업 시작 시 컨테이너에 전달하는 시크릿 읽기 |
| `com.amazonaws.<region>.appconfigdata` | Interface | 코드, AWS AppConfig에서 <Link path="/guides/runtime-config">런타임 구성</Link> 읽기 |
| `com.amazonaws.<region>.sts` | Interface | 코드, AWS STS에서 임시 자격 증명 요청 시(예: 다른 역할 가정) |

인터페이스 엔드포인트는 작업에서 HTTPS(포트 443)를 허용하는 보안 그룹이 필요합니다. Amazon ECR 엔드포인트에 대한 자세한 내용은 [Amazon ECR interface VPC endpoints](https://docs.aws.amazon.com/AmazonECR/latest/userguide/vpc-endpoints.html)를 참조하세요.

### 보안 기본값

생성된 인프라는 기본적으로 다음 설정을 적용합니다:

- 로드 밸런서는 내부용입니다. 어떤 보안 그룹도 `0.0.0.0/0` 또는 `::/0`에서의 인바운드 트래픽을 허용하지 않습니다.
- 작업은 프라이빗 서브넷에서 실행되며 퍼블릭 IP 주소를 받지 않습니다.
- 로드 밸런서는 VPC 링크(`http-api`) 또는 VPC의 주소 범위(`private`)에서만 트래픽을 허용합니다. 작업은 컨테이너 포트에서 로드 밸런서로부터만 트래픽을 허용합니다.
- 작업은 포트 443에서만 아웃바운드 트래픽을 보낼 수 있습니다. 데이터베이스 연결은 데이터베이스 포트를 추가합니다.
- 작업 역할(서버 코드가 실행되는 역할)은 사용자나 연결이 더 많은 권한을 부여할 때까지 AWS AppConfig에서 런타임 구성만 읽을 수 있습니다.
- 실행 역할(ECS가 작업을 시작하는 데 사용하는 역할)은 서비스의 이미지를 가져오고, 로그 그룹에 쓰고, 나열한 시크릿만 읽을 수 있습니다.
- 시크릿은 AWS Secrets Manager 또는 AWS Systems Manager Parameter Store에 대한 참조로만 컨테이너에 도달하며, 일반 환경 값으로는 절대 전달되지 않습니다.
- 컨테이너는 읽기 전용 루트 파일 시스템을 가지며 uid 1000, 비루트 사용자로 실행됩니다. ECS Exec(실행 중인 작업에 대한 셸 액세스)는 꺼져 있습니다.
- 헬스 체크에 실패한 배포는 중지되고 이전 버전으로 롤백됩니다.
- HTTP API는 액세스 로그를 작성하고 요청을 제한합니다. 다르게 선택하지 않는 한 IAM으로 인증합니다.
- 로그는 1년 동안 보관됩니다.

생성된 코드는 다음 [Checkov](https://www.checkov.io/) 검사를 억제하며(Checkov는 안전하지 않은 설정에 대해 인프라 코드를 스캔합니다), 각 억제 옆에 이유를 명시합니다:

- `CKV_AWS_91`은 로드 밸런서 액세스 로그를 요청합니다. 대신 HTTP API 액세스 로그 또는 서비스 자체 로그가 요청을 기록합니다.
- `CKV_AWS_2`와 `CKV_AWS_103`은 TLS를 사용하는 HTTPS 리스너를 요청합니다. 로드 밸런서는 내부용이고 VPC 내부의 호출자만 도달할 수 있으므로 일반 HTTP를 수신합니다. `http-api`의 경우 TLS는 API Gateway에서 종료됩니다.

Terraform 모듈은 동일한 HTTP 리스너 이유로 `CKV2_AWS_20`과 `CKV_AWS_378`도 건너뛰며, 서비스를 삭제할 수 있도록 로드 밸런서 삭제 보호가 꺼져 있기 때문에 `CKV_AWS_150`도 건너뜁니다.

### 서비스 호출하기

서비스의 URL은 <Link path="/guides/runtime-config">런타임 구성</Link>에 `connection.services.<NameClassName>`으로 작성됩니다. 여기서 `<NameClassName>`은 PascalCase의 서비스 이름입니다. `--name=orders`의 경우 키는 `Orders`입니다. 이름이 없으면 서비스 이름은 `<project>-service`이므로, `my-project`라는 프로젝트의 경우 키는 `MyProjectService`입니다. 이 경우 소스 폴더와 타겟 접두사는 여전히 `service`입니다.

<Tabs syncKey="auth">
<TabItem label="IAM" _filter={{ ingress: 'http-api', auth: 'iam' }}>
호출자는 API를 호출할 수 있는 AWS 자격 증명을 사용하여 `execute-api` 서비스에 대한 [AWS Signature Version 4 (SigV4)](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_sigv.html)로 각 요청에 서명합니다. API Gateway는 서비스에 도달하기 전에 유효한 서명이 없는 요청을 거부합니다.

<Infrastructure>
<Fragment slot="cdk">
`grantInvoke`로 역할이나 함수에 서비스를 호출할 권한을 부여합니다:

```ts title="packages/infra/src/stacks/application-stack.ts"
const service = new MyService(this, 'MyService', { vpc });
service.grantInvoke(myFunction);
```
</Fragment>
<Fragment slot="terraform">
서비스 모듈이 `api_execution_arn`으로 출력하는 API의 실행 ARN에 대한 `execute-api:Invoke` 정책으로 역할에 서비스를 호출할 권한을 부여합니다:

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_role_policy" "invoke_my_service" {
  role = aws_iam_role.caller.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["execute-api:Invoke"]
      Resource = ["${module.my_service.api_execution_arn}/*"]
    }]
  })
}
```
</Fragment>
</Infrastructure>
</TabItem>
<TabItem label="Cognito" _filter={{ ingress: 'http-api', auth: 'cognito' }}>
호출자는 `Authorization` 헤더에 Amazon Cognito 사용자 풀에서 발급한 JSON Web Token (JWT)을 보냅니다. HTTP API는 토큰이 사용자 풀에서 왔으며 허용된 앱 클라이언트 중 하나에 발급되었는지 확인합니다.

<Infrastructure>
<Fragment slot="cdk">
Cognito 서비스에 대해 생성된 구성은 `auth` prop을 받지 않습니다. 대신 필수 `identity` prop에 사용자 풀과 앱 클라이언트를 전달합니다:

```ts title="packages/infra/src/stacks/application-stack.ts"
new MyService(this, 'MyService', {
  vpc,
  identity: { userPool, userPoolClient },
});
```
</Fragment>
<Fragment slot="terraform">
서비스 모듈 `app/services/<name>/<name>.tf`의 필수 `user_pool_id`와 `user_pool_client_ids` 변수를 설정합니다. 모듈은 이를 `ecs-service` 모듈로 전달합니다.
</Fragment>
</Infrastructure>
</TabItem>
<TabItem label="None" _filter={{ ingress: 'http-api', auth: 'none' }}>
HTTP API는 인증 없이 요청을 허용합니다. URL을 아는 사람은 누구나 서비스를 호출할 수 있으므로 자체 코드에서 호출자를 확인하세요.
</TabItem>
<TabItem label="Private" _filter={{ ingress: 'private' }}>
`private` 서비스에는 HTTP API가 없습니다. URL은 내부 로드 밸런서의 주소이며, VPC 내부의 호출자만 도달할 수 있습니다. 로드 밸런서는 리스너 포트에서 VPC의 주소 범위로부터 트래픽을 허용합니다. 예를 들어, 동일한 VPC의 Lambda 함수나 다른 ECS 서비스에서 호출하세요.
</TabItem>
</Tabs>

### 고급 구성

생성된 서비스는 이름, `ingress`, `auth`를 설정합니다. 아래 예제는 생성된 서비스가 전달하지 않는 설정이나 인스턴스별로 `ingress`와 `auth`를 선택하기 위해 범용 `EcsService` 구성과 `ecs-service` 모듈을 직접 사용합니다.

CDK에서 `common-constructs` 패키지는 서비스 구성 옆에 `EcsService`를 내보내므로 동일한 방식으로 가져옵니다: `import { EcsService } from '@my-scope/common-constructs'`. 생성된 구성은 `EcsService`를 확장하고 다른 모든 prop을 전달합니다. 예를 들어 `cluster`, `loadBalancer`, `environment`, `secrets`, `grantTaskRole`입니다. 선택적 `image` prop은 프로젝트에서 빌드된 이미지를 대체합니다. `auth` prop은 없습니다. Cognito 서비스는 대신 `identity`를 받으며, 다른 서비스는 항상 생성된 `auth`를 사용합니다.

Terraform에서 서비스 모듈은 `ecs-service` 모듈의 일부 변수만 설정할 수 있습니다: `vpc_id`, `subnet_ids`, `cluster_arn`, `environment`, `secrets`, `task_role_policy_statements`, `tags`, 그리고 Cognito 서비스의 경우 `user_pool_id`와 `user_pool_client_ids`입니다. 다른 변수를 설정하려면 서비스 모듈의 `module "ecs_service"` 블록을 편집하세요.

#### 사전 빌드된 이미지

이미 빌드된 이미지를 실행하려면, 예를 들어 퍼블릭 레지스트리에서, URI를 전달합니다. 로컬에서는 아무것도 빌드되지 않습니다. 프라이빗 Amazon ECR 리포지토리의 이미지의 경우, CDK는 해당 리포지토리에 대한 실행 역할 풀 액세스를 부여합니다. Terraform은 `image_repository_arn`도 전달할 때만 풀 액세스를 부여합니다.

<Infrastructure>
<Fragment slot="cdk">

```ts
new EcsService(this, 'Prebuilt', {
  serviceName: 'Prebuilt',
  vpc,
  image: { imageUri: 'public.ecr.aws/my-org/my-image@sha256:<digest>' },
});
```

</Fragment>
<Fragment slot="terraform">

```hcl
module "prebuilt" {
  source = "../../common/terraform/src/core/container/ecs-service"

  service_name = "Prebuilt"
  vpc_id       = aws_vpc.main.id
  subnet_ids   = aws_subnet.private[*].id
  image_uri    = "public.ecr.aws/my-org/my-image@sha256:<digest>"
  # For an image in a private Amazon ECR repository, also pass:
  # image_repository_arn = aws_ecr_repository.my_image.arn
}
```

</Fragment>
</Infrastructure>

#### 로드 밸런서가 없는 워커

워커는 큐에서 읽거나 백그라운드 작업을 실행하며, 아무것도 호출하지 않습니다. 로드 밸런서를 끄면 로드 밸런서, HTTP API, URL이 없는 서비스를 얻습니다.

<Infrastructure>
<Fragment slot="cdk">

```ts
new EcsService(this, 'Worker', {
  serviceName: 'Worker',
  vpc,
  image: { directory: '<path to the folder with the Dockerfile>' },
  loadBalancer: false,
});
```

</Fragment>
<Fragment slot="terraform">
사전 빌드된 이미지와 마찬가지로, Terraform은 `image_repository_arn`을 전달할 때만 프라이빗 Amazon ECR 리포지토리에 대한 풀 액세스를 부여합니다.

```hcl
module "worker" {
  source = "../../common/terraform/src/core/container/ecs-service"

  service_name  = "Worker"
  vpc_id        = aws_vpc.main.id
  subnet_ids    = aws_subnet.private[*].id
  image_uri     = "<image uri pinned by digest>"
  load_balancer = false
  # For an image in a private Amazon ECR repository, also pass:
  # image_repository_arn = aws_ecr_repository.my_image.arn
}
```

</Fragment>
</Infrastructure>

#### 하나의 스택에 여러 서비스

각 서비스는 전달하지 않는 한 자체 ECS 클러스터를 생성합니다. 여러 서비스를 하나의 클러스터에서 실행하려면 각각에 동일한 클러스터를 전달하세요.

각 HTTP API 서비스는 서비스가 클러스터를 공유하더라도 자체 VPC 링크를 생성합니다. API Gateway는 기본적으로 계정당 리전당 10개의 VPC 링크를 허용하며, 증가를 요청할 수 있습니다.

<Infrastructure>
<Fragment slot="cdk">

```ts
const cluster = new Cluster(this, 'Cluster', { vpc });

new MyService(this, 'MyService', { vpc, cluster });
new MyOtherService(this, 'MyOtherService', { vpc, cluster });
```

</Fragment>
<Fragment slot="terraform">
각 `ecs-service` 모듈에 동일한 `cluster_arn`을 전달합니다. 첫 번째 서비스의 `cluster_arn` 출력이 하나를 제공합니다:

```hcl
cluster_arn = module.my_service.cluster_arn
```

</Fragment>
</Infrastructure>

#### 환경 변수 및 시크릿

일반 설정은 `environment`에 넣습니다. 작업 정의를 읽을 수 있는 사람은 누구나 읽을 수 있으므로 시크릿 값은 절대 넣지 마세요. 대신 시크릿을 참조로 전달합니다. 실행 역할은 나열한 시크릿만 읽을 수 있습니다.

<Infrastructure>
<Fragment slot="cdk">

```ts
new EcsService(this, 'MyService', {
  // ...
  environment: { LOG_LEVEL: 'info' },
  secrets: { API_KEY: Secret.fromSecretsManager(apiKeySecret) },
});
```

</Fragment>
<Fragment slot="terraform">

```hcl
environment = { LOG_LEVEL = "info" }
secrets     = { API_KEY = aws_secretsmanager_secret.api_key.arn }
```

</Fragment>
</Infrastructure>

#### 크기 조정 및 스케일링

각 작업은 기본적으로 256 CPU 단위(vCPU의 1/4)와 512MiB의 메모리를 받습니다. 서비스는 하나의 작업을 시작하고, 오토스케일링은 평균 CPU 사용량이 70%를 초과하면 작업을 추가하여 1개에서 2개 사이의 작업을 유지합니다.

| 설정 | CDK prop | Terraform 변수 | 기본값 |
| --- | --- | --- | --- |
| 작업당 CPU 단위 | `cpu` | `cpu` | 256 |
| 작업당 메모리 (MiB) | `memoryLimitMiB` | `memory` | 512 |
| 시작 시 작업 수 | `desiredCount` | `desired_count` | 1 |
| 최소 작업 수 | `minCapacity` | `min_capacity` | 1 |
| 최대 작업 수 | `maxCapacity` | `max_capacity` | 2 |
| 목표 평균 CPU (%) | `targetCpuUtilizationPercent` | `target_cpu_utilization` | 70 |

#### 작업 역할 권한

서비스 구성이나 모듈의 작업 역할은 런타임 구성에 대한 읽기 액세스만으로 시작합니다. 코드에 필요한 권한을 추가하세요:

<Infrastructure>
<Fragment slot="cdk">

```ts
new EcsService(this, 'MyService', {
  // ...
  grantTaskRole: (taskRole) => myTable.grantReadData(taskRole),
});
```

</Fragment>
<Fragment slot="terraform">

```hcl

  Effect   = "Allow"
  Action   = ["dynamodb:GetItem", "dynamodb:Query"]
  Resource = [aws_dynamodb_table.my_table.arn]
}]
```

</Fragment>
</Infrastructure>

#### 컨테이너 사용자

작업 정의는 컨테이너를 uid 1000, 비루트 사용자로 실행합니다. 이는 제공된 Dockerfile이 설정하는 `node` 사용자와 일치합니다. 다른 사용자로 실행하려면 CDK `user` prop 또는 Terraform `container_user` 변수를 설정하세요. Terraform은 `0`과 `root`를 거부합니다.

| 설정 | CDK prop | Terraform 변수 | 기본값 |
| --- | --- | --- | --- |
| 컨테이너가 실행되는 사용자 | `user` | `container_user` | `'1000'` (CDK), `"1000:1000"` (Terraform) |

#### CORS 및 제한

이러한 설정은 `ingress`가 `http-api`로 설정된 경우에만 적용됩니다. CORS(교차 출처 리소스 공유)는 브라우저에서 서비스를 호출할 수 있는 웹사이트를 결정합니다. 기본적으로 HTTP API는 모든 출처에서, 모든 메서드로, `authorization`, `content-type`, `x-amz-content-sha256`, `x-amz-date`, `x-amz-security-token` 헤더와 함께 브라우저 요청을 허용합니다. 마지막 세 개는 SigV4 서명이 추가하는 헤더입니다. HTTP API는 또한 초당 10,000개의 안정적인 속도로 요청을 제한하며, 최대 5,000개까지 버스트할 수 있습니다.

| 설정 | CDK | Terraform 변수 | 기본값 |
| --- | --- | --- | --- |
| 허용된 CORS 출처 | `restrictCorsTo(...origins)` 메서드, 또는 `corsPreflight` prop | `cors_allow_origins` | 모든 출처 (`["*"]`) |
| 기타 CORS 설정 | `corsPreflight` prop | none | 모든 메서드, 위의 헤더 |
| 제한 | `throttle` prop | none | `{ rateLimit: 10000, burstLimit: 5000 }` |

`corsPreflight` prop은 전체 기본값을 대체하므로 호출자가 보내는 모든 헤더를 나열하세요. `restrictCorsTo` 메서드는 다른 CORS 설정을 유지하고 허용된 출처만 변경합니다:

```ts
const service = new MyService(this, 'MyService', { vpc });
service.restrictCorsTo('https://app.example.com');
```

Terraform에서 `cors_allow_origins`와 `container_user`는 `ecs-service` 모듈의 변수입니다. 서비스 모듈은 이를 전달하지 않으므로 `module "ecs_service"` 블록에서 설정하세요. 제한 값은 `ecs-service.tf`에 고정되어 있습니다.

### 비용

컨테이너 서비스는 Lambda 함수와 달리 유휴 상태일 때도 요금이 청구됩니다. 다음 부분은 서비스를 호출하는지 여부와 관계없이 시간당 요금이 청구됩니다:

- Fargate 작업, vCPU당 및 GB 메모리당. `desiredCount`와 `minCapacity`는 최소 하나의 작업을 실행 상태로 유지합니다.
- Application Load Balancer, 시간당 및 로드 밸런서 용량 단위당.
- 인터페이스 VPC 엔드포인트, 각 가용 영역에서 시간당, 또는 NAT 게이트웨이, 시간당 및 처리하는 데이터 GB당.
- CloudWatch Logs의 로그 스토리지 및 Amazon ECR의 이미지 스토리지.

HTTP API는 요청당 요금이 청구됩니다. 리전 및 트래픽에 대한 비용을 추정하려면 [AWS Pricing Calculator](https://calculator.aws/)를 사용하세요.
