`connection` 생성기를 사용하면 React 웹사이트가 <Link path="guides/ts-container">`ts#container`</Link> 또는 <Link path="guides/py-container">`py#container`</Link>로 만든 컨테이너 서비스를 호출할 수 있습니다. 런타임 구성에서 서비스의 URL을 읽고 각 요청에 서비스가 예상하는 인증을 추가하는 React 훅을 추가합니다.

## 작동 방식

`infra=ecs`를 사용하는 컨테이너 서비스는 내부 Application Load Balancer 뒤에서 Amazon ECS(Elastic Container Service)에서 실행됩니다. 기본값인 `ingress=http-api`를 사용하면 Amazon API Gateway HTTP API(관리형 HTTPS 엔드포인트)가 VPC 링크를 통해 해당 로드 밸런서에 도달합니다. VPC 링크는 API Gateway가 VPC에 연결하는 프라이빗 연결입니다. 웹사이트는 HTTP API를 호출합니다.

서비스의 `auth` 옵션은 HTTP API가 각 요청을 확인하는 방법을 결정합니다:

- `iam` (기본값): 요청은 AWS 요청 서명 프로세스인 SigV4로 서명되어야 합니다. 훅은 웹사이트의 Cognito 자격 증명 풀이 로그인한 사용자에게 제공하는 임시 AWS 자격 증명으로 서명합니다.
- `cognito`: 요청에는 로그인한 사용자의 Cognito 액세스 토큰이 bearer 토큰으로 포함되어야 합니다.
- `none`: HTTP API는 모든 요청을 수락합니다.

HTTP API는 30초 이상 걸리는 요청을 종료하므로, 더 오래 실행되는 라우트는 조기에 반환하고 백그라운드에서 작업을 완료해야 합니다.

생성기는 도달할 수 없는 서비스를 거부합니다. `infra=none`은 엔드포인트를 생성하지 않으므로 서비스는 `infra=ecs`를 가져야 합니다. 또한 `private` 서비스는 VPC 내부에서만 도달할 수 있으므로 `ingress=http-api`를 가져야 합니다.

## 전제 조건

이 생성기를 사용하기 전에 다음이 필요합니다:

1. React 웹사이트 (<Link path="guides/react-website">`ts#website` 생성기</Link>를 사용하여 생성)
2. `infra=ecs` 및 `ingress=http-api`를 사용하는 컨테이너 서비스 (<Link path="guides/ts-container">`ts#container`</Link> 또는 <Link path="guides/py-container">`py#container`</Link> 생성기를 사용하여 생성)
3. 서비스의 `auth`가 `iam` 또는 `cognito`인 경우 <Link path="guides/react-website-auth">`ts#website#auth` 생성기</Link>를 통해 추가된 Cognito Auth

## 생성기 출력

생성기는 React 웹사이트에 다음 파일을 생성합니다:

<FileTree>

- src
  - hooks
    - use\<ServiceName>.tsx 서비스의 URL과 서비스의 인증을 추가하는 `fetch`를 반환하는 훅
    - useSigV4.tsx SigV4로 요청에 서명하기 위한 훅 (`iam`만 해당)
  - components
    - RuntimeConfig/index.tsx 로컬 개발에서 훅이 로컬 서비스를 가리키도록 함

</FileTree>

`<ServiceName>`은 서비스의 클래스 이름입니다. 예를 들어 `orders`라는 서비스의 경우 `useOrders`입니다. 생성기는 또한 웹사이트에 다음 종속성을 추가합니다:

- `aws4fetch`, `oidc-client-ts`, `@aws-sdk/credential-provider-cognito-identity`, `react-oidc-context`, 그리고 개발 종속성 `@smithy/types` (`iam`)
- `react-oidc-context` (`cognito`)

## 훅 사용하기

훅은 서비스의 `url`과 `fetch` 함수를 반환합니다. `fetch`는 서비스에 상대적인 경로와 일반적인 `fetch` 옵션을 받습니다:

```tsx
import { useEffect, useState } from 'react';
import { useMyService } from './hooks/useMyService';

export const ServiceStatus = () => {
  const myService = useMyService();
  const [status, setStatus] = useState<number>();

  useEffect(() => {
    myService.fetch('/health').then((response) => setStatus(response.status));
  }, [myService.fetch]);

  return <p>Service status: {status ?? 'loading'}</p>;
};
```

배포된 서비스는 `connection.services.<ServiceName>` 아래의 <Link path="guides/runtime-config">런타임 구성</Link>에 URL을 작성하며, 웹사이트는 `runtime-config.json`에서 이를 읽습니다.

웹사이트는 브라우저에서 HTTP API를 호출하므로 HTTP API의 CORS(교차 출처 리소스 공유) 설정이 웹사이트의 출처를 허용해야 합니다. 생성기는 이를 변경하지 않습니다. 기본적으로 HTTP API는 훅이 보내는 `authorization`, `content-type` 및 SigV4 헤더와 함께 모든 출처의 요청을 수락합니다. 웹사이트에서만 요청을 수락하려면 CDK에서 `myService.restrictCorsTo('https://<your website domain>')`를 호출하세요. Terraform에서는 서비스 모듈의 `module "ecs_service"` 블록에서 `cors_allow_origins`를 설정하세요. 자세한 내용은 <Link path="guides/ts-container#cors-and-throttling">CORS 및 제한</Link>을 참조하세요.

## 인프라

`auth=iam`의 경우 웹사이트의 로그인한 사용자는 서비스의 HTTP API를 호출할 권한이 필요합니다. 생성기는 스택이나 루트 Terraform 모듈을 변경하지 않습니다. 대신 추가할 코드를 출력하며, 이는 `my-service`라는 서비스에 대해 아래에 표시됩니다. 이를 추가할 때까지 HTTP API는 웹사이트의 요청을 403 Forbidden으로 거부합니다. `cognito` 및 `none`의 경우 추가할 것이 없습니다.

<Infrastructure>
<Fragment slot="cdk">

예제에서 `myService`는 `MyService` 구성이고 `identity`는 `UserIdentity` 구성입니다:

```ts title="packages/infra/src/stacks/application-stack.ts"
myService.grantInvoke(identity.identityPool.authenticatedRole);
```

`grantInvoke`는 자격 증명 풀의 인증된 역할이 서비스의 HTTP API에서 `execute-api:Invoke`를 호출할 수 있도록 허용합니다.

</Fragment>
<Fragment slot="terraform">

예제에서 `module "my_service"`는 서비스를 배포하고 `module "user_identity"`는 웹사이트의 자격 증명 풀을 배포합니다:

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_role_policy" "authenticated_my_service_invoke" {
  name = "authenticated-my-service-invoke"
  role = module.user_identity.authenticated_role_name

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = ["execute-api:Invoke"]
        Resource = ["${module.my_service.api_execution_arn}/*"]
      },
    ]
  })
}
```

</Fragment>
</Infrastructure>
