`connection` 생성기는 <Link path="guides/ts-container">TypeScript 컨테이너 서비스</Link>가 <Link path="guides/ts-dynamodb">TypeScript DynamoDB</Link> 프로젝트를 사용할 수 있도록 합니다. 서비스와 DynamoDB Local이 함께 시작되도록 로컬 개발을 구성하고, 서비스에 필요한 권한을 출력합니다.

## 작동 방식

`infra=ecs`를 사용하는 컨테이너 서비스는 Amazon ECS(Elastic Container Service)에서 태스크로 실행됩니다. 각 태스크는 서비스의 태스크 역할로 실행되며, 이는 추가 권한을 부여하기 전까지는 런타임 구성만 읽을 수 있는 IAM 역할입니다. 테이블을 읽고 쓰려면 태스크 역할에 테이블과 인덱스에 대한 DynamoDB 작업 권한과 테이블의 AWS KMS 암호화 키 사용 권한이 필요합니다.

생성기는 `infra=none`을 사용하는 서비스를 거부합니다. 이러한 서비스에는 액세스 권한을 부여할 태스크 역할이 없기 때문입니다.

## 전제 조건

이 생성기를 사용하기 전에 다음이 필요합니다:

1. `infra=ecs`를 사용하는 컨테이너 서비스 (<Link path="guides/ts-container">`ts#container`</Link> 생성기를 사용하여 생성)
2. <Link path="guides/ts-dynamodb">`ts#dynamodb`</Link> 프로젝트

## 생성기 출력

생성기는 `project.json`에서 서비스의 `<service-name>-serve` 타겟을 업데이트하여 DynamoDB 프로젝트의 `dev` 타겟에 의존하도록 합니다. 소스 파일은 수정되지 않습니다.

## 서비스에서 DynamoDB 사용

DynamoDB 패키지에서 엔티티 팩토리를 가져와 요청을 처리하는 곳에서 사용합니다:

```ts title="packages/my-project/src/my-service/examples.ts"
import { createExampleEntity } from '@my-scope/my-table';

export const listExamples = async () => {
  const entity = await createExampleEntity();
  const result = await entity.scan.go();
  return result.data;
};
```

## 인프라

생성기는 스택이나 루트 Terraform 모듈을 변경하지 않습니다. 대신 추가할 코드를 출력하며, 아래에 `my-service`라는 서비스와 `my-table`이라는 테이블에 대한 예시가 나와 있습니다. 이를 추가하기 전까지는 서비스의 테이블 요청이 거부됩니다.

<Infrastructure>
<Fragment slot="cdk">

예시에서 `myService`는 `MyService` 구성이고 `myTable`은 `MyTable` 구성입니다:

```ts title="packages/infra/src/stacks/application-stack.ts"
myTable.grantReadWriteData(myService.taskRole);
```

`grantReadWriteData`는 서비스의 태스크 역할에 DynamoDB 및 KMS 권한을 모두 부여합니다.

<Fragment slot="terraform">

예시에서 `module "my_service"`는 서비스를 배포하고 `module "my_table"`은 테이블을 배포합니다:

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_role_policy" "my_service_my_table_access" {
  name = "my-service-my-table-access"
  role = module.my_service.task_role_name

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Action = [
          "dynamodb:GetItem", "dynamodb:PutItem", "dynamodb:UpdateItem",
          "dynamodb:DeleteItem", "dynamodb:Query", "dynamodb:Scan",
          "dynamodb:BatchGetItem", "dynamodb:BatchWriteItem",
        ]
        Resource = [
          module.my_table.table_arn,
          "${module.my_table.table_arn}/index/*",
        ]
      },
      {
        Effect = "Allow"
        Action = [
          "kms:Encrypt",
          "kms:Decrypt",
          "kms:ReEncrypt*",
          "kms:GenerateDataKey*",
          "kms:DescribeKey",
        ]
        Resource = [module.my_table.kms_key_arn]
      },
    ]
  })
}
```

## 로컬 개발

<NxCommands commands={["<service-name>-serve <project-name>"]} />

이 명령은 서비스와 DynamoDB Local을 시작합니다. `LOCAL_DEV=true`가 설정되면 `getDynamoDBClient()`와 `resolveTableName()`은 AWS 대신 DynamoDB Local에 연결됩니다.
