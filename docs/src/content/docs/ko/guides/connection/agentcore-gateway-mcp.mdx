`connection` 제너레이터는 MCP 서버(<Link path="guides/ts-mcp-server">TypeScript</Link> 또는 <Link path="guides/py-mcp-server">Python</Link>)를 <Link path="guides/agentcore-gateway">AgentCore Gateway</Link>의 대상으로 등록할 수 있습니다.

연결되면 Gateway는 MCP 서버의 도구를 단일 MCP 엔드포인트로 집계하고, Cedar 정책 엔진에 대해 호출을 평가하며, MCP 서버로 나가는 트래픽에 IAM SigV4로 서명합니다.

## 사전 요구 사항

이 제너레이터를 사용하기 전에 다음이 필요합니다:

1. <Link path="guides/agentcore-gateway">`agentcore-gateway`</Link> 프로젝트
2. `infra: agentcore` 및 `auth: iam`으로 생성된 MCP 서버 컴포넌트(<Link path="guides/ts-mcp-server">`ts#mcp-server`</Link> 또는 <Link path="guides/py-mcp-server">`py#mcp-server`</Link>)

Gateway는 `protocol: mcp`를 가져야 하고 MCP 서버는 `auth: iam`을 가져야 합니다 — 제너레이터는 둘 다 검증합니다. Gateway가 SigV4로 나가는 트래픽에 서명하기 때문에 IAM이 아닌 MCP 서버는 연결할 수 없습니다.

## 제너레이터 출력

제너레이터는 새 소스 파일을 생성하는 대신 기존 프로젝트를 함께 연결합니다. 다음 파일이 수정됩니다:

<FileTree>

- packages/\<gateway>
  - project.json Gateway의 `dev` 타겟이 MCP 서버의 `<mcp>-dev`에 대한 종속성을 얻습니다
  - local-dev.ts `ATTACHED_MCP_SERVERS`가 업데이트되어 로컬 게이트웨이가 MCP 서버를 집계합니다

</FileTree>

Gateway 프로젝트의 `dev` 타겟은 MCP 서버의 `<mcp>-dev` 타겟에 대한 종속성을 얻으므로 Gateway를 로컬에서 실행하면 MCP 서버도 시작됩니다. MCP 서버는 Gateway 프로젝트의 `local-dev.ts`에도 등록되어 로컬 게이트웨이가 해당 도구를 집계합니다.

## 스택에 MCP 서버 대상 추가하기

제너레이터는 Gateway를 인스턴스화하는 스택이나 모듈을 알 수 없기 때문에 MCP 서버 대상을 인프라에 자동으로 연결할 수 **없습니다**. `gateway.addMcpServer(server)`에 대한 단일 호출을 직접 추가하세요.

<Infrastructure>
<Fragment slot="cdk">
Gateway를 인스턴스화하는 스택에서 MCP 서버를 대상으로 등록합니다:

```ts title="packages/infra/src/stacks/application-stack.ts" {4-7}
const myMcpServer = new MyMcpServer(this, 'MyMcpServer');
const myGateway = new MyGateway(this, 'MyGateway');

// Register the MCP server as a target of the Gateway. The target name
// defaults to the MCP server's `mcpServerName` (its class name in
// kebab-case, e.g. `MyMcpServer` -> `my-mcp-server`).
myGateway.addMcpServer(myMcpServer);
```

Gateway 대상 이름(기본적으로 MCP 서버의 `mcpServerName`)은 Cedar 액션 이름의 접두사로 사용됩니다 — 액션 형식은 ``AgentCore::Action::"<targetName>___<toolName>"``입니다. <Link path="guides/agentcore-gateway">정책 작성 섹션</Link>을 참조하세요. 대상 이름을 짧고 안정적으로 유지하세요. 나중에 변경하면 이전 이름을 참조하는 Cedar 정책이 무효화됩니다.

기본 대상 이름을 재정의하려면 `gatewayTargetName`을 전달하세요:

```ts
myGateway.addMcpServer(myMcpServer, { gatewayTargetName: 'my-mcp' });
```

구성은 `iamCredentialProvider.service = 'bedrock-agentcore'`로 대상을 구성하여 Gateway가 자체 실행 역할을 사용하여 나가는 호출에 서명하도록 합니다.
</Fragment>
<Fragment slot="terraform">
Gateway를 인스턴스화하는 Terraform 파일에서 MCP 서버 대상을 연결합니다:

```hcl title="packages/infra/src/main.tf" {7,10-28}
module "my_mcp_server" {
  source = "../../common/terraform/src/app/mcp-servers/my-mcp-server"
}

module "my_gateway" {
  source              = "../../common/terraform/src/app/gateways/my-gateway"
  policy_dependencies = [aws_bedrockagentcore_gateway_target.my_mcp_server.target_id]
}

# Register the MCP server as a target of the Gateway
resource "aws_bedrockagentcore_gateway_target" "my_mcp_server" {
  gateway_identifier = module.my_gateway.gateway_id
  name               = "my-mcp-server"

  target_configuration {
    mcp {
      mcp_server {
        endpoint = module.my_mcp_server.invocation_url
      }
    }
  }

  credential_provider_configuration {
    gateway_iam_role {
      service = "bedrock-agentcore"
    }
  }
}
```

대상 `name`(위의 `my-mcp-server`)은 Cedar 액션 이름의 접두사로 사용됩니다 — <Link path="guides/agentcore-gateway">정책 작성 섹션</Link>을 참조하세요. `policy_dependencies`는 이 대상의 액션을 참조하는 Cedar 정책이 대상이 등록한 후에 생성되도록 보장합니다.
</Fragment>
</Infrastructure>

## 로컬 개발

다음 명령으로 Gateway를 로컬에서 실행하면:

<NxCommands commands={["dev <gateway-name>"]} />

로컬 게이트웨이와 할당된 로컬 포트의 모든 연결된 MCP 서버가 시작됩니다. 로컬 게이트웨이는 연결된 서버의 도구를 집계하는 단일 MCP 엔드포인트를 노출합니다. <Link path="guides/connection/ts-agent-gateway">TypeScript</Link> 또는 <Link path="guides/connection/py-agent-gateway">Python</Link> 게이트웨이 연결 제너레이터를 통해 Gateway에 연결된 에이전트는 `LOCAL_DEV=true`로 실행할 때 이를 가리킵니다.

:::caution[로컬 충실도]
로컬 개발은 **로컬 대체 게이트웨이**를 사용합니다 — Gateway 프로젝트에서 시작된 경량 MCP 집계기이며, AgentCore Gateway 서비스가 아닙니다. 결과적으로 **Cedar 정책은 로컬에서 평가되지 않습니다**. 모든 에이전트는 연결된 모든 MCP 서버의 모든 도구를 볼 수 있습니다. Cedar 정책을 실행하려면 대신 에이전트의 `serve` 타겟을 실행하여(<Link path="guides/connection/ts-agent-gateway">TypeScript</Link> / <Link path="guides/connection/py-agent-gateway">Python</Link> 에이전트 연결 가이드 참조) 로컬에서 실행 중인 에이전트가 배포된 Gateway를 호출하도록 하세요.

도구 이름은 배포된 Gateway의 네임스페이스와 일치하도록 로컬에서 여전히 `<target-name>___<tool-name>`으로 접두사가 붙으므로 에이전트의 시스템 프롬프트와 참조하는 Cedar 액션 이름이 로컬 및 배포된 실행에서 일관되게 유지됩니다.
:::
