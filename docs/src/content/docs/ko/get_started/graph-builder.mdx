워크스페이스에 필요한 프로젝트와 그들 간의 연결을 스케치하면, 빌더가 그린 내용을 정확히 스캐폴딩하는 명령어를 생성합니다. 명령어를 복사하고 실행하면 작동하는 워크스페이스가 완성됩니다.

팔레트에서 캔버스로 컴포넌트를 드래그하고, 컴포넌트의 오른쪽 가장자리에서 다른 컴포넌트로 드래그하여 연결하고, 오른쪽에서 각 컴포넌트의 속성을 편집하세요. 하단의 생성된 명령어는 모든 변경 사항에 따라 업데이트됩니다 — **Copy**를 눌러 전체 스크립트를 가져가세요.

## 작동 방식

캔버스의 각 컴포넌트는 제너레이터에 매핑되고, 각 연결은 <Link path="guides/connection">connection 제너레이터</Link>에 매핑됩니다. 명령어는 의존성 순서대로 생성됩니다: 먼저 워크스페이스, 그 다음 프로젝트, 그들이 호스팅하는 컴포넌트, 마지막으로 이들을 연결하는 연결입니다.

웹사이트는 항상 생성 직후 <Link path="guides/react-website-auth">Cognito 인증</Link>이 추가됩니다. `ts#website`는 이를 후속 제너레이터에 맡기기 때문입니다.

`infra` 프로젝트는 마지막에 추가됩니다 — IaC 선택에 따라 <Link path="guides/typescript-infrastructure">`ts#infra`</Link> 또는 <Link path="guides/terraform-project">`terraform#project`</Link>가 추가됩니다. 생성된 모든 프로젝트는 이것이 인스턴스화할 구성을 제공하므로, 이것이 배포하는 대상입니다. 이 이름을 소유하기 때문에 캔버스의 어떤 컴포넌트도 `infra`라고 부를 수 없습니다.

툴바의 **Vertical** / **Horizontal**을 사용하여 그래프가 흐르는 방향을 전환하세요 — 연결 지점이 각 컴포넌트의 상단과 하단 가장자리로 이동하고, 레이아웃이 이에 맞춰 전환됩니다.

캔버스 배경을 드래그하여 이동하고, 컴포넌트를 드래그하여 위치를 변경하세요. Shift-클릭으로 여러 컴포넌트를 선택하고 그룹으로 이동할 수 있습니다. 연결을 클릭하여 선택한 다음 <kbd>Delete</kbd>를 눌러 제거하세요 (또는 연결 자체의 ✕를 사용하세요).

팔레트는 연결에 참여할 수 있는 모든 프로젝트 및 컴포넌트 유형을 나열하며, 플러그인이 지원하는 연결만 그릴 수 있습니다 — 따라서 유효성 검사를 통과한 그래프는 스캐폴딩할 수 있는 그래프입니다.

알아둘 만한 세 가지 규칙이 있습니다:

- **컴포넌트는 호스트 프로젝트를 공유합니다.** 에이전트와 MCP 서버는 자체 프로젝트가 아니라 프로젝트_에_ 추가됩니다. 동일한 호스트 프로젝트 이름을 지정하면 하나의 프로젝트에 배치되고, 다른 이름을 지정하면 각각 하나의 프로젝트에 배치됩니다.
- **일부 연결은 엔드포인트를 제약합니다.** 예를 들어 에이전트를 다른 에이전트에 연결하려면 대상이 `a2a` 프로토콜을 사용해야 합니다. 속성 설정이 그린 연결을 깨뜨릴 경우, 빌더가 컴포넌트와 연결에 대해 이를 알려줍니다.
- **연결을 그리면 대상이 조정될 수 있습니다.** 웹사이트를 에이전트에 연결하면 해당 에이전트가 `ag-ui` 프로토콜로 전환되고, 에이전트를 다른 에이전트에 연결하면 대상이 `a2a`로 전환됩니다 — 이러한 연결이 기반으로 하는 프로토콜입니다. 직접 설정한 속성은 절대 변경되지 않습니다.

:::tip[AI로 빌드하는 것을 선호하시나요?]
플러그인은 MCP 서버를 제공하므로, 코딩 에이전트가 프로젝트를 스캐폴딩하고 연결할 수 있습니다. <Link path="get_started/building-with-ai">Building with AI</Link>를 참조하세요.
:::
