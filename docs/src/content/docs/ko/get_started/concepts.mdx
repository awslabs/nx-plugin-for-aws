`@aws/nx-plugin`은 AWS에서 풀스택 애플리케이션을 빌드하고 배포하기 위한 툴킷을 제공하는 [Nx](https://nx.dev/) 플러그인입니다. 모범 사례 애플리케이션 코드 _및_ 이를 배포할 인프라를 스캐폴딩하는 [제너레이터](#generators) 모음을 제공합니다 — 타입 안전하고, 로컬에서 실행 가능하며, 처음부터 배포 가능하여 프로덕션에 더 가까워집니다.

빈 페이지에서 시작하는 대신, 여러분(또는 여러분의 AI 에이전트)이 필요한 컴포넌트를 선택합니다 — API, 웹사이트, 인증, AI 에이전트, 인프라 — 몇 가지 구성 옵션을 제공하면, 플러그인이 모범 사례 스타터 코드를 생성합니다. 심지어 프로젝트를 자동으로 연결하여(AST 변환을 통해 기존 파일 업데이트 포함) 프론트엔드와 백엔드 간에 타입 안전한 클라이언트를 생성합니다.

## Nx와 제너레이터 기반

[Nx](https://nx.dev)는 모노레포를 관리하기 위한 스마트 빌드 프레임워크입니다. 언어에 구애받지 않아 TypeScript, Python, 인프라 등이 단일 워크스페이스에서 함께 존재하고 빌드될 수 있습니다. 빌드 시스템은 캐싱과 의존성 그래프 분석을 사용하여 변경된 부분만 다시 빌드하고 작업을 병렬로 실행하여, 워크스페이스가 성장해도 테스트, 린팅, 빌드를 빠르게 유지합니다.

`@aws/nx-plugin`의 모든 기능은 Nx [제너레이터](https://nx.dev/features/generate-code)로 제공됩니다 — 사전 정의된 템플릿에서 일관된 코드 구조를 생성하는 자동화된 스캐폴딩입니다. 제너레이터는 [Nx CLI](https://nx.dev/features/generate-code#invoke-generators), [Nx Console IDE 플러그인](https://nx.dev/getting-started/editor-setup), 또는 <Link path="/get_started/building-with-ai">Nx Plugin for AWS MCP Server</Link>를 통한 AI 어시스턴트로 호출할 수 있습니다.

모든 컴포넌트가 제너레이터이기 때문에, 필요할 때 필요한 것만 추가하면 됩니다. API로 시작하고, 나중에 웹사이트를 추가하고, 준비가 되면 연결하세요 — 각 단계는 단일 명령입니다.

## 검증된 프레임워크로 빌드

`@aws/nx-plugin`은 이미 알고 있는 도구 위에 커스텀 추상화를 구축하는 것을 의도적으로 피합니다. 맞춤형 프레임워크, 런타임 또는 래퍼를 만드는 대신, 확립되고 널리 채택된 오픈소스 프로젝트를 사용하여 관용적인 코드를 스캐폴딩합니다. 이는 기존 기술을 직접 활용할 수 있고, 각 프레임워크의 공식 문서를 신뢰할 수 있으며, 이 플러그인만 이해하는 레이어에 갇히지 않는다는 것을 의미합니다.

## 수정 가능

생성된 모든 코드는 _여러분의_ 코드입니다. `@aws/nx-plugin`은 빌드 타임 도구이지 런타임 의존성이 아닙니다 — 제너레이터가 실행되면, 플러그인은 더 이상 관여하지 않습니다. 생성된 모든 파일을 읽고, 커밋하고, 원하는 대로 변경할 수 있습니다.

이는 다음을 의미합니다:

- **탈출구가 필요 없습니다.** 제너레이터가 예상하지 못한 작업을 수행해야 할 때 배우거나 씨름해야 할 독점 구성 표면이 없습니다. 직접 작성한 코드를 편집하는 것과 같은 방식으로 생성된 코드를 직접 편집합니다.
- **새로운 추상화 레이어가 없습니다.** 제너레이터는 기본 프레임워크를 위한 평범하고 관용적인 코드를 생성합니다. React, tRPC, FastAPI, CDK 또는 다른 도구들 사이에 래퍼 API나 마법 같은 간접 참조가 없습니다 — 보이는 것이 실행되는 것입니다.
- **플러그인은 의존성이 아닙니다.** 코드를 생성하고 물러납니다. 애플리케이션은 런타임에 `@aws/nx-plugin`을 가져오거나 의존하지 않으므로, 플러그인에 의해 차단되거나 종속되지 않습니다.

생성된 코드에서 마음에 들지 않는 부분이 있다면 자유롭게 수정할 수 있습니다. 제너레이터는 출발점을 제공하지, 감옥이 아닙니다.

## 개선 사항과 보조 맞추기

코드를 소유하는 것은 보통 대가가 따릅니다: 스캐폴드를 편집하기 시작하는 순간, 업스트림에서 이루어진 수정 및 개선 사항과 단절됩니다. 이를 다시 채택하려면 변경 로그를 읽고, 재생성하고, 수동으로 차이점을 조정해야 합니다. <Link path="/get_started/upgrading">마이그레이션</Link>은 `@aws/nx-plugin`이 이러한 일이 발생하지 않도록 작동하는 방식입니다.

릴리스는 마이그레이션과 함께 제공되며, 이전 제너레이터가 생성한 코드를 우리가 그 이후로 만든 개선 사항과 보조를 맞추도록 합니다. 버그를 수정하거나, 보안 기본값을 강화하거나, 생성된 패턴을 개선할 때, `nx migrate`를 실행하면 해당 변경 사항이 코드에 적용됩니다 — 변경 로그에서 직접 찾아 이식하도록 남겨두는 대신 말입니다.

실제로:

- **업그레이드는 자동화되며, 재채택 작업이 아닙니다.** 몇 달 전에 생성된 워크스페이스도 플러그인에서 멀어지는 대신 플러그인과 함께 앞으로 나아갈 수 있습니다.
- **커스터마이징은 패턴 매칭되며, 덮어쓰지 않습니다.** 마이그레이션은 파일이 여전히 제너레이터가 생성한 형태와 일치하는지 확인합니다. 안전하게 업데이트할 수 있는 범위를 벗어난 경우, 코드를 그대로 두고 대신 수동 후속 조치를 보고합니다.
- **일부 변경 사항은 에이전트 프롬프트로 도착합니다.** 올바른 편집이 여러분이 빌드한 것에 따라 달라지는 경우, 마이그레이션은 코드모드가 아니라 AI 코딩 에이전트가 적용하는 프롬프트입니다.
- **업그레이드는 선택 사항입니다.** `nx migrate`를 실행하기로 선택할 때까지 워크스페이스의 어떤 것도 변경되지 않습니다.

마이그레이션은 격차를 좁히지만 완전히 닫지는 않습니다: 코드가 얼마나 이동했는지가 마이그레이션이 할 수 있는 일의 양을 결정하며, 일부 단계는 여전히 여러분의 손이 필요합니다.

## 최소한의 의존성

`@aws/nx-plugin`은 전역 의존성의 수를 최소한으로 유지하기 위해 노력합니다. 시작하는 데 필요한 것은 호출하는 제너레이터에 따라 달라집니다.

예를 들어, TypeScript 기반 제너레이터는 [Node](https://nodejs.org/en/download)만 설치되어 있으면 됩니다. Python 기반 프로젝트의 경우, [UV](https://docs.astral.sh/uv/)만 필요합니다.

## 타입 안전성

`@aws/nx-plugin`은 IDE 자동 완성을 통해 개발자 경험을 단순화하고, 타입 안전하지 않은 구현에서만 발생할 런타임 오류를 제거하기 위해 타입 안전성을 사용합니다. 따라서 제공되는 모든 컴포넌트는 기본적으로 타입 안전합니다.

타입 안전성은 프로젝트 경계를 넘어 흐릅니다: 웹사이트를 API에 연결하면, 생성된 클라이언트가 백엔드와 타입을 공유하므로, API 계약의 변경이 프로덕션의 버그가 아니라 프론트엔드의 컴파일 타임 오류로 나타납니다. 자신 있게 리팩터링하세요.
