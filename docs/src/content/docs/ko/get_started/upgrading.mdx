Nx와 `@aws/nx-plugin` 모두 [`nx migrate`](https://nx.dev/docs/features/automate-updating-dependencies)를 사용하여 업그레이드 시 워크스페이스를 자동으로 업데이트하는 마이그레이션을 제공합니다. 이 가이드는 각각을 업그레이드하는 과정을 안내합니다.

<Aside type="tip">
<Link path="get_started/building-with-ai">MCP 서버</Link>를 사용하여 선택한 에이전트 코딩 도구로 워크스페이스를 업그레이드할 수 있습니다. 다음 프롬프트를 시도해 보세요:

> Upgrade Nx and the Nx Plugin for AWS in this workspace.
</Aside>

`nx migrate <package>@<version>`은 지정한 패키지를 대상으로 하므로 Nx 자체를 업그레이드하는 것과 `@aws/nx-plugin`을 업그레이드하는 것은 별도의 업그레이드이며, 각각 동일한 주기를 따릅니다:

<Steps>

1. **생성** — `nx migrate <package>@latest`는 `package.json`에서 패키지 버전을 업데이트하고 실행할 마이그레이션 목록이 담긴 `migrations.json`을 작성합니다. 아직 설치되거나 다른 파일이 수정되지 않으므로 먼저 버전 변경 사항을 검토할 수 있습니다.

2. **설치** — 패키지 매니저로 새 버전을 설치합니다 (예: `pnpm install --no-frozen-lockfile`).

3. **실행** — `nx migrate --run-migrations`는 대기 중인 각 마이그레이션을 워크스페이스에 하나씩 적용합니다.

4. **커밋** — 워크스페이스가 빌드되는지 확인한 다음 `migrations.json`을 삭제하고 커밋합니다.

</Steps>

<Aside type="caution" title="한 번에 하나의 패키지만">
다음 패키지를 시작하기 전에 한 패키지의 전체 주기를 완료하세요: 각 `nx migrate <package>`는 `migrations.json`을 **덮어쓰므로**, `nx migrate @aws/nx-plugin@latest`를 실행한 직후 `nx migrate latest`를 실행하면 플러그인의 대기 중인 마이그레이션이 실행되기 전에 삭제됩니다.
</Aside>

## @aws/nx-plugin 업그레이드

플러그인을 대상으로 주기를 시작합니다:

<NxCommands commands={['migrate @aws/nx-plugin@latest']} />

```
 NX   The migrate command has run successfully.

- package.json has been updated.
- migrations.json has been generated.
- 1 AI migration prompt(s) have been written to tools/ai-migrations/.

 NX   Next steps:

- Make sure package.json changes make sense and then run 'pnpm install --no-frozen-lockfile',
- Review and tweak the AI migration prompts in tools/ai-migrations/ as needed.
- Run 'pnpm exec nx migrate --run-migrations'
- To learn more go to https://nx.dev/features/automate-updating-dependencies
```

`package.json` 변경 사항을 검토하고 설치한 다음 마이그레이션을 실행합니다:

<NxCommands commands={['migrate --run-migrations']} />

### 결정론적 마이그레이션

대부분의 마이그레이션은 결정론적 코드모드입니다 — 무인으로 실행되며 의도적으로 건너뛴 항목을 보고합니다:

```
 NX   Running migrations from 'migrations.json'

Running the following migrations:
- @aws/nx-plugin: update-vitest-workspace-config — Add a coverage reporter to vitest configs
- @aws/nx-plugin: update-custom-api-handlers — Update custom API handlers for the new middleware signature

── Migration 1 of 2 · @aws/nx-plugin:update-vitest-workspace-config ─────
→ Running generator…
Changes:
  UPDATE packages/api/vite.config.mts

...

 NX   Successfully finished running migrations from 'migrations.json'.

2 migrations applied, 0 commits created.

 NX   Some migrations have additional information, see below.

- packages/website/vite.config.mts has a customised shape; add a coverage reporter manually.
```

끝부분의 **추가 정보**에 주의하세요: 마이그레이션이 안전하게 업데이트할 수 있는 범위를 넘어 사용자 정의한 파일을 발견하면 변경 사항을 그대로 두고 대신 수동 후속 조치를 보고합니다.

### 에이전트 마이그레이션

일부 마이그레이션은 사용자가 소유한 코드를 대상으로 하며, 올바른 편집은 사용자가 구축한 내용에 따라 달라집니다 — 이러한 마이그레이션은 로컬 AI 코딩 에이전트(Claude Code, Codex 또는 OpenCode)가 적용하는 프롬프트로 제공됩니다. 대기 중인 마이그레이션이 있으면 Nx는 에이전트를 사용하기 전에 동의를 요청합니다:

```
? Enable the agentic flow? …
❯ Yes, just this time      Apply 1 prompt migration and validate generator output with an AI agent
  Yes, always              Saved to nx.json so Nx won't ask again
  No, just this time       Skip prompts and run generators without AI validation
  No, never                Saved to nx.json so Nx won't ask again
```

수락하면 에이전트가 각 프롬프트 마이그레이션을 제자리에 적용하고 변경 사항을 요약합니다:

```
── Migration 2 of 2 · @aws/nx-plugin:update-custom-api-handlers ─────────
→ Running prompt with Claude Code…
✓ update-custom-api-handlers: Updated 3 API handlers to the new middleware signature.
```

거부하거나 에이전트가 설치되지 않았거나 실행이 비대화형(예: CI)인 경우 프롬프트 마이그레이션은 건너뛰고 수동으로 적용할 수 있도록 저장됩니다:

```
── Migration 2 of 2 · @aws/nx-plugin:update-custom-api-handlers ─────────
↷ Skipped — agentic flow disabled. Listed in next steps.

 NX   Successfully finished running migrations from 'migrations.json'.

1 migration applied, 0 commits created, 1 prompt migration skipped.

 NX   Some migrations have additional information, see below.

- Some prompt migrations were skipped. Review and apply each of the following
  prompt files to the workspace, in the listed order:
  - tools/ai-migrations/@aws/nx-plugin/2.0.0/prompt.md
```

건너뛴 각 프롬프트는 `tools/ai-migrations/`에 있는 독립적인 마크다운 지침 파일입니다 — 코딩 에이전트에 붙여넣거나 수동으로 단계를 따르세요.

마지막으로 모든 것이 여전히 빌드되는지 확인한 다음 `migrations.json`을 삭제하고 커밋합니다:

<NxCommands commands={['run-many --target build --all']} />

## Nx 업그레이드

Nx 자체(및 `@nx/*` 플러그인)를 업그레이드하는 것은 `nx`를 대상으로 하는 동일한 주기입니다:

<NxCommands commands={['migrate latest']} />

그런 다음 이전과 같이 설치하고 마이그레이션을 실행하고 확인한 후 커밋합니다:

<NxCommands commands={['migrate --run-migrations']} />

<Aside type="tip">
여러 Nx 주요 버전을 건너뛸 때는 한 번에 하나의 주요 버전씩 업그레이드하세요 — 자세한 내용은 [Automate Updating Dependencies](https://nx.dev/docs/features/automate-updating-dependencies)를 참조하세요.
</Aside>

<Aside type="note" title="pnpm 빌드 스크립트">
`nx migrate latest`가 `ERR_PNPM_IGNORED_BUILDS`로 실패하면 pnpm이 `nx` 패키지의 post-install 스크립트를 차단한 것입니다. `pnpm-workspace.yaml`에서 허용하고 다시 실행하세요:

```yaml
# pnpm-workspace.yaml
allowBuilds:
  nx: true
```
</Aside>
