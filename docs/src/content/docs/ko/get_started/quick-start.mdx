## 1단계: 새로운 Nx 워크스페이스 초기화

다음 명령을 실행하여 원하는 패키지 매니저로 <Link path="guides/workspace">Nx 워크스페이스</Link>를 생성합니다:

<CreateNxWorkspaceCommand workspace="my-project" />

:::tip[IaC 제공자 선택]
선호하는 Infrastructure as Code(IaC) 제공자로 [CDK](https://docs.aws.amazon.com/cdk/) 또는 [Terraform](https://developer.hashicorp.com/terraform) 중 하나를 선택하라는 메시지가 표시됩니다. `--iac` 옵션과 함께 명령을 실행하여 프롬프트를 건너뛸 수 있습니다. 예:

<Infrastructure>
<Fragment slot="cdk">
<CreateNxWorkspaceCommand workspace="my-project" iac="cdk" />
</Fragment>
<Fragment slot="terraform">
<CreateNxWorkspaceCommand workspace="my-project" iac="terraform" />
</Fragment>
</Infrastructure>
:::

완료되면 프로젝트 디렉토리로 이동합니다:

```sh
cd my-project
```

## 2단계: 제너레이터를 사용하여 프로젝트 스캐폴딩

이 빠른 시작 가이드에서는 tRPC API, React 웹사이트, Cognito 인증, 그리고 CDK 또는 Terraform 인프라를 추가합니다. 구축하려는 프로젝트 유형에 따라 제너레이터의 조합을 선택하여 프로젝트를 빠르게 부트스트랩할 수 있습니다. 왼쪽 탐색 바의 __제너레이터__를 확인하여 전체 옵션 목록을 보거나, <Link path="get_started/graph-builder">그래프 빌더</Link>를 사용하여 워크스페이스를 시각적으로 구성해 보세요.

단축키로 아래 버튼을 사용하여 전체 애플리케이션을 스캐폴딩하는 명령을 복사할 수 있습니다.

<EmbeddedGraph preset="quick-start" workspace="my-project" iac="cdk" orientation="horizontal" skipWorkspace />

:::tip[AI로 빌드하기]
<Link path="get_started/building-with-ai">Nx Plugin for AWS MCP Server</Link>가 이미 워크스페이스에 구성되어 있으므로, CLI 명령을 직접 입력하는 대신 Kiro 또는 Claude와 같은 좋아하는 AI 코딩 에이전트에게 이러한 프로젝트를 빌드하도록 요청할 수 있습니다.
:::

그렇지 않으면 아래 단계를 따라 각 제너레이터를 직접 실행하세요.

## 3단계: 웹사이트와 API를 로컬에서 실행

다음 명령을 사용하여 웹사이트와 연결된 API에 대한 로컬 개발 서버를 시작합니다:

<PackageManagerShortCommand commands={["dev"]} />

웹사이트는 `http://localhost:4200`에서 사용할 수 있습니다.

로컬 웹사이트와 API 서버가 모두 핫 리로드되므로 웹사이트와 API의 변경 사항이 실시간으로 반영됩니다.

## 4단계: 클라우드 리소스 정의 및 AWS에 배포

<Infrastructure>
<Fragment slot="cdk">
`packages/infra/src/stacks/application-stack.ts`를 열고 다음 코드를 추가합니다:

```typescript
import { Stack, StackProps } from 'aws-cdk-lib';
import { DemoApi, DemoWebsite, UserIdentity } from '@my-project/common-constructs';
import { Construct } from 'constructs';

export class ApplicationStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props);

    const identity = new UserIdentity(this, 'identity');
    const api = new DemoApi(this, 'api', {
      integrations: DemoApi.defaultIntegrations(this).build(),
    });
    api.grantInvokeAccess(identity.identityPool.authenticatedRole);

    new DemoWebsite(this, 'website');
  }
}
```

이것이 풀스택 애플리케이션을 배포하기 위해 작성해야 하는 모든 CDK 코드입니다.
</Fragment>
<Fragment slot="terraform">
`packages/infra/src/main.tf`를 열고 다음 코드를 추가합니다:

```hcl
# Include metrics tracking for @aws/nx-plugin usage
module "metrics" {
  source = "../../common/terraform/src/metrics"
}

# Deploy user identity
module "user_identity" {
  source = "../../common/terraform/src/core/user-identity"
}

# Shared asset bucket — stages Lambda deployment zips for every lambda / API module
module "asset_bucket" {
  source = "../../common/terraform/src/core/asset-bucket"
}

# Deploy API
module "demo_api" {
  source = "../../common/terraform/src/app/apis/demo-api"

  asset_bucket_name = module.asset_bucket.bucket_name
}

# Grant authenticated users access to invoke the API
resource "aws_iam_policy" "api_invoke_policy" {
  name        = "DemoApiInvokePolicy"
  description = "Policy to allow authenticated users to invoke the API"

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Action = "execute-api:Invoke"
        Resource = "${module.demo_api.api_execution_arn}/*/*"
      }
    ]
  })
}

resource "aws_iam_role_policy_attachment" "authenticated_api_access" {
  role       = module.user_identity.authenticated_role_name
  policy_arn = aws_iam_policy.api_invoke_policy.arn
}

# Deploy website
provider "aws" {
  alias  = "us_east_1"
  region = "us-east-1"
}

module "demo_website" {
  source = "../../common/terraform/src/app/static-websites/demo-website"

  providers = {
    aws.us_east_1 = aws.us_east_1
  }

  depends_on = [module.user_identity, module.demo_api]
}
```

이것이 풀스택 애플리케이션을 배포하기 위해 작성해야 하는 모든 Terraform 코드입니다.
</Fragment>
</Infrastructure>

### 인프라 빌드 및 배포

다음으로, 다음 명령을 실행하여 프로젝트를 빌드합니다:

<PackageManagerShortCommand commands={["build"]} />

:::tip[린트 오류 수정]
린트 오류가 발생하면 다음 명령을 실행하여 자동으로 수정할 수 있습니다.

<PackageManagerShortCommand commands={["lint"]} />
:::

인프라를 부트스트랩합니다:

<Infrastructure>
<Fragment slot="cdk">
<NxCommands commands={['bootstrap infra']} />

:::tip[부트스트랩 리전]
CDK 부트스트래핑은 대상 배포 AWS 리전과 웹사이트용 AWS WAF WebACL 배포를 허용하기 위한 `us-east-1` 모두에 필요합니다.
:::
</Fragment>
<Fragment slot="terraform">
<NxCommands commands={['bootstrap infra']} />

:::tip[일회성 설정]
Terraform 부트스트래핑은 Terraform 상태 파일을 저장할 S3 버킷을 생성합니다. 이는 AWS 계정/리전 조합당 한 번만 수행하면 됩니다.
:::
</Fragment>
</Infrastructure>

프로젝트를 배포합니다:

<Infrastructure>
<Fragment slot="cdk">
<NxCommands commands={['deploy-sandbox infra']} />
</Fragment>
<Fragment slot="terraform">
<NxCommands commands={['apply infra']} />

:::tip[적용 전 계획]
이 명령은 먼저 `terraform plan`을 실행하여 어떤 변경 사항이 적용될지 보여준 다음, 해당 변경 사항을 적용하여 인프라를 배포합니다.
:::
</Fragment>
</Infrastructure>

## 5단계: 배포된 클라우드 리소스로 웹사이트 테스트

<Steps>
1. `runtime-config.json` 파일을 가져옵니다:

    <NxCommands commands={['load-runtime-config demo-website']} />

2. 로컬 웹사이트 서버를 시작합니다

    <NxCommands commands={['serve demo-website']} />
</Steps>

웹사이트는 `http://localhost:4200`에서 사용할 수 있으며, API 및 인증을 위해 배포한 리소스를 가리킵니다.
