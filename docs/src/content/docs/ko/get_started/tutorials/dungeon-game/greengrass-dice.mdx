<Link path="get_started/tutorials/dungeon-game/4">모듈 4</Link>에서 배포한 던전을 유지하세요.
파괴하기 전에 Story Agent에 주사위 디바이스를 제공하세요:

> "자물쇠를 따려고 합니다. 성공 여부를 확인하기 위해 d20을 굴려주세요."

에이전트는 `roll-dice`를 호출합니다. Greengrass 코어의 Python 컴포넌트가
주사위 굴림을 생성하고, MCP 도구가 해당 디바이스 결과를 에이전트에 반환합니다. 응답은
"d20: 17"이라고 말하고 결과를 설명할 수 있습니다.

이 선택적 경로는 소프트웨어 주사위 시뮬레이터가 있는 EC2 코어를 사용합니다. 나중에
난수 함수를 물리적 주사위 트레이의 입력으로 교체할 수 있습니다.
<Link path="get_started/tutorials/greengrass/overview">독립형 Greengrass 튜토리얼</Link>은
빈 워크스페이스에서 컴포넌트 생성을 배우는 별도의 방법으로 남아 있습니다.

## 추가할 내용

```d2
direction: right
player: Player
agent: Story Agent
tool: "Inventory MCP server\nroll-dice"
dice_shadow: "AWS IoT Core\nnamed shadow: dungeon-dice"
device: "Greengrass core\ncom.example.DungeonDice"
player -> agent: "Attempt an action"
agent -> tool: "roll-dice(sides=20)"
tool -> dice_shadow: "Desired request + request ID"
dice_shadow -> device: "MQTT delta through IPC"
device -> dice_shadow: "Reported result + same ID"
dice_shadow -> tool: "Correlated result"
tool -> agent: "d20 = 17"
agent -> player: "Result and consequence"
```

클라우드 섀도우는 하나의 대기 중인 요청과 가장 최근 결과를 보유합니다. 도구는
최대 12초 동안 대기하며, 대체 굴림을 생성하지 않습니다. 버전 확인은
동시 호출자가 활성 요청을 교체하는 것을 방지합니다. 디바이스는
게시하기 전에 마지막 결과를 저장하므로 MQTT 재전송 및 컴포넌트
재시작이 동일한 요청을 다시 굴리지 않습니다.

이 샌드박스는 플레이어 간에 하나의 주사위 디바이스를 공유합니다. 사용 중인 디바이스는
오류를 반환합니다. 플릿 전체 큐를 추가하거나 개인 디바이스를
Cognito 사용자와 연결하지 않습니다. 이는 멀티플레이어 제품을 위한 별도의 확장입니다.

## 1. 던전을 해체하지 않고 코어 프로비저닝

배포된 던전과 동일한 AWS 계정 및 리전을 사용하세요. 프로필을
명시적으로 설정하고, 디바이스 리소스에 새 접두사를 사용하세요:

```bash
export TUTORIAL_AWS_PROFILE=<your-dungeon-profile>
export TUTORIAL_AWS_REGION=<your-dungeon-region>
export TUTORIAL_PREFIX=gg-dungeon-dice
```

임시 설치 프로그램 정책 제거를 포함하여 **던전 워크스페이스**에서
<Link path="get_started/tutorials/greengrass/2">코어 디바이스 프로비저닝</Link>을 따르세요.
해당 페이지는 인스턴스를 생성하고 `.greengrass-tutorial.env`를 작성합니다.
다른 Nx 워크스페이스를 생성하거나 독립형 하트비트 모듈을 실행하지 마세요.
설정 스크립트의 기존 기본값은 변경되지 않습니다.

```bash
source .greengrass-tutorial.env
export DICE_IOT_ENDPOINT=$(aws --profile "$TUTORIAL_AWS_PROFILE" --region "$TUTORIAL_AWS_REGION" \
  iot describe-endpoint --endpoint-type iot:Data-ATS --query endpointAddress --output text)
```

도구를 활성화하기 전에 새 디바이스의 명명된 섀도우를 한 번 초기화하세요. 활성 주사위 요청이 있는
디바이스에 대해 이 재설정을 실행하지 마세요:

```bash
aws --profile "$TUTORIAL_AWS_PROFILE" --region "$TUTORIAL_AWS_REGION" \
  iot-data update-thing-shadow --endpoint-url "https://${DICE_IOT_ENDPOINT}" \
  --thing-name "$TUTORIAL_THING_NAME" --shadow-name dungeon-dice \
  --cli-binary-format raw-in-base64-out \
  --payload '{"state":{"desired":{"command":null},"reported":{"command":null,"result":null}}}' \
  /tmp/dungeon-dice-shadow.json
```

EC2 워크스루는 x86_64 Linux를 사용합니다. 64비트 Linux를 실행하는 Raspberry Pi는
대신 `linux-arm64`를 사용합니다. 생성된 레시피와 네이티브 종속성 모두
해당 아키텍처를 대상으로 해야 합니다. <Link path="guides/greengrass-component#하드웨어-및-운영-체제">하드웨어 지원</Link>을 참조하세요.
ESP32는 게이트웨이에 센서 입력을 제공할 수 있지만 이 Python 컴포넌트를 실행할 수 없습니다.

기존 애플리케이션 스택의 나머지 부분을 유지하세요. `DiceResources`는
디바이스 매개변수, 아티팩트 권한 부여, 컴포넌트 및 그
배포를 소유합니다.

세 가지 권한 경계가 있습니다:

- 코어의 기존 IoT 인증서 정책은 `$aws/things/<thing-name>/shadow/*`에 대한 게시, 구독
  및 수신을 허용하며, 여기에는 이미 명명된 `dungeon-dice` 섀도우가 포함됩니다.
  추가 인증서 정책이 필요하지 않습니다.
- 주사위 레시피는 IPC를 통해 해당 주제에 대한 컴포넌트 액세스 권한을 부여합니다.
- Inventory MCP 런타임은 이 사물의 명명된 `dungeon-dice` 섀도우에만
  `GetThingShadow` 및 `UpdateThingShadow`를 받습니다.

아티팩트 권한 부여는 코어의 토큰 교환 역할이 `com.example.DungeonDice/*`만
가져올 수 있도록 합니다. 배포는 컴포넌트 게시에 따라 달라집니다.

빌드한 다음 네 가지 매개변수 값으로 모두 배포하세요:

<NxCommands commands={['sync']} />
<InstallCommand />
<PackageManagerShortCommand commands={['lint --skip-nx-cache']} />
<NxCommands commands={['run-many --target build --all']} />

<NxCommands env={{ AWS_PROFILE: '"$TUTORIAL_AWS_PROFILE"', AWS_REGION: '"$TUTORIAL_AWS_REGION"' }} commands={['run @dungeon-adventure/infra:deploy -- "dungeon-adventure-infra-sandbox/**" --parameters dungeon-adventure-infra-sandbox-Application:DiceThingName="$TUTORIAL_THING_NAME" --parameters dungeon-adventure-infra-sandbox-Application:DiceEndpoint="$DICE_IOT_ENDPOINT" --parameters dungeon-adventure-infra-sandbox-Application:TokenExchangeRoleArn="$TUTORIAL_TOKEN_EXCHANGE_ROLE_ARN" --parameters dungeon-adventure-infra-sandbox-Application:ThingGroupArn="$TUTORIAL_THING_GROUP_ARN"']} />

WAF 스택이 매개변수를 정의하지 않으므로 애플리케이션 스택에 대한 매개변수를 한정하세요.

이 워크스루에는 `deploy`를 사용하세요. 컴포넌트/버전 변경은
CloudFormation 리소스를 교체합니다. <Link path="guides/greengrass-component#배포-수정">배포 수정</Link>은
`deploy-sandbox`에 필요한 추가 롤백 플래그를 설명합니다.

컴포넌트가 `RUNNING`이 될 때까지 기다리세요:

```bash
aws --profile "$TUTORIAL_AWS_PROFILE" --region "$TUTORIAL_AWS_REGION" \
  greengrassv2 list-installed-components --core-device-thing-name "$TUTORIAL_THING_NAME" \
  --query "installedComponents[?componentName=='com.example.DungeonDice'].[componentVersion,lifecycleState]" \
  --output table
```

## 5. 에이전트가 굴리도록 하기

배포된 게임을 열고 새 대화를 시작하거나 기존 대화를 다시 로드한 다음
물어보세요:

> "이 자물쇠를 따려는 시도를 위해 주사위 디바이스에서 d20을 굴려주세요."

에이전트는 `roll-dice`를 호출하고 반환된 값과 결과를 설명해야 합니다.
클라우드 섀도우를 읽어 `reported.result`를 도구 결과 및 에이전트의 응답과 비교하세요:

```bash
aws --profile "$TUTORIAL_AWS_PROFILE" --region "$TUTORIAL_AWS_REGION" \
  iot-data get-thing-shadow --endpoint-url "https://${DICE_IOT_ENDPOINT}" \
  --thing-name "$TUTORIAL_THING_NAME" --shadow-name dungeon-dice \
  /tmp/dungeon-dice-shadow.json
cat /tmp/dungeon-dice-shadow.json
```

성공적인 결과에는 `requestId`, `sides`, `value` 및 `rolledAt`이 포함됩니다.
`/greengrass/v2/logs/com.example.DungeonDice.log`의 디바이스 로그는
동일한 요청 ID와 값을 기록합니다. 성공적인 배포만으로는 이 왕복을 증명하지 못합니다.

실패 경로를 실행하려면 Systems Manager 터미널을 통해 이 일회용 코어에서
Greengrass 서비스를 중지하고, 다른 굴림을 요청하고, 제한된 대기 후
도구가 오류를 보고하는지 확인하세요. 에이전트는 챌린지를 결정하는 대신
디바이스를 사용할 수 없다고 알려야 합니다. 계속하기 전에 서비스를 다시 시작하세요.
만료된 대기 중인 요청은 디바이스가 다시 연결될 때 굴려서는 안 됩니다.
새 도구 호출은 새 요청을 생성합니다.

버전 업데이트 실습을 위해 컴포넌트의 로그 메시지를 변경하고 다시 빌드한 다음
동일한 배포 명령을 실행하세요. `NEXT_PATCH`는 새 버전을 게시합니다.
새로 실행 중인 버전을 확인한 다음 다른 굴림을 요청하세요.

## 6. 계속 플레이하거나 모두 제거

확장만 제거하려면:

1. 애플리케이션 스택에서 `DiceArtifactBucket`, `DiceComponentArn` 및 `DiceDeploymentId`
   출력을 기록하세요.
2. `packages/infra/src/dice-resources.ts`에서 `this.deployment.addComponent(component)`를 제거하세요.
   동일한 매개변수로 재배포하세요. 이렇게 하면 빈 배포 수정이 전송됩니다.
   `list-installed-components`가 더 이상 `com.example.DungeonDice`를 나열하지 않을 때까지 기다리세요.
3. 기본 <Link path="get_started/tutorials/dungeon-game/3">Story Agent 프롬프트</Link>를 복원하고,
   `registerDiceTool` import 및 호출을 제거하고,
   <Link path="get_started/tutorials/dungeon-game/2#스택-연결">모듈 2 애플리케이션 스택</Link>을 복원하세요.
   던전을 다시 빌드하고 배포하세요. 이렇게 하면 MCP 권한 및 주사위 구성이 제거됩니다.
4. <Link path="get_started/tutorials/greengrass/cleanup#작업-3-보존된-greengrass-리소스-삭제">보존된 리소스 정리 절차</Link>를 사용하여
   보존된 Greengrass 배포 레코드, 컴포넌트 버전 및 아티팩트 버킷을 삭제하세요.
   `com.example.Pulse`를 `com.example.DungeonDice`로 대체하고 기록된 주사위 출력을 사용하세요.
   업데이트 실습으로 생성된 모든 버전/수정을 포함하세요.
5. 명명된 섀도우를 삭제한 다음 설정 스크립트의 정리를 실행하고
   <Link path="get_started/tutorials/greengrass/cleanup">디바이스 정리 가이드</Link>에 설명된 대로
   소유자 관리 인스턴스 프로필 및 역할을 제거하세요.

```bash
aws --profile "$TUTORIAL_AWS_PROFILE" --region "$TUTORIAL_AWS_REGION" \
  iot-data delete-thing-shadow --endpoint-url "https://${DICE_IOT_ENDPOINT}" \
  --thing-name "$TUTORIAL_THING_NAME" --shadow-name dungeon-dice \
  /tmp/dungeon-dice-shadow-deleted.json
```

이러한 단계 후에도 던전은 배포된 상태로 유지됩니다. 전체 애플리케이션을 제거하려면
보존된 사용자 풀, SMS 역할 및 대화 기록 버킷을 포함하여
<Link path="get_started/tutorials/dungeon-game/wrap-up#리소스-삭제">리소스 파괴</Link>를 계속하세요.
