---
title: AgentCore Runtime Hosting
---

`infra` オプションは、[Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 上でコードをパッケージ化してホストする方法を選択します：

- **`agentcore`** (デフォルト) は [直接コードデプロイ](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-code-deploy-node.html) を使用します：ビルドされたコードは `.zip` としてパッケージ化され、S3 にアップロードされ、AgentCore が管理する言語ランタイム上で実行されます。コンテナイメージのビルド、ECR リポジトリの管理、イメージのプッシュが不要なため、ビルドとデプロイのサイクルが大幅に高速化されます。
- **`agentcore-ecr`** は、提供される `Dockerfile` から `arm64` コンテナイメージをビルドし、ECR からホストします。オペレーティングシステムイメージを制御する必要がある場合（例えば、ネイティブシステムライブラリをインストールする場合）や、確立されたコンテナパイプラインがある場合に選択してください。このオプションは、Trivy イメージスキャンターゲットも提供します（下記の Image Scanning を参照）。
- **`none`** はインフラストラクチャを一切生成しないため、プロジェクトはローカルでのみ実行できます。

両方のホストオプションは、[AWS Distro for OpenTelemetry](https://aws.amazon.com/otel/) (ADOT) による可観測性が設定されています。

:::note[Docker は agentcore-ecr の場合のみ必要です]
`agentcore` はコンテナエンジンを必要としないため、ビルドやデプロイに [Docker](https://www.docker.com/) をインストールする必要はありません。コンテナイメージをビルドしたい場合は `agentcore-ecr` を選択し、以下のようなエラーを回避するために Docker がインストールされ、実行されていることを確認してください：

```
ERROR: Cannot connect to the Docker daemon at unix://path/to/docker.sock.
```
:::
