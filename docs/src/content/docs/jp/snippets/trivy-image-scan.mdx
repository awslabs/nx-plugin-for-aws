このプロジェクト用にビルドされた Docker イメージは、[ECR ホスト版 Trivy イメージ](https://gallery.ecr.aws/aquasecurity/trivy)から実行される [Trivy](https://trivy.dev/) を使用して脆弱性をスキャンできます。

プロジェクトに `trivy` ターゲットが追加され、ビルドされたイメージをスキャンし、`HIGH` または `CRITICAL` の深刻度の脆弱性が見つかった場合は**非ゼロで終了**します。生成された `Dockerfile` は、生成時点でこれらの深刻度の既知の修正可能な脆弱性がないベースイメージを使用し、バンドルされたツール（`npm` など）をアップグレードしてその状態を維持します。

スキャンはイメージビルドと同じコンテナエンジン（`docker` または `finch`）を使用するため、追加のツールは必要ありません。スキャンはキャッシュされません。これは、読み取るイメージがディスク上ではなくコンテナエンジン内に存在するためです — そのため、常に実際のイメージをスキャンし、もはや存在しないイメージに対してキャッシュされた合格を報告するのではなく、明確に失敗します。提供される `trivy` ルートスクリプトは、ワークスペース内のすべてのイメージをスキャンします：

<PackageManagerShortCommand commands={['trivy']} />

:::tip[CI で Trivy を実行]
Trivy の脆弱性データベースは新しい CVE で継続的に更新されるため、開発中の反復時に不要な摩擦が生じる可能性があるため、スキャンは意図的に `build` に組み込まれていません。

代わりに、本番ステージへのデプロイ前に CI パイプラインの専用ステップとして上記のコマンドを実行することをお勧めします。
:::

:::caution[修正不可能な脆弱性は無視されます]
スキャンは `--ignore-unfixed` で実行されるため、利用可能な修正がない脆弱性はビルドを失敗させません。これは、`Dockerfile` 内のツールをアップグレードすることでアクションできないためです — これらはビルドのスキャン出力に報告されません。新しい脆弱性が開示されると、スキャンの結果は時間の経過とともに変わる可能性があるため、フラグなしで `trivy image <your-image>` を実行してイメージを定期的に確認し、修正が公開されたら新しいベースイメージに対して再ビルドする（または利用可能なパッチを適用するコンテナステップを追加する）ことをお勧めします。
:::

#### Trivy の検出結果の抑制

特定の脆弱性を抑制したい場合があります。たとえば、まだ修正が利用できず、リスクを許容可能と評価した場合などです。

脆弱性 ID（1 行に 1 つ）をプロジェクトのルート（つまり `project.json` の隣）にある `.trivyignore` ファイルに追加します：

```gitignore
# .trivyignore
# node-tar arbitrary file write - not exploitable in our usage
CVE-2024-XXXXX
```

検出結果のフィルタリングの詳細については、[Trivy フィルタリングドキュメント](https://trivy.dev/latest/docs/configuration/filtering/#by-finding-ids)を参照してください。
