---
title: 管理者認証情報
---
import Infrastructure from '@components/infrastructure.astro';

Auroraの管理者（マスター）ユーザーのパスワードは、[RDS管理のマスターユーザーパスワード](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/rds-secrets-manager.html)を使用して、Aurora自身がAWS Secrets Managerで生成およびローテーションします。インフラストラクチャコードはパスワードを受け取らないため、CloudFormationテンプレートやTerraformステートファイルに漏洩することはありません。Auroraは、デプロイや保守が必要なローテーション関数なしで、7日ごとにシークレットをローテーションします。

シークレットは、クラスターと同じカスタマー管理のKMSキーで暗号化されます。

アプリケーションはこれらの認証情報を使用しません。IAM認証を使用して最小権限のデータベースユーザーとして接続します。マイグレーションとcreate-db-userハンドラーのみが管理者シークレットを読み取り、それぞれにそのシークレットとそのKMSキーへのアクセスのみが付与されます。

<Infrastructure>
<Fragment slot="cdk">

管理者シークレットは、基盤となるクラスターの`secret.secretArn`として公開され、`grantSecretRead`はコンシューマーにそれへの読み取りアクセスを付与します：

```ts title="packages/infra/src/stacks/application-stack.ts"
import { MyDatabase } from '@my-scope/common-constructs';

const db = new MyDatabase(this, 'Db', { ... });

db.grantSecretRead(myFunction);
```
</Fragment>
<Fragment slot="terraform">

管理者シークレットのARNは、復号化に必要な`kms_key_arn`と共に`secret_arn`出力として公開されます：

```hcl title="packages/infra/src/main.tf"
module "my_database" {
  source = "../../common/terraform/src/app/dbs/my-database"
  ...
}

output "database_secret_arn" {
  value = module.my_database.secret_arn
}
```

RDS管理のシークレットは、`username`と`password`のみを含むJSONオブジェクトを保持します。接続の詳細は含まれません。ホスト、ポート、データベース名は、モジュールの`writer_endpoint`、`cluster_port`、`database_name`出力から取得してください。
</Fragment>
</Infrastructure>

:::caution[手動でのローテーション]
Auroraのスケジュール外で管理者パスワードをローテーションするには、Secrets Managerではなく、RDS API（`modify-db-cluster --rotate-master-user-password --apply-immediately`）を使用します。RDS管理のシークレットに独自のローテーション関数をアタッチすることは拒否されます。
:::
