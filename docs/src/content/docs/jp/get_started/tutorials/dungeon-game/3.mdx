## タスク1: Storyエージェントの実装

Storyエージェントは、<Link path="get_started/tutorials/dungeon-game/1">モジュール1</Link>で`--protocol=ag-ui`を使用して生成された[Strands](https://strandsagents.com/)エージェントです。これにより、UIはCopilotKitを介して[Agent-User Interactionプロトコル](https://docs.copilotkit.ai/aws-strands/protocol)経由でストリーミングできます。Inventory MCP Serverを使用してプレイヤーのアイテムを管理し、モジュール1でジェネレーターがプロビジョニングした`session.py`を介して会話履歴を既に永続化しています。デプロイされると、これはStrandsの組み込み[`S3SessionManager`](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/agents/sessions/)であり、Game APIの`queryActions`が読み取るのと同じS3バケットに書き込むため、ブラウザは再訪時にトランスクリプトを再構築できます。

### エージェントの実装

`packages/story/dungeon_adventure_story/agent`の`agent.py`を更新します:

<E2EDiff lang="python" before="dungeon-adventure/3/agent.py.old.template" after="dungeon-adventure/3/agent.py.template" />

`agent.py`はサンプルの`subtract`ツールを削除し、システムプロンプトをダンジョンマスター用のものに置き換えます。これは、最初のユーザーメッセージでプレイヤーの名前とジャンルを述べるよう促し、Inventory MCP Serverのツールを使用します。`main.py`はここでは変更不要です。エージェントが生成された時点でセッション管理は既に配線されています。

### エージェントとチャットする

生成された`agent-chat`ターゲットは、エージェントに対してインタラクティブなREPLを開きます。これはスタンドアロンで実行され、ローカルで実行中のエージェントに接続するため、まず1つのターミナルでエージェントのローカルサーバーを起動します:

<NxCommands commands={["agent-dev story"]} />

次に、2つ目のターミナルでチャットを開始します:

<NxCommands commands={["agent-chat story"]} />

最初のメッセージでは、エージェントにヒーローの名前とジャンルを伝える必要があります（例: `My name is Alice. Start my zombie adventure.`）。ストーリーがストリーミングで返されます。

<Aside type="caution" title="AWS認証情報が必要">
エージェントはローカルで実行されますが、LLMのために[Amazon Bedrock](https://aws.amazon.com/bedrock/)を呼び出します。[Strandsデフォルトモデル](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/model-providers/amazon-bedrock/)にアクセスできるAWS認証情報が環境に必要です。詳細については、[Strandsモデルプロバイダーのドキュメント](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/model-providers/amazon-bedrock/)を参照してください。
</Aside>
