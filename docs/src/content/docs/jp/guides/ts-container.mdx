このジェネレーターは、既存のTypeScriptプロジェクトにコンテナ化されたHTTPサービスを追加します。`GET /health`ルートを持つ小さなHTTPサーバー、Dockerfile、そしてサーバーをローカルで実行し、イメージをビルドしてスキャンするためのターゲットが提供されます。また、[Amazon Elastic Container Service (Amazon ECS)](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/Welcome.html)（コンテナを実行およびスケーリングするAWSサービス）上でイメージを実行するCDKまたはTerraformコードも取得できます。

サービスは[AWS Fargate](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/AWS_Fargate.html)上で実行されます。これは、管理するサーバーなしで各コンテナを実行します。サービスは、独自のVPC（仮想プライベートクラウド、AWSアカウント内の隔離されたネットワーク）内で、VPC内のアドレスからのみ到達可能な内部[Application Load Balancer](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html)（ALB）の背後で実行されます。デフォルトでは、[Amazon API Gateway HTTP API](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api.html)が呼び出し元からのリクエストを受信し、VPCリンク（API GatewayのVPCへのプライベート接続）を通じてALBに渡します。呼び出し元は認証されたHTTPSエンドポイントを取得し、ロードバランサーはインターネットに公開されません。

### オプション

<GeneratorParameters generator="ts#container" />

`infra`、`ingress`、`auth`オプションは相互に依存しています。`infra`を`none`に設定すると、ジェネレーターはインフラストラクチャを生成せず、警告とともに`ingress`と`auth`を無視します。`ingress`は`infra`が`ecs`に設定されている場合にのみ適用されます。`auth`は`ingress`が`http-api`に設定されている場合にのみ適用されます。これは、`private`サービスには認証するHTTP APIがないためです。

## ジェネレーターの出力

ジェネレーターは、プロジェクトに以下のファイルを追加します。ソースフォルダーは`name`オプションに従って命名されます。省略した場合は`service`になります：

<FileTree>
  - your-project/
    - src/
      - service/ (または選択した名前)
        - server.ts HTTPルート：`GET /health`とサンプルルート`GET /hello`
        - index.ts `PORT`を読み取りサーバーを起動するエントリーポイント。バンドルと`<name>-serve`ターゲットはこのファイルから開始されます
        - Dockerfile コンテナイメージ定義
        - .dockerignore イメージビルドコンテキストから除外されるファイル
    - rolldown.config.ts `index.ts`のバンドルエントリーで更新されます
    - project.json `bundle`ターゲットと、サービス用の`<name>-serve`、`<name>-docker`、`<name>-trivy`ターゲットで更新されます
</FileTree>

ターゲット名は`name`オプションで始まります。省略した場合は`service`で始まります。例えば、名前なしの場合、ターゲットは`service-serve`、`service-docker`、`service-trivy`となり、`--name=orders`の場合は`orders-serve`、`orders-docker`、`orders-trivy`となります。`bundle`ターゲットは、プロジェクト内のすべてのバンドルされたエントリーポイントで共有されます。

## サービスをローカルで実行する

`<name>-serve`ターゲットは、コンテナなしでマシン上でサーバーを実行します：

<NxCommands commands={['run your-project:service-serve']} />

サーバーは`PORT`環境変数のポートでリッスンします。`<name>-serve`ターゲットは、ジェネレーターが割り当てたポートに設定します。8081から開始し、ワークスペース内の他のプロジェクトがすでに使用しているポートをスキップします。コンテナ内では、サーバーはポート8080でリッスンします。

ヘルスルートでサーバーが起動していることを確認します。これはステータス200と`{"status":"ok"}`を返します：

```bash
curl http://localhost:<port>/health
```

サーバーには、独自のルートに置き換えるサンプルルートもあります。`GET /hello?name=<x>`は`{"message":"Hello, <x>!"}`を返し、`name`のデフォルトは`world`です。その他のパスはステータス404を返します。

## イメージのビルドとスキャン

`<name>-docker`ターゲットは、サービスのlinux/arm64イメージをビルドします。最初に`bundle`ターゲットを実行するため、イメージにはバンドルされたサーバーが含まれます。次に、`Dockerfile`と`.dockerignore`をバンドル出力フォルダー`dist/<project root>/bundle/container/<name>`にコピーし、そのフォルダーをビルドコンテキスト（イメージビルドが読み取れるファイル）としてイメージをビルドします。ワークスペースで設定されているコンテナエンジン、`docker`または[Finch](https://runfinch.com/)を使用します。このターゲットは、プロジェクト内のすべてのイメージをビルドする集約`docker`ターゲットの一部として実行されます。

<NxCommands commands={['run your-project:service-docker']} />

ロードバランサーのターゲットグループ（ロードバランサーがリクエストを送信するタスクのリスト）のみが`GET /health`をチェックして、タスクがトラフィックの準備ができているかどうかを判断します。ECSはDockerfileの`HEALTHCHECK`命令を無視します。イメージのビルドと公開の詳細については、<Link path="/guides/docker-bundling">Docker Bundling</Link>を参照してください。

## サービスのデプロイ

### インフラストラクチャへのサービスの追加

コンストラクトとモジュールはVPCを作成しません。スタックまたはルートモジュールでVPCを作成またはインポートし、それを渡します。タスクとロードバランサーは、NATゲートウェイ（プライベートサブネットがアウトバウンド接続を行えるようにする管理されたゲートウェイ）またはVPCエンドポイント（VPCからAWSサービスへのプライベート接続）を通じてAWSサービスに到達する、エグレス付きのプライベートサブネットで実行されます。

<Infrastructure>
<Fragment slot="cdk">
CDKコンストラクトは`common/constructs`に作成され、サービスにちなんで命名されます。新しいVPCでの使用例：

```ts title="packages/infra/src/stacks/application-stack.ts"
import { MyService } from '@my-scope/common-constructs';
import { Stack, StackProps } from 'aws-cdk-lib';
import { SubnetType, Vpc } from 'aws-cdk-lib/aws-ec2';
import { Construct } from 'constructs';

export class ApplicationStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props);

    const vpc = new Vpc(this, 'Vpc', { natGateways: 1 });

    new MyService(this, 'MyService', {
      vpc,
      vpcSubnets: { subnetType: SubnetType.PRIVATE_WITH_EGRESS },
    });
  }
}
```

既存のVPCを使用するには、`Vpc.fromLookup(this, 'Vpc', { vpcId: '<vpc-id>' })`で検索し、`vpc`として渡します。
</Fragment>

  asset_ecr_repository_arn = module.asset_ecr.repository_arn

  appconfig_application_id  = module.runtime_config_appconfig.application_id
  appconfig_application_arn = module.runtime_config_appconfig.application_arn
}
```

### リクエスト制限

API Gatewayは30秒後にサービスの待機を停止し、呼び出し元にエラーを返します。この統合タイムアウトを引き上げることはできません。HTTP APIが受け入れる最大のリクエストペイロードは10 MBで、この制限も引き上げることはできません。両方の値は[Amazon API Gateway quotas for HTTP APIs](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-quotas.html)ページから来ています。

したがって、30秒より長く実行されるリクエストや、長時間にわたってデータをストリーミングするレスポンスは、HTTP APIを通じて機能しません。それらの場合は、`ingress`を`private`に設定し、VPC内から内部ロードバランサーを呼び出してください。
</OptionFilter>

### NATゲートウェイなしでの実行

タスクが起動すると、ECSはイメージをプルし、タスクに代わってログを送信します。サーバーコードもAWSサービスを呼び出す可能性があります。NATゲートウェイのないプライベートサブネットでは、これらの呼び出しのそれぞれにVPCエンドポイントが必要です。適切なエンドポイントがないと、タスクは起動に失敗するか、AWSを呼び出すときにタイムアウトします。

VPCに以下のエンドポイントを作成し、`<region>`をAWSリージョンに置き換えてください：

| エンドポイント | タイプ | 使用者 |
| --- | --- | --- |
| `com.amazonaws.<region>.ecr.api` | Interface | ECS、Amazon ECRで認証しイメージを検索するため |
| `com.amazonaws.<region>.ecr.dkr` | Interface | ECS、Amazon ECRからイメージをプルするため |
| `com.amazonaws.<region>.s3` | Gateway | ECS、Amazon ECRがAmazon S3に保存するイメージレイヤーをダウンロードするため |
| `com.amazonaws.<region>.logs` | Interface | コンテナのログ出力、Amazon CloudWatch Logsに送信されます |
| `com.amazonaws.<region>.secretsmanager` | Interface | ECS、タスク起動時にコンテナに渡すシークレットを読み取るため |
| `com.amazonaws.<region>.appconfigdata` | Interface | コード、AWS AppConfigから<Link path="/guides/runtime-config">ランタイム設定</Link>を読み取るため |
| `com.amazonaws.<region>.sts` | Interface | コード、AWS STSから一時的な認証情報をリクエストするとき（例：別のロールを引き受ける） |

インターフェースエンドポイントには、タスクからのHTTPS（ポート443）を許可するセキュリティグループが必要です。Amazon ECRエンドポイントの詳細については、[Amazon ECR interface VPC endpoints](https://docs.aws.amazon.com/AmazonECR/latest/userguide/vpc-endpoints.html)を参照してください。

### セキュリティのデフォルト

生成されたインフラストラクチャは、デフォルトで以下の設定を適用します：

- ロードバランサーは内部です。`0.0.0.0/0`または`::/0`からのインバウンドトラフィックを許可するセキュリティグループはありません。
- タスクはプライベートサブネットで実行され、パブリックIPアドレスを取得しません。
- ロードバランサーは、VPCリンク（`http-api`）またはVPCのアドレス範囲（`private`）からのトラフィックのみを受け入れます。タスクは、コンテナポートでロードバランサーからのトラフィックのみを受け入れます。
- タスクは、ポート443でのみアウトバウンドトラフィックを送信できます。データベースへの接続は、データベースポートを追加します。
- タスクロール（サーバーコードが実行されるロール）は、ユーザーまたは接続がさらに許可を付与するまで、AWS AppConfigからランタイム設定を読み取ることのみができます。
- 実行ロール（ECSがタスクを起動するために使用するロール）は、サービスのイメージをプルし、ロググループに書き込み、リストしたシークレットを読み取ることのみができます。
- シークレットは、AWS Secrets ManagerまたはAWS Systems Manager Parameter Storeへの参照としてのみコンテナに到達し、プレーンな環境値としては決して到達しません。
- コンテナは読み取り専用のルートファイルシステムを持ち、uid 1000（非rootユーザー）として実行されます。ECS Exec（実行中のタスクへのシェルアクセス）はオフです。
- ヘルスチェックに失敗したデプロイは停止し、以前のバージョンにロールバックします。
- HTTP APIはアクセスログを書き込み、リクエストをスロットルします。特に選択しない限り、IAMで認証します。
- ログは1年間保持されます。

生成されたコードは、以下の[Checkov](https://www.checkov.io/)チェック（Checkovはインフラストラクチャコードを安全でない設定についてスキャンします）を抑制し、各抑制の横に理由を記載しています：

- `CKV_AWS_91`はロードバランサーのアクセスログを要求します。代わりに、HTTP APIアクセスログまたはサービス自身のログがリクエストを記録します。
- `CKV_AWS_2`と`CKV_AWS_103`は、TLSを使用したHTTPSリスナーを要求します。ロードバランサーは内部であり、VPC内の呼び出し元のみが到達できるため、プレーンHTTPでリッスンします。`http-api`の場合、TLSはAPI Gatewayで終了します。

Terraformモジュールは、同じHTTPリスナーの理由で`CKV2_AWS_20`と`CKV_AWS_378`もスキップし、サービスを破棄できるようにロードバランサーの削除保護がオフになっているため`CKV_AWS_150`もスキップします。

### サービスの呼び出し

サービスのURLは、<Link path="/guides/runtime-config">ランタイム設定</Link>に`connection.services.<NameClassName>`として書き込まれます。ここで、`<NameClassName>`はPascalCaseのサービス名です。`--name=orders`の場合、キーは`Orders`です。名前がない場合、サービス名は`<project>-service`となるため、`my-project`というプロジェクトの場合、キーは`MyProjectService`です。その場合でも、ソースフォルダーとターゲットプレフィックスは`service`のままです。

### 高度な設定

生成されたサービスは、名前、`ingress`、`auth`を設定します。以下の例では、生成されたサービスが渡さない設定や、インスタンスごとに`ingress`と`auth`を選択するために、汎用の`EcsService`コンストラクトと`ecs-service`モジュールを直接使用します。

CDKでは、`common-constructs`パッケージがサービスのコンストラクトの隣に`EcsService`をエクスポートするため、同じ方法でインポートします：`import { EcsService } from '@my-scope/common-constructs'`。生成されたコンストラクトは`EcsService`を拡張し、他のすべてのプロップを渡します。例えば、`cluster`、`loadBalancer`、`environment`、`secrets`、`grantTaskRole`などです。オプションの`image`プロップは、プロジェクトからビルドされたイメージを置き換えます。`auth`プロップはありません。Cognitoサービスは代わりに`identity`を取り、他のサービスは常に生成された`auth`を使用します。

Terraformでは、サービスのモジュールは`ecs-service`モジュールの変数の一部のみを設定できます：`vpc_id`、`subnet_ids`、`cluster_arn`、`environment`、`secrets`、`task_role_policy_statements`、`tags`、およびCognitoサービスの場合は`user_pool_id`と`user_pool_client_ids`です。他の変数を設定するには、サービスのモジュール内の`module "ecs_service"`ブロックを編集します。

#### ビルド済みイメージ

すでにビルドされているイメージ（例：パブリックレジストリから）を実行するには、そのURIを渡します。ローカルでは何もビルドされません。プライベートAmazon ECRリポジトリのイメージの場合、CDKはそのリポジトリに対する実行ロールのプルアクセスを付与します。Terraformは、リポジトリのARNを`image_repository_arn`として渡した場合にのみプルアクセスを付与します。

new EcsService(this, 'Prebuilt', {
  serviceName: 'Prebuilt',

  image: { imageUri: 'public.ecr.aws/my-org/my-image@sha256:<digest>' },

```

#### サイジングとスケーリング

各タスクは、デフォルトで256 CPUユニット（vCPUの4分の1）と512 MiBのメモリを取得します。サービスは1つのタスクを起動し、オートスケーリングは1つから2つのタスクを実行し続け、平均CPU使用率が70%を超えるとタスクを追加します。

| 設定 | CDKプロップ | Terraform変数 | デフォルト |
| --- | --- | --- | --- |
| タスクあたりのCPUユニット | `cpu` | `cpu` | 256 |
| タスクあたりのメモリ（MiB） | `memoryLimitMiB` | `memory` | 512 |
| 起動時のタスク数 | `desiredCount` | `desired_count` | 1 |
| 最小タスク数 | `minCapacity` | `min_capacity` | 1 |
| 最大タスク数 | `maxCapacity` | `max_capacity` | 2 |
| ターゲット平均CPU（%） | `targetCpuUtilizationPercent` | `target_cpu_utilization` | 70 |

#### タスクロールの権限

サービスのコンストラクトまたはモジュールのタスクロールは、ランタイム設定への読み取りアクセスのみで開始します。コードが必要とする権限を追加します：

#### コンテナユーザー

タスク定義は、uid 1000（非rootユーザー）としてコンテナを実行します。これは、提供されたDockerfileが設定する`node`ユーザーと一致します。別のユーザーとして実行するには、CDKの`user`プロップまたはTerraformの`container_user`変数を設定します。Terraformは`0`と`root`を拒否します。

| 設定 | CDKプロップ | Terraform変数 | デフォルト |
| --- | --- | --- | --- |
| コンテナが実行されるユーザー | `user` | `container_user` | `'1000'`（CDK）、`"1000:1000"`（Terraform） |

#### CORSとスロットリング

これらの設定は、`ingress`が`http-api`に設定されている場合にのみ適用されます。CORS（クロスオリジンリソース共有）は、どのWebサイトがブラウザからサービスを呼び出せるかを決定します。デフォルトでは、HTTP APIは任意のオリジンから、任意のメソッドで、`authorization`、`content-type`、`x-amz-content-sha256`、`x-amz-date`、`x-amz-security-token`ヘッダーを使用したブラウザリクエストを受け入れます。最後の3つは、SigV4署名が追加するヘッダーです。HTTP APIは、リクエストを毎秒10,000の安定したレートにスロットルし、最大5,000のバーストを許可します。

| 設定 | CDK | Terraform変数 | デフォルト |
| --- | --- | --- | --- |
| 許可されたCORSオリジン | `restrictCorsTo(...origins)`メソッド、または`corsPreflight`プロップ | `cors_allow_origins` | 任意のオリジン（`["*"]`） |
| その他のCORS設定 | `corsPreflight`プロップ | none | 任意のメソッド、および上記のヘッダー |
| スロットリング | `throttle`プロップ | none | `{ rateLimit: 10000, burstLimit: 5000 }` |

`corsPreflight`プロップはデフォルト全体を置き換えるため、呼び出し元が送信するすべてのヘッダーをリストします。`restrictCorsTo`メソッドは他のCORS設定を保持し、許可されたオリジンのみを変更します：

```ts
const service = new MyService(this, 'MyService', { vpc });
service.restrictCorsTo('https://app.example.com');
```

Terraformでは、`cors_allow_origins`と`container_user`は`ecs-service`モジュールの変数です。サービスのモジュールはそれらを渡さないため、その`module "ecs_service"`ブロックで設定します。スロットリング値は`ecs-service.tf`で固定されています。

### コスト

コンテナサービスは、Lambda関数とは異なり、アイドル状態でも課金されます。これらの部分は、誰かがサービスを呼び出すかどうかに関係なく、時間単位で課金されます：

- Fargateタスク、vCPUごとおよびメモリのGBごと。`desiredCount`と`minCapacity`は少なくとも1つのタスクを実行し続けます。
- Application Load Balancer、時間ごとおよびロードバランサー容量ユニットごと。
- インターフェースVPCエンドポイント、各アベイラビリティーゾーンで時間ごと、またはNATゲートウェイ、時間ごとおよび処理するデータのGBごと。
- CloudWatch Logsのログストレージ、およびAmazon ECRのイメージストレージ。

HTTP APIはリクエストごとに課金されます。リージョンとトラフィックのコストを見積もるには、[AWS Pricing Calculator](https://calculator.aws/)を使用してください。

## サービスの接続

<Link path="/guides/connection">`connection`</Link>ジェネレーターを使用して、サービスをワークスペース内の他のプロジェクトに接続します：

<RunGenerator generator="connection" />

Webサイトまたはエージェントがサービスを呼び出すことができ、サービスはリレーショナルデータベースまたはDynamoDBテーブルを使用できます。各接続には独自のガイドがあります：

- <Link path="guides/connection/react-container">React to Container Service</Link>
- <Link path="guides/connection/ts-agent-container">TypeScript Agent to Container Service</Link>
- <Link path="guides/connection/py-agent-container">Python Agent to Container Service</Link>
- <Link path="guides/connection/ts-container-rdb">TypeScript Container Service to Relational Database</Link>
- <Link path="guides/connection/ts-container-dynamodb">TypeScript Container Service to DynamoDB</Link>

各接続には条件もあります：

- Webサイトまたはエージェントは、`ingress`が`http-api`に設定されているサービスにのみ接続できます。
- エージェントは、`auth`が`iam`に設定されているサービスにのみ接続できます。
- データベースまたはDynamoDB接続には、`infra`が`ecs`に設定されているサービスが必要です。
