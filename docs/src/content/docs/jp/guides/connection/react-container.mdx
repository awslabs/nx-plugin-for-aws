`connection` ジェネレーターを使用すると、React ウェブサイトから <Link path="guides/ts-container">`ts#container`</Link> または <Link path="guides/py-container">`py#container`</Link> で作成されたコンテナサービスを呼び出すことができます。このジェネレーターは、ランタイム設定からサービスの URL を読み取り、各リクエストにサービスが期待する認証を追加する React フックを追加します。

## 仕組み

`infra=ecs` を持つコンテナサービスは、内部 Application Load Balancer の背後で Amazon ECS (Elastic Container Service) 上で実行されます。デフォルトの `ingress=http-api` では、Amazon API Gateway HTTP API（マネージド HTTPS エンドポイント）が VPC リンクを介してそのロードバランサーに到達します。VPC リンクは、API Gateway が VPC への専用接続です。ウェブサイトは HTTP API を呼び出します。

サービスの `auth` オプションは、HTTP API が各リクエストをチェックする方法を決定します：

- `iam`（デフォルト）：リクエストは AWS リクエスト署名プロセスである SigV4 で署名される必要があります。フックは、ウェブサイトの Cognito アイデンティティプールがサインインユーザーに提供する一時的な AWS 認証情報を使用してリクエストに署名します。
- `cognito`：リクエストには、サインインユーザーの Cognito アクセストークンがベアラートークンとして含まれている必要があります。
- `none`：HTTP API はすべてのリクエストを受け入れます。

HTTP API は 30 秒以上かかるリクエストを終了するため、より長く実行されるルートは早期に戻り、バックグラウンドで作業を完了する必要があります。

ジェネレーターは、到達できないサービスを拒否します。サービスは `infra=ecs` を持つ必要があります。なぜなら、`infra=none` はエンドポイントを作成しないからです。また、`ingress=http-api` を持つ必要があります。なぜなら、`private` サービスは VPC 内部からのみ到達可能だからです。

## 前提条件

このジェネレーターを使用する前に、以下を確認してください：

1. React ウェブサイト（<Link path="guides/react-website">`ts#website` ジェネレーター</Link>を使用して生成）
2. `infra=ecs` と `ingress=http-api` を持つコンテナサービス（<Link path="guides/ts-container">`ts#container`</Link> または <Link path="guides/py-container">`py#container`</Link> ジェネレーターを使用して生成）
3. サービスの `auth` が `iam` または `cognito` の場合、<Link path="guides/react-website-auth">`ts#website#auth` ジェネレーター</Link>を介して追加された Cognito Auth

## ジェネレーターの出力

ジェネレーターは、React ウェブサイトに以下のファイルを作成します：

<FileTree>

- src
  - hooks
    - use\<ServiceName>.tsx Hook returning the service's URL and a `fetch` that adds the service's authentication
    - useSigV4.tsx Hook for signing requests with SigV4 (`iam` only)
  - components
    - RuntimeConfig/index.tsx Points the hook at the local service in local development

</FileTree>

`<ServiceName>` はサービスのクラス名です。例えば、`orders` という名前のサービスの場合は `useOrders` です。ジェネレーターは、ウェブサイトに以下の依存関係も追加します：

- `aws4fetch`、`oidc-client-ts`、`@aws-sdk/credential-provider-cognito-identity`、`react-oidc-context`、および開発依存関係 `@smithy/types`（`iam`）
- `react-oidc-context`（`cognito`）

## フックの使用

フックはサービスの `url` と `fetch` 関数を返します。`fetch` は、サービスに対する相対パスと通常の `fetch` オプションを受け取ります：

```tsx
import { useEffect, useState } from 'react';
import { useMyService } from './hooks/useMyService';

export const ServiceStatus = () => {
  const myService = useMyService();
  const [status, setStatus] = useState<number>();

  useEffect(() => {
    myService.fetch('/health').then((response) => setStatus(response.status));
  }, [myService.fetch]);

  return <p>Service status: {status ?? 'loading'}</p>;
};
```

デプロイされたサービスは、その URL を <Link path="guides/runtime-config">ランタイム設定</Link>の `connection.services.<ServiceName>` に書き込み、ウェブサイトは `runtime-config.json` からそれを読み取ります。

ウェブサイトはブラウザから HTTP API を呼び出すため、HTTP API の CORS（クロスオリジンリソース共有）設定はウェブサイトのオリジンを許可する必要があります。ジェネレーターはそれらを変更しません。デフォルトでは、HTTP API は任意のオリジンからのリクエストを、フックが送信する `authorization`、`content-type`、および SigV4 ヘッダーとともに受け入れます。ウェブサイトからのリクエストのみを受け入れるには、CDK で `myService.restrictCorsTo('https://<your website domain>')` を呼び出します。Terraform では、サービスのモジュールの `module "ecs_service"` ブロックで `cors_allow_origins` を設定します。詳細については、<Link path="guides/ts-container#cors-and-throttling">CORS and Throttling</Link> を参照してください。

## インフラストラクチャ

`auth=iam` の場合、ウェブサイトのサインインユーザーはサービスの HTTP API を呼び出す権限が必要です。ジェネレーターはスタックまたはルート Terraform モジュールを変更しません。代わりに、追加するコードを出力します。以下は、`my-service` という名前のサービスの例です。これを追加するまで、HTTP API はウェブサイトのリクエストを 403 Forbidden で拒否します。`cognito` と `none` の場合、追加するものはありません。

<Infrastructure>
<Fragment slot="cdk">

この例では、`myService` は `MyService` コンストラクトで、`identity` は `UserIdentity` コンストラクトです：

```ts title="packages/infra/src/stacks/application-stack.ts"
myService.grantInvoke(identity.identityPool.authenticatedRole);
```

`grantInvoke` は、アイデンティティプールの認証済みロールがサービスの HTTP API で `execute-api:Invoke` を呼び出すことを許可します。

</Fragment>
<Fragment slot="terraform">

この例では、`module "my_service"` がサービスをデプロイし、`module "user_identity"` がウェブサイトのアイデンティティプールをデプロイします：

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_role_policy" "authenticated_my_service_invoke" {
  name = "authenticated-my-service-invoke"
  role = module.user_identity.authenticated_role_name

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = ["execute-api:Invoke"]
        Resource = ["${module.my_service.api_execution_arn}/*"]
      },
    ]
  })
}
```

## ローカル開発

<NxCommands commands={["dev <website-project-name>"]} />

ウェブサイトの `dev` ターゲットは、サービスの `<service-name>-serve` ターゲットも起動し、フックは `http://localhost:<port>` でサービスを呼び出します。ポートは、コンテナジェネレーターがサービスに割り当てたポートです。ローカル開発では、`runtime-config.json` に Cognito 設定がない場合、`useSigV4` フックはリクエストに署名しません。
