`connection`ジェネレーターは、<Link path="guides/react-website">React website</Link>を、`protocol: http`で生成された<Link path="guides/agentcore-gateway">AgentCore Gateway</Link>によってフロントされるエージェントに接続できます。

ブラウザはGatewayとのみ通信します — `<gatewayUrl>/<targetName>/invocations`へのリクエストは、その背後にあるエージェントランタイムにプロキシされます。WebsiteがランタイムへのアクセスをWebsiteが直接必要としないため、エージェントはVPC内にデプロイでき、Gatewayが認証と可観測性を提供する単一の管理されたエントリーポイントとなります。

## 前提条件

このジェネレーターを使用する前に、以下を確認してください：

1. <Link path="guides/react-website">React website</Link>プロジェクト
2. `protocol: http`で生成された<Link path="guides/agentcore-gateway">`agentcore-gateway`</Link>プロジェクト
3. <Link path="guides/connection/agentcore-gateway-agent">GatewayからエージェントへのConnectionジェネレーター</Link>を介してGatewayに接続された少なくとも1つのAG-UIまたはHTTPエージェント

ジェネレーターは、Gatewayに接続された**各**AG-UIまたはHTTPエージェントに対してWebsiteクライアントを作成します（A2Aターゲットはスキップされます — これらはブラウザプロトコルではなく、エージェント間JSON-RPCを使用します）。Websiteを各エージェントに直接接続する場合と同じクライアント（AG-UIエージェントには<Link path="guides/connection/react-agui">AG-UI/CopilotKit</Link>、Python HTTPエージェントには<Link path="guides/connection/react-py-agent">OpenAPIクライアント</Link>）を生成しますが、ランタイムではなくGatewayを経由してルーティングされます。

:::note[認証]
ブラウザはエージェントではなく**Gateway**で認証します：IAM Gatewayの場合はSigV4（Websiteの Cognito identity poolを介して）、Cognito GatewayのJWT bearerトークンです。
:::

## ジェネレーターの出力

フロントされた各AG-UIエージェントに対して、<Link path="guides/connection/react-agui">ReactからAG-UIエージェントへの接続</Link>と同じファイル（`AguiProvider`、`useAgui<Agent>`フック、テーマ付きCopilotKitコンポーネントモジュール）が生成され、フックはランタイム設定からGatewayのURLを読み取ります：

<FileTree>

- packages/\<website>/src
  - components
    - AguiProvider.tsx 各エージェントを登録するCopilotKitプロバイダー
    - copilot/ テーマ付きチャットコンポーネント
  - hooks
    - useAgui\<Agent>.tsx Gatewayの`/<targetName>/invocations`ルートを介してエージェントに接続

</FileTree>

フロントされた各Python HTTPエージェントに対して、<Link path="guides/connection/react-py-agent">ReactからPythonエージェントへの接続</Link>と同じファイル（型安全なOpenAPIクライアント、フック、プロバイダー）が生成され、クライアントのベースURLはGatewayを経由してルーティングされます。

GatewayのURLは<Link path="guides/runtime-config">Runtime Configuration</Link>の`connection.gateways.<GatewayClassName>`名前空間に登録されるため、Websiteの`runtime-config.json`に公開されます。

## Websiteユーザーへのアクセス許可

**IAM** Gatewayの場合、Websiteの認証済みユーザーに呼び出し権限を付与します（**Cognito** Gatewayでは付与は不要です — ブラウザは代わりにJWT bearerトークンで認証します）：

<Infrastructure>
<Fragment slot="cdk">

```ts title="packages/infra/src/stacks/application-stack.ts" {6}
const identity = new UserIdentity(this, 'UserIdentity');
new Website(this, 'Website');

const myGateway = new MyGateway(this, 'MyGateway');
myGateway.addAgent(myAgent);
myGateway.grantInvokeAccess(identity.identityPool.authenticatedRole);
```
</Fragment>
<Fragment slot="terraform">

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_policy" "gateway_invoke_policy" {
  name = "GatewayInvokePolicy"

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = ["bedrock-agentcore:InvokeGateway"]
```

## ローカル開発

Websiteの`dev`ターゲットはGatewayプロジェクトの`dev`ターゲットに依存関係を持ち、ローカルゲートウェイと接続されたすべてのエージェントを起動します。Websiteのランタイム設定は`local-dev`モードでオーバーライドされ、GatewayのURLがローカルゲートウェイを指すようになるため、ブラウザはローカルで同じ`/<targetName>/invocations`ルートを実行します：

<NxCommands commands={["dev <website-name>"]} />

## 新しいエージェントの接続

ジェネレーターは、**実行時に**Gatewayに接続されているエージェントにWebsiteを接続します。Gatewayに別のエージェントを接続した後、Connectionジェネレーターを再実行してそのWebsiteクライアントを生成します — 既存のクライアントはそのまま残ります。
