`connection` ジェネレーターは、<Link path="guides/ts-container">TypeScript コンテナサービス</Link>が<Link path="guides/ts-dynamodb">TypeScript DynamoDB</Link>プロジェクトを使用できるようにします。ローカル開発環境を構成してサービスと DynamoDB Local が一緒に起動するようにし、サービスに必要な権限を出力します。

## 仕組み

`infra=ecs` を持つコンテナサービスは、Amazon ECS (Elastic Container Service) 上でタスクとして実行されます。各タスクはサービスのタスクロール（IAM ロール）として実行され、追加の権限を付与するまではランタイム設定の読み取りのみが可能です。テーブルの読み書きを行うには、タスクロールにテーブルとそのインデックスに対する DynamoDB アクションと、テーブルの AWS KMS 暗号化キーの使用権限が必要です。

ジェネレーターは `infra=none` を持つサービスを拒否します。このようなサービスにはアクセス権を付与するタスクロールが存在しないためです。

## 前提条件

このジェネレーターを使用する前に、以下を確認してください：

1. `infra=ecs` を持つコンテナサービス（<Link path="guides/ts-container">`ts#container`</Link> ジェネレーターを使用して生成）
2. <Link path="guides/ts-dynamodb">`ts#dynamodb`</Link> プロジェクト

## ジェネレーターの出力

ジェネレーターは、`project.json` 内のサービスの `<service-name>-serve` ターゲットを更新して、DynamoDB プロジェクトの `dev` ターゲットに依存するようにします。ソースファイルは変更されません。

## サービスでの DynamoDB の使用

DynamoDB パッケージからエンティティファクトリーをインポートし、リクエストを処理する場所で使用します：

```ts title="packages/my-project/src/my-service/examples.ts"
import { createExampleEntity } from '@my-scope/my-table';

export const listExamples = async () => {
  const entity = await createExampleEntity();
  const result = await entity.scan.go();
  return result.data;
};
```

## インフラストラクチャ

ジェネレーターはスタックやルート Terraform モジュールを変更しません。代わりに、追加するコードを出力します。以下は、`my-service` という名前のサービスと `my-table` という名前のテーブルの例です。これを追加するまで、サービスからテーブルへのリクエストは拒否されます。

この例では、`myService` は `MyService` コンストラクトで、`myTable` は `MyTable` コンストラクトです：

```ts title="packages/infra/src/stacks/application-stack.ts"
myTable.grantReadWriteData(myService.taskRole);
```

`grantReadWriteData` は、サービスのタスクロールに DynamoDB と KMS の両方の権限を付与します。

<Fragment slot="terraform">

この例では、`module "my_service"` がサービスをデプロイし、`module "my_table"` がテーブルをデプロイします：

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_role_policy" "my_service_my_table_access" {
  name = "my-service-my-table-access"
  role = module.my_service.task_role_name

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Action = [
          "dynamodb:GetItem", "dynamodb:PutItem", "dynamodb:UpdateItem",
          "dynamodb:DeleteItem", "dynamodb:Query", "dynamodb:Scan",
          "dynamodb:BatchGetItem", "dynamodb:BatchWriteItem",
        ]
        Resource = [
          module.my_table.table_arn,
          "${module.my_table.table_arn}/index/*",
        ]
      },
      {
        Effect = "Allow"
        Action = [
          "kms:Encrypt",
          "kms:Decrypt",
          "kms:ReEncrypt*",
          "kms:GenerateDataKey*",
          "kms:DescribeKey",
        ]
        Resource = [module.my_table.kms_key_arn]
      },
    ]
  })
}
```

## ローカル開発

<NxCommands commands={["<service-name>-serve <project-name>"]} />

これにより、サービスと DynamoDB Local が起動します。`LOCAL_DEV=true` が設定されている場合、`getDynamoDBClient()` と `resolveTableName()` は AWS ではなく DynamoDB Local に接続します。
