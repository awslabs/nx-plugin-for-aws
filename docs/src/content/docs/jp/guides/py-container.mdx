このジェネレーターは、既存のPythonプロジェクトにコンテナベースのHTTPサービスを追加します。小さな[FastAPI](https://fastapi.tiangolo.com/)サーバーが提供され、[uvicorn](https://www.uvicorn.org/)ウェブサーバーで実行され、`GET /health`ルート、Dockerfile、およびサーバーをローカルで実行し、イメージをビルドしてスキャンするためのターゲットが含まれます。また、[Amazon Elastic Container Service (Amazon ECS)](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/Welcome.html)上でイメージを実行するCDKまたはTerraformコードも取得できます。これは、コンテナを実行およびスケーリングするAWSサービスです。

サービスは[AWS Fargate](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/AWS_Fargate.html)上で実行され、管理するサーバーなしで各コンテナを実行します。独自のVPC（仮想プライベートクラウド、AWSアカウント内の分離されたネットワーク）内で実行され、VPC内のアドレスのみがアクセスできる内部[Application Load Balancer](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html)（ALB）の背後にあります。デフォルトでは、[Amazon API Gateway HTTP API](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api.html)が呼び出し元からリクエストを受信し、VPCリンク（API GatewayのVPCへのプライベート接続）を通じてALBに渡します。呼び出し元は認証されたHTTPSエンドポイントを取得し、ロードバランサーはインターネットに直接公開されません。

`infra`、`ingress`、`auth`オプションは相互に依存しています。`infra`を`none`に設定すると、ジェネレーターはインフラストラクチャを生成せず、警告とともに`ingress`と`auth`を無視します。`ingress`は`infra`が`ecs`に設定されている場合にのみ適用されます。`auth`は`ingress`が`http-api`に設定されている場合にのみ適用されます。`private`サービスには認証するHTTP APIがないためです。

## サービスのローカル実行

`<name>-serve`ターゲットは、コンテナなしでマシン上でサーバーを実行します：

<NxCommands commands={['run your-project:service-serve']} />

サーバーは`PORT`環境変数のポートでリッスンします。`<name>-serve`ターゲットは、ジェネレーターが割り当てるポートに設定し、8081から始まり、ワークスペース内の他のプロジェクトがすでに使用しているポートをスキップします。コンテナ内では、サーバーはポート8080でリッスンします。

ヘルスルートでサーバーが起動していることを確認します。これはステータス200と`{"status":"ok"}`を返します：

```bash
curl http://localhost:<port>/health
```

サーバーには、独自のルートに置き換えるサンプルルートもあります。`GET /echo?message=<x>`は`{"message":"<x>"}`を返します。`message`パラメータは必須で、最大1024文字です。パラメータなし、または長い値のリクエストは、ステータス422を取得します。

## イメージのビルドとスキャン

`<name>-docker`ターゲットは、サービスのlinux/arm64イメージをビルドします。最初に`bundle-arm`ターゲットを実行し、コードとlinux/arm64依存関係を`dist/<project root>/bundle-arm`に書き込みます。集約`bundle`ターゲットは`bundle-arm`に依存します。次に、`<name>-docker`ターゲットは、そのフォルダー、`Dockerfile`、`.dockerignore`を`dist/<project root>/docker/<name>`にコピーし、そのフォルダーをビルドコンテキスト（イメージビルドが読み取れるファイル）としてイメージをビルドします。ワークスペースが設定されているコンテナエンジン、`docker`または[Finch](https://runfinch.com/)を使用します。ターゲットは、プロジェクト内のすべてのイメージをビルドする集約`docker`ターゲットの一部として実行されます。

<NxCommands commands={['run your-project:service-docker']} />

ロードバランサーのターゲットグループ（ロードバランサーがリクエストを送信するタスクのリスト）のみが`GET /health`をチェックし、タスクがトラフィックの準備ができているかどうかを判断します。ECSはDockerfileの`HEALTHCHECK`命令を無視します。イメージのビルドと公開方法の詳細については、<Link path="/guides/docker-bundling">Docker Bundling</Link>を参照してください。

## サービスのデプロイ

### インフラストラクチャへのサービスの追加

コンストラクトとモジュールはVPCを作成しません。スタックまたはルートモジュールでVPCを作成またはインポートし、それを渡します。タスクとロードバランサーは、NATゲートウェイ（プライベートサブネットがアウトバウンド接続を行えるようにする管理ゲートウェイ）またはVPCエンドポイント（VPCからAWSサービスへのプライベート接続）を通じてAWSサービスに到達する、エグレス付きプライベートサブネットで実行されます。

<Infrastructure>
<Fragment slot="cdk">
CDKコンストラクトは`common/constructs`に作成され、サービスにちなんで名付けられます。新しいVPCでの使用例：

```ts title="packages/infra/src/stacks/application-stack.ts"
import { MyService } from '@my-scope/common-constructs';
import { Stack, StackProps } from 'aws-cdk-lib';
import { SubnetType, Vpc } from 'aws-cdk-lib/aws-ec2';
import { Construct } from 'constructs';

export class ApplicationStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props);

    const vpc = new Vpc(this, 'Vpc', { natGateways: 1 });

    new MyService(this, 'MyService', {
      vpc,
      vpcSubnets: { subnetType: SubnetType.PRIVATE_WITH_EGRESS },
    });
  }
}
```

既存のVPCを使用するには、`Vpc.fromLookup(this, 'Vpc', { vpcId: '<vpc-id>' })`で検索し、`vpc`として渡します。

### リクエスト制限

API Gatewayは30秒後にサービスの待機を停止し、呼び出し元にエラーを返します。この統合タイムアウトを引き上げることはできません。HTTP APIが受け入れる最大リクエストペイロードは10 MBで、この制限も引き上げることはできません。両方の値は[Amazon API Gateway quotas for HTTP APIs](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-quotas.html)ページから来ています。

したがって、30秒より長く実行されるリクエスト、および長時間にわたってデータをストリーミングするレスポンスは、HTTP APIを通じて機能しません。これらの場合は、`ingress`を`private`に設定し、VPC内から内部ロードバランサーを呼び出します。
</OptionFilter>

<OptionFilter when={{ infra: 'ecs' }} description="ネットワーキング、セキュリティ、呼び出し、高度な設定、コスト、破棄">
### NATゲートウェイなしでの実行

タスクが起動すると、ECSはイメージをプルし、タスクに代わってログを送信します。サーバーコードもAWSサービスを呼び出す可能性があります。NATゲートウェイのないプライベートサブネットでは、これらの呼び出しのそれぞれにVPCエンドポイントが必要です。適切なエンドポイントがないと、タスクは起動に失敗するか、AWSを呼び出すときにタイムアウトします。

VPCにこれらのエンドポイントを作成し、`<region>`をAWSリージョンに置き換えます：

| エンドポイント | タイプ | 使用者 |
| --- | --- | --- |
| `com.amazonaws.<region>.ecr.api` | Interface | ECS、Amazon ECRで認証し、イメージを検索するため |
| `com.amazonaws.<region>.ecr.dkr` | Interface | ECS、Amazon ECRからイメージをプルするため |
| `com.amazonaws.<region>.s3` | Gateway | ECS、Amazon ECRがAmazon S3に保存するイメージレイヤーをダウンロードするため |
| `com.amazonaws.<region>.logs` | Interface | コンテナのログ出力、Amazon CloudWatch Logsに送信される |
| `com.amazonaws.<region>.secretsmanager` | Interface | ECS、タスク起動時にコンテナに渡すシークレットを読み取るため |
| `com.amazonaws.<region>.appconfigdata` | Interface | コード、AWS AppConfigから<Link path="/guides/runtime-config">ランタイム設定</Link>を読み取るため |
| `com.amazonaws.<region>.sts` | Interface | コード、AWS STSから一時的な認証情報を要求するとき（例：別のロールを引き受けるため） |

インターフェースエンドポイントには、タスクからのHTTPS（ポート443）を許可するセキュリティグループが必要です。Amazon ECRエンドポイントの詳細については、[Amazon ECR interface VPC endpoints](https://docs.aws.amazon.com/AmazonECR/latest/userguide/vpc-endpoints.html)を参照してください。

### セキュリティのデフォルト

生成されたインフラストラクチャは、デフォルトで以下の設定を適用します：

- ロードバランサーは内部です。`0.0.0.0/0`または`::/0`からのインバウンドトラフィックを許可するセキュリティグループはありません。
- タスクはプライベートサブネットで実行され、パブリックIPアドレスを取得しません。
- ロードバランサーは、VPCリンク（`http-api`）またはVPCのアドレス範囲（`private`）からのトラフィックのみを受け入れます。タスクは、コンテナポートでロードバランサーからのトラフィックのみを受け入れます。
- タスクは、ポート443でのみアウトバウンドトラフィックを送信できます。データベースへの接続は、データベースポートを追加します。
- タスクロール（サーバーコードが実行されるロール）は、ユーザーまたは接続がさらに許可するまで、AWS AppConfigからランタイム設定を読み取ることのみができます。
- 実行ロール（ECSがタスクを起動するために使用するロール）は、サービスのイメージをプルし、ロググループに書き込み、リストしたシークレットを読み取ることのみができます。
- シークレットは、AWS Secrets ManagerまたはAWS Systems Manager Parameter Storeへの参照としてのみコンテナに到達し、プレーンな環境値としては決して到達しません。
- コンテナには読み取り専用のルートファイルシステムがあり、uid 1000、非rootユーザーとして実行されます。ECS Exec（実行中のタスクへのシェルアクセス）はオフです。
- ヘルスチェックに失敗したデプロイは停止し、以前のバージョンにロールバックします。
- HTTP APIはアクセスログを書き込み、リクエストをスロットルします。別の選択をしない限り、IAMで認証します。
- ログは1年間保持されます。

生成されたコードは、これらの[Checkov](https://www.checkov.io/)チェック（Checkovはインフラストラクチャコードを安全でない設定についてスキャンします）を抑制し、各抑制の横に理由を記載します：

- `CKV_AWS_91`はロードバランサーアクセスログを求めます。代わりに、HTTP APIアクセスログ、またはサービス自身のログがリクエストを記録します。
- `CKV_AWS_2`と`CKV_AWS_103`は、TLSを使用したHTTPSリスナーを求めます。ロードバランサーは内部であり、VPC内の呼び出し元のみがアクセスできるため、プレーンHTTPでリッスンします。`http-api`の場合、TLSはAPI Gatewayで終了します。

Terraformモジュールは、同じHTTPリスナーの理由で`CKV2_AWS_20`と`CKV_AWS_378`もスキップし、サービスを破棄できるようにロードバランサー削除保護がオフになっているため`CKV_AWS_150`もスキップします。

### サービスの呼び出し

サービスのURLは、<Link path="/guides/runtime-config">ランタイム設定</Link>に`connection.services.<NameClassName>`として書き込まれます。ここで、`<NameClassName>`はPascalCaseのサービス名です。`--name=orders`の場合、キーは`Orders`です。名前がない場合、サービス名は`<project>-service`なので、`my-project`というプロジェクトの場合、キーは`MyProjectService`です。その場合でも、ソースフォルダーとターゲットプレフィックスは`service`です。

### 高度な設定

生成されたサービスは、名前、`ingress`、`auth`を設定します。以下の例では、生成されたサービスが渡さない設定、またはインスタンスごとに`ingress`と`auth`を選択するために、汎用の`EcsService`コンストラクトと`ecs-service`モジュールを直接使用します。

CDKでは、`common-constructs`パッケージがサービスのコンストラクトの横に`EcsService`をエクスポートするため、同じ方法でインポートします：`import { EcsService } from '@my-scope/common-constructs'`。生成されたコンストラクトは`EcsService`を拡張し、他のすべてのプロパティを渡します。例えば、`cluster`、`loadBalancer`、`environment`、`secrets`、`grantTaskRole`です。オプションの`image`プロパティは、プロジェクトからビルドされたイメージを置き換えます。`auth`プロパティはありません。Cognitoサービスは代わりに`identity`を取り、他のサービスは常に生成された`auth`を使用します。

Terraformでは、サービスのモジュールは`ecs-service`モジュールの変数の一部のみを設定できます：`vpc_id`、`subnet_ids`、`cluster_arn`、`environment`、`secrets`、`task_role_policy_statements`、`tags`、およびCognitoサービスの場合は`user_pool_id`と`user_pool_client_ids`です。他の変数を設定するには、サービスのモジュールの`module "ecs_service"`ブロックを編集します。

#### ビルド済みイメージ

すでにビルドされているイメージ、例えばパブリックレジストリからのイメージを実行するには、そのURIを渡します。ローカルでは何もビルドされません。プライベートAmazon ECRリポジトリのイメージの場合、CDKはそのリポジトリに対する実行ロールのプルアクセスを付与します。Terraformは、`image_repository_arn`としてリポジトリのARNも渡す場合にのみプルアクセスを付与します。

<Infrastructure>
<Fragment slot="cdk">

```ts
new EcsService(this, 'Prebuilt', {
  serviceName: 'Prebuilt',
  vpc,
  image: { imageUri: 'public.ecr.aws/my-org/my-image@sha256:<digest>' },
});
```

</Fragment>
<Fragment slot="terraform">

```hcl
module "prebuilt" {
  source = "../../common/terraform/src/core/container/ecs-service"

  service_name = "Prebuilt"
  vpc_id       = aws_vpc.main.id
  subnet_ids   = aws_subnet.private[*].id
  image_uri    = "public.ecr.aws/my-org/my-image@sha256:<digest>"
  # For an image in a private Amazon ECR repository, also pass:
  # image_repository_arn = aws_ecr_repository.my_image.arn
}
```

</Fragment>
</Infrastructure>

#### ロードバランサーなしのワーカー

ワーカーはキューから読み取るか、バックグラウンドジョブを実行し、何も呼び出しません。ロードバランサーをオフにして、ロードバランサー、HTTP API、URLのないサービスを取得します。

<Infrastructure>
<Fragment slot="cdk">

```ts
new EcsService(this, 'Worker', {
  serviceName: 'Worker',
  vpc,
  image: { directory: '<path to the folder with the Dockerfile>' },
  loadBalancer: false,
});
```

</Fragment>
<Fragment slot="terraform">
ビルド済みイメージと同様に、Terraformは`image_repository_arn`を渡す場合にのみ、プライベートAmazon ECRリポジトリに対するプルアクセスを付与します。

```hcl
module "worker" {
  source = "../../common/terraform/src/core/container/ecs-service"

  service_name  = "Worker"
  vpc_id        = aws_vpc.main.id
  subnet_ids    = aws_subnet.private[*].id
  image_uri     = "<image uri pinned by digest>"
  load_balancer = false
  # For an image in a private Amazon ECR repository, also pass:
  # image_repository_arn = aws_ecr_repository.my_image.arn
}
```

</Fragment>
</Infrastructure>

#### 1つのスタック内の複数のサービス

各サービスは、渡さない限り独自のECSクラスターを作成します。1つのクラスターで複数のサービスを実行するには、同じクラスターをそれぞれに渡します。

各HTTP APIサービスは、サービスがクラスターを共有している場合でも、独自のVPCリンクを作成します。API Gatewayは、デフォルトでアカウントごと、リージョンごとに10個のVPCリンクを許可し、増加をリクエストできます。

<Infrastructure>
<Fragment slot="cdk">

```ts
const cluster = new Cluster(this, 'Cluster', { vpc });

new MyService(this, 'MyService', { vpc, cluster });
new MyOtherService(this, 'MyOtherService', { vpc, cluster });
```

</Fragment>
<Fragment slot="terraform">
各`ecs-service`モジュールに同じ`cluster_arn`を渡します。最初のサービスの`cluster_arn`出力が1つを提供します：

```hcl
cluster_arn = module.my_service.cluster_arn
```

</Fragment>
</Infrastructure>

#### 環境変数とシークレット

プレーン設定は`environment`に入れます。タスク定義を読み取れる人は誰でも読み取れるため、シークレット値をそこに入れないでください。代わりに、シークレットを参照として渡します。実行ロールは、リストしたシークレットのみを読み取ることができます。

<Infrastructure>
<Fragment slot="cdk">

```ts
new EcsService(this, 'MyService', {
  // ...
  environment: { LOG_LEVEL: 'info' },
  secrets: { API_KEY: Secret.fromSecretsManager(apiKeySecret) },
});
```

</Fragment>
<Fragment slot="terraform">

```hcl
environment = { LOG_LEVEL = "info" }
secrets     = { API_KEY = aws_secretsmanager_secret.api_key.arn }
```

</Fragment>
</Infrastructure>

#### サイジングとスケーリング

各タスクは、デフォルトで256 CPUユニット（vCPUの4分の1）と512 MiBのメモリを取得します。サービスは1つのタスクを開始し、オートスケーリングは1つから2つのタスクを実行し続け、平均CPU使用率が70%を超えるとタスクを追加します。

| 設定 | CDKプロパティ | Terraform変数 | デフォルト |
| --- | --- | --- | --- |
| タスクあたりのCPUユニット | `cpu` | `cpu` | 256 |
| タスクあたりのメモリ（MiB） | `memoryLimitMiB` | `memory` | 512 |
| 起動時のタスク | `desiredCount` | `desired_count` | 1 |
| 最小タスク数 | `minCapacity` | `min_capacity` | 1 |
| 最大タスク数 | `maxCapacity` | `max_capacity` | 2 |
| ターゲット平均CPU（%） | `targetCpuUtilizationPercent` | `target_cpu_utilization` | 70 |

#### タスクロールの権限

サービスのコンストラクトまたはモジュールのタスクロールは、ランタイム設定への読み取りアクセスのみで開始します。コードが必要とする権限を追加します：

<Infrastructure>
<Fragment slot="cdk">

```ts
new EcsService(this, 'MyService', {
  // ...
  grantTaskRole: (taskRole) => myTable.grantReadData(taskRole),
});
```

</Fragment>
<Fragment slot="terraform">

```hcl
task_role_policy_statements = [{
  Effect   = "Allow"
  Action   = ["dynamodb:GetItem", "dynamodb:Query"]
  Resource = [aws_dynamodb_table.my_table.arn]
}]
```

</Fragment>
</Infrastructure>

#### コンテナユーザー

タスク定義は、uid 1000、非rootユーザーとしてコンテナを実行します。提供されるDockerfileはそれに一致します：uidとgid 1000でユーザー`app`を作成し、`USER 1000:1000`を設定します。別のユーザーとして実行するには、CDK `user`プロパティまたはTerraform `container_user`変数を設定します。Terraformは`0`と`root`を拒否します。

| 設定 | CDKプロパティ | Terraform変数 | デフォルト |
| --- | --- | --- | --- |
| コンテナが実行されるユーザー | `user` | `container_user` | `'1000'`（CDK）、`"1000:1000"`（Terraform） |

#### CORSとスロットリング

これらの設定は、`ingress`が`http-api`に設定されている場合にのみ適用されます。CORS（クロスオリジンリソース共有）は、ブラウザからサービスを呼び出すことができるウェブサイトを決定します。デフォルトでは、HTTP APIは任意のオリジンから、任意のメソッドで、`authorization`、`content-type`、`x-amz-content-sha256`、`x-amz-date`、`x-amz-security-token`ヘッダーを使用したブラウザリクエストを受け入れます。最後の3つは、SigV4署名が追加するヘッダーです。HTTP APIは、リクエストを毎秒10,000の安定したレートにスロットルし、最大5,000のバーストを許可します。

| 設定 | CDK | Terraform変数 | デフォルト |
| --- | --- | --- | --- |
| 許可されるCORSオリジン | `restrictCorsTo(...origins)`メソッド、または`corsPreflight`プロパティ | `cors_allow_origins` | 任意のオリジン（`["*"]`） |
| その他のCORS設定 | `corsPreflight`プロパティ | なし | 任意のメソッド、および上記のヘッダー |
| スロットリング | `throttle`プロパティ | なし | `{ rateLimit: 10000, burstLimit: 5000 }` |

`corsPreflight`プロパティはデフォルト全体を置き換えるため、呼び出し元が送信するすべてのヘッダーをリストします。`restrictCorsTo`メソッドは他のCORS設定を保持し、許可されるオリジンのみを変更します：

```ts
const service = new MyService(this, 'MyService', { vpc });
service.restrictCorsTo('https://app.example.com');
```

Terraformでは、`cors_allow_origins`と`container_user`は`ecs-service`モジュールの変数です。サービスのモジュールはそれらを渡さないため、`module "ecs_service"`ブロックで設定します。スロットリング値は`ecs-service.tf`で固定されています。

### コスト

コンテナサービスは、Lambda関数とは異なり、アイドル状態でも課金されます。これらの部分は、誰かがサービスを呼び出すかどうかに関係なく、時間単位で課金されます：

- Fargateタスク、vCPUごとおよびメモリのGBごと。`desiredCount`と`minCapacity`は少なくとも1つのタスクを実行し続けます。
- Application Load Balancer、時間ごとおよびロードバランサー容量ユニットごと。
- インターフェースVPCエンドポイント、各アベイラビリティゾーンで時間ごと、またはNATゲートウェイ、時間ごとおよび処理するデータのGBごと。
- CloudWatch Logsのログストレージ、およびAmazon ECRのイメージストレージ。

HTTP APIはリクエストごとに課金されます。リージョンとトラフィックのコストを見積もるには、[AWS Pricing Calculator](https://calculator.aws/)を使用してください。

## サービスの接続

<Link path="/guides/connection">`connection`</Link>ジェネレーターを使用して、ワークスペース内の他のプロジェクトにサービスを接続します：

<RunGenerator generator="connection" />

ウェブサイトまたはエージェントがサービスを呼び出すことができ、サービスはリレーショナルデータベースまたはDynamoDBテーブルを使用できます。各接続には独自のガイドがあります：

- <Link path="guides/connection/react-container">React to Container Service</Link>
- <Link path="guides/connection/ts-agent-container">TypeScript Agent to Container Service</Link>
- <Link path="guides/connection/py-agent-container">Python Agent to Container Service</Link>
- <Link path="guides/connection/py-container-rdb">Python Container Service to Relational Database</Link>
- <Link path="guides/connection/py-container-dynamodb">Python Container Service to DynamoDB</Link>

各接続には条件もあります：

- ウェブサイトまたはエージェントは、`ingress`が`http-api`に設定されているサービスにのみ接続できます。
- エージェントは、`auth`が`iam`に設定されているサービスにのみ接続できます。
- データベースまたはDynamoDB接続には、`infra`が`ecs`に設定されているサービスが必要です。
