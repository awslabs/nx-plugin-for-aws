既存の`py#agent`にLangfuseトレース表示を追加します。ローカル開発時とデプロイ後の両方で利用できます。この実験的なコンポーネントジェネレーターは、**Python Strands、HTTP、AgentCore zipデプロイメント（`infra: agentcore`）、CDK、およびIAM認証**をサポートします。エージェントのモデル、ツール、および設定されたセッションストレージは保持されます。

その他の言語、フレームワーク、プロトコル、MCPサーバー、コンテナ、Terraform、および`infra: none`は拒否されます。Langfuseエクスポートは、AgentCoreプラットフォームV1を選択し、V2のCDK検証で失敗します。資格情報とエクスポーター接続は、非修飾のスタートアップスナップショットにキャプチャされてはなりません。ジェネレーターは、Langfuseをデプロイしたり、シークレットを作成したりしません。

既存のエージェントは、このジェネレーターを実行しない限り、生成されたトレーシング設定を引き続き使用します。Langfuseは次のローカル`dev`実行時に開始されます。デプロイされたエージェントは、再ビルドと再デプロイ後に切り替わります。実験的なジェネレーターとして、その出力はアップグレードマイグレーションなしで変更される可能性があります。ユーザーはこれらの変更を自分で確認して調整する必要があります。

## CloudWatchへの影響

:::caution[アプリケーショントレースがLangfuseに移動します]
デプロイされたエージェントの場合、Langfuseを有効にするとADOTが無効になり、zipエントリーポイントが変更されます。**エージェント、モデル呼び出し、およびツールからの新しいアプリケーションスパンは、CloudWatchではなくLangfuseに送信されます。**これらはCloudWatch GenAI ObservabilityおよびTransaction Searchから消えます。**デュアルエクスポートはサポートされていません。**ローカル呼び出しもLangfuseにエクスポートされます。stdout/stderrはローカルターミナルに残ります。
:::

| シグナルまたは機能 | Langfuse有効時の影響 |
| --- | --- |
| エージェント/モデル/ツールのアプリケーションスパン | Langfuseにエクスポートされます。これらのスパンは、`aws/spans`またはランタイムのアプリケーションスパンストリームに配信されなくなります。 |
| ランタイムサービスメトリクス | Invocations、Latency、UserErrors、およびSystemErrorsはCloudWatchで引き続き利用できます。 |
| エージェントのstdout/stderr | Uvicornログとアプリケーション出力は、引き続きランタイムのCloudWatchロググループに送信されます。アプリによって出力されたプロンプトやツールの結果も、AWSログに残る可能性があります。 |
| ADOT構造化テレメトリログ | ADOTとともに無効になります。通常のアプリケーションログは独立して継続されます。ADOTを復元すると、構造化テレメトリログも復元されます。 |
| 個別に配信されるAgentCoreサービススパン | このアプリケーションエクスポーターによってリダイレクトされません。Memory、Gateway、Identity、および組み込みツールの個別配信設定を確認してください。この統合は、それらの配信を設定または保証しません。 |
| AgentCore Evaluations | CloudWatchベースのオンライン/バッチ評価と`CloudWatchAgentSpanCollector`は、このエージェントの新しいアプリケーションスパンを失います。オンデマンドEvaluate APIは呼び出し元が提供するスパンを受け入れることができますが、このジェネレーターは代替コレクターを提供しません。 |
| アプリケーションテスト、ダッシュボード、および評価ジョブ | 生成されたアプリケーションテストは、CloudWatchトレースを必要としません。CloudWatchからアプリケーションスパンを読み取るダッシュボード、アラーム、または評価ジョブは、これらの新しいスパンを失います。Langfuseを有効にする前に、各統合で使用されるトレースソースを確認してください。 |

サービス配信と評価要件については、AWSの[サポートされている評価テレメトリ](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/supported-frameworks-telemetry.html)および[オブザーバビリティ設定](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-configure.html)を参照してください。

### データレジデンシーとコスト

**ローカルおよびデプロイされた呼び出し**からのプロンプト、補完、モデル使用状況、およびツールの入出力は、設定されたLangfuseエンドポイントに送信されます。Langfuse Cloudを使用する場合、このデータはラップトップまたはAWS環境からサードパーティサービスに送信されます。セルフホストLangfuseを使用する場合は、選択したホストに送信されます。エクスポートを有効にする前に、エンドポイント、リージョン、保持期間、およびアクセス制御をデータ処理要件と照らし合わせて確認してください。このジェネレーターは、トレースコンテンツを編集しません。

切り替えられたアプリケーショントレースに関連するCloudWatch/X-Ray使用料金は減少します。ランタイムメトリクスとログの料金は残ります。Langfuseには独自のプランまたはホスティングコストがあり、Secrets Managerとアウトバウンド転送により料金が追加される場合があります。このバージョンには、デュアルエクスポートコストはありません。

エクスポーターはスパンをバッチ処理し、各呼び出しの最終応答フレームの前にフラッシュを試みます。10秒のガード内に8秒のフラッシュタイムアウトがあります。これにより、最終応答フレームの前に最大10秒のレイテンシが追加される可能性があります。エクスポートの失敗またはプロセスの中断により、テレメトリが失われる可能性があります。トレースは永続的な監査ログではありません。

このジェネレーターを実行する前に、既存のワークスペースの変更をコミットしてください。依存関係のインストールを含むLangfuseの変更を個別に確認してコミットし、後で統合を元に戻せるようにします。

### シークレットとエンドポイントを準備

トレースデータの保管場所を選択する際は、[AWSでのLangfuseのセルフホスティング](https://langfuse.com/self-hosting)をお勧めします。既存の保護されたHTTPSインストールを使用してください。このジェネレーターはプロビジョニングしません。エンドポイントを明示的に選択すると、Langfuse Cloudもサポートされます。

エージェントのAWSアカウントとリージョンにSecrets Managerシークレットを作成します。そのJSONには、Langfuseプロジェクトのキーを含む文字列フィールド`LANGFUSE_PUBLIC_KEY`と`LANGFUSE_SECRET_KEY`が含まれている必要があります。Secrets Managerコンソールまたは承認されたシークレット管理プロセスを使用してください。ジェネレーターフラグ、ソースファイル、シェル履歴、またはランタイム環境変数にキーを入れないでください。

この最初のバージョンでは、AWS管理のSecrets Manager暗号化キーを使用してください。カスタマー管理のKMSキーで暗号化されたシークレットには、このジェネレーターが作成しない追加の明示的にスコープされた復号化許可が必要です。

シークレットの**完全なARN**（6文字のサフィックスを含む）と、AWSで既にホストしているものなど、既存のLangfuseデプロイメントのHTTPSベースURLを渡します。エンドポイントは、**開発マシンとデプロイされたエージェントの両方**から到達可能である必要があります。**デフォルトの宛先はありません。`--host`は初回使用時に必須です。**この実験的なジェネレーターは、`aws`、`aws-us-gov`、および`aws-cn`パーティションのARNを受け入れます。ISOパーティションはサポートされていません。

```sh
pnpm nx g @aws/nx-plugin:observability#langfuse \
  --project=my_agent \
  --secretArn="$LANGFUSE_SECRET_ARN" \
  --host=https://langfuse.example.com
```

ここで、`LANGFUSE_SECRET_ARN`にはARNのみが含まれ、キーは含まれません。CDKは、正確にそのARNに対して`secretsmanager:GetSecretValue`を許可します。アプリケーションは、プロセス起動時に両方のキーを一度ロードし、メモリ内でBasic認証を構築します。キーをローテーションする際は、ランタイムの再起動を手配してください。変更されていないCDKデプロイメントは、実行中のプロセスを更新しません。

CDKヘルパーは、ホストとシークレットARNを`agentcore.langfuse.<AgentClass>`のAppConfigに書き込み、他のエージェントのエントリを保持します。デプロイされた起動は、エージェントの既存のAppConfig読み取り許可を使用して、`get_agentcore_runtime_config()`を通じてこのエントリを読み取ります。生成されたランタイムは`DISABLE_ADOT_OBSERVABILITY=true`を設定するため、AgentCoreの管理されたADOTパイプラインはトレーシングをアプリケーションに任せます。ホストとシークレットARNは、ランタイム環境変数ではありません。

`https://langfuse.example.com`を既存のエンドポイントに置き換えてください。Langfuse Cloudを使用するには、EUの場合は`https://cloud.langfuse.com`、USの場合は`https://us.cloud.langfuse.com`など、リージョナルベースURLを明示的に渡します。パスプレフィックスがサポートされています。`/api/public/otel`なしでベースURLを提供してください。URLの資格情報、クエリパラメータ、およびフラグメントは拒否されます。繰り返し実行すると、置換を提供しない限り、以前のホストとシークレットが保持されます。いずれかの入力を空白のままにすると、保存された値が保持されます。

エクスポーターは、`x-langfuse-ingestion-version: 4`でOTLP/HTTPを使用します。セルフホストインストールは、その取り込みコントラクトをサポートする必要があります。エンドポイントを選択する際は、Langfuseの[OpenTelemetry統合](https://langfuse.com/integrations/native/opentelemetry)および[v4移行ガイド](https://langfuse.com/integrations/native/opentelemetry/migration-to-v4)を参照してください。

### ローカルで実行

`AWS_PROFILE`で選択された認証済みAWSプロファイルなど、通常のAWS開発資格情報を使用します。そのIDには、エージェントがモデルとツールに通常必要とする権限に加えて、選択したシークレットに対する`secretsmanager:GetSecretValue`が必要です。生成された実行ロール許可は、デプロイされたエージェントをカバーします。開発者IDに権限を付与しません。

```sh
pnpm nx run my_agent:dev
```

エージェントの`dev`および`serve`ターゲットは、自動リロードでUvicornを通じて`langfuse_dev.py`を実行します。ホストとシークレットARNのみを保存し、Secrets Managerからキーを読み取り、エージェントをインポートする前にトレーシングを初期化します。**ローカルトレーシングを開始するために、デプロイされたAppConfigアプリケーションは必要ありません。**割り当てられたローカルポートは保持されます。キーは、ローカルの`.env`ファイルまたはLangfuse環境変数から読み取られることはありません。

**ローカル開発は、Langfuseシークレットアクセスなしで実行できます。**設定または資格情報をロードできない場合、起動時に警告がログに記録され、ローカルエージェントはLangfuseエクスポートなしで続行されます。リクエストは、シークレットルックアップを再試行しません。AWS資格情報、シークレット読み取り権限、または設定を修正してから、`dev`/`serve`を再起動してトレーシングを有効にします。エージェントには、通常のモデルとツールの権限が引き続き必要です。デプロイされたエージェントは、Langfuse資格情報をロードできない場合、起動に失敗し続けます。

生成されたチャットクライアントまたはHTTPエンドポイントを使用して、ローカルエージェントを呼び出します。ローカルとデプロイされた呼び出しの両方で、同じLangfuse宛先とセッションマッピングを使用します。エージェントのローカルHTTPサーバーは、通常の動作を維持します。HTTPS要件は、Langfuse宛先に適用されます。`http://localhost:3000`などのラップトップ専用Langfuseエンドポイントはサポートされていません。

ビルド、OpenAPI生成、および生成されたテストは、Langfuseキーを取得しません。生成されたオフラインPythonテストは、合成資格情報とインメモリエクスポーターを使用して、ローカル設定とAppConfig設定の両方をチェックします。

### ビルド、デプロイ、およびトレースの確認

<Link path="guides/py-agent">Pythonエージェントガイド</Link>で説明されているように、ワークスペースをビルドします。ジェネレーターはデプロイメントファイルを変更します。デプロイはしません。

:::caution[設定変更にはロールバック対応デプロイメントを使用]
既存のスタックでLangfuseを有効にする、ホストまたはシークレットARNを変更する、または統合を元に戻すと、不変のAppConfig設定バージョンが置き換えられます。生成された`deploy-sandbox`ターゲットは、デフォルトでロールバックが無効になっているエクスプレスモードを使用します。これにより、リソースの置換が拒否され、スタックが`UPDATE_FAILED`のままになる可能性があります。

これらの変更には、ロールバックが有効になっている標準デプロイメントを使用してください。`my_infra`をインフラストラクチャプロジェクト名に置き換えます。

```sh
pnpm nx run my_infra:deploy-sandbox --no-express --rollback
```

他のステージの場合は、<Link path="guides/typescript-infrastructure">インフラストラクチャガイド</Link>で説明されているように、明示的なステージまたはスタックセレクターとロールバックが有効になっている`deploy`ターゲットを使用します。

以前のデプロイメントで既にスタックが`UPDATE_FAILED`のままになっている場合は、デプロイメントモードを切り替える前に回復してください。CloudFormationは、スタックが完全な状態に達するまで、同じエクスプレス設定を使用するフォローアップ操作を要求する場合があります。AWSの[失敗したスタックの回復ガイダンス](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/stack-failure-options.html)に従ってください。デプロイメントフラグを変更するだけでは、失敗したスタックは回復しません。
:::

ツールを呼び出すプロンプトを使用して、ローカルまたはデプロイされたエージェントを呼び出します。Langfuse UIでトレース詳細ビューを開き、呼び出しルート、エージェント/モデル/ツールの子、およびそれらの入出力コンテンツを確認します。モデル（生成）オブザベーションを選択して、トークン使用量を確認します。トレースのセッションを開いてAgentCoreセッションIDを確認し、そのセッションで短いリクエストを繰り返して、フラッシュとグループ化を確認します。

アプリケーションルートは、アップストリームAWSトレースと親IDを保持します。Langfuse SDKは、AWSサービスの親がLangfuseにエクスポートされていない場合でも、論理アプリケーションルートとしてマークします。

33〜200文字のセッションIDは、Langfuseで変更されずに表示されます。長いIDは、64文字のSHA-256 16進ダイジェストをLangfuseセッションIDとして使用するため、繰り返しリクエストは同じセッションに表示されます。このマッピングは、Langfuseグループ化のみを変更します。アプリケーションに送信されるAgentCoreセッションIDは変更されません。IDが欠落しているか、33文字未満の場合、その呼び出しに対して新しいUUIDが取得されます。生成されたクライアントは、これらの制限内でUUIDを使用します。

## 生成されたファイルと繰り返し実行

ジェネレーターは、エージェントの横に`langfuse_telemetry.py`と`langfuse_dev.py`、個別の`package/<agent>/langfuse_main.py`エントリーポイント、およびPythonエクスポーターテストを追加します。既存のCDKコンストラクトを`langfuse-observability.ts`に配線し、デプロイメントエントリーポイントをzipにコピーし、その依存関係を宣言します。ストックADOTランチャーはパッケージ化されたままです。

Langfuseエントリーポイントは、エージェントをインポートする前に1つのプロバイダーを作成します。FastAPIの重複するトレーシングは、そのプロセスでのみ無効になります。ネイティブStrandsスパンは、同じプロバイダーを使用します。Langfuse SDKのパブリックオブザベーションAPIは、アプリケーションルートとセッション属性を提供します。呼び出しの入出力キャプチャは、それぞれ1 MiBに制限されています。ルートは、その制限を超えると`content_truncated`を記録します。

依存関係セットは、Langfuse 4.18.0およびADOT 0.22.0を使用します。ベンダー提供のOpenTelemetryピンは、API/SDK/HTTPエクスポーター1.45.1を含むADOTの要件に一致し、その互換性を維持するために保持されます。ADOTとLangfuseは、リポジトリの定期的な依存関係更新の対象のままです。アップグレード時に互換性を確認し、OpenTelemetryピンを調整してください。StarletteはFastAPIの依存関係要件に従います。

同じ入力でジェネレーターを繰り返しても、配線が重複したり、ランタイムの編集が上書きされたりすることはありません。依存関係のインストール設定は引き続き尊重されるため、失敗または延期されたインストールを再試行するために再実行できます。ホストまたはシークレットを変更すると、ローカルエントリーポイントとCDK設定の両方が更新されます。ローカル開発を再起動し、再ビルドして、[ロールバック対応デプロイメントコマンド](#build-deploy-and-check-a-trace)を使用して、両方の環境で変更を適用します。いずれかの設定を編集したり、ローカル起動コマンドをカスタマイズしたりすると、ジェネレーターはオプションを変更する前に調整を求めます。これにより、オプションの変更がカスタム配線を黙って置き換えることを防ぎます。

`langfuse_dev.py`のない以前の実験的なセットアップは、元に戻して、更新されたジェネレーターで再生成する必要があります。カスタマイズは個別に保存して再適用してください。

## CloudWatchに戻す

Langfuseジェネレーターの変更を含む専用コミットを元に戻します。

```sh
git revert <langfuse-setup-commit>
```

後続のエージェント変更との競合について、リバートを確認してください。他のジェネレーターが`packages/common/constructs/src/core/app.ts`の同じ配列に使用状況メトリックタグを追加している可能性があります。競合を解決する際は、これらのタグを保持してください。他のエージェントがまだLangfuseを使用していない場合にのみ、Langfuseタグ（`g79`）を削除し、残りの統合に必要な共有依存関係を保持してください。

ワークスペースの依存関係を再インストールし、再ビルドしてから、[ロールバック対応デプロイメントコマンド](#build-deploy-and-check-a-trace)を使用して再デプロイします。AppConfigエントリを削除するには、リソースの置換も必要です。このステップでは、デフォルトのエクスプレスコマンドを使用しないでください。完全なセットアップを元に戻すと、ストックADOTエントリーポイントとローカル起動コマンドが復元され、Langfuse配線、ファイル、依存関係の追加、ランタイム設定、およびシークレット読み取り許可が削除されます。実行中のローカル`dev`プロセスを再起動します。新しいセッションでデプロイされたエージェントを呼び出し、CloudWatchで新しいアプリケーショントレースを確認します。

ジェネレーターにはロールバックフラグがありません。セットアップコミットから無関係な変更を除外して、元に戻しても削除されないようにします。

既存のシークレットは、管理するために残ります。統合を元に戻しても、バックエンド間で履歴トレースがコピー、削除、または移動されることはありません。Langfuseを再度有効にするには、ホストとシークレットARNを使用してジェネレーターを実行します。
