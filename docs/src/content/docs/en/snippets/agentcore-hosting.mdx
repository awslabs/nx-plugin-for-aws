---
title: AgentCore Runtime Hosting
---

The `infra` option selects how your code is packaged and hosted on [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html):

- **`agentcore`** (default) uses [direct code deployment](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-code-deploy-node.html): your built code is packaged as a `.zip`, uploaded to S3, and run on an AgentCore managed language runtime. There is no container image to build, no ECR repository to manage, and no image to push, which makes for a substantially faster build and deploy cycle.
- **`agentcore-ecr`** builds an `arm64` container image from a vended `Dockerfile` and hosts it from ECR. Choose this when you need control over the operating system image — for example to install native system libraries — or when you have an established container pipeline. This option additionally vends a Trivy image scan target (see Image Scanning below).
- **`none`** generates no infrastructure at all, so the project can only be run locally.

Both hosted options are configured for observability with the [AWS Distro for OpenTelemetry](https://aws.amazon.com/otel/) (ADOT). Under `agentcore` the ADOT distribution is packaged alongside your code and loaded via the `opentelemetry-instrument` entry point; under `agentcore-ecr` it is installed in the image and loaded by the `Dockerfile`'s command.

:::note[Docker is only required for agentcore-ecr]
`agentcore` needs no container engine, so you do not need [Docker](https://www.docker.com/) installed to build or deploy. Select `agentcore-ecr` if you would rather build a container image, and make sure Docker is installed and running to avoid errors such as:

```
ERROR: Cannot connect to the Docker daemon at unix://path/to/docker.sock.
```
:::

:::caution[Switching between the two]
The `infra` option you pass is always applied, so re-running the generator with `agentcore` on a project previously generated with `agentcore-ecr` switches it to code packaging, deleting the `Dockerfile` and its image build and scan targets.

The generated infrastructure is yours to edit and so is never overwritten. When switching, delete the generated construct or module for the component and re-run the generator so it is rewritten for the new packaging.
:::
