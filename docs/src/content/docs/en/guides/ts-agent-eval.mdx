Add an evaluation harness to a <Link path="guides/ts-agent">TypeScript Agent</Link>. The harness runs a set of test cases against your agent and checks each response with deterministic scorers, so you can catch regressions in your agent's behaviour locally or in CI.

## Usage

### Generate an Agent Evaluation Harness

You will need an existing TypeScript project containing an agent created with the `ts#agent` generator.

## Generator Output

The generator adds the following files to your project, where `<agent>` is the name of your agent component (`agent` by default):

<FileTree>
  - \<your-project>/
    - evals/\<agent>/
      - cases.json Your evaluation cases
    - scripts/\<agent>/
      - eval.ts Runs each case against your agent and scores the response
</FileTree>

It also adds an `<agent>-eval` target to your project.

## Writing Evaluation Cases

Each case in `cases.json` has a `name`, a `prompt` sent to your agent, and a list of checks in `expect` that the agent's response must pass:

```json title="evals/agent/cases.json"
{
  "cases": [
    {
      "name": "multiplies with its spellbook",
      "prompt": "Please multiply 6 by 7",
      "expect": [{ "regex": "\\b42\\b" }, { "toolCalled": "Multiply" }]
    }
  ]
}
```

The following checks are supported:

- `contains`: the response includes the given text (case-insensitive)
- `notContains`: the response does not include the given text (case-insensitive)
- `regex`: the response matches the given regular expression (case-insensitive)
- `toolCalled`: the agent called the tool with the given name

A case passes when all of its checks pass. Each case runs in a fresh session, so cases do not affect one another.

## Running Evaluations

Run the evaluation target for your agent:

<NxCommands commands={['run your-project:agent-eval']} />

The harness creates your agent in-process using `getAgent()` from your agent's `agent.ts`, so no server needs to be running. It uses whichever model your agent is configured with, so you need AWS credentials with access to that model in Amazon Bedrock.

The harness prints a result for each case and a final score, and exits with a non-zero code if any case fails. This lets you run evaluations as a step in your CI pipeline.

:::note
Model responses can vary between runs. Prefer checks that express the behaviour you care about (such as a tool being called, or a number appearing in the answer) over exact wording.
:::

The following environment variables customise a run:

- `CASES`: the path to the cases file, relative to your project (default `evals/<agent>/cases.json`)
- `EVAL_TIMEOUT_MS`: the time allowed for each case before it fails (default `60000`)
