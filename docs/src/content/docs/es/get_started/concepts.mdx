El `@aws/nx-plugin` es un plugin de [Nx](https://nx.dev/) que proporciona un conjunto de herramientas para construir y desplegar aplicaciones full-stack en AWS. Te ofrece una colección de [Generadores](#generators) que generan código de aplicación listo para producción _y_ la infraestructura para desplegarlo — con seguridad de tipos, ejecutable localmente y listo para enviar.

En lugar de comenzar desde una página en blanco, tú (o tu agente de IA) eliges los componentes que necesitas — APIs, sitios web, autenticación, agentes de IA, infraestructura — proporcionas algunas opciones de configuración, y el plugin genera código inicial siguiendo las mejores prácticas. Incluso conecta proyectos entre sí (incluyendo la actualización de archivos existentes mediante transformaciones AST) para producir clientes con seguridad de tipos entre tu frontend y backend.

## Construido sobre Nx y sus generadores

[Nx](https://nx.dev) es un framework de construcción inteligente para gestionar monorepos. Es agnóstico del lenguaje, permitiendo que TypeScript, Python, infraestructura y más convivan y se construyan juntos en un único espacio de trabajo. Su sistema de construcción utiliza caché y análisis de grafos de dependencias para reconstruir solo lo que cambió y ejecutar tareas en paralelo, manteniendo las pruebas, el linting y la construcción rápidos a medida que tu espacio de trabajo crece.

Cada pieza de funcionalidad en el `@aws/nx-plugin` se entrega como un [Generator](https://nx.dev/features/generate-code) de Nx — andamiaje automatizado que produce estructuras de código consistentes a partir de plantillas predefinidas. Los generadores pueden invocarse a través del [Nx CLI](https://nx.dev/features/generate-code#invoke-generators), el [plugin IDE Nx Console](https://nx.dev/getting-started/editor-setup), o por tu asistente de IA a través del <Link path="/get_started/building-with-ai">Nx Plugin for AWS MCP Server</Link>.

Debido a que cada componente es un generador, solo agregas lo que necesitas, cuando lo necesitas. Comienza con una API, agrega un sitio web más tarde, conéctalos cuando estés listo — cada paso es un solo comando.

## Construye con frameworks probados

El `@aws/nx-plugin` evita deliberadamente construir abstracciones personalizadas sobre las herramientas que ya conoces. En lugar de inventar frameworks, runtimes o wrappers personalizados, genera código idiomático utilizando proyectos de código abierto establecidos y ampliamente adoptados. Esto significa que tus habilidades existentes se transfieren directamente, puedes confiar en la documentación oficial de cada framework, y nunca estás atrapado en una capa que solo este plugin entiende.

## Abierto para modificación

Todo el código generado es _tu_ código. El `@aws/nx-plugin` es una herramienta de tiempo de construcción, no una dependencia de tiempo de ejecución — una vez que un generador se ha ejecutado, el plugin ya no está en la ecuación. Puedes leer cada archivo que produjo, confirmarlo y cambiarlo como quieras.

Esto significa:

- **Sin escotillas de escape.** No hay una superficie de configuración propietaria que aprender o con la que luchar cuando necesitas hacer algo que el generador no anticipó. Editas el código generado directamente, de la misma manera que editarías cualquier código que escribiste tú mismo.
- **Sin nuevas capas de abstracción.** Los generadores emiten código plano e idiomático para los frameworks subyacentes. No hay una API envolvente o indirección mágica entre tú y React, tRPC, FastAPI, CDK o cualquiera de las otras herramientas — lo que ves es lo que se ejecuta.
- **El plugin no es una dependencia.** Genera código y se aparta del camino. Tu aplicación no importa ni depende de `@aws/nx-plugin` en tiempo de ejecución, por lo que nunca estás bloqueado por él y nunca estás atrapado.

Si no te gusta algo en el código generado, eres libre de modificarlo. Los generadores te dan una ventaja inicial, no una jaula.

## Al paso con las mejoras

Ser dueño de tu código generalmente tiene un costo: en el momento en que comienzas a editar un andamiaje, te desconectas de las correcciones y mejoras realizadas en el origen. Adoptarlas nuevamente significa leer un registro de cambios, regenerar y reconciliar un diff a mano. Las <Link path="/get_started/upgrading">Migraciones</Link> son la forma en que el `@aws/nx-plugin` trabaja para evitar que eso suceda.

Los lanzamientos incluyen migraciones junto con ellos, con el objetivo de llevar el código que los generadores anteriores produjeron al paso con las mejoras que hemos hecho desde entonces. Cuando corregimos un error, reforzamos un valor predeterminado de seguridad o refinamos un patrón generado, ejecutar `nx migrate` aplica ese cambio a tu código, en el lugar — en lugar de dejarte detectarlo en un registro de cambios y portarlo tú mismo.

En la práctica:

- **La actualización es automatizada, no un ejercicio de re-adopción.** Un espacio de trabajo generado hace meses puede avanzar con el plugin en lugar de alejarse más de él.
- **Las personalizaciones se comparan con patrones, no se sobrescriben.** Las migraciones verifican que un archivo aún coincida con la forma que el generador produjo. Donde ha divergido más allá de lo que pueden actualizar de manera segura, dejan tu código solo y reportan el seguimiento manual en su lugar.
- **Algunos cambios llegan como prompts de agente.** Donde la edición correcta depende de lo que has construido, la migración es un prompt que tu agente de codificación de IA aplica en lugar de un codemod.
- **Las actualizaciones son opcionales.** Nada en tu espacio de trabajo cambia hasta que eliges ejecutar `nx migrate`.

Las migraciones reducen la brecha en lugar de cerrarla: qué tan lejos se ha movido tu código decide cuánto pueden hacer, y algunos pasos aún necesitarán tus manos.

## Dependencias mínimas

El `@aws/nx-plugin` se esfuerza por mantener el número de dependencias globales al mínimo. Lo que necesitas para comenzar se reduce a qué generadores invocas.

Como ejemplo, cualquier generador basado en TypeScript solo requerirá que [Node](https://nodejs.org/en/download) esté instalado. Para proyectos basados en Python, [UV](https://docs.astral.sh/uv/) es el único requisito.

## Seguridad de tipos

El `@aws/nx-plugin` emplea seguridad de tipos para simplificar la experiencia del desarrollador a través de autocompletados del IDE, al mismo tiempo que elimina errores en tiempo de ejecución que de otro modo solo surgirían en una implementación sin seguridad de tipos. Como tal, todos los componentes que se proporcionan tienen seguridad de tipos por defecto.

La seguridad de tipos fluye a través de los límites del proyecto: cuando conectas un sitio web a una API, el cliente generado comparte tipos con el backend, por lo que un cambio en un contrato de API aparece como un error en tiempo de compilación en tu frontend en lugar de un error en producción. Refactoriza con confianza.
