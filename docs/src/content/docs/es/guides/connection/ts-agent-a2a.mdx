El generador `connection` puede conectar tu <Link path="guides/ts-agent">Agente TypeScript</Link> a un agente [A2A](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-a2a.html) remoto — ya sea <Link path="guides/ts-agent">TypeScript</Link> o <Link path="guides/py-agent">Python</Link> — para que tu agente pueda delegar a otro agente como una herramienta.

El generador configura todo el cableado necesario para que tu agente pueda descubrir e invocar el agente A2A remoto, tanto cuando se despliega en AWS (a través de Bedrock AgentCore) como cuando se ejecuta localmente.

## Requisitos previos

Antes de usar este generador, asegúrate de tener:

1. Un proyecto TypeScript con un componente <Link path="guides/ts-agent">Strands Agent</Link> (cualquier protocolo)
2. Un proyecto con un componente Agent generado con `--protocol=a2a` y `--auth=iam` (ya sea <Link path="guides/ts-agent">`ts#agent`</Link> o <Link path="guides/py-agent">`py#agent`</Link>)
3. Ambos componentes creados con `infra: agentcore`

## Salida del Generador

El generador crea un paquete compartido `agent-connection` y modifica el código de tu agente:

<FileTree>

- packages/common/agent-connection
  - src
    - app
      - \<target-agent-name>-client-strands.ts High-level Strands client for the connected A2A agent
    - core
      - agentcore-endpoints.ts Framework-agnostic ARN/URL resolution
      - agentcore-fetch.ts Framework-agnostic SigV4 / JWT / session-forwarding fetch
      - agentcore-a2a-client-config.ts Framework-agnostic A2A client config (signed `clientFactory`)
      - agentcore-a2a-client-strands.ts Strands A2A client wrapping the config
    - index.ts Exports all clients
  - project.json
  - tsconfig.json

</FileTree>

Además:
- Transforma el `agent.ts` de tu agente para registrar el agente A2A remoto como una `tool` de Strands
- Actualiza el target `dev` del agente para que dependa del target `dev` del agente destino
- Instala las dependencias requeridas

## Usar el Agente A2A Conectado

El generador transforma el `agent.ts` de tu agente para envolver el agente A2A remoto como una herramienta:

```ts title="packages/example/src/my-agent/agent.ts" {2,5-12,15}
import { Agent, tool } from '@strands-agents/sdk';
import { RemoteAgentClientStrands } from '@my-scope/agent-connection';
import { z } from 'zod';

export const getAgent = async () => {
  const remoteAgent = await RemoteAgentClientStrands.create();
  const remoteAgentTool = tool({
    name: 'askRemoteAgent',
    description: 'Delegate a question to the remote RemoteAgent A2A agent and return its reply.',
    inputSchema: z.object({ prompt: z.string() }),
    callback: async ({ prompt }) => (await remoteAgent.invoke(prompt)).toString(),
  });
  return new Agent({
    systemPrompt: '...',
    tools: [remoteAgentTool],
  });
};
```

El ID de sesión de AgentCore se propaga al agente remoto automáticamente a través del encabezado `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id`, por lo que `create()` no toma argumentos: el servidor del agente vincula la sesión de la solicitud entrante en un contexto [`AsyncLocalStorage`](https://nodejs.org/api/async_context.html#class-asynclocalstorage) (`enterSessionContext` en el `router.ts` generado, o `runWithSessionId` en el middleware de sesión A2A/AG-UI), y el fetch del cliente de conexión en `agentcore-fetch.ts` lo estampa en cada llamada saliente — asegurando consistencia para la [Observabilidad de Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html).

Internamente, `RemoteAgentClientStrands.create()` devuelve un `A2AAgent` de Strands configurado con un `clientFactory` que firma con SigV4 cuando se despliega en AWS, y un endpoint simple `http://localhost:<port>/` cuando `LOCAL_DEV=true`. La firma y la resolución de endpoints residen en el `agentcore-a2a-client-config.ts` independiente del framework; solo el delgado `agentcore-a2a-client-strands.ts` depende de Strands.

## Desarrollo Local

El generador configura el target `dev` del agente anfitrión para:
1. Iniciar los agentes A2A conectados automáticamente
2. Establecer `LOCAL_DEV=true` para que el cliente generado se conecte directamente a `http://localhost:<port>/` en lugar de AgentCore

Ejecuta el agente localmente con:

<NxCommands commands={["<agent-name>-dev <project-name>"]} />

Esto iniciará tanto el agente anfitrión como todos los agentes A2A conectados, con el agente anfitrión llamando a los agentes remotos a través de HTTP simple en sus puertos locales asignados.
