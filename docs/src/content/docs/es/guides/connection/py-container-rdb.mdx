El generador `connection` permite que un <Link path="guides/py-container">servicio de contenedor Python</Link> use un proyecto de <Link path="guides/py-rdb">Base de Datos Relacional Python</Link>. Agrega el paquete de la base de datos como una dependencia del proyecto del servicio y prepara la imagen Docker del servicio para conexiones SSL a Amazon Aurora.

## Cómo funciona esto

Un servicio de contenedor con `infra=ecs` se ejecuta como tareas en Amazon ECS (Elastic Container Service) en tu VPC. Cada tarea se ejecuta como el rol de tarea del servicio, un rol de IAM que no tiene permisos hasta que los otorgas, y se encuentra en el grupo de seguridad del servicio, que permite tráfico saliente solo en el puerto 443. Para usar la base de datos, el servicio necesita dos cosas que no tiene por defecto:

- Permiso de IAM para `rds-db:connect`, para que pueda iniciar sesión en la base de datos con autenticación IAM.
- Un par de reglas de grupo de seguridad en el puerto de la base de datos: una regla de entrada en el grupo de seguridad de la base de datos y una regla de salida en el grupo de seguridad del servicio. Sin la regla de salida, el servicio no puede alcanzar la base de datos, porque su grupo de seguridad solo permite el puerto 443 de salida.

El generador rechaza un servicio con `infra=none`, porque tal servicio no tiene un rol de tarea al cual otorgar acceso.

## Requisitos previos

Antes de usar este generador, asegúrate de tener:

1. Un servicio de contenedor con `infra=ecs` (generado usando el generador <Link path="guides/py-container">`py#container`</Link>)
2. Un proyecto <Link path="guides/py-rdb">`py#rdb`</Link>

## Usar la Base de Datos en el Servicio

Importa `session_context` desde tu paquete de base de datos y úsalo donde manejes una solicitud:

```python title="packages/my_project/my_project/my_service/orders.py"
from sqlmodel import select
from my_scope_my_database import session_context
from my_scope_my_database.models.example import ExampleModel


async def list_examples() -> list[dict]:
    async with session_context() as session:
        items = (await session.execute(select(ExampleModel))).scalars().all()
        return [item.model_dump() for item in items]
```

El paquete de la base de datos lee los detalles de conexión de la base de datos desde la <Link path="guides/runtime-config">configuración de tiempo de ejecución</Link>, usando la variable de entorno `RUNTIME_CONFIG_APP_ID`.

El servicio de contenedor generado establece `RUNTIME_CONFIG_APP_ID` y otorga a su rol de tarea acceso de lectura a la configuración de tiempo de ejecución, por lo que no necesitas agregar ninguno de los dos tú mismo. En Terraform, el bloque del módulo del servicio debe pasar `appconfig_application_id` y `appconfig_application_arn`, como se muestra en la <Link path="guides/py-container">guía de contenedor</Link>.

## Infraestructura

El generador no cambia tu stack o módulo raíz de Terraform. En su lugar, imprime el código a agregar, que se muestra a continuación para un servicio llamado `my-service` y una base de datos llamada `my-database`. Hasta que lo agregues, el servicio no puede alcanzar el puerto de la base de datos y la base de datos rechaza su autenticación IAM.

<Infrastructure>
<Fragment slot="cdk">

En el ejemplo, `myService` es tu constructo `MyService` y `myDatabase` es tu constructo `MyDatabase`:

```ts title="packages/infra/src/stacks/application-stack.ts"
myDatabase.allowDefaultPortFrom(myService);
myDatabase.grantConnect(myService.taskRole);
```

`allowDefaultPortFrom` agrega la regla de entrada en el grupo de seguridad de la base de datos y la regla de salida en el grupo de seguridad del servicio. `grantConnect` otorga `rds-db:connect` al rol de tarea del servicio.

</Fragment>
<Fragment slot="terraform">

En el ejemplo, `module "my_service"` despliega el servicio y `module "my_database"` despliega la base de datos. Las fuentes de datos `data "aws_region" "current"` y `data "aws_caller_identity" "current"` se declaran en el `providers.tf` generado:

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_role_policy" "my_service_my_database_connect" {
  name = "my-service-my-database-connect"
  role = module.my_service.task_role_name

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = ["rds-db:connect"]
        Resource = ["arn:aws:rds-db:${data.aws_region.current.region}:${data.aws_caller_identity.current.account_id}:dbuser:${module.my_database.connect_resource_id}/${module.my_database.database_runtime_user}"]
      },
    ]
  })
}

resource "aws_vpc_security_group_ingress_rule" "my_service_to_my_database" {
  description                  = "Allow the my-service container service to connect to the database"
  security_group_id            = module.my_database.security_group_id
  referenced_security_group_id = module.my_service.security_group_id
  from_port                    = module.my_database.cluster_port
  to_port                      = module.my_database.cluster_port
  ip_protocol                  = "tcp"
}

resource "aws_vpc_security_group_egress_rule" "my_service_to_my_database" {
  description                  = "Allow the my-service container service to reach the database"
  security_group_id            = module.my_service.security_group_id
  referenced_security_group_id = module.my_database.security_group_id
  from_port                    = module.my_database.cluster_port
  to_port                      = module.my_database.cluster_port
  ip_protocol                  = "tcp"
}
```

### Requisitos de SSL al Conectarse sin RDS Proxy

Cuando el servicio se conecta al clúster de Aurora directamente, sin RDS Proxy, debe confiar en la autoridad de certificación de Amazon RDS. El generador agrega estas líneas al Dockerfile del servicio, antes de su línea `EXPOSE`, para instalar el paquete de CA de Amazon RDS en el almacén de confianza del sistema:

```dockerfile
ADD https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem /usr/local/share/ca-certificates/rds-global-bundle.crt
RUN update-ca-certificates
```

Cuando usas RDS Proxy, no necesitas el paquete de CA de RDS.

## Desarrollo Local

<NxCommands commands={["<service-name>-serve <project-name>"]} />

Esto inicia el servicio y la base de datos Docker local de la base de datos. Con `LOCAL_DEV=true` establecido, el cliente de la base de datos se conecta a la base de datos local en lugar de Aurora.
