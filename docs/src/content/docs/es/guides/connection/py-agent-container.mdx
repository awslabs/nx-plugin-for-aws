El generador `connection` permite que un <Link path="guides/py-agent">Python Agent</Link> llame a un servicio de contenedor creado con <Link path="guides/ts-container">`ts#container`</Link> o <Link path="guides/py-container">`py#container`</Link>. Agrega un cliente al proyecto compartido `agent_connection` que lee la URL del servicio desde la configuración de tiempo de ejecución y firma cada solicitud con las credenciales de AWS propias del agente.

## Cómo funciona esto

Un servicio de contenedor con `infra=ecs` se ejecuta en Amazon ECS (Elastic Container Service) detrás de un Application Load Balancer interno. Con el valor predeterminado `ingress=http-api`, una API HTTP de Amazon API Gateway (un endpoint HTTPS administrado) alcanza ese balanceador de carga a través de un enlace VPC, que es la conexión privada de API Gateway a tu VPC. El agente llama a la API HTTP.

El cliente firma cada solicitud con SigV4, el proceso de firma de solicitudes de AWS, utilizando las credenciales del rol del agente. La API HTTP acepta la solicitud cuando ese rol puede llamar a `execute-api:Invoke` en ella. La API HTTP finaliza cualquier solicitud que tarde más de 30 segundos, por lo que una ruta que se ejecute más tiempo debe retornar temprano y finalizar su trabajo en segundo plano.

El generador rechaza un servicio al que no puede llegar de esta manera. El servicio debe tener `infra=ecs`, porque `infra=none` no crea ningún endpoint. Debe tener `ingress=http-api`, porque un servicio `private` es accesible solo desde dentro de su VPC. Debe tener `auth=iam`, porque el agente firma sus solicitudes con credenciales de IAM y no tiene ningún token de Cognito para enviar.

## Requisitos previos

Antes de usar este generador, asegúrate de tener:

1. Un proyecto <Link path="guides/py-agent">`py#agent`</Link>
2. Un servicio de contenedor con `infra=ecs`, `ingress=http-api` y `auth=iam` (generado usando el generador <Link path="guides/ts-container">`ts#container`</Link> o <Link path="guides/py-container">`py#container`</Link>)

## Salida del Generador

El generador crea los siguientes archivos en el proyecto compartido `agent_connection`:

<FileTree>

- packages/common/agent\_connection
  - my\_scope\_agent\_connection
    - app
      - \<service\_name>\_client.py Cliente que lee la URL del servicio desde la configuración de tiempo de ejecución y firma solicitudes con SigV4
    - \_\_init\_\_.py Exporta `get_<service_name>_client`

</FileTree>

Agrega `httpx` y `boto3` al proyecto `agent_connection`, agrega el proyecto `agent_connection` como una dependencia del proyecto de tu agente, y hace que el objetivo `<agent-name>-dev` del agente inicie el objetivo `<service-name>-serve` del servicio.

## Usar el Cliente

`get_<service_name>_client()` lee la URL del servicio desde el espacio de nombres `connection` de la <Link path="guides/runtime-config">configuración de tiempo de ejecución</Link>, bajo `services.<ServiceName>`. Retorna un `httpx.Client` cuyas rutas son relativas al servicio. El generador no cambia el código de tu agente. Para permitir que el modelo llame al servicio, envuelve el cliente en una herramienta:

```python title="packages/my_project/my_project/my_agent/agent.py"
from my_scope_agent_connection import get_my_service_client
from strands import tool


@tool
def check_my_service() -> int:
    """Check whether the MyService container service is healthy."""
    with get_my_service_client() as client:
        return client.get("/health").status_code
```

Agrega `check_my_service` a la lista `tools` de tu agente. `get_my_service_client()` genera un error cuando `RUNTIME_CONFIG_APP_ID` no está configurado, cuando no puede encontrar una región de AWS (desde `AWS_REGION`, `AWS_DEFAULT_REGION` o la sesión de boto3) para firmar solicitudes, o cuando la configuración de tiempo de ejecución no tiene una entrada para el servicio.

## Infraestructura

El rol del agente necesita permiso para llamar a la API HTTP del servicio. El generador no cambia tu stack o módulo raíz de Terraform. En su lugar, imprime el código a agregar, que se muestra a continuación para un agente llamado `my-agent` y un servicio llamado `my-service`. Hasta que lo agregues, la API HTTP rechaza las solicitudes del agente con 403 Forbidden.

<Infrastructure>
<Fragment slot="cdk">

En el ejemplo, `myService` es tu constructo `MyService` y `myAgent` es tu constructo `MyAgent`:

```ts title="packages/infra/src/stacks/application-stack.ts"
myService.grantInvoke(myAgent);
```

`grantInvoke` permite que el rol del agente llame a `execute-api:Invoke` en la API HTTP del servicio.

</Fragment>
<Fragment slot="terraform">

Agrega la declaración a los `additional_iam_policy_statements` del agente, junto a cualquier declaración que el bloque ya enumere. En el ejemplo, `module "my_service"` despliega el servicio:

```hcl title="packages/infra/src/main.tf"
module "my_agent" {
  source = "../../common/terraform/src/app/agents/my-agent"
  # ...existing arguments...
  additional_iam_policy_statements = [
    {
      Effect   = "Allow"
      Action   = ["execute-api:Invoke"]
      Resource = ["${module.my_service.api_execution_arn}/*"]
    },
  ]
}
```

</Fragment>
</Infrastructure>

## Desarrollo Local

<NxCommands commands={["<agent-name>-dev <project-name>"]} />

Esto inicia el agente y el objetivo `<service-name>-serve` del servicio. El objetivo de desarrollo del agente establece `LOCAL_DEV=true`, por lo que el cliente llama al servicio en `http://localhost:<port>` sin firmar. El puerto es el que el generador de contenedor asignó al servicio.
