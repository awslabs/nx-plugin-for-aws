El generador `connection` permite que tu sitio web React llame a un servicio de contenedor creado con <Link path="guides/ts-container">`ts#container`</Link> o <Link path="guides/py-container">`py#container`</Link>. Agrega un hook de React que lee la URL del servicio desde la configuración en tiempo de ejecución y añade la autenticación que el servicio espera a cada solicitud.

## Cómo funciona esto

Un servicio de contenedor con `infra=ecs` se ejecuta en Amazon ECS (Elastic Container Service) detrás de un Application Load Balancer interno. Con el `ingress=http-api` predeterminado, una API HTTP de Amazon API Gateway (un endpoint HTTPS administrado) alcanza ese balanceador de carga a través de un enlace VPC, que es la conexión privada de API Gateway a tu VPC. El sitio web llama a la API HTTP.

La opción `auth` del servicio decide cómo la API HTTP verifica cada solicitud:

- `iam` (predeterminado): la solicitud debe estar firmada con SigV4, el proceso de firma de solicitudes de AWS. El hook la firma con las credenciales temporales de AWS que el grupo de identidades de Cognito de tu sitio web le da a un usuario autenticado.
- `cognito`: la solicitud debe contener el token de acceso de Cognito del usuario autenticado como un token bearer.
- `none`: la API HTTP acepta cada solicitud.

La API HTTP finaliza cualquier solicitud que tarde más de 30 segundos, por lo que una ruta que se ejecute más tiempo debe retornar temprano y terminar su trabajo en segundo plano.

El generador rechaza un servicio al que no puede acceder. El servicio debe tener `infra=ecs`, porque `infra=none` no crea ningún endpoint. También debe tener `ingress=http-api`, porque un servicio `private` es accesible solo desde dentro de su VPC.

## Requisitos previos

Antes de usar este generador, asegúrate de tener:

1. Un sitio web React (generado usando el <Link path="guides/react-website">generador `ts#website`</Link>)
2. Un servicio de contenedor con `infra=ecs` e `ingress=http-api` (generado usando el generador <Link path="guides/ts-container">`ts#container`</Link> o <Link path="guides/py-container">`py#container`</Link>)
3. Cognito Auth agregado a través del <Link path="guides/react-website-auth">generador `ts#website#auth`</Link>, si el `auth` del servicio es `iam` o `cognito`

## Salida del Generador

El generador crea los siguientes archivos en tu sitio web React:

<FileTree>

- src
  - hooks
    - use\<ServiceName>.tsx Hook que devuelve la URL del servicio y un `fetch` que agrega la autenticación del servicio
    - useSigV4.tsx Hook para firmar solicitudes con SigV4 (solo `iam`)
  - components
    - RuntimeConfig/index.tsx Apunta el hook al servicio local en desarrollo local

</FileTree>

`<ServiceName>` es el nombre de clase del servicio, por ejemplo `useOrders` para un servicio llamado `orders`. El generador también agrega estas dependencias al sitio web:

- `aws4fetch`, `oidc-client-ts`, `@aws-sdk/credential-provider-cognito-identity`, `react-oidc-context`, y la dependencia de desarrollo `@smithy/types` (`iam`)
- `react-oidc-context` (`cognito`)

## Usando el Hook

El hook devuelve la `url` del servicio y una función `fetch`. `fetch` toma una ruta relativa al servicio y las opciones habituales de `fetch`:

```tsx
import { useEffect, useState } from 'react';
import { useMyService } from './hooks/useMyService';

export const ServiceStatus = () => {
  const myService = useMyService();
  const [status, setStatus] = useState<number>();

  useEffect(() => {
    myService.fetch('/health').then((response) => setStatus(response.status));
  }, [myService.fetch]);

  return <p>Service status: {status ?? 'loading'}</p>;
};
```

El servicio desplegado escribe su URL en la <Link path="guides/runtime-config">configuración en tiempo de ejecución</Link> bajo `connection.services.<ServiceName>`, que el sitio web lee desde `runtime-config.json`.

El sitio web llama a la API HTTP desde el navegador, por lo que la configuración de CORS (intercambio de recursos de origen cruzado) de la API HTTP debe permitir el origen del sitio web. El generador no las cambia. Por defecto, la API HTTP acepta solicitudes de cualquier origen, con los encabezados `authorization`, `content-type` y SigV4 que el hook envía. Para aceptar solicitudes solo de tu sitio web, llama a `myService.restrictCorsTo('https://<tu dominio del sitio web>')` en CDK. En Terraform, establece `cors_allow_origins` en el bloque `module "ecs_service"` del módulo de tu servicio. Para más detalles, consulta <Link path="guides/ts-container#cors-and-throttling">CORS and Throttling</Link>.

## Infraestructura

Para `auth=iam`, los usuarios autenticados del sitio web necesitan permiso para llamar a la API HTTP del servicio. El generador no cambia tu stack o módulo raíz de Terraform. En su lugar, imprime el código a agregar, que se muestra a continuación para un servicio llamado `my-service`. Hasta que lo agregues, la API HTTP rechazará las solicitudes del sitio web con 403 Forbidden. Para `cognito` y `none` no hay nada que agregar.

<Infrastructure>
<Fragment slot="cdk">

En el ejemplo, `myService` es tu constructo `MyService` e `identity` es tu constructo `UserIdentity`:

```ts title="packages/infra/src/stacks/application-stack.ts"
myService.grantInvoke(identity.identityPool.authenticatedRole);
```

`grantInvoke` permite que el rol autenticado del grupo de identidades llame a `execute-api:Invoke` en la API HTTP del servicio.

</Fragment>
<Fragment slot="terraform">

En el ejemplo, `module "my_service"` despliega el servicio y `module "user_identity"` despliega el grupo de identidades de tu sitio web:

```hcl title="packages/infra/src/main.tf"
resource "aws_iam_role_policy" "authenticated_my_service_invoke" {
  name = "authenticated-my-service-invoke"
  role = module.user_identity.authenticated_role_name

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = ["execute-api:Invoke"]
        Resource = ["${module.my_service.api_execution_arn}/*"]
      },
    ]
  })
}
```

## Desarrollo Local

<NxCommands commands={["dev <website-project-name>"]} />

El objetivo `dev` del sitio web también inicia el objetivo `<service-name>-serve` del servicio, y el hook llama al servicio en `http://localhost:<port>`. El puerto es el que el generador de contenedor asignó al servicio. En desarrollo local, el hook `useSigV4` no firma solicitudes cuando `runtime-config.json` no tiene configuraciones de Cognito.
