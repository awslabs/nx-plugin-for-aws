:::note[Configuración CORS en Terraform]
Si tu solución incluye un módulo de sitio web de Terraform, entonces puedes usar su nombre de dominio de CloudFront para restringir CORS.
Dado un nombre de dominio de CloudFront `<domain_name>`, dentro del módulo de Terraform para desplegar tu API agrega
- una propiedad `cors_allow_origins`, establecida en `["http://localhost:4200", "http://localhost:4300", "https://<domain name>"]`, para APIs HTTP. Esto restringe el CORS del API gateway a esta distribución y localhost.
- una variable de entorno `ALLOWED_ORIGINS`, establecida en `"https://<domain_name>"`, para APIs REST. Esto establece la distribución de CloudFront como el único origen CORS permitido (además de localhost) en las integraciones de AWS Lambda. Ten en cuenta que esta restricción no se aplica a las solicitudes preflight OPTIONS - por favor +1 en [este issue de GitHub](https://github.com/awslabs/nx-plugin-for-aws/issues/377) para ayudar a priorizar la resolución de esto.

```hcl {6,9}
module "my_api" {
  source = "../../common/terraform/src/app/apis/my-api"

  asset_bucket_name = module.asset_bucket.bucket_name

  cors_allow_origins = ["http://localhost:4200", "http://localhost:4300", "https://<domain name>"] // Only required for HTTP API

  env = {
    ALLOWED_ORIGINS = "https://<domain name>" // Only required for REST API
    ENVIRONMENT = var.environment
    LOG_LEVEL   = "INFO"
  }
}
```
El constructor `MyWebsite` puede ser generado usando el <Link path="/es/guides/react-website">generador `ts#website`</Link>. Este ejemplo asume que los puertos locales del sitio web son `4200`/`4300` - verifica su `project.json` (o `vite.config.mts`) para los puertos realmente asignados, ya que cada sitio web generado de esta manera obtiene los suyos propios.
:::
