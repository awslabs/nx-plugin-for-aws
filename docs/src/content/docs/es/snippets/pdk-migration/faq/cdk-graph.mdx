[CDK Graph](https://aws.github.io/aws-pdk/developer_guides/cdk-graph/index.html) construye gráficos de tus recursos CDK conectados, y proporcionó dos plugins:

#### Diagram Plugin

El [CDK Graph Diagram Plugin](https://aws.github.io/aws-pdk/developer_guides/cdk-graph-plugin-diagram/index.html) genera diagramas de arquitectura de AWS a partir de tu infraestructura CDK.

Para un enfoque determinístico similar, una alternativa viable es [CDK-Dia](https://github.com/pistazie/cdk-dia).

Con los avances en IA Generativa, muchos modelos fundacionales son capaces de crear diagramas de alta calidad a partir de tu infraestructura CDK. Recomendamos probar el [AWS Diagram MCP Server](https://github.com/awslabs/mcp/tree/main/src/aws-diagram-mcp-server). Consulta [esta publicación del blog](https://aws.amazon.com/blogs/machine-learning/build-aws-architecture-diagrams-using-amazon-q-cli-and-mcp/) para un tutorial.

#### Threat Composer Plugin

El [CDK Graph Threat Composer Plugin](https://aws.github.io/aws-pdk/developer_guides/cdk-graph-plugin-threat-composer/index.html) genera un [Threat Composer](https://github.com/awslabs/threat-composer/) inicial de modelo de amenazas a partir de tu código CDK.

Este plugin funcionaba simplemente filtrando un [modelo de amenazas base](https://github.com/aws/aws-pdk/tree/mainline/packages/cdk-graph-plugin-threat-composer/src/model-generator/base-model) que contenía amenazas de ejemplo, y filtrándolas según los recursos que tu stack utilizaba.

Si estás interesado en estas amenazas de ejemplo específicas, puedes copiar y filtrar el modelo de amenazas base, o usarlo como contexto para ayudar a un modelo fundacional a generar uno similar.
