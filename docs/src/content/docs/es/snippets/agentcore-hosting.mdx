---
title: Alojamiento de AgentCore Runtime
---

La opción `infra` selecciona cómo se empaqueta y aloja tu código en [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html):

- **`agentcore`** (predeterminado) utiliza [despliegue directo de código](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-code-deploy-node.html): tu código compilado se empaqueta como un `.zip`, se sube a S3 y se ejecuta en un runtime de lenguaje administrado por AgentCore. No hay imagen de contenedor que construir, no hay repositorio ECR que administrar y no hay imagen que enviar, lo que resulta en un ciclo de compilación e implementación sustancialmente más rápido.
- **`agentcore-ecr`** construye una imagen de contenedor `arm64` a partir de un `Dockerfile` proporcionado y la aloja desde ECR. Elige esta opción cuando necesites control sobre la imagen del sistema operativo — por ejemplo, para instalar bibliotecas nativas del sistema — o cuando tengas un pipeline de contenedores establecido. Esta opción también proporciona un objetivo de escaneo de imagen Trivy (consulta Escaneo de Imágenes a continuación).
- **`none`** no genera ninguna infraestructura, por lo que el proyecto solo se puede ejecutar localmente.

Ambas opciones alojadas están configuradas para observabilidad con [AWS Distro for OpenTelemetry](https://aws.amazon.com/otel/) (ADOT).

:::note[Docker solo es necesario para agentcore-ecr]
`agentcore` no necesita ningún motor de contenedores, por lo que no necesitas tener [Docker](https://www.docker.com/) instalado para compilar o desplegar. Selecciona `agentcore-ecr` si prefieres construir una imagen de contenedor, y asegúrate de que Docker esté instalado y en ejecución para evitar errores como:

```
ERROR: Cannot connect to the Docker daemon at unix://path/to/docker.sock.
```
:::
