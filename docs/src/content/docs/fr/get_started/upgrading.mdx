Nx et `@aws/nx-plugin` fournissent tous deux des migrations qui mettent à jour votre espace de travail automatiquement lorsque vous les mettez à niveau, en utilisant [`nx migrate`](https://nx.dev/docs/features/automate-updating-dependencies). Ce guide explique comment mettre à niveau chacun d'eux.

<Aside type="tip">
Vous pouvez utiliser l'outil de codage agentique de votre choix pour mettre à niveau votre espace de travail à votre place, en utilisant le <Link path="get_started/building-with-ai">serveur MCP</Link>. Essayez le prompt :

> Upgrade Nx and the Nx Plugin for AWS in this workspace.
</Aside>

`nx migrate <package>@<version>` cible le package que vous nommez — ainsi la mise à niveau de Nx lui-même et la mise à niveau de `@aws/nx-plugin` sont des mises à niveau distinctes, chacune suivant le même cycle :

<Steps>

1. **Générer** — `nx migrate <package>@latest` met à jour les versions du package dans `package.json` et écrit un fichier `migrations.json` listant les migrations à exécuter. Rien n'est installé et aucun autre fichier n'est touché pour l'instant, vous pouvez donc d'abord examiner les changements de version.

2. **Installer** — installez les nouvelles versions avec votre gestionnaire de packages (par exemple `pnpm install --no-frozen-lockfile`).

3. **Exécuter** — `nx migrate --run-migrations` applique chaque migration en attente à votre espace de travail, une à la fois.

4. **Valider** — vérifiez que votre espace de travail se construit, puis supprimez `migrations.json` et validez.

</Steps>

<Aside type="caution" title="Un package à la fois">
Complétez le cycle complet pour un package avant de commencer le suivant : chaque `nx migrate <package>` **écrase** `migrations.json`, donc exécuter `nx migrate @aws/nx-plugin@latest` suivi immédiatement de `nx migrate latest` supprime les migrations en attente du plugin avant qu'elles ne s'exécutent.
</Aside>

## Mise à niveau de @aws/nx-plugin

Commencez le cycle en ciblant le plugin :

<NxCommands commands={['migrate @aws/nx-plugin@latest']} />

```
 NX   The migrate command has run successfully.

- package.json has been updated.
- migrations.json has been generated.
- 1 AI migration prompt(s) have been written to tools/ai-migrations/.

 NX   Next steps:

- Make sure package.json changes make sense and then run 'pnpm install --no-frozen-lockfile',
- Review and tweak the AI migration prompts in tools/ai-migrations/ as needed.
- Run 'pnpm exec nx migrate --run-migrations'
- To learn more go to https://nx.dev/features/automate-updating-dependencies
```

Examinez les modifications de `package.json` puis installez :

<InstallDependenciesCommand />

Ensuite, exécutez les migrations :

<NxCommands commands={['migrate --run-migrations']} />

### Migrations déterministes

La plupart des migrations sont des codemods déterministes — elles s'exécutent sans surveillance et signalent tout ce qu'elles ont délibérément ignoré :

```
 NX   Running migrations from 'migrations.json'

Running the following migrations:
- @aws/nx-plugin: update-vitest-workspace-config — Add a coverage reporter to vitest configs
- @aws/nx-plugin: update-custom-api-handlers — Update custom API handlers for the new middleware signature

── Migration 1 of 2 · @aws/nx-plugin:update-vitest-workspace-config ─────
→ Running generator…
Changes:
  UPDATE packages/api/vite.config.mts

...

 NX   Successfully finished running migrations from 'migrations.json'.

2 migrations applied, 0 commits created.

 NX   Some migrations have additional information, see below.

- packages/website/vite.config.mts has a customised shape; add a coverage reporter manually.
```

Faites attention aux **informations supplémentaires** à la fin : lorsqu'une migration trouve un fichier que vous avez personnalisé au-delà de ce qu'elle peut mettre à jour en toute sécurité, elle laisse vos modifications intactes et signale le suivi manuel à effectuer à cet endroit.

### Migrations agentiques

Certaines migrations ciblent du code que vous possédez, où la bonne modification dépend de ce que vous avez construit — celles-ci sont fournies sous forme de prompts appliqués par votre agent de codage IA local (Claude Code, Codex ou OpenCode). Lorsqu'il y en a en attente, Nx demande le consentement avant d'impliquer un agent :

```
? Enable the agentic flow? …
❯ Yes, just this time      Apply 1 prompt migration and validate generator output with an AI agent
  Yes, always              Saved to nx.json so Nx won't ask again
  No, just this time       Skip prompts and run generators without AI validation
  No, never                Saved to nx.json so Nx won't ask again
```

Si vous acceptez, l'agent applique chaque migration de prompt en place et résume ce qu'il a modifié :

```
── Migration 2 of 2 · @aws/nx-plugin:update-custom-api-handlers ─────────
→ Running prompt with Claude Code…
✓ update-custom-api-handlers: Updated 3 API handlers to the new middleware signature.
```

Si vous refusez — ou qu'aucun agent n'est installé, ou que l'exécution est non interactive (par exemple CI) — les migrations de prompt sont ignorées et enregistrées pour que vous les appliquiez manuellement :

```
── Migration 2 of 2 · @aws/nx-plugin:update-custom-api-handlers ─────────
↷ Skipped — agentic flow disabled. Listed in next steps.

 NX   Successfully finished running migrations from 'migrations.json'.

1 migration applied, 0 commits created, 1 prompt migration skipped.

 NX   Some migrations have additional information, see below.

- Some prompt migrations were skipped. Review and apply each of the following
  prompt files to the workspace, in the listed order:
  - tools/ai-migrations/@aws/nx-plugin/2.0.0/prompt.md
```

Chaque prompt ignoré est un fichier d'instructions markdown autonome dans `tools/ai-migrations/` — collez-le dans votre agent de codage, ou suivez ses étapes manuellement.

Enfin, vérifiez que tout se construit toujours, puis supprimez `migrations.json` et validez :

<NxCommands commands={['run-many --target build --all']} />

## Mise à niveau de Nx

La mise à niveau de Nx lui-même (et de ses plugins `@nx/*`) suit le même cycle, en ciblant `nx` :

<NxCommands commands={['migrate latest']} />

Ensuite, installez, exécutez les migrations, vérifiez et validez comme précédemment :

<NxCommands commands={['migrate --run-migrations']} />

<Aside type="tip">
La mise à niveau de `@aws/nx-plugin` ne met pas à niveau Nx (ou vice versa) — `nx migrate` ne met à jour que le package que vous nommez. Lorsque vous sautez plusieurs versions majeures de Nx, mettez à niveau une version majeure à la fois — consultez [Automate Updating Dependencies](https://nx.dev/docs/features/automate-updating-dependencies) pour plus de détails.
</Aside>

## Mise à niveau avec un agent IA

L'ensemble du flux peut être piloté par un agent de codage IA de bout en bout — rien ne bloque sur un terminal interactif. Lorsque `nx migrate --run-migrations` s'exécute depuis l'intérieur d'un agent, Nx le détecte, ignore le prompt de consentement agentique, et au lieu de générer un agent imbriqué, il **reporte** chaque migration de prompt à l'agent qui pilote l'exécution :

```
── Migration 2 of 2 · @aws/nx-plugin:update-custom-api-handlers ─────────
↷ Skipped — deferred to the AI agent driving this run. Listed in next steps.

 NX   Successfully finished running migrations from 'migrations.json'.

1 migration applied, 0 commits created, 1 prompt migration deferred.

 NX   Next steps for the AI agent driving this run

Apply the deferred prompts below, in order:
  1. tools/ai-migrations/@aws/nx-plugin/2.0.0/prompt.md
       (update-custom-api-handlers — prompt-only migration)
Then relay these migration-emitted notes to the user:
  - packages/website/vite.config.mts has a customised shape; add a coverage reporter manually.
Finally, summarize what was done across the run and commit the changes per workspace conventions.
```

Un agent effectuant une mise à niveau devrait :

1. Exécuter le cycle ci-dessus pour un package à la fois (`nx migrate <package>@latest`, installer, `nx migrate --run-migrations`), en passant `--no-interactive` pour supprimer les prompts restants.
2. Après l'exécution, lire chaque fichier de prompt reporté listé sous **Next steps**, dans l'ordre indiqué, et appliquer ses étapes directement à l'espace de travail.
3. Relayer toutes les notes émises par les migrations (fichiers personnalisés ignorés, suivis manuels) à l'utilisateur.
4. Vérifier que l'espace de travail se construit, puis supprimer `migrations.json` et valider avant de commencer la mise à niveau du package suivant.
e à niveau du package suivant.
s supprimer `migrations.json` et valider avant de commencer la mise à niveau du package suivant.
