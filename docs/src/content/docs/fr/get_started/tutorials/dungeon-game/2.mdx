## Tâche 1 : Implémenter l'API Game

Nous allons implémenter les API suivantes dans cette section :

1. `saveGame` - créer ou mettre à jour une partie.
2. `queryGames` - retourner une liste paginée des parties précédemment sauvegardées.
3. `queryInventory` - retourner une liste paginée des objets dans l'inventaire d'un joueur.
4. `queryActions` - retourner l'historique de conversation pour une partie donnée.

:::note[Où chaque élément d'état réside]
- `games` et `inventory` sont dans **DynamoDB** (via ElectroDB) — les lambdas de l'API Game et le serveur MCP Inventory les lisent/écrivent.
- `actions` (transcription du chat) est dans **S3** — le `S3SessionManager` du Story Agent écrit un blob JSON par tour, et `queryActions` dans l'API Game les relit pour que l'interface utilisateur puisse rejouer l'historique lors du rechargement de la page. Il n'y a pas de procédure `saveAction` ; l'agent est le seul rédacteur.
:::

## Tâche 4 : Tester l'API Game localement

Il n'est pas nécessaire de déployer sur AWS pour essayer notre API — la cible `dev` exécute l'API Game contre [DynamoDB Local](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/DynamoDBLocal.html). Parce que nous avons connecté l'API Game au projet `DungeonDb` dans le Module 1, cette cible démarre également DynamoDB Local automatiquement.

Les procédures et le serveur MCP que nous venons d'écrire importent `@dungeon-adventure/dungeon-db`, une nouvelle importation inter-projets, donc commencez par synchroniser l'espace de travail :

</Aside>

### Démarrer le serveur local

Démarrez l'API Game localement avec la cible `dev`, qui démarre également DynamoDB Local :

<NxCommands commands={["dev game-api"]} />

<Aside type="tip" title="Première exécution">
La première exécution télécharge l'image du conteneur DynamoDB Local, ce qui peut prendre un moment. Laissez le serveur s'exécuter dans ce terminal et ouvrez un second terminal pour les commandes `curl` ci-dessous.
</Aside>

### Tester l'API

Une fois votre serveur opérationnel, interrogez la liste (vide) des parties :

```bash
curl -X GET 'http://localhost:2022/games.query?input=%7B%7D'
```

:::note[Encodage d'URL]
Le `%7B%7D` que nous passons pour tester l'API est un objet JSON vide encodé en URI (`{}`).
:::

Vous verrez une liste vide :

```json
{"result":{"data":{"items":[],"cursor":null}}}
```

Maintenant, sauvegardez une partie :

```bash
curl -X POST 'http://localhost:2022/games.save' \
  -H 'Content-Type: application/json' \
  -d '{"playerName":"Alice","genre":"zombie"}'
```

La sauvegarde retourne la partie persistée (avec l'horodatage `lastUpdated` que l'entité définit pour vous) :

```json
{"result":{"data":{"playerName":"Alice","genre":"zombie","lastUpdated":"..."}}}
```

Interrogez à nouveau pour confirmer qu'elle est persistée dans DynamoDB Local :

```bash
curl -X GET 'http://localhost:2022/games.query?input=%7B%7D'
```

Cette réponse inclut maintenant la partie sauvegardée :

```json
{"result":{"data":{"items":[{"playerName":"Alice","genre":"zombie","lastUpdated":"..."}],"cursor":null}}}
```

Vous pouvez arrêter le serveur local (`Ctrl+C`) une fois que vous avez terminé.

## Tâche 5 : Tester le serveur MCP Inventory localement

Nous pouvons essayer les outils du serveur MCP avec le [MCP Inspector](https://github.com/modelcontextprotocol/inspector) en utilisant la cible générée `mcp-server-inspect` :

<NxCommands commands={["mcp-server-inspect inventory"]} />

Cela sert le serveur MCP localement (en démarrant également DynamoDB Local) et lance le MCP Inspector à `http://localhost:6274` préconfiguré pour s'y connecter. Basculez l'interrupteur à côté du serveur `localhost:8000` pour vous connecter, passez à l'onglet **Tools**, et essayez `add-to-inventory` (par exemple `playerName: Alice`, `itemName: Rusty Sword`, `emoji: ⚔️`) suivi de `list-inventory-items` pour le voir persisté dans DynamoDB Local. Arrêtez le serveur (`Ctrl+C`) lorsque vous avez terminé.
