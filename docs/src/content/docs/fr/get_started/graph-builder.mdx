Esquissez les projets dont votre espace de travail a besoin et les connexions entre eux, et le constructeur génère les commandes qui génèrent exactement ce que vous avez dessiné. Copiez-les, exécutez-les, et vous avez un espace de travail fonctionnel.

Faites glisser les composants de la palette sur le canevas, faites glisser depuis le bord droit d'un composant vers un autre pour les connecter, et modifiez les propriétés de chaque composant sur la droite. Les commandes générées en bas se mettent à jour à chaque changement — cliquez sur **Copy** pour prendre le script complet.

## Comment ça fonctionne

Chaque composant sur le canevas correspond à un générateur, et chaque connexion au <Link path="guides/connection">générateur de connexion</Link>. Les commandes sont émises dans l'ordre des dépendances : l'espace de travail d'abord, puis les projets, puis les composants qu'ils hébergent, puis les connexions qui les relient.

Un projet `infra` est ajouté à la fin — <Link path="guides/typescript-infrastructure">`ts#infra`</Link> ou <Link path="guides/terraform-project">`terraform#project`</Link>, correspondant à votre choix d'IaC. Chaque projet généré fournit des constructions pour qu'il puisse les instancier, c'est donc ce que vous déployez. Parce qu'il possède ce nom, aucun composant sur le canevas ne peut s'appeler `infra`.

Faites glisser l'arrière-plan du canevas pour vous déplacer, et faites glisser un composant pour le repositionner. Shift-clic pour sélectionner plusieurs composants et les déplacer en groupe. Cliquez sur une connexion pour la sélectionner, puis appuyez sur <kbd>Delete</kbd> pour la supprimer (ou utilisez le ✕ sur la connexion elle-même).

La palette répertorie tous les types de projets et de composants qui peuvent participer à une connexion, et vous ne pouvez dessiner que les connexions prises en charge par le plugin — donc un graphe qui valide est un graphe qui se génère.

Deux règles sont à connaître :

- **Les composants partagent un projet hôte.** Un agent et un serveur MCP sont ajoutés _à_ un projet plutôt que d'être des projets à part entière. Donnez-leur le même nom de projet hôte pour les placer dans un seul projet, ou des noms différents pour un projet chacun.
- **Certaines connexions contraignent leurs points de terminaison.** Connecter un agent à un autre agent nécessite que la cible utilise le protocole `a2a`, par exemple. Lorsqu'un paramètre de propriété casserait une connexion que vous avez dessinée, le constructeur le signale sur le composant et la connexion.

:::tip[Vous préférez construire avec l'IA ?]
Le plugin fournit un serveur MCP, donc votre agent de codage peut générer et connecter des projets pour vous. Voir <Link path="get_started/building-with-ai">Construire avec l'IA</Link>.
:::
