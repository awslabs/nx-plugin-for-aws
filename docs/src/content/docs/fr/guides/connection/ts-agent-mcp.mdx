Le générateur `connection` peut connecter votre <Link path="guides/ts-agent">Agent TypeScript</Link> à un serveur MCP (soit <Link path="guides/ts-mcp-server">TypeScript</Link> soit <Link path="guides/py-mcp-server">Python</Link>).

Le générateur configure tout le câblage nécessaire pour que votre agent puisse découvrir et invoquer les outils du serveur MCP, à la fois lorsqu'il est déployé sur AWS (via Bedrock AgentCore) et lors de l'exécution locale.

## Prérequis

Avant d'utiliser ce générateur, assurez-vous d'avoir :

1. Un projet TypeScript avec un composant <Link path="guides/ts-agent">Strands Agent</Link>
2. Un projet avec un composant serveur MCP (soit <Link path="guides/ts-mcp-server">`ts#mcp-server`</Link> soit <Link path="guides/py-mcp-server">`py#mcp-server`</Link>)
3. Les deux composants créés avec `infra: agentcore`

## Sortie du générateur

Le générateur crée un package partagé `agent-connection` et modifie le code de votre agent :

<FileTree>

- packages/common/agent-connection
  - src
    - app
      - \<mcp-server-name>-client-strands.ts Client Strands de haut niveau pour le serveur MCP connecté
    - core
      - agentcore-endpoints.ts Résolution ARN/URL indépendante du framework
      - agentcore-fetch.ts Fetch SigV4 / JWT / session-forwarding indépendant du framework
      - agentcore-transport.ts Plomberie de transport AgentCore partagée
      - agentcore-mcp-transport.ts Transport MCP indépendant du framework
      - agentcore-mcp-client-strands.ts Client MCP Strands encapsulant le transport
    - index.ts Exporte tous les clients
  - project.json
  - tsconfig.json

</FileTree>

De plus, il :
- Transforme le fichier `agent.ts` de votre agent pour importer et utiliser les outils du serveur MCP
- Met à jour la cible `dev` de l'agent pour dépendre de la cible serve du serveur MCP
- Installe les dépendances requises

## Utiliser le serveur MCP connecté

Le générateur transforme le fichier `agent.ts` de votre agent pour utiliser les outils du serveur MCP :

```ts title="packages/example/src/my-agent/agent.ts" {2,5,8}
import { Agent, tool } from '@strands-agents/sdk';
import { MyMcpServerClientStrands } from '@my-scope/agent-connection';

export const getAgent = async () => {
  const myMcpServerClient = await MyMcpServerClientStrands.create();
  return new Agent({
    systemPrompt: '...',
    tools: [myMcpServerClient],
  });
};
```

L'ID de session AgentCore est propagé automatiquement au serveur MCP via l'en-tête `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id`, donc `create()` ne prend aucun argument : le serveur de l'agent lie la session de la requête entrante dans un contexte [`AsyncLocalStorage`](https://nodejs.org/api/async_context.html#class-asynclocalstorage) (`enterSessionContext` dans le `router.ts` généré, ou `runWithSessionId` dans le middleware de session A2A/AG-UI), et le fetch du client de connexion dans `agentcore-fetch.ts` l'appose sur chaque appel sortant — garantissant la cohérence pour l'[observabilité Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html).

## Infrastructure

<Snippet name="connection/infra-project-prerequisite" />

<Infrastructure>
<Fragment slot="cdk">
Après avoir exécuté le générateur de connexion, vous devez accorder à l'agent la permission d'invoquer le serveur MCP :

```ts title="packages/infra/src/stacks/application-stack.ts" {5}
const mcpServer = new MyMcpServer(this, 'MyMcpServer');
const myAgent = new MyAgent(this, 'MyAgent');

// Grant the agent permissions to invoke the MCP server
mcpServer.grantInvokeAccess(myAgent);
```

`grantInvokeAccess` configure les actions d'invocation AgentCore (`InvokeAgentRuntime`, `InvokeAgentRuntimeForUser` et `InvokeAgentRuntimeWithWebSocketStream`) sur l'ARN du runtime du serveur MCP.

L'ARN du runtime AgentCore du serveur MCP est automatiquement enregistré dans l'espace de noms `agentcore` de la <Link path="guides/runtime-config">Configuration d'exécution</Link> par la construction CDK générée, afin que l'agent puisse le découvrir au moment de l'exécution.
</Fragment>
<Fragment slot="terraform">
Après avoir exécuté le générateur de connexion, vous devez accorder à l'agent la permission d'invoquer le serveur MCP dans votre configuration Terraform :

```hcl title="packages/infra/src/main.tf" {9-31}
module "inventory_mcp_server" {
  source = "../../common/terraform/src/app/mcp-servers/inventory-mcp"
}

module "story_agent" {
  source = "../../common/terraform/src/app/agents/story-agent"
}

# Grant the agent permissions to invoke the MCP server
resource "aws_iam_policy" "agent_invoke_mcp" {
  name = "AgentInvokeMcpPolicy"
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect = "Allow"
      Action = [
        "bedrock-agentcore:InvokeAgentRuntime",
        "bedrock-agentcore:InvokeAgentRuntimeWithWebSocketStream",
      ]
      Resource = [
        module.inventory_mcp_server.agent_core_runtime_arn,
        "${module.inventory_mcp_server.agent_core_runtime_arn}/*",
      ]
    }]
  })
}

resource "aws_iam_role_policy_attachment" "agent_invoke_mcp" {
  role       = module.story_agent.agent_core_runtime_role_arn
  policy_arn = aws_iam_policy.agent_invoke_mcp.arn
}
```

L'ARN du runtime AgentCore du serveur MCP est automatiquement enregistré dans l'espace de noms `agentcore` de la <Link path="guides/runtime-config">Configuration d'exécution</Link> par le module Terraform généré, afin que l'agent puisse le découvrir au moment de l'exécution.
</Fragment>

## Développement local

Le générateur configure la cible `dev` de l'agent pour :
1. Démarrer automatiquement le(s) serveur(s) MCP connecté(s)
2. Définir `LOCAL_DEV=true` afin que le client généré utilise le transport HTTP direct au lieu d'AgentCore

Exécutez l'agent localement avec :

<NxCommands commands={["<agent-name>-dev <project-name>"]} />

Cela démarrera à la fois l'agent et tous les serveurs MCP connectés, l'agent se connectant aux serveurs MCP directement via HTTP sur leurs ports locaux assignés.
