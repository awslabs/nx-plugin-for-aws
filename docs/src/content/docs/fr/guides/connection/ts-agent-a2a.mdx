Le générateur `connection` peut connecter votre <Link path="guides/ts-agent">TypeScript Agent</Link> à un agent [A2A](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-a2a.html) distant — soit <Link path="guides/ts-agent">TypeScript</Link> soit <Link path="guides/py-agent">Python</Link> — afin que votre agent puisse déléguer à un autre agent en tant qu'outil.

Le générateur configure tout le câblage nécessaire pour que votre agent puisse découvrir et invoquer l'agent A2A distant, à la fois lorsqu'il est déployé sur AWS (via Bedrock AgentCore) et lors de l'exécution locale.

## Prérequis

Avant d'utiliser ce générateur, assurez-vous d'avoir :

1. Un projet TypeScript avec un composant <Link path="guides/ts-agent">Strands Agent</Link> (n'importe quel protocole)
2. Un projet avec un composant Agent généré avec `--protocol=a2a` et `--auth=iam` (soit <Link path="guides/ts-agent">`ts#agent`</Link> soit <Link path="guides/py-agent">`py#agent`</Link>)
3. Les deux composants créés avec `infra: agentcore`

## Sortie du générateur

Le générateur crée un package partagé `agent-connection` et modifie le code de votre agent :

<FileTree>

- packages/common/agent-connection
  - src
    - app
      - \<target-agent-name>-client-strands.ts High-level Strands client for the connected A2A agent
    - core
      - agentcore-endpoints.ts Framework-agnostic ARN/URL resolution
      - agentcore-fetch.ts Framework-agnostic SigV4 / JWT / session-forwarding fetch
      - agentcore-a2a-client-config.ts Framework-agnostic A2A client config (signed `clientFactory`)
      - agentcore-a2a-client-strands.ts Strands A2A client wrapping the config
    - index.ts Exports all clients
  - project.json
  - tsconfig.json

</FileTree>

De plus, il :
- Transforme le fichier `agent.ts` de votre agent pour enregistrer l'agent A2A distant en tant qu'`tool` Strands
- Met à jour la cible `dev` de l'agent pour dépendre de la cible `dev` de l'agent cible
- Installe les dépendances requises

## Utiliser l'agent A2A connecté

Le générateur transforme le fichier `agent.ts` de votre agent pour encapsuler l'agent A2A distant en tant qu'outil :

```ts title="packages/example/src/my-agent/agent.ts" {2,5-12,15}
import { Agent, tool } from '@strands-agents/sdk';
import { RemoteAgentClientStrands } from '@my-scope/agent-connection';
import { z } from 'zod';

export const getAgent = async () => {
  const remoteAgent = await RemoteAgentClientStrands.create();
  const remoteAgentTool = tool({
    name: 'askRemoteAgent',
    description: 'Delegate a question to the remote RemoteAgent A2A agent and return its reply.',
    inputSchema: z.object({ prompt: z.string() }),
    callback: async ({ prompt }) => (await remoteAgent.invoke(prompt)).toString(),
  });
  return new Agent({
    systemPrompt: '...',
    tools: [remoteAgentTool],
  });
};
```

L'ID de session AgentCore est propagé automatiquement à l'agent distant via l'en-tête `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id`, donc `create()` ne prend aucun argument : le serveur d'agent lie la session de la requête entrante dans un contexte [`AsyncLocalStorage`](https://nodejs.org/api/async_context.html#class-asynclocalstorage) (`enterSessionContext` dans le `router.ts` généré, ou `runWithSessionId` dans le middleware de session A2A/AG-UI), et le fetch du client de connexion dans `agentcore-fetch.ts` l'appose sur chaque appel sortant — garantissant la cohérence pour l'[observabilité Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html).

Sous le capot, `RemoteAgentClientStrands.create()` retourne un `A2AAgent` Strands configuré avec une `clientFactory` signant SigV4 lorsqu'il est déployé sur AWS, et un point de terminaison `http://localhost:<port>/` simple lorsque `LOCAL_DEV=true`. La signature et la résolution du point de terminaison se trouvent dans le fichier `agentcore-a2a-client-config.ts` indépendant du framework ; seul le mince `agentcore-a2a-client-strands.ts` dépend de Strands.

## Développement local

Le générateur configure la cible `dev` de l'agent hôte pour :
1. Démarrer automatiquement le(s) agent(s) A2A connecté(s)
2. Définir `LOCAL_DEV=true` afin que le client généré se connecte directement à `http://localhost:<port>/` au lieu d'AgentCore

Exécutez l'agent localement avec :

<NxCommands commands={["<agent-name>-dev <project-name>"]} />

Cela démarrera à la fois l'agent hôte et tous les agents A2A connectés, l'agent hôte appelant les agents distants via HTTP simple sur leurs ports locaux assignés.
