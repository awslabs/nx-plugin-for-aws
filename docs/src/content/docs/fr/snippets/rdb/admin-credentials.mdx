---
title: Identifiants administrateur
---
import Infrastructure from '@components/infrastructure.astro';

Le mot de passe de l'utilisateur administrateur (master) Aurora est généré et pivoté par Aurora lui-même dans AWS Secrets Manager, en utilisant les [mots de passe d'utilisateur master gérés par RDS](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/rds-secrets-manager.html). Votre code d'infrastructure ne reçoit jamais le mot de passe, il ne peut donc pas fuir dans un modèle CloudFormation ou un fichier d'état Terraform. Aurora pivote le secret tous les 7 jours sans aucune fonction de rotation à déployer ou maintenir.

Le secret est chiffré avec la même clé KMS gérée par le client que le cluster.

Votre application n'utilise jamais ces identifiants. Elle se connecte en tant qu'utilisateur de base de données à privilèges minimaux en utilisant l'authentification IAM — seuls les gestionnaires de migration et de création d'utilisateur de base de données lisent le secret administrateur, et chacun se voit accorder l'accès uniquement à ce secret et à sa clé KMS.

<Infrastructure>
<Fragment slot="cdk">

Le secret administrateur est exposé en tant que `secret.secretArn` sur le cluster sous-jacent, et `grantSecretRead` accorde à un consommateur un accès en lecture à celui-ci :

```ts title="packages/infra/src/stacks/application-stack.ts"
import { MyDatabase } from '@my-scope/common-constructs';

const db = new MyDatabase(this, 'Db', { ... });

db.grantSecretRead(myFunction);
```
</Fragment>
<Fragment slot="terraform">

L'ARN du secret administrateur est exposé en tant que sortie `secret_arn`, aux côtés du `kms_key_arn` nécessaire pour le déchiffrer :

```hcl title="packages/infra/src/main.tf"
module "my_database" {
  source = "../../common/terraform/src/app/dbs/my-database"
  ...
}

output "database_secret_arn" {
  value = module.my_database.secret_arn
}
```

Un secret géré par RDS contient un objet JSON avec uniquement `username` et `password` — aucun détail de connexion. Prenez l'hôte, le port et le nom de la base de données à partir des sorties `writer_endpoint`, `cluster_port` et `database_name` du module.
</Fragment>
</Infrastructure>
