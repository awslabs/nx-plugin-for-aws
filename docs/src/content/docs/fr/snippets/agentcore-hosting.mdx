---
title: Hébergement du Runtime AgentCore
---

L'option `infra` sélectionne la manière dont votre code est empaqueté et hébergé sur [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) :

- **`agentcore`** (par défaut) utilise le [déploiement direct de code](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-code-deploy-node.html) : votre code compilé est empaqueté sous forme de `.zip`, téléchargé vers S3, et exécuté sur un runtime de langage géré par AgentCore. Il n'y a pas d'image de conteneur à construire, pas de dépôt ECR à gérer, et pas d'image à pousser, ce qui permet un cycle de construction et de déploiement nettement plus rapide.
- **`agentcore-ecr`** construit une image de conteneur `arm64` à partir d'un `Dockerfile` fourni et l'héberge depuis ECR. Choisissez cette option lorsque vous avez besoin de contrôler l'image du système d'exploitation — par exemple pour installer des bibliothèques système natives — ou lorsque vous disposez d'un pipeline de conteneurs établi. Cette option fournit également une cible d'analyse d'image Trivy (voir Analyse d'image ci-dessous).
- **`none`** ne génère aucune infrastructure, de sorte que le projet ne peut être exécuté que localement.

Les deux options hébergées sont configurées pour l'observabilité avec [AWS Distro for OpenTelemetry](https://aws.amazon.com/otel/) (ADOT).

:::note[Docker n'est requis que pour agentcore-ecr]
`agentcore` n'a besoin d'aucun moteur de conteneur, vous n'avez donc pas besoin d'avoir [Docker](https://www.docker.com/) installé pour construire ou déployer. Sélectionnez `agentcore-ecr` si vous préférez construire une image de conteneur, et assurez-vous que Docker est installé et en cours d'exécution pour éviter des erreurs telles que :

```
ERROR: Cannot connect to the Docker daemon at unix://path/to/docker.sock.
```
:::
