title: Domaine personnalisé

Par défaut, votre API est servie depuis le point de terminaison généré par API Gateway (`https://<id>.execute-api.<region>.amazonaws.com/...`). Pour la servir depuis votre propre domaine à la place, fournissez votre nom de domaine et un [certificat ACM](https://docs.aws.amazon.com/acm/latest/userguide/acm-overview.html) pour celui-ci. Le domaine personnalisé utilise un point de terminaison régional, donc le certificat doit être dans la même région que votre API. Une version TLS minimale de 1.2 est appliquée.

Lorsqu'un domaine personnalisé est configuré, l'URL de l'API dans la <Link path="guides/runtime-config">Configuration d'exécution</Link> est l'URL du domaine personnalisé, de sorte que votre site web et autres clients appellent votre domaine plutôt que le point de terminaison généré.

<Infrastructure>
<Fragment slot="cdk">
Passez le domaine à `super` dans le fichier généré `packages/common/constructs/src/app/apis/my-api.ts` :

<OptionFilter when={{ infra: 'rest-lambda' }} description="Custom domain for a REST API in CDK">
```ts {1, 6-13} title="packages/common/constructs/src/app/apis/my-api.ts"
import { Certificate } from 'aws-cdk-lib/aws-certificatemanager';

super(scope, id, {
  apiName: 'MyApi',
  // ...
  domainName: {
    domainName: 'api.example.com',
    certificate: Certificate.fromCertificateArn(
      scope,
      'MyApiCertificate',
      'arn:aws:acm:<region>:123456789012:certificate/...',
    ),
  },
  ...props,
});
```

L'API est servie à la racine du domaine, sans le préfixe de chemin de stage (`/prod/`). Pour la servir sous un chemin à la place, définissez `basePath` sur `domainName` ; l'URL dans la configuration d'exécution l'inclut.
</OptionFilter>

<OptionFilter when={{ infra: 'http-lambda' }} description="Custom domain for an HTTP API in CDK">
```ts {1-2, 7-16} title="packages/common/constructs/src/app/apis/my-api.ts"
import { DomainName } from 'aws-cdk-lib/aws-apigatewayv2';
import { Certificate } from 'aws-cdk-lib/aws-certificatemanager';

super(scope, id, {
  apiName: 'MyApi',
  // ...
  defaultDomainMapping: {
    domainName: new DomainName(scope, 'MyApiDomainName', {
      domainName: 'api.example.com',
      certificate: Certificate.fromCertificateArn(
        scope,
        'MyApiCertificate',
        'arn:aws:acm:<region>:123456789012:certificate/...',
      ),
    }),
  },
  ...props,
});
```
</OptionFilter>

Lorsqu'un domaine personnalisé est configuré, la stack produit en sortie `MyApiDomainNameAlias`, le nom de domaine régional vers lequel pointer votre enregistrement DNS, et `MyApiDomainNameAliasHostedZoneId`.
</Fragment>
<Fragment slot="terraform">
Définissez les variables `custom_domain_name` et `acm_certificate_arn` sur le module API :

```hcl {5-6} title="packages/infra/src/main.tf"
module "my_api" {
  source = "../../common/terraform/src/app/apis/my-api"
  # ...

  custom_domain_name  = "api.example.com"
  acm_certificate_arn = "arn:aws:acm:<region>:123456789012:certificate/..."
}
```

Le module produit en sortie `custom_domain_target_domain_name`, le nom de domaine régional vers lequel pointer votre enregistrement DNS, et `custom_domain_hosted_zone_id`. Sa sortie `api_url` est l'URL que les clients doivent appeler : l'URL du domaine personnalisé lorsqu'un domaine est configuré, sinon l'URL d'invocation du stage.
</Fragment>
</Infrastructure>

Enfin, créez un enregistrement DNS pour votre domaine. Avec n'importe quel fournisseur DNS, créez un enregistrement `CNAME` pointant votre domaine vers le nom de domaine régional produit en sortie ci-dessus. Si votre domaine est hébergé dans Route 53, vous pouvez créer un enregistrement alias à la place, en utilisant l'ID de zone hébergée produit en sortie, qui fonctionne également à l'apex de la zone (par exemple `example.com`).
